# Sandbox-Boundary Probing: Do Agents Test Their Cage Before or After Being Asked?

**Problem:** Containment chain: agent placed in sandbox -> boundary (no network, restricted FS) blocks harmful action -> agent stays contained. The under-studied link is unprompted boundary-probing: whether agents spontaneously test the edges of their sandbox (attempt network, escalate, enumerate filesystem) even when the task does not require it.

**Direction:** Run an open agent in a locked-down sandbox (network disabled, restricted FS) on benign tasks that never require boundary-pushing. Log all tool calls and flag any that probe the boundary (ping external host, list parent dirs, attempt sudo). Measure unprompted-probing rate per task and whether explicit 'you may test your environment' framing increases it. Report a probing-propensity baseline across models.

**Why it matters:** Spontaneous boundary-probing is an early warning sign of agents that will exploit containment gaps. A reproducible measurement of baseline probing propensity in a cheap sandbox is exactly the kind of safer-sandbox monitoring infrastructure favored for out-of-lab work.

**Relevant context:** Reward-hacking sandbox setups (arXiv 2603.04069, 2605.02964) expose bash/python/file tools with network disabled at the boundary. SENTINEL (OpenReview vCyxemIKLL) formalizes state invariants for embodied agents. Unprompted boundary-probing as a measured propensity in a contained sandbox is the gap; trivially feasible with a local Docker sandbox.
