# Empirical Sample-Complexity of Detecting Reward Gaming from Behavior Alone

**Problem:** Theory says reward gaming is detectable in principle if you can compare proxy and true return, but in deployment you often only observe behavior. How many trajectories must a monitor see to distinguish a gaming policy from an honest one? This learning-theoretic question is under-explored empirically.

**Direction:** In a small enumerable environment with a known true and proxy reward, generate trajectory samples from an honest policy and a gaming policy. Train a simple classifier (or use a likelihood-ratio test) on observed-behavior features and measure detection accuracy vs number of observed trajectories — an empirical sample-complexity curve for gaming detection. Vary how 'subtle' the gaming is.

**Why it matters:** Quantifies the monitoring budget needed to catch reward hacking — directly informing oversight/control infrastructure. Pure simulation, no GPU, and a building block for safer monitoring harnesses.

**Relevant context:** Skalse et al. (arXiv 2209.13085) define gaming via proxy-vs-true return divergence. Lilian Weng 'Reward Hacking in Reinforcement Learning' surveys detection difficulty.
