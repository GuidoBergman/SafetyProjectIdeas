# Best-of-n as a reward-hacking amplifier: where does the proxy-true correlation invert?

**Problem:** Best-of-n / rejection sampling against a reward model is a common alignment technique, and theory warns that as n grows the selected sample increasingly exploits proxy errors. The empirical n at which a real open reward model's selections stop improving true quality and start degrading it is rarely pinned down on small models.

**Direction:** Take an open-source reward model and a small open generator. For a set of prompts, sample n completions, score with the reward model, and evaluate the best-of-n pick's *true* quality with an independent rubric/judge. Sweep n from 1 to a few hundred and plot true-quality vs n, locating the inversion point where increasing optimization pressure hurts. Relate the inversion point to reward-model confidence.

**Why it matters:** Gives a concrete, reproducible measurement of the extremal-Goodhart failure underlying RLHF/best-of-n pipelines — a safety-relevant, capability-scaling threat — using only public models and no training.

**Relevant context:** Grounded in reward-hacking-in-RLVR findings that more optimization yields more hacking (arXiv:2604.15149, arXiv:2605.02964) and the classic best-of-n KL/reward-overoptimization framing.
