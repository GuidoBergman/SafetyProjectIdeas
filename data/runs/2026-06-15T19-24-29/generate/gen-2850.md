# A Lightweight Score-Distribution Anomaly Detector for Sandbagging

**Problem:** If a model sandbags by lowering accuracy, its per-item error pattern may look statistically different from a genuinely weaker model (e.g. missing easy items it should know). There is no simple, dependency-free tool that flags such anomalies from raw eval logs.

**Direction:** Use item difficulty estimated from a reference panel of models, then compute a per-model 'person-fit'-style residual: does the model miss easy items while passing hard ones? Build a small Python tool that ingests Inspect-style logs and outputs an anomaly score. Validate by inducing sandbagging via prompting on an open model and checking the detector separates honest-weak vs. sandbagged-strong runs.

**Why it matters:** Provides evaluators a cheap, post-hoc screening signal needing only eval logs (no weights access), directly targeting the unsolved 'detect concealed capability' problem. Counterfactually valuable outside labs.

**Relevant context:** Open Problem: 'Develop evaluations that detect dangerous capabilities models may be concealing (sandbagging)' (100+ Open Problems in Evals). Detection 'suffers from false positives'; only on-distribution finetuning reliably removes sandbagging (auditing-game results). Item-difficulty patterns are an unexploited signal distinct from IRT person-fit already catalogued.
