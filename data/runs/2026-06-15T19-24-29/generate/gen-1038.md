# Homogeneity of Code Suggestions: Do Models Recommend the Same Insecure Pattern?

**Problem:** Hivemind studied natural-language creativity. In code generation, homogeneity has a sharp safety edge: if many models default to the same insecure idiom (e.g. the same SQL-injection-prone pattern), a shared blind spot propagates into real software at scale.

**Direction:** Vary the domain of the homogeneity experiment to code. On a fixed set of open-ended coding prompts that admit secure and insecure solutions, collect completions from several open code models and measure (a) how often they converge on the SAME solution structure and (b) whether the shared solution carries the same security flaw, using a static analyzer for labeling.

**Why it matters:** Correlated insecure-code suggestions are a concrete, near-to-medium-horizon systemic vulnerability in the software supply chain. Static-analysis-based labeling makes it tractable and objective on a single GPU.

**Relevant context:** Artificial Hivemind (arXiv:2510.22954); correlated errors (arXiv:2506.07962); open code models (Qwen-Coder, StarCoder-class); public insecure-code prompt sets.
