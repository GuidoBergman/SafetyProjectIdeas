# The Sandbox-Escape Recognition Link: Do Eval Harnesses Leak That They Are Sandboxes?

**Problem:** Safe-eval chain: dangerous capability is tested in a sandbox -> model must believe it is in a real environment to behave naturally -> if model detects the sandbox, it sandbags or behaves safely -> eval invalid. The under-studied link is which sandbox artifacts (fake hostnames, stub APIs, suspiciously permissive permissions) tip off the model.

**Direction:** Build a toy agentic sandbox with several detectability levels (obvious stub responses vs realistic mocked services) and prompt a small open agent to assess whether it is in a test environment. Measure detection rate per artifact and whether detection correlates with more cautious behavior, yielding a checklist of sandbox-realism best practices.

**Why it matters:** Produces directly reusable guidance for building safer, less-detectable eval sandboxes (strategically valuable infrastructure) and quantifies how sandbox detection invalidates dangerous-capability evals. Open models + toy sandbox only.

**Relevant context:** Eval-awareness work (arXiv 2510.20487, 2507.01786) shows models distinguish eval vs deployment; ForesightSafety/RepliBench run dangerous-capability tests in sandboxes whose realism directly affects validity.
