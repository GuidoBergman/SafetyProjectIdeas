# Replicating SAE Feature Splitting Behavior Across Dictionary Sizes on Vision Transformers

**Problem:** In language SAEs, increasing dictionary size causes 'feature splitting' — a coarse feature fractures into multiple specific ones. ViT-Prisma offers SAEs of varying widths but whether vision SAEs exhibit the same monotonic feature-splitting behavior as dictionary size grows, and whether the split features remain human-interpretable, is not well characterized.

**Direction:** Use Prisma's pre-trained CLIP SAEs at different dictionary widths (or train a couple of small ones at different widths on a fixed activation cache, single-GPU feasible). Replicate the feature-splitting analysis: track a coarse feature in the small SAE and identify the cluster of finer features in the larger SAE via activation overlap. The twist: assess in the vision domain whether splits yield genuinely more specific, still-interpretable visual concepts, comparing to the language-SAE narrative.

**Why it matters:** Feature splitting determines whether SAEs give a stable, faithful decomposition or an arbitrary one dependent on width — central to trusting SAE-based safety analysis. Characterizing this in vision (a named open problem) with public SAEs on one GPU tests how universal the SAE 'feature geometry' story is across modalities, informing whether interpretability scales beyond language.

**Relevant context:** Feature splitting was described in Anthropic's 'Towards Monosemanticity' / 'Scaling Monosemanticity' for language SAEs. Prisma (arXiv:2504.19475) ships CLIP SAEs of varying widths; 'Interpretable and Testable Vision Features via SAEs' (arXiv:2502.06755) provides interpretation tooling.
