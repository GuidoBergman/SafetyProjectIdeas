# How Many SAE Features Must You Monitor to Cover a Safety Behavior?

**Problem:** A success state: 'a feasible monitoring budget covers a safety-relevant behavior.' Backcasting from 'tractable monitoring', a prerequisite is measuring how distributed a behavior is across SAE features — can one feature gate it, or does it take dozens?

**Direction:** For one behavior (e.g., refusal), rank Gemma Scope features by causal effect via single-feature ablation/steering. Build a cumulative coverage curve: how many top features are needed to recover X% of the behavioral effect. Compare a clean single-gate behavior vs. a diffuse one.

**Why it matters:** Tells us whether safety monitoring can rely on a few features (cheap, robust) or must track many (expensive, brittle) — directly informing whether SAE monitoring scales. Public SAEs, inference-only.

**Relevant context:** GSAE (arXiv 2512.06655) argues safety representations are smooth/distributed across multiple features, not single latents, contrasting with standard single-feature assumptions. Gemma Scope provides the SAEs for measurement.
