# Where Irreversibility Enters: Auditing the Reversibility-Awareness Gap in Tool Calls

**Problem:** The risk 'agent causes irreversible harm' decomposes as: task -> plan -> tool call with irreversible side-effect (delete, transfer, send) -> no recovery. The under-studied link is whether agents even represent which of their available tools are irreversible before invoking them. Most safety work targets the final 'block' step; almost none measures whether the model internally distinguishes reversible from irreversible actions at decision time.

**Direction:** Build a small taxonomy of ~40 tool stubs labeled reversible (read_file, list) vs irreversible (delete_file, send_email, transfer_funds). With an API agent in a mock sandbox, present matched task pairs that can be solved reversibly or irreversibly. Measure: (1) how often the agent picks the irreversible path when a reversible one exists, (2) whether prompting it to first classify each tool's reversibility changes behavior, (3) whether it verbalizes reversibility in its reasoning. Success = a quantified 'reversibility-awareness gap' across 2-3 open/API models.

**Why it matters:** Irreversible autonomous actions (autonomous crypto theft) are the canonical agentic catastrophe. If agents do not natively flag irreversibility, then any human-in-the-loop gate keyed to it will be miscalibrated. This is a cheap, lab-independent diagnostic of a missing internal representation.

**Relevant context:** Adversa AI 2025 reports agentic systems produced irreversible attacks including autonomous crypto theft. AgentTrust (arXiv 2605.04785) explicitly recommends retaining human-in-the-loop review for irreversible operations, implying agents do not handle them safely alone. Verifiably-safe tool use work (arXiv 2601.08012) and SENTINEL (OpenReview vCyxemIKLL) formalize action constraints but do not measure native reversibility awareness.
