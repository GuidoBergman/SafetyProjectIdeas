# Agent Sandbox Escape: Prototyping the Containment Link in the Autonomous-Misuse Chain

**Problem:** Agentic-misuse chain: 'agent given a task' -> 'agent takes actions via tools' -> 'sandbox contains side effects' -> 'no real-world harm'. As governance shifts to autonomous agents, the containment link is under-specified; few beginner-accessible artifacts show how easily a tool-using agent exceeds its intended scope.

**Direction:** Build a minimal monitoring harness around a small open model acting as a tool-using agent in a constrained sandbox (file + shell tools), and log every action against an allowlist policy. Measure how often the agent attempts out-of-policy actions on benign tasks and which simple policy rules catch them. Ship the harness as reusable safety infrastructure.

**Why it matters:** Strategically valuable monitoring/sandbox infrastructure is exactly the kind of counterfactual work labs deprioritize. A small open prototype that quantifies containment-link failures and is reusable by others advances agent governance concretely. Small open model, one GPU, no training.

**Relevant context:** microsoft/agent-governance-toolkit (policy enforcement, execution sandboxing, OWASP Agentic Top 10); arXiv:2505.18003 'An Example Safety Case for Safeguards Against Misuse'; structured access literature.
