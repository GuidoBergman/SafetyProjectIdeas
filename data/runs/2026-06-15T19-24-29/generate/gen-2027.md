# Fuzzing the Constitution: Random Principle Perturbation

**Problem:** Constitutional AI prompts are hand-written and brittle; small wording changes may produce large safety swings, but this sensitivity is rarely tested systematically.

**Direction:** Import fuzz testing from software security. Programmatically generate many small perturbations of constitutional principles (synonym swaps, negation insertion, reordering) and run the self-critique pipeline (inference only) on a fixed harmful-prompt set for each perturbation, logging which perturbations cause large jumps in harmful-output rate. Report the most 'crash-inducing' perturbations.

**Why it matters:** Surfaces fragile constitutional wording that adversaries or accidental edits could exploit, hardening a widely used alignment method. Inference-only fuzzing on one GPU; produces reusable robustness infrastructure.

**Relevant context:** Fuzzing finds crash-inducing inputs by mass random perturbation; LLMs are hyper-sensitive to prompt wording (arXiv:2502.04134, arXiv:2507.06253 'emergent misalignment as prompt sensitivity'). Constitutional context mitigates misalignment (LessWrong 'Context Awareness').
