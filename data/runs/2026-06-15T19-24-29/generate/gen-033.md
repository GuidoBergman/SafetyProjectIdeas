# Agent Safety Is a Trajectory, Not a Turn: A Minimal Compounding-Failure Eval No Single-Turn Benchmark Catches

**Problem:** GAP TARGETED: agentic safety evaluation is named the single biggest benchmark gap, and no subfield owns the fact that the most dangerous agent failures emerge GRADUALLY across a trajectory (compounding planning errors, delayed exploitation of earlier permissions) rather than in any one response. Almost all safety benchmarks score single responses.

**Direction:** Build a tiny scripted tool-use sandbox (3-5 mock tools, e.g., read_file, send_email, delete, fetch_url) with a handful of scenarios where each individual step looks benign but a specific SEQUENCE is harmful (e.g., quietly acquire a credential early, use it 4 steps later). Run an open agent model and score at two granularities: per-step (does any single action look unsafe?) vs whole-trajectory (does the sequence realize harm?). Measure the gap — harm that only a trajectory-level monitor catches.

**Why it matters:** Bridges agentic_safety + ai_control + evaluations_benchmarks. It demonstrates concretely that single-turn evals miss compounding harm, motivating trajectory-level monitoring. Fully counterfactual: mock tools, an open small model, one GPU, no proprietary agent infra, and a >1yr threat model (autonomous agents) labs deprioritize for near-term concerns.

**Relevant context:** ATBench (arXiv:2604.02022) argues safety risks 'emerge gradually over extended interaction traces'; OpenAgentSafety (arXiv:2507.06134) and the taxonomy survey (arXiv:2605.16282) note most multi-agent benchmarks are single-turn/sandboxed. Outcome-driven constraint violations occur in 30-50%+ of multi-step KPI-pressured scenarios.
