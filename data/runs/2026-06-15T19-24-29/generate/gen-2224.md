# Weak-to-Strong Generalization on Code Correctness Labels

**Problem:** OpenAI's weak-to-strong work and the EleutherAI replication tested W2S mostly on NLP classification (sentiment, NLI) and reward modeling. It is unclear whether the elicitation phenomenon holds when the 'hard' task is judging program correctness, a domain where weak supervisors make structured, systematic mistakes.

**Direction:** Take a small open model (e.g. Qwen1.5-0.5B) as the weak supervisor and a larger open model (e.g. Qwen1.5-7B) as the strong student, using the public openai/weak-to-strong codebase scaffolding. Generate weak labels for 'is this code correct' on a slice of HumanEval/MBPP-style problems (using public unit-test execution as ground truth), finetune the strong model on weak labels, and measure the performance gap recovered (PGR) versus the NLP-domain baseline.

**Why it matters:** Code correctness is a domain where ground truth is cheaply checkable, so it is an ideal external testbed for whether weak supervisors can elicit latent strong-model capability. If W2S degrades in code relative to NLP, it warns that the phenomenon does not transfer to structured reasoning domains that matter for superhuman oversight. Needs only open models and public datasets, no lab infrastructure.

**Relevant context:** Burns et al. 2023 (openai/weak-to-strong) found GPT-2-level supervisors recover most GPT-4 NLP performance but struggle on reward modeling and chess. EleutherAI replicated consistent W2S across 21 NLP datasets with Qwen1.5 and Llama 3. Code correctness with unit-test ground truth is an untested domain for the W2S elicitation framing.
