# Async-Lag Monitoring Risk: Measuring Damage Done Before a Slow Monitor Flags It

**Problem:** In realistic deployments, monitoring is asynchronous — the agent keeps acting while the monitor catches up — so there is a window where harmful actions execute before being flagged. There is no simple tool to estimate, given a monitor's latency and an attack's step structure, the probability that irreversible harm completes before the flag.

**Direction:** Model an agent trajectory as a sequence of steps with a designated 'point of no return' step. Parameterize monitor latency (steps behind) and per-step catch probability. Build a small simulator that, given empirical per-step monitor scores from open data, computes the probability the monitor flags before the point-of-no-return under various latencies. Report safety vs. monitor-lag curves.

**Why it matters:** Establishing what runtime controls are needed for different risk levels and preventing irreversible actions are stated open problems. Quantifying how monitor latency erodes safety informs kill-switch and human-in-the-loop design. Pure simulation + open scores; no lab infra.

**Relevant context:** 'Async Control: Stress-Testing Asynchronous Control Measures for LLM Agents' (arXiv 2512.13526) motivates asynchronous monitoring risk. Subfield open problems include preventing irreversible harmful actions and defining minimum runtime controls. A lightweight latency-to-safety simulator is a gap.
