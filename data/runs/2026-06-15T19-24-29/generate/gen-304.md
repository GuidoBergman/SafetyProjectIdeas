# Does Indirect Injection Need the Tool, or Just the Text? Isolating the Trust-Boundary Link

**Problem:** The indirect-prompt-injection chain is: malicious text in external data -> model treats data as instruction -> agent executes harmful action. The under-studied link is whether the model's failure to distinguish data-from-instruction occurs already at the comprehension stage (before any tool exists), which would make it a model property rather than a tooling property.

**Direction:** Without building an agent, present open instruct models with documents containing embedded injected instructions and a benign user task. Measure how often the model 'obeys' the injected instruction in its text output as a function of framing cues (quotation, delimiters, role tags). This isolates the trust-boundary failure from the execution layer.

**Why it matters:** Pinpoints whether the IPI vulnerability lives in the model's data/instruction confusion (text-only) rather than the tool harness, informing where defenses should sit. Pure prompt-in/text-out experiment, no agent infra, no training, highly counterfactual since labs focus on full-agent patches.

**Relevant context:** OWASP LLM01:2025 and 'The Landscape of Prompt Injection Threats in LLM Agents' (arXiv:2602.10453) describe IPI embedding adversarial instructions in external data; EchoLeak (CVE-2025-32711) is a real zero-click M365 Copilot IPI incident. AgentSentry (arXiv:2602.22724) frames an attention-mediated threshold mechanism.
