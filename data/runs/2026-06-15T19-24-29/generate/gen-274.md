# Property-Based Testing of Safety Guardrails with Shrinking

**Problem:** Red-teaming finds individual failing prompts but not the minimal property-violating input, so it is hard to characterize the boundary of a guardrail's failure region.

**Direction:** Borrow QuickCheck-style property-based testing (PBT) and its key idea of automatic shrinking. State a property like 'for all prompts semantically requesting category X, the model refuses', generate random prompts by composing templates/obfuscations, find counterexamples, then SHRINK each counterexample to the minimal prompt that still bypasses the guardrail (delete words/clauses until refusal returns). Build a tiny PBT harness around an open model + a keyword/refusal classifier; report the distribution of minimal jailbreak structures.

**Why it matters:** Minimal counterexamples reveal the actual fragile token patterns rather than verbose attack strings, improving interpretability of defenses. Pure black-box, no training, runs on a single GPU. Directly probes 'shallow alignment'.

**Relevant context:** Property-based testing originates in QuickCheck; ChekProp (arXiv:2505.23549) uses LLM-generated PBTs to guardrail cyber-physical systems. Context: Qi et al. ICLR 2025 shallow-alignment (arXiv:2406.05946).
