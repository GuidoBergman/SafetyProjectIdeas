# Mutation Testing the Monitor: Measuring Sabotage-Detection Coverage

**Problem:** We don't know how thorough a control monitor really is. A monitor may catch the specific sabotage examples in a benchmark but miss large classes of attack it was never tested on. There is no 'coverage' metric for monitors.

**Direction:** Adapt mutation testing: programmatically generate a diverse zoo of 'sabotage mutants' (insert a subtle data exfiltration, a logic backdoor, a silent error-swallow, a permission escalation) into otherwise-benign agent trajectories, then measure the monitor's mutation kill rate (fraction of injected sabotages caught). Categorize surviving mutants to map the monitor's blind spots. Run on open transcripts with a small open-weight monitor.

**Why it matters:** Provides a quantitative, attack-class-stratified coverage score for monitors, exposing blind spots before deployment. Mirrors Meta's mutation-guided hardening but for safety monitors, and is doable with API/consumer GPU only.

**Relevant context:** Mutation testing introduces faults to measure a test suite's detection ability; Meta's ACH combines LLM test gen with mutation (engineering.fb.com 2025; arXiv:2503.08182). Maps directly onto control's red-team/blue-team framing (Redwood AI Control 2023).
