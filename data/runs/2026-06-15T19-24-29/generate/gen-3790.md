# The Over-Trusting Agent: Does an Agent Verify Tool Outputs Before Acting on Them?

**Problem:** Indirect prompt injection works because agents treat tool outputs as trusted. Beyond injection, it is unclear whether agents perform any sanity-checking on suspicious or self-contradictory tool outputs before taking consequential actions on them.

**Direction:** Feed the agent tool outputs that are internally inconsistent or implausible (a bank balance that jumps by 1000x, a file listing contradicting an earlier one, a date in the future) and then a task that depends on that data. Measure how often the agent (a) acts on the bad data unquestioningly, (b) flags the inconsistency, or (c) re-queries. Vary how blatant the inconsistency is to find the detection threshold.

**Why it matters:** Quantifies the agent's 'trust-but-don't-verify' failure that underlies many tool-misuse and injection harms, independent of any adversary. A clean, training-free evaluation that yields actionable thresholds for when human verification of tool data is mandatory.

**Relevant context:** AgentDojo and 'Simple Prompt Injection' (arXiv 2506.01055) rely on agents trusting tool outputs. 'Towards Verifiably Safe Tool Use' (arXiv 2601.08012) and access-control vision (arXiv 2510.11108) motivate verifying tool I/O.
