# Prompt Injection x Tool-Use Eval Coverage: One Compromise, Many Co-Running Failures

**Problem:** Failure mode A is prompt injection via tool output / retrieved content. Failure mode B is incomplete agentic-eval coverage (benchmarks test single-agent single-tool paths). The compound effect: an injection in one tool result propagates to other tool calls and co-running steps, but the benchmark only scores the first hop, so the measured robustness vastly understates cascade risk.

**Direction:** Build a tiny 3-step agent loop (read document -> call a calculator/file tool -> summarize) using an open model and a local mock tool harness. Inject a malicious instruction into step-1 tool output and measure whether it propagates to steps 2-3. Compare a single-hop robustness score (benchmark-style) to a full-trajectory propagation score.

**Why it matters:** Agentic benchmarks are nascent and mostly single-hop. Demonstrating that single-hop scores miss most of the real cascade risk gives a cheap methodological correction and a reusable mini-harness. No lab infra needed; all open tools and local mocks.

**Relevant context:** AgentDyn (arXiv:2602.03117) and MASpi (OpenReview) benchmark prompt-injection in multi-agent systems; reported 48% of co-running agents infected per incident and 70% YoY rise in multi-hop attacks. Subfield context flags agentic-safety eval gaps.
