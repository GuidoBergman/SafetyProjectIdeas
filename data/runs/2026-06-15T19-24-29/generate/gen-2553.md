# CoT-vs-Action Monitoring Gap: A Reusable Metric for When Reasoning Traces Actually Help

**Problem:** The GPT-5 system card and OpenAI claim CoT monitoring is 'substantially more informative' than action/output-only monitoring, but there is no simple, model-agnostic metric a non-expert can compute to quantify the size of that gap on a given task. Practitioners can't easily tell whether reading the CoT buys them much detection power for their specific deployment.

**Direction:** On an open reasoning model with visible CoT, run a set of trajectories containing seeded deceptive/sandbagging behaviors. Score each with two monitors: one that sees only the final action/output, one that also sees the CoT. Define a 'CoT informativeness' metric as the AUC/catch-rate uplift from adding CoT. Report it across several behavior types and check whether the uplift shrinks for subtler behaviors.

**Why it matters:** Tells deployers when CoT monitoring is worth the cost and when action-only monitoring suffices, and provides a yardstick to track as models change. Replicating the CoT-monitoring result across open models (a named follow-up in the context) is high-value and needs only API/open-weights access.

**Relevant context:** GPT-5 system card found CoT monitoring substantially more informative than output-only (cited in subfield context as a follow-up target). MonitorBench (arXiv 2603.28590) and 'A Pragmatic Way to Measure CoT Monitorability' (arXiv 2510.23966) provide methodology; the context explicitly flags 'replicate CoT monitoring across architectures' as a desired direction.
