# Minimal Sandbox Firewall: Default-Deny Tool Egress Prototype

**Problem:** A safety success state is that agents physically cannot take high-stakes actions without passing a gate. Most agent scaffolds default-allow tool calls. Strategically valuable infra — a default-deny egress firewall — is missing as a small reusable prototype.

**Direction:** Backcast from 'irreversible actions require passing a firewall'. Build a thin wrapper around an OpenHands/AgentDojo-style tool layer that intercepts every tool call, classifies it by a reversibility/risk policy, and blocks or routes high-risk calls to a confirmation step. Evaluate on AgentDojo security cases: how many attacks does the firewall stop and how much benign utility does it cost?

**Why it matters:** Containment infrastructure that doesn't depend on the model behaving — a robust complement to monitoring. A small open prototype is exactly the kind of safety tooling valuable to build outside a lab and reusable by others.

**Relevant context:** Design Patterns to Secure LLM Agents (reversec, 2025) and 2025 best practices describe execution previews and human confirmation for high-risk/irreversible actions. AgentDojo (arXiv 2406.13352) provides an extensible tool environment with 629 security cases. OpenAgentSafety (arXiv 2507.06134) runs in sandboxed Docker.
