# Cost-to-Elicit Meter: Quantifying How Cheap It Is to Surface a Harmful Capability

**Problem:** Threat-actor cost-reduction is a named methodology, but most evals report binary 'can/can't elicit' rather than the effort/queries needed. There is no simple metric for how many attempts it takes to elicit a borderline harmful behavior from a model.

**Direction:** For a set of borderline-harmful (but safe-to-study) tasks, run a fixed automated elicitation loop against open models and record the number of reformulations/queries until success (or a cap). Report an 'expected queries to elicit' distribution per model as a cost-to-elicit metric.

**Why it matters:** Reframes safety from binary refusal to attacker effort, a more decision-relevant measure for deployment and policy; uses only open models and a small attempt budget, high counterfactual value.

**Relevant context:** Common Methodology: 'cost-reduction estimation for threat actors' and 'capability elicitation' (subfield context). METR elicitation guidance treats elicitation effort as central. Existing red-teaming reports success rates but rarely effort distributions, leaving a clear measurement gap.
