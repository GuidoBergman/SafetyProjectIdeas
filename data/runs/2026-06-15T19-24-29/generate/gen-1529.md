# Does combining a steering monitor with a steering controller create a self-defeating loop?

**Problem:** Closed-loop safety chain: a probe reads activations -> if harmful, a steering vector is applied to correct -> but the correction changes activations -> which the same probe now reads as 'safe' even if the surface behavior didn't actually change. This monitor-controller feedback link could produce false reassurance. Beaglehole et al. propose unifying steering and monitoring but don't test this coupling.

**Direction:** On an open model, set up a simple closed loop: probe flags harmful intent -> apply refusal vector -> re-read probe. Independently judge whether the OUTPUT actually became safe (via held-out criteria) vs whether only the probe value moved. Measure the gap between 'probe says fixed' and 'output is actually fixed'. Success criterion: rate of cases where the loop silences the probe without changing the harmful output.

**Why it matters:** Unifying monitoring and steering (the Science paper's vision) risks a system that gates on the very signal it perturbs — a subtle but serious design flaw. Demonstrating it on one open model is cheap and directly informs safe monitor-controller architecture.

**Relevant context:** Beaglehole et al. propose universal steering AND monitoring together; this tests their interaction. Self-defeating feedback between probe and intervention is the novel, neglected causal link, all on one open model.
