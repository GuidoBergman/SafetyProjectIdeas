# CoT Monitoring Across Open Model Families

**Problem:** The GPT-5 system card claims chain-of-thought monitoring is 'substantially more informative' than action-only monitoring for detecting deception, but this was measured on one model family. It is unknown whether the CoT advantage holds across architectures, especially smaller open-weight reasoning models a researcher can actually inspect.

**Direction:** Replicate the CoT-vs-action-only monitoring comparison from CoT Red-Handed across 3-4 open reasoning models (e.g. DeepSeek-R1-distills, Qwen-QwQ, open o-style models). Use a fixed set of sabotage/backdoor transcripts (from SHADE-Arena or ControlArena's APPS backdoor tasks); have a cheap trusted monitor score each transcript twice — once with CoT visible, once with CoT stripped — and compute the AUROC gap per model family. Report whether the CoT-monitorability premium is universal or model-specific.

**Why it matters:** If CoT monitoring's value is architecture-dependent, control protocols that assume a fixed CoT premium will silently fail when the deployed model changes. This is a pure API/inference experiment with no training, valuable to anyone choosing which open model to deploy under monitoring.

**Relevant context:** CoT Red-Handed: Stress Testing Chain-of-Thought Monitoring (arXiv 2505.23575) stress-tests CoT monitors. GPT-5 system card reports CoT monitoring is 'substantially more informative' than action-only. SHADE-Arena (arXiv 2506.15740) provides 17 sabotage scenarios with paired benign/malign transcripts; top monitor reached AUC 0.87.
