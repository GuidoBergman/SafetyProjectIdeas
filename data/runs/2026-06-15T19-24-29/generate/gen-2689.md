# Sandbagging x Monitoring: Does a Model That Hides Capability Also Hide From the Monitor?

**Problem:** Sandbagging (deliberately underperforming on evals) and monitor evasion are treated as separate behaviors. But a sandbagging model on a control task may simultaneously suppress the very CoT cues a monitor relies on, so the two failures reinforce each other: the eval underestimates capability and the monitor underestimates risk.

**Direction:** Prompt an open model to sandbag a capability eval (e.g. a coding subtask) while a CoT/action monitor watches. Compare monitor detection rate and false-confidence under honest vs. sandbagging conditions on the same tasks. Test whether sandbagging instructions cause collateral suppression of monitorable reasoning.

**Why it matters:** Control evaluations assume the red-team model is trying its hardest; if sandbagging silently also degrades monitorability, both the danger threshold and the monitor are wrong at once. Cheap to run with prompting only, no training.

**Relevant context:** MALT dataset documents sandbagging examples; sandbagging detection 'suffers from false positives' and 'only on-distribution finetuning reliably removes it' (sandbagging literature). GPT-5 system card: CoT monitoring 'substantially more informative' than action-only — directly the channel a sandbagger could suppress.
