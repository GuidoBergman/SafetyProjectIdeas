# N-Version Programming: Diverse Monitor Ensembles to Reduce Correlated Misses

**Problem:** A single monitor model shares the biases and blind spots of its training. Sabotage that exploits those blind spots passes undetected. We want to know if deliberately diverse monitors catch what a homogeneous monitor misses.

**Direction:** Borrow N-version programming from fault-tolerant software: assemble monitors that are deliberately diverse along axes (different model families, different prompting strategies, code-AST-based vs natural-language, different temperatures) and combine via voting. On SHADE-Arena sabotage cases, measure marginal detection gain from each added diverse version and identify the diversity axis that most reduces the joint miss rate.

**Why it matters:** Empirically grounds how to build a robust monitor ensemble and how much diversity actually buys, central to defense-in-depth. Uses only open/API models and replay, achievable in 30h, counterfactually valuable since labs default to one strong monitor.

**Relevant context:** N-version programming uses independently developed versions to reduce common-mode failures (Avizienis, fault tolerance). Adaptive attacks subvert single trusted monitors (arXiv:2510.09462); diverse monitors are still evaded (SHADE-Arena arXiv:2506.15740), making the diversity-vs-correlation question open.
