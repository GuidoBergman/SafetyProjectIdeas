# Tool-Metadata Manipulation x Monitor Trust: Compounding a Schema Lie Into Unmonitored Execution

**Problem:** Failure mode A: adversarial tool metadata (names/descriptions/schemas) biases the agent into selecting a malicious tool. Failure mode B: behavioral monitors that read declared tool semantics rather than actual effects. The compound failure is a tool that is named 'log_message' but exfiltrates, slipping past both selection logic and the monitor.

**Direction:** Create a small registry of paired tools (benign-named / malicious-effect). Measure how often an API agent selects the disguised tool, AND how often a description-reading monitor flags it. The product of these miss rates quantifies the compounded exposure. Test an effect-based (not description-based) monitor as mitigation.

**Why it matters:** Shows that monitoring built on self-declared semantics is defeated by the same lie that fools tool selection — a strategically valuable insight for safer agent sandboxes/harnesses. Pure prompt + mock tools.

**Relevant context:** 2025 work shows adversaries manipulate tool metadata to bias tool selection without prompt injection or model internals (search summary on tool-call vulnerabilities); RSB and Agent Security Bench (ICLR 2025) document tool-misuse attack/defense surfaces.
