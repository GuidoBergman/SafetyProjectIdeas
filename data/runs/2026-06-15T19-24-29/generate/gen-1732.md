# Regression-Test Suite for SAE Feature Drift Across Model Updates

**Problem:** When a model is fine-tuned or updated, we have no regression suite that tells us which interpretable features changed, so safety properties verified on version N may silently break in N+1.

**Direction:** Transfer regression testing from software engineering. Fix a battery of probe inputs and reference feature-activation 'snapshots' for a base open model; after applying a public fine-tune (e.g., base vs. chat variant of the same family), re-run and diff the feature activations to flag features that drifted, disappeared, or newly appeared. Produce a 'feature regression report'.

**Why it matters:** Fine-tuning is where safety properties most plausibly regress; a reusable regression harness lets anyone audit an update without lab infrastructure, a directly deployable monitoring contribution.

**Relevant context:** Regression testing is core software engineering practice. Base/chat model pairs (e.g., Llama, Gemma, Qwen) are public, and shared SAEs let the same feature set be tracked across the pair, enabling the diff with only inference.
