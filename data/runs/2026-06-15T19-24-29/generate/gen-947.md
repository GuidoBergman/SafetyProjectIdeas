# Seed-Sensitivity of Safety Features Across SAE Reruns

**Problem:** SAEs trained with different seeds or hyperparameters converge to different feature sets. If a 'refusal' or 'harmful-content' feature is found in one SAE but not in a sibling trained on the same model with a different seed, then any safety claim built on a single SAE is fragile and non-reproducible.

**Direction:** Take two or more openly released SAEs for the same model/layer (different seeds/hyperparameters, available on Neuronpedia/SAELens) and attempt to match a small set of safety-relevant features (refusal, toxicity, deception) across them via activation-correlation matching. Report what fraction of safety-relevant features are stable vs. seed-specific.

**Why it matters:** Establishes whether SAE-based safety findings replicate across training runs — a prerequisite for using SAEs in deployment decisions. Requires no training, only public weights, and directly addresses the interpretability-to-safety-guarantee gap.

**Relevant context:** 2025 SAE reviews note SAEs trained with different seeds/hyperparameters converge to different feature sets. Neuronpedia and SAELens host multiple SAEs per model. Open Phil RFP lists interpretability-to-safety-guarantee benchmarks as a priority.
