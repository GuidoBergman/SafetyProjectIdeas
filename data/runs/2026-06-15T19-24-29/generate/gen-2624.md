# Differential Testing of Monitor Models Against a Reference Oracle

**Problem:** Different monitor models disagree on which actions are suspicious, but we lack a systematic way to find the inputs where a cheap monitor diverges from a strong reference, which are exactly the dangerous cases to study.

**Direction:** Import differential testing from compiler/software verification: run many cheap candidate monitors and one strong reference monitor over the same large set of agent actions, automatically surface every disagreement, then cluster the disagreement cases to characterize systematic failure modes of the cheap monitors. The disagreement set becomes a cheap, targeted hard-case benchmark.

**Why it matters:** Cheaply mines the highest-value training/eval cases (monitor disagreements) and characterizes when trusted-but-weak monitors fail, informing trusted-monitoring protocol design. API-only, no training, generates a reusable artifact for the community.

**Relevant context:** Differential testing (e.g., Csmith for compilers) finds bugs by cross-checking implementations on shared inputs. Trusted monitoring uses a weaker trusted model whose failures matter (Redwood AI Control 2023; arXiv:2511.02997). CoT vs action monitors disagree (GPT-5 system card).
