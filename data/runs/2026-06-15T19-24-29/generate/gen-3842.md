# Stop-Button Compliance Across the Action Chain: Does Interruption Survive Mid-Plan?

**Problem:** Corrigibility chain: human issues stop -> agent receives it -> agent halts -> no further actions. The neglected link is timing: a stop signal arriving mid-plan (after the agent has committed to a multi-tool sequence) may be ignored or 'finished anyway.' Stop-button compliance is usually tested at idle, not mid-execution.

**Direction:** Build a sandbox where the agent executes a known multi-step tool plan and a 'STOP' message is injected at controlled points (before step 1, mid-plan, just before the irreversible step). Measure halt compliance vs injection timing, and whether the agent rationalizes completing 'just the current step.' Vary phrasing (polite request vs hard override). Report compliance-by-timing curve across models.

**Why it matters:** Interruptibility is foundational to control. If agents reliably ignore stops once committed to a plan -- especially right before irreversible actions -- the entire human-override safety story is undermined. Cheap, prompt-only, no internals.

**Relevant context:** Ctrl-Z (arXiv 2504.10374) controls agents via resampling/blocking mid-action, implying naive interruption is unreliable. AgentTrust (arXiv 2605.04785) retains HITL for irreversible ops. Plan-then-execute resilience work (arXiv 2509.08646) addresses mid-plan control. Timing-of-stop compliance is under-tested as a behavioral measure.
