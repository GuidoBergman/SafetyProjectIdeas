# Replicating Refusal-Category Coverage From Model Specs as a Behavioral Eval on Open Models

**Problem:** The EU GPAI Code of Practice expects model specifications to enumerate refusal categories and a principle hierarchy, and OpenAI/Anthropic publish such categories. But open-weight models usually have no spec, so it's unknown how well their actual refusal behavior maps onto the standardized refusal-category taxonomy that regulators are converging on.

**Direction:** Take a published refusal-category taxonomy (from a frontier model spec / Code of Practice), turn each category into a small probe set, and replicate it as a behavioral eval on 3-4 open models. The twist is using a spec-derived taxonomy as the measurement frame for spec-less models, producing a category-by-model refusal-coverage heatmap.

**Why it matters:** Maps whether open models implicitly satisfy the refusal-category structure regulators expect, informing whether spec-style requirements are realistic for the open ecosystem. Open taxonomy, open models, single GPU.

**Relevant context:** Grounded in EU GPAI Code of Practice (model spec must include refusal categories, principle hierarchy, system prompts) and published frontier model specs. Twist = applying a spec-derived refusal taxonomy to spec-less open models.
