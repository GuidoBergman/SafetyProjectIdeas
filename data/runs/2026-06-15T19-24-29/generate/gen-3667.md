# Do Agents Generalize Safety Constraints to Novel Tools?

**Problem:** An agent told 'never send money' may obey for a known payment tool but comply when an equivalent capability appears under a novel, innocuously-named tool — whether safety constraints generalize across tool surface forms is untested.

**Direction:** Give an open agent a natural-language safety constraint, then present functionally equivalent forbidden capabilities under varied tool names/schemas (obvious name, neutral name, obfuscated name). Measure constraint-adherence rate as a function of how clearly the tool matches the constraint's wording.

**Why it matters:** If safety constraints are pattern-matched to tool names rather than understood semantically, agents are trivially bypassable by renaming tools — a serious, cheap-to-test robustness gap directly relevant to agent security standards.

**Relevant context:** OWASP LLM06 Excessive Agency (functionality the agent shouldn't use). Augustus/Praetorian multi-agent and latent-injection probes. NIST AI Agent Standards open problem on identity/security and behavior boundaries.
