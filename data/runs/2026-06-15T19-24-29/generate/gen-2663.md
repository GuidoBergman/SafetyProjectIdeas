# What Information Does a Monitor Actually Need? Backcasting Minimal-Context Sabotage Detection

**Problem:** Success state: a control deployment that gives the monitor exactly enough context to catch sabotage without leaking so much that it slows the system or enables collusion. Backward: we need to know the marginal detection value of each context slice (task description, prior actions, environment state).

**Direction:** On SHADE-Arena's 5 public agent-task transcripts (benign main task + sabotage side task), run an open monitor under ablated context conditions: action-only, action+task, action+task+history. Measure catch rate per condition to produce a 'context-to-detection' curve. Result: 'a ranking of which context slices buy the most detection per token.'

**Why it matters:** Real monitoring is bottlenecked by context cost and leakage risk. Knowing the cheapest sufficient context is directly actionable and feasible on a single GPU with public SHADE-Arena tasks.

**Relevant context:** 'How does information access affect LLM monitors' ability to detect sabotage?' (arXiv:2601.21112) and SHADE-Arena (Anthropic, 17 tasks, 5 public) provide the setting and motivation.
