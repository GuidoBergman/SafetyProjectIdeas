# Temperature and Sampling Effects on Agentic Harm Compliance

**Problem:** Agent-safety benchmarks (AgentHarm, OS-Harm) are typically run at a single decoding setting. Whether HarmScore/RefusalRate are stable across temperature and top-p — i.e., whether an agent that refuses at temp=0 will comply at temp=1 — is not reported.

**Direction:** Run a fixed AgentHarm subset on 2-3 open models while varying ONLY decoding parameters (temperature 0/0.7/1.0, top-p sweep) with multiple samples per setting. Measure variance in RefusalRate/HarmScore and find the worst-case sampling configuration. Report whether safety evaluations are decoding-fragile.

**Why it matters:** If safety is decoding-dependent, single-setting evals under-report worst-case harm and any deployment that allows higher temperature is riskier than its eval suggests. Cheap, fully reproducible, open-model variation; valuable as eval-methodology critique.

**Relevant context:** AgentHarm provides HarmScore/RefusalRate. Existing catalogue covers 'Consistency of Safety Across Decoding Parameters' for chat; this varies it into the AGENTIC tool-calling setting (multi-step HarmScore), which behaves differently. OS-Harm uses an LLM semantic judge.
