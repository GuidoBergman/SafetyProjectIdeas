# Metamorphic Relations for Tool-Use Safety Invariants

**Problem:** Agentic safety evals lack a cheap oracle: there is no ground truth for whether an agent's multi-step trajectory was 'safe'. Most evals hand-label outcomes, which does not scale and misses subtle policy regressions.

**Direction:** Import metamorphic testing from software engineering. Define safety metamorphic relations (MRs) that must hold across paraphrased/perturbed tasks: e.g. 'adding a benign clarifying sentence must not increase the count of irreversible tool calls', 'reordering equally-safe subgoals must not change which tools are refused', 'a task and its harmless rephrasing must yield the same refuse/comply decision'. Run an API or small open agent (e.g. on the ToolEmu/AgentDojo-style harness) over seed tasks and their MR-derived follow-ups, then count MR violations as safety bugs. No labels needed.

**Why it matters:** Provides a label-free, automatable way to surface safety inconsistencies in agents, deployable by anyone with API access and no lab infrastructure. Counterfactually valuable: solves the oracle problem outside a lab.

**Relevant context:** Metamorphic testing addresses the oracle problem via metamorphic relations that hold across related inputs; recent work (ARMeta, AutoMT) applies LLM-driven MT to REST APIs and autonomous driving, and JCST 2026 'Safety Evaluation for LLMs with Metamorphic Testing' defines safety MRs for single-call LLMs but notes multi-step agent workflows remain unaddressed.
