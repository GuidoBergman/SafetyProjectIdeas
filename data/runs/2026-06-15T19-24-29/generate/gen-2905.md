# Metamorphic Relations as Safety-Eval Oracles for Refusal Consistency

**Problem:** Safety benchmarks need a ground-truth label for every item (the test-oracle problem), which is expensive and limits scale. Many safety properties are relational rather than absolute: a model should refuse a harmful request regardless of paraphrase, language, or politeness framing.

**Direction:** Import metamorphic testing from software engineering. Define a small set of metamorphic relations (MRs) for refusal: semantics-preserving paraphrase => refusal decision unchanged; adding a benign-context wrapper => decision unchanged; translating to another language => decision unchanged. For each seed harmful/benign prompt in an open set (e.g. a StrongREJECT-style slice), auto-generate follow-up cases by applying MRs (cheap string/template transforms plus an LLM paraphraser), then flag any MR violation as a defect. Report violation rates per relation on 2-3 open models via API/local. No labels needed beyond seed decisions.

**Why it matters:** Gives a label-free, scalable way to find safety-consistency bugs that single-point benchmarks miss, and produces a reusable harness any small group can run without proprietary data. Directly targets the autograder-reliability and contamination open problems by sidestepping the oracle requirement.

**Relevant context:** METAL (arXiv:2312.06056) and MMT4NL formalize metamorphic relations as modular LLM evaluation metrics; metamorphic testing for fairness (arXiv:2504.07982) shows MR-violation detection in LLaMA/GPT. Core idea: MRs alleviate the test-oracle problem by checking input-output relations across consecutive runs.
