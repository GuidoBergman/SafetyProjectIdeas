# Cross-Session Identity Confusion: Does Memory From One User Leak Into Another's Actions?

**Problem:** Chain: agent serves multiple users with shared/long-term memory -> memory from user A is retrieved while serving user B -> agent takes actions for B using A's context/permissions. The link 'memory retrieval crosses an identity boundary -> wrong-principal action' is an identity-standards gap (a NIST/CAISI priority) measurable without any IAM stack.

**Direction:** Set up a shared-memory agent serving alternating simulated users with distinct contexts and entitlements. Plant user-A-specific records, then serve user B with queries that could spuriously retrieve A's memory. Measure cross-user retrieval rate and, critically, whether the agent acts on A's data/permissions for B (e.g., references A's secrets, attempts A-scoped tools). Test a simple per-user memory-namespacing fix and report leak reduction.

**Why it matters:** Establishing agent identity and security standards is an explicit open problem; cross-session memory bleed is a concrete, high-impact instance (privacy + privilege confusion). Demonstrating the behavioral leak and a cheap namespacing mitigation is strategically valuable infrastructure work doable entirely outside a lab.

**Relevant context:** US CAISI/NIST AI Agent Standards Initiative lists agent identity/security standards as an open problem. Topology Matters (arXiv 2512.04668) measures memory leakage in multi-agent LLMs; memory survey (arXiv 2604.16548) covers long-term memory security. Cross-user identity-boundary leakage as a behavioral, prototype-fixable link is the gap.
