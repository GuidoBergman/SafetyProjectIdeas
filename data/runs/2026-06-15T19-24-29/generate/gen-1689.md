# Mapping the Boundaries of Feature Absorption in a Pretrained SAE

**Problem:** Feature absorption is a documented SAE failure where a latent meant to detect a general concept (e.g. 'word starts with S') silently fails on specific tokens because another, more specific latent absorbs that case to satisfy sparsity. It is unclear how prevalent absorption is across concept types and how to predict which inputs trigger silent failures.

**Direction:** Using a pretrained Gemma-2-2B SAE from SAELens/Neuronpedia, pick several candidate 'general' features with known absorption (first-letter, part-of-speech, sentiment) and systematically test them over a token set. For each input where the primary latent fails, search for the absorbing latent via cosine similarity to a linear probe direction and projection contribution. Build a small map of which token classes are most absorption-prone and report a per-feature 'silent failure rate'.

**Why it matters:** If a safety-relevant feature (e.g. a 'deception' or 'refusal' latent) silently fails on a fraction of inputs because of absorption, monitoring built on that latent has blind spots an attacker could exploit. Characterizing where absorption strikes tells us when SAE-based monitors cannot be trusted.

**Relevant context:** Chanin et al., 'A is for Absorption: Studying Feature Splitting and Absorption in Sparse Autoencoders' (arXiv:2409.14507) shows absorption arises from sparsity pressure on hierarchical concepts and that absorbed cases can be found via cosine similarity to a probe direction and projection contribution. SAEBench (arXiv:2503.09532) provides absorption metrics.
