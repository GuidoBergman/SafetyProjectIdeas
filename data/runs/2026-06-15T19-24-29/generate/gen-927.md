# API-Access Restrictions x Third-Party Audit Mandates: The Accountability Paradox Quantified

**Problem:** Failure mode A: governance increasingly mandates independent third-party audits. Failure mode B: providers tighten API/logprob/system-access restrictions. The two collide: the audits regulators require become technically impossible to perform, so 'audited' becomes a paper formality.

**Direction:** Catalogue the access surfaces (logprobs, system prompts, fine-tuning, rate limits, ToS audit clauses) actually offered by ~6 major public APIs, then map each against the concrete data access that a published audit method (e.g. a red-team or bias audit) requires. Produce an 'auditability matrix' showing which mandated audits are currently un-runnable, and which API change would unlock each.

**Why it matters:** Operationalizes the documented accountability paradox into a checklist regulators can attach to audit mandates. Needs only public API docs and ToS — quintessential civil-society work labs won't do against themselves.
