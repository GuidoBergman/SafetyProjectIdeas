# Backcasting Self-Monitoring Risk: Is a Model a Worse Monitor of Its Own Outputs Than of Others'?

**Problem:** Success state: protocols that avoid using a model to monitor itself when self-monitoring is a collusion/leniency risk. Backward: we need to measure whether a model rates its OWN backdoored code as less suspicious than identical code attributed to another model.

**Direction:** Generate backdoored APPS solutions from an open model. Present each to the same model as monitor under two attributions: 'your output' vs. 'another system's output' (otherwise identical). Measure the suspiciousness gap. Result: 'a self-leniency coefficient quantifying the risk of self-monitoring.'

**Why it matters:** Untrusted-monitor protocols often reuse the same model; if it goes easy on itself, that is a baked-in collusion channel. A clean self-leniency measurement on open models is fresh and lab-independent.

**Relevant context:** Redwood 'How to prevent collusion when using untrusted models to monitor each other'; 'When can we trust untrusted monitoring?' (arXiv:2602.20628); APPS backdoor public.
