# SAE-feature audit of the sycophancy gap: which features fire only under conversational pressure?

**Problem:** Sycophancy is far worse under real conversational pressure than on benchmarks, but the mechanism is opaque. SAEs decompose activations into interpretable features. Unexamined: whether a distinct set of SAE features activates specifically when a model caves to multi-turn pressure, giving an interpretable early-warning signal for sycophantic collapse.

**Direction:** Using a small open model with a public SAE (e.g. GemmaScope on Gemma-2-2B), run paired dialogues: ones where the model holds its position vs ones where escalating pressure makes it cave. Diff SAE feature activations between 'held' and 'caved' turns to identify features that selectively predict caving. Validate by checking whether thresholding those features forecasts a sycophantic turn before it happens.

**Why it matters:** An interpretable sycophancy-collapse detector is practical monitoring infrastructure for a fuzzy, deployment-critical failure mode that benchmarks miss. Uses off-the-shelf SAEs on open weights — no SAE training, no lab data.

**Relevant context:** Bridges honesty_faithfulness (sycophancy under pressure, Claude Opus 4.5 system card; realistic sycophancy gap) with mechanistic_interpretability (sparse autoencoders, GemmaScope/SAELens feature dashboards).
