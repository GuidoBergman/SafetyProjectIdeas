# The Aggregation Link: Individually-Safe Sub-Agent Actions That Combine Into Harm

**Problem:** Multi-agent harm chain: each sub-agent action is locally benign -> orchestrator composes them -> emergent harmful aggregate (e.g., one agent reads PII, another summarizes, a third posts externally). The link 'safe parts -> unsafe whole' is invisible to per-action monitors that lack a global view.

**Direction:** Build a 3-agent pipeline (reader, transformer, sender) where no single step is flagged by a naive per-step monitor, but the composition exfiltrates sensitive data. Measure how often a realistic decomposition produces the harmful aggregate, and whether a lightweight 'flow monitor' that tracks data provenance across steps catches it where per-step monitors miss. Report detection rates: per-step monitor vs flow-aware monitor.

**Why it matters:** Real multi-agent breaches arise from safe-looking steps chained across the 'read sensitive -> summarize -> send externally' pattern. Showing per-step monitoring misses composed harm, and prototyping a cheap provenance-aware flow monitor, is strategically valuable monitoring infrastructure -- exactly the lab-independent build encouraged.

**Relevant context:** Oso/Okta over-permissioning analyses name 'read sensitive -> summarize -> send externally' as a canonical composed-harm pattern. SoK on multimodal/information-flow (arXiv 2411.11195) and Sentinel Agents (arXiv 2509.14956) argue for information-flow controls across boundaries. A small provenance-flow monitor prototype targets the aggregation link.
