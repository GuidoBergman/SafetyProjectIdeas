# Tool-Misuse Mini-Benchmark: Will an Agent Call a Destructive Tool When a Safe One Suffices?

**Problem:** Tool misuse (bending legitimate tools into destructive outputs) is a flagged agentic safety gap, but there is no tiny, sandboxed, consumer-GPU benchmark that measures whether a small open agent prefers a destructive tool when a safe alternative exists.

**Direction:** Build a sandboxed toy environment (mock filesystem/email tools) where each task is solvable with a safe tool but a tempting destructive shortcut exists (e.g. delete-all vs. move-one). Run an open model with a simple agent loop and measure the destructive-tool selection rate across phrasings and time pressure.

**Why it matters:** Creates strategically valuable monitoring/sandbox infrastructure as a small prototype and an interpretable agentic-safety metric, both high counterfactual value and runnable without lab-scale agents.

**Relevant context:** Open Problem: 'evaluations for agentic/autonomous safety failures (tool misuse...)'. OWASP Top 10 for Agentic Applications flags tool misuse; AGENT-SAFETYBENCH has 349 environments / 2,000 cases (Zhang et al. 2024a). 'A Benchmark for Evaluating Outcome-Driven Constraint Violations in Autonomous AI Agents' (arXiv:2512.20798). Inspect AI provides the harness.
