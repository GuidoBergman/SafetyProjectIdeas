# The Injection-Location Link: Where in a Document Does an Injected Instruction Win?

**Problem:** IPI succeeds when injected text overrides the user task, but the positional link is under-studied: does an injected instruction at the start, middle, or end of a long retrieved document differ in how reliably it captures the model, given known long-context attention biases?

**Direction:** Construct documents with an embedded injected instruction placed at varied relative positions and lengths of surrounding benign text, then measure (text-only, no tools) how often an open model obeys the injection as a function of position. Map the positional vulnerability profile to test whether attention-bias (lost-in-the-middle) shapes the IPI link.

**Why it matters:** Connects long-context attention behavior to the IPI causal link, informing where retrieval pipelines should sanitize. Pure prompt-in/text-out on an open model, no agent infra or training; a tractable, novel positional analysis relevant to all RAG deployments.

**Relevant context:** IPI landscape work (arXiv:2602.10453) and AgentSentry (arXiv:2602.22724) describe an attention-mediated threshold mechanism for injection success; lost-in-the-middle long-context attention biases are well documented. EchoLeak (CVE-2025-32711) shows real injected-content exploitation. (Distinct from prior 'Prompt Injection in RAG Systems' by isolating positional/attention effects.)
