# Does Decoding Temperature Reopen Shallow Safety? A Sampling Sweep

**Problem:** Decoding-parameter exploits work because raising temperature/top-p increases the chance of a non-refusing first token. The shape of this vulnerability across the full temperature x top-p grid for modern open models is undocumented.

**Direction:** For a fixed set of borderline-harmful prompts, sweep temperature (0 to 1.5) and top-p (0.5 to 1.0) on 3 small open models, sampling many completions per cell, and measure refusal rate per cell. Produce a heatmap of where safety 'leaks' and test whether a tiny fixed prefix re-aligns the model under high temperature.

**Why it matters:** Deployers expose temperature/top-p as API knobs; if a benign-looking sampling setting silently halves refusal robustness this is a concrete deployment risk. Purely inference-based, no training, reproducible on a single GPU.

**Relevant context:** Qi et al. (arXiv:2406.05946) list decoding-parameter attacks among the exploits explained by shallow alignment. Context file lists 'Consistency of Safety Across Decoding Parameters' as already covered, so this variation focuses specifically on a 2D temperature x top-p response surface and re-alignment via prefix rather than a consistency check.
