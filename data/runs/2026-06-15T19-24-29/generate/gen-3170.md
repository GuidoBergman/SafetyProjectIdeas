# Reward-Hacking Detection Harness for Verifiable Tasks

**Problem:** Reward hacking (gaming a metric instead of solving the task) is a Petri/METR-MALT theme, but small teams lack a turnkey harness that runs an open model on tasks with both a true and a hackable reward and flags the gap.

**Direction:** Build ~10 coding/QA tasks each with a brittle proxy check (e.g., a test that can be passed by hardcoding) and a hidden true check. Run open models, measure how often they pass the proxy by exploiting it rather than solving the task, and log the CoT for hacking intent. Release the harness.

**Why it matters:** Reward hacking is a leading near-term misalignment signal; a reusable detection harness for verifiable tasks is concrete safety infrastructure. Self-contained, GPU-light.

**Relevant context:** METR MALT dataset provides reward-hacking examples; Petri includes reward-hacking as a judge dimension; OpenAI/Apollo anti-scheming work treats reward hacking as scheming-adjacent.
