# Monitor-the-Monitor: Detecting When a Monitor Has Been Manipulated

**Problem:** Prompt injections silently corrupt a trusted monitor's judgment, and downstream protocols that trust the monitor's score then fail. There is little work on a cheap meta-signal that flags 'this monitoring call was probably manipulated' independent of the score itself.

**Direction:** Run a monitor on clean vs prompt-injected inputs and look for cheap manipulation tells: monitor output self-consistency across paraphrases of the same input, sudden score drops when injection text is stripped, or the monitor referencing the injected instruction in its rationale. Build a simple meta-detector and measure how well it flags injected cases.

**Why it matters:** Protecting the monitor itself is a single-point-of-failure problem that current protocols largely ignore. A lightweight manipulation-detector is reusable defensive infrastructure and squarely feasible with API access and no training.

**Relevant context:** Adaptive Attacks on Trusted Monitors (arxiv 2510.09462): injections bypass downstream protocols that begin only after content is flagged; the monitor is a single point of failure (Redwood). Monitoring Monitorability (arxiv 2512.18311) studies meta-monitoring signals.
