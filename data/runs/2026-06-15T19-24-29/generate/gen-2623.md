# Provenance Tracking (Taint Analysis) for Tracing Sabotage Through Agent Trajectories

**Problem:** When a monitor flags a harmful final action, it's hard to know which earlier step planted it. Without provenance, blue teams can't tell whether an attack was a single act or a multi-step plan, which matters for resampling/rollback decisions.

**Direction:** Adapt dynamic taint analysis / data provenance from program analysis. Instrument a sandboxed agent so each piece of state is tagged with the action(s) that produced it; when a harmful action occurs, back-trace the taint chain to the originating steps. On SHADE-Arena attack trajectories, measure how far back the true sabotage seed is from the visible harm and whether taint chains distinguish single-step vs multi-step attacks.

**Why it matters:** Enables targeted rollback/resampling and supports the 'concentrated vs distributed failure' distinction UK AISI calls out. Builds reusable monitoring infrastructure on a single machine, no training, novel application of taint tracking.

**Relevant context:** Dynamic taint analysis tracks data flow from sources to sinks for security. UK AISI flags detecting concentrated vs distributed failures as needing different approaches (ai_control context). Resampling/rollback decisions depend on attack structure (Ctrl-Z arXiv:2504.10374).
