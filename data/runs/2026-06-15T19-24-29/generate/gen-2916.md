# LTL Specification Coverage as an Agent-Safety Benchmark Metric

**Problem:** Agent benchmarks score task success but rarely check temporal safety properties (e.g. 'never call a destructive tool before confirmation', 'always stop when budget exceeded'). There is no notion of how many safety specs a benchmark even exercises.

**Direction:** Import linear temporal logic (LTL) specification and runtime monitoring from formal methods. Write a small library of LTL safety properties over agent execution traces, instrument an open agent on existing open task suites (e.g. METR-style tasks) to log tool-call traces, and check each trace against the monitors. Report per-property violation rates and 'specification coverage' (which safety properties the benchmark actually stresses). No theorem proving — just runtime trace checking.

**Why it matters:** Brings precise, machine-checkable safety properties to agentic evals (a flagged gap) and reveals which safety behaviors current benchmarks never test. Lightweight runtime monitors on open suites; reusable infrastructure with strong counterfactual value.

**Relevant context:** AgentVerify (Preprints 202604.1029) specifies agent safety via temporal logic over tool-call protocols and human-in-the-loop boundaries with runtime monitoring; VeriGuard (arXiv:2510.05156) checks agent actions against safety specs.
