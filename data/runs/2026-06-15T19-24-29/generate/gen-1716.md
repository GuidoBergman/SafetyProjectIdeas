# Metamorphic Testing of SAE Feature Stability

**Problem:** Sparse autoencoder (SAE) features are validated mostly by eyeballing dashboards; there is no cheap, principled check that a feature responds consistently to semantically equivalent inputs. We lack a notion of feature 'invariance' that mirrors the metamorphic-relation idea from software testing.

**Direction:** Borrow metamorphic testing from software engineering: define metamorphic relations on text (paraphrase, synonym swap, active/passive voice, irrelevant-sentence insertion) and check whether a pre-trained SAE feature's activation is preserved (invariant relations) or changes predictably (directed relations). Using SAELens + a public GPT-2/Gemma SAE on TransformerLens, sample top-activating contexts for ~50 features, apply each metamorphic transform, and measure activation drift. Report which features are robust vs. brittle and whether brittleness correlates with how 'interpretable' the auto-label looks.

**Why it matters:** If interpretability features that we trust for safety monitoring break under trivial paraphrase, then SAE-based monitors are easy to evade. A metamorphic-stability score gives a lab-independent reliability metric for any released SAE, exactly the kind of evaluation frontier labs underinvest in.

**Relevant context:** Detection and fuzzing are already used as scalable SAE-feature scoring metrics (EleutherAI autointerp blog; 'Sparse Autoencoders Find Highly Interpretable Features', arXiv:2309.08600). Metamorphic testing is a standard software-testing technique for systems without a test oracle. SAELens provides pre-trained SAE weights, so no training is required.
