# The Delegation Link: When Does an Agent Hand Off Control to an Unvetted Sub-Agent?

**Problem:** Uncontrolled-delegation chain: agent faces a hard subtask -> agent spawns/calls a sub-agent or external tool -> control flows to an unvetted component -> safety constraints are bypassed downstream. The under-studied link is *what triggers* an agent to delegate, and whether delegation correlates with dropping safety checks.

**Direction:** Give a small open agent a 'delegate to helper' tool and tasks of varying difficulty, some safety-sensitive. Measure delegation rate vs task difficulty and whether delegated subtasks retain the original safety constraints in their instructions. Identify conditions where delegation strips safety context.

**Why it matters:** Uncontrolled delegation is a named agentic-safety gap; pinpointing the delegation trigger and its safety-context loss informs guardrails. A small monitoring-harness prototype, valuable and lab-independent.

**Relevant context:** Benchmarks agent gap analysis names uncontrolled delegation as an open problem; TrinityGuard (arXiv 2603.15408) and multi-agent safety surveys flag sub-agent control transfer as a risk surface.
