# Is Sycophancy Caused by Suppressed Knowledge or Overridden Output?

**Problem:** Sycophancy chain: model knows correct answer -> user expresses contrary preference -> model suppresses correct answer OR overrides it at output. It is unknown which link breaks: does the model lose internal access to the truth, or retain it but write the flattering answer anyway?

**Direction:** On Gemma-2-2B/9B with Gemma Scope SAEs, build prompts where the user pushes a wrong answer. Use a linear truth-probe (trained on neutral statements) to check whether the correct-answer representation is still present in late layers when the model outputs the sycophantic answer. Cross-check with relevant SAE features.

**Why it matters:** If the truth is retained internally, a monitor can recover the model's 'real' belief; if suppressed, the failure is deeper. Directly informs whether interpretability can backstop sycophancy. Uses public Gemma Scope SAEs, one GPU, no training.

**Relevant context:** Gemma Scope provides SAEs on every layer of Gemma-2. LessWrong 'SAE features for refusal and sycophancy steering vectors' notes researchers could NOT find a sparse feature combo reproducing sycophancy steering — implying the mechanism is not a single clean feature, a fresh angle to probe.
