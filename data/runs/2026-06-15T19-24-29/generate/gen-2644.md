# Trusted-Monitor Competence Ceiling: Backdoor Subtlety the Weak Model Cannot See

**Problem:** Risk: trusted monitoring fails when the untrusted model's actions exceed the weak monitor's comprehension. Causal chain: untrusted (strong) model writes a backdoor -> weak trusted monitor must comprehend the code to flag it -> if the backdoor exploits logic beyond the monitor's competence, it passes. The under-studied link is mapping the subtlety threshold: as a function of code complexity and exploit subtlety, where exactly does a given trusted-monitor model's detection collapse?

**Direction:** Curate backdoored code examples graded by exploit subtlety (obvious magic-number checks -> subtle off-by-one / type-coercion exploits). Run several trusted monitors of different sizes (1B-8B open models) and plot detection rate vs. subtlety per monitor size. Identify the subtlety frontier where each monitor falls to chance.

**Why it matters:** The whole trusted/untrusted gap rests on the monitor being competent enough; quantifying the subtlety ceiling per monitor size tells protocol designers how big a trusted model they actually need. Uses public backdoor examples and open models, single GPU, no training.
