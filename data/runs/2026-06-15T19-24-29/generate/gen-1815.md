# Quantization Shifts Features Plus Audited-Model-Differs-From-Deployed-Model

**Problem:** Compound: (1) quantization/distillation moves internal features so interp results don't transfer (interp portability failure) amplifying (2) the deployment gap where the audited full-precision model is not the quantized model users hit. A safety feature validated in fp16 may not exist or may relocate in the int4 deployed variant.

**Direction:** Take an open model in fp16 and a 4-bit quantized version. Find a safety-relevant probe/feature in fp16; test whether the same probe direction still detects the concept in the quantized model. Measure detection degradation and feature drift, quantifying how much an fp16 interp audit over-states safety of the deployed quantized model.

**Why it matters:** Almost all real deployment is quantized, but interp/audits run on full precision. Measuring the audit-to-deployment feature gap is a fresh, practically important compound risk runnable on a single consumer GPU.

**Relevant context:** Search results: 'Position: Prioritize Feature Consistency in SAEs' (arXiv:2505.20254) on feature instability across conditions. Quantization is standard (bitsandbytes int4/int8) on consumer GPUs. TransformerLens / probe tooling supports both precisions.
