# Code Coverage Criteria Adapted to Safety-Behavior Coverage

**Problem:** Software testing has rich coverage criteria (statement, branch, MC/DC) that quantify how thoroughly a system is exercised. Safety evals have no analogous notion of how thoroughly the model's REFUSAL decision boundary is exercised.

**Direction:** Define a 'refusal-branch coverage' metric. Treat the safety taxonomy (e.g. AILuminate's 12 hazard categories x several intensity levels x several framings) as a coverage matrix, and measure what fraction of cells a given test suite exercises and at what cells the model's refusal flips. Run on an open model; produce a coverage report highlighting under-tested hazard/framing combinations and 'decision branches' the model handles inconsistently.

**Why it matters:** Turns ad-hoc benchmarking into a measurable coverage discipline and surfaces systematically untested corners. Uses public benchmark prompts only; trivially reproducible by anyone outside a lab.

**Relevant context:** Branch/MC-DC coverage are foundational software-testing concepts. AILuminate (MLCommons, 24K+ prompts, 12 hazard categories) and HELM Safety from context file provide the taxonomy grid.
