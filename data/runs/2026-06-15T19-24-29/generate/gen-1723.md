# Phylogenetic Tracking of Feature Emergence Across Checkpoints

**Problem:** We don't understand how features emerge during training (a stated open problem on training dynamics). There is no principled way to relate features across consecutive checkpoints.

**Direction:** Borrow phylogenetic tree construction from evolutionary biology. Across released Pythia training checkpoints, match SAE/probe-defined features between adjacent checkpoints by activation-correlation distance, then build a 'feature phylogeny' showing births, splits, and deaths of features over training. Identify when safety-relevant features (e.g., a sentiment or refusal direction) first stabilize. Uses pre-released checkpoints; no training.

**Why it matters:** Maps when alignment-relevant representations crystallize during training, a counterfactually valuable, long-horizon question labs rarely study because it needs no production scale, only the public Pythia suite.

**Relevant context:** Pythia provides 154 public checkpoints expressly for studying training dynamics. Phylogenetic distance/tree methods (MDPI Bioengineering 11(5):480) are mature. The context lists 'how training dynamics shape features' as an open problem.
