# Fuzzing-Style Coverage Metrics for Agent Action Spaces

**Problem:** Red-teaming and safety evals of agents explore only a tiny slice of possible action sequences, but unlike code fuzzing there is no notion of 'coverage' to know what remains untested.

**Direction:** Import coverage-guided fuzzing concepts. Define an action-space coverage metric (e.g. distinct tool-call bigrams or state-transition edges exercised). Run a simple fuzzer that perturbs task prompts to maximize new coverage, and report the coverage curve and which dangerous tool-transition edges remain unreached by standard benchmarks. Lightweight: only API calls + bookkeeping.

**Why it matters:** Gives agent safety testing a quantitative 'how much have we explored' metric and exposes systematic blind spots in existing benchmarks — reusable infrastructure for anyone red-teaming agents.

**Relevant context:** Coverage-guided fuzzing (e.g. AFL) is standard in software security; ReliabilityBench and AgentDojo-style harnesses evaluate agents but report no action-space coverage. The roadmap arXiv 2406.05438 calls for adapting classical testing (incl. coverage) to LLM-based systems.
