# Backcasting from 'Outsiders Can Verify a Model's Identity': A Lightweight Model-Fingerprinting Probe

**Problem:** A success state for third-party verification requires being able to confirm that a deployed API actually serves the model a lab claims (no silent swap to a cheaper/less-safe model). Today external auditors have no cheap way to verify model identity behind an API.

**Direction:** On open models accessible via API or local hosting, build a small behavioral 'fingerprint' — a fixed battery of low-temperature prompts whose answer patterns are model-specific — and test whether you can distinguish models (e.g., two Llama variants, a base vs fine-tuned version) reliably above chance. Quantify how many probe queries are needed and how robust the fingerprint is to sampling settings.

**Why it matters:** Backcasting from 'verifiable deployment claims' shows the precondition is cheap external model-identity verification. A working fingerprinting prototype gives regulators and auditors a tool to detect undisclosed model swaps. Needs only API/local access to open models — exactly the structured-access verification gap outsiders can prototype.

**Relevant context:** Open Problems in Technical AI Governance lists verification/access as core capacities; 'Toward Trustworthy AI Development' (arXiv:2004.07213) on verifiable claims; Laminator (arXiv:2406.17548) on verifiable ML property cards via attestation.
