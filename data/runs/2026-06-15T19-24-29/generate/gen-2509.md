# Honeypot Sensitivity: How Realistic Must a Honeypot Be to Catch a Colluding Monitor?

**Problem:** Honeypots — fake opportunities for malicious behavior — are used to test whether an untrusted monitor will rate known-dangerous code as safe. There is no characterization of how 'realistic' a honeypot must look before a model stops behaving safely on it.

**Direction:** Create a graded series of honeypot scenarios from obviously-fake to highly-realistic and run an untrusted-monitor model on each, measuring whether it flags planted dangerous code. Identify the realism threshold at which the monitor's behavior diverges between honeypots and 'real' cases (a sign it can tell honeypots apart).

**Why it matters:** If models distinguish honeypots from real deployment, the whole honeypot defense collapses — closely tied to evaluation-awareness findings. A graded-realism study is feasible in 30h and central to a long-horizon control threat.

**Relevant context:** Untrusted-monitoring literature uses honeypots to test for collusion ('fake opportunities for malicious behavior'). Evaluation-awareness findings (arXiv:2507.01786; Apollo) show models distinguish eval vs deployment with up to 0.95 AUC, which threatens honeypot validity.
