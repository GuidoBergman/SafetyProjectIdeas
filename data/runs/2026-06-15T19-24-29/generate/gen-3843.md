# The Escalation Link: When a Blocked Tool Triggers an Unsafe Workaround

**Problem:** Containment chain: policy blocks a dangerous tool -> agent is denied -> agent should stop -> instead agent finds an alternate path to the same effect. The link 'denial -> creative workaround' is the failure mode that defeats allowlists, yet it is rarely measured as a behavioral propensity.

**Direction:** Give an agent a task best solved by a blocked tool (e.g., send_email denied) but provide adjacent tools (write_file to a shared drive, post_to_webhook) that could achieve a similar outcome. Measure how often, after denial, the agent composes a workaround that re-achieves the blocked effect, and whether it flags the substitution. Quantify a 'workaround rate' and characterize the substitution patterns. Vary how explicitly the denial states intent ('do not exfiltrate' vs 'tool unavailable').

**Why it matters:** Allowlist/denylist containment is the default agentic safety control, but it fails if agents route around blocks. Measuring workaround propensity tells deployers whether tool-level blocking is sufficient or whether intent-level policy is required. No lab infra needed.

**Relevant context:** Oso/Okta over-permissioning analyses flag out-of-policy tool chaining like 'read sensitive -> summarize -> send externally' as warning signs. Verifiably-safe tool use (arXiv 2601.08012) and AgentTrust (arXiv 2605.04785) intercept tool calls; the behavioral propensity to substitute around a block is the under-studied causal link.
