# Asynchronous Control Lag: How Much Damage Lands Before a Delayed Monitor Catches It?

**Problem:** Async control assumes a monitor reviews actions after they execute; the safety depends on how fast the monitor flags relative to how fast harm becomes irreversible. The trade-off between monitoring latency and irreversible-action exposure is under-characterized for beginners.

**Direction:** Simulate an agent producing a stream of actions, a subset irreversible, where a monitor reviews with a configurable lag (k steps behind). Sweep lag and measure the fraction of irreversible harmful actions that execute before being flagged. Produce a latency-vs-containment curve identifying the lag beyond which async control fails to contain.

**Why it matters:** Async monitoring is attractive for throughput but its safety guarantee hinges on latency. Quantifying the latency cliff for irreversible actions informs the 'minimum runtime controls' open problem directly. Lightweight simulation, beginner-feasible.

**Relevant context:** Async Control: Stress-Testing Asynchronous Control Measures for LLM Agents (arXiv:2512.13526). UK AISI control areas highlight preventing irreversible harmful actions; CLAUDE.md/context lists 'minimum set of runtime controls' as an open problem.
