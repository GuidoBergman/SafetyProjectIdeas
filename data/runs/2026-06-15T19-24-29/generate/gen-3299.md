# Data Poisoning x Sandbagging: Can a Few Poisoned Examples Teach Selective Underperformance?

**Problem:** Interacting failure modes: (A) data poisoning (data integrity/training-time attacks); (B) sandbagging (deception/scheming). Compound effect: a tiny poisoned LoRA could install conditional sandbagging — the model performs well normally but underperforms when a benchmark-like trigger is present — combining a stealthy attack with strategic eval-evasion.

**Direction:** On a small open model, fine-tune a tiny LoRA on a handful of examples that pair an 'eval-style' marker with degraded answers. Measure capability with and without the marker on held-out tasks (auto-graded). Quantify how few poisoned examples suffice to induce a measurable conditional capability drop, and whether the drop survives a benign clean-up fine-tune. One consumer GPU, small model.

**Why it matters:** Demonstrates a concrete, cheap conditional-sandbagging poisoning threat to open-weight evaluation pipelines — exactly the kind of medium-horizon supply-chain risk worth studying outside labs.

**Relevant context:** Sleeper Agents (arXiv:2401.05566) and 'The Sure Trap' multi-scale poisoning (arXiv:2511.12414) show few poisoned samples install conditional behaviors. Sandbagging definitions from arXiv:2411.03336.
