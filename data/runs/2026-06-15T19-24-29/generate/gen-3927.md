# A Minimal Pre-Execution Firewall Prototype Inspired by AEGIS

**Problem:** AEGIS (security-risks analysis, arXiv:2605.09721 / reframing paper arXiv:2605.24309, May 2026) argues model-generated tool calls reach the execution layer with no framework-agnostic control point, and post-execution observability can't stop side effects. A minimal, openly-reproducible pre-execution firewall has not been benchmarked by independents.

**Direction:** Implement a tiny pre-execution gate that intercepts tool calls from an open agent, classifies each as low/medium/high-impact via a small rubric+LLM check, and blocks or requires confirmation for high-impact ones (e.g. delete, send, transfer). Measure how many harmful actions it stops vs how much benign throughput it blocks on a small task suite.

**Why it matters:** A safer-sandbox/firewall prototype is exactly the strategically valuable, infra-free infrastructure the steering favors; an open reference implementation aids agent-security standards.

**Relevant context:** Security Risks in Tool-Enabled AI Agents (arXiv:2605.09721, May 2026, IEEE COMPSAC 2026); Reframing LLM Agent Security as an Agent-Human Interaction Problem (arXiv:2605.24309, May 2026).
