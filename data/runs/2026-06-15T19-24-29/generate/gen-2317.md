# Software Code-Coverage Analogues for Oversight Question Coverage

**Problem:** We red-team oversight protocols with ad hoc questions and never know what fraction of the 'argument space' the judge has actually been probed on, leaving blind spots.

**Direction:** Transfer code-coverage thinking to oversight: define a coverage taxonomy of reasoning-error categories (logical, factual, statistical, citation, scope) and measure what fraction of categories a given evaluation set exercises on a weak judge. Build a small coverage report tool and apply it to an existing debate-judging dataset to reveal under-tested error types.

**Why it matters:** Coverage gaps are where strategic models hide; a coverage instrument for oversight evals is reusable infrastructure that any small group can build and share.

**Relevant context:** Code coverage as test-adequacy metric in software testing; unified adequacy metrics for MT/mutation (cho-icsme-2025). Rethinking testing for LLM applications (arXiv:2508.20737). Systematic oversight-failure characterization (FR68 hint).
