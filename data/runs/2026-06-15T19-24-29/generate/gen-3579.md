# Backcasting Faithful 'Because' Statements: Do Models' Stated Reasons Match Their Causal Drivers in Classification?

**Problem:** A success state is a model whose stated reason for a decision matches the feature that actually drove it. Backward, we need an accessible causal test of explanation faithfulness on a controlled task. The biasing-features literature does this for hints; a clean, controllable-feature version on a simple classification task gives crisp ground truth.

**Direction:** On a controllable text-classification task (e.g., sentiment with an injected spurious token like a name or topic that biases the label), have the open model classify and explain. Causally vary the spurious feature to confirm it drives the label, then check whether the model's stated reason mentions it. Report faithfulness as the rate the explanation cites the actual causal driver.

**Why it matters:** A controllable-ground-truth setup makes explanation faithfulness measurable without ambiguity, advancing the core 'is CoT faithful to computation' question with a clean, reproducible design.

**Relevant context:** Biasing-features and counterfactual-edit faithfulness metrics (Turpin 2023; Chen 2025; FaithCoT-Bench arXiv 2510.04040); Is CoT Really Not Explainability? (arXiv 2512.23032) warns lexical checks can mislead.
