# Refusal Direction Transfer Across Chat Templates and System Prompts

**Problem:** Refusal-direction work extracts the direction with a fixed prompt format. In practice the same open weights are deployed with very different chat templates and system prompts. It is unverified whether a refusal direction extracted under one template still mediates refusal under a different template/system prompt.

**Direction:** Extract the difference-of-means refusal direction for one open chat model under its default template. Then evaluate steering (ablate/add the direction) when the model is run with (a) no system prompt, (b) a 'be maximally helpful' system prompt, (c) an alternate but valid chat template. Measure refusal-rate change on a held-out harmful-prompt set under each condition. Report direction-transfer robustness.

**Why it matters:** Safety interventions and red-team probes are validated under one configuration but deployed under many. If a refusal direction is template-fragile, jailbreaks via template manipulation become an interpretable, predictable attack surface — a finding any outside researcher can produce and that is directly deployment-relevant.

**Relevant context:** Arditi et al. (NeurIPS 2024) difference-of-means refusal direction; representation-engineering literature notes steering vectors are sensitive to prompt distribution (e.g. 'Predicting Where Steering Vectors Succeed').
