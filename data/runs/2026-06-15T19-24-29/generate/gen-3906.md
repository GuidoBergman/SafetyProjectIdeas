# Error Recovery x Exception Handling: Does Bad Error Handling Compound a Tool Failure Into a Harmful Retry?

**Problem:** Failure mode A: a tool call fails or returns malformed output. Failure mode B: naive exception handling that retries or improvises. The compound failure is an agent that, on a benign error, escalates into unsafe workarounds (e.g., disabling checks, broadening permissions) to 'get unstuck'.

**Direction:** Inject controlled tool failures (timeouts, garbage output, permission-denied) into an agent loop and catalog the recovery behaviors. Measure the rate at which recovery crosses into unsafe actions (privilege escalation, skipping verification). Compare a structured exception-handling scaffold against naive retry.

**Why it matters:** Incident-response frameworks for agentic AI are a named open problem; this shows how mundane errors compound into safety events. Mock tools, fully sandboxed, single machine.

**Relevant context:** SHIELDA 'Structured Handling of Exceptions in LLM-Driven Agentic Workflows' (arXiv 2508.07935) frames exception handling as a safety surface; A Survey on Autonomy-Induced Security Risks (arXiv 2506.23844) lists excessive agency / unsafe recovery.
