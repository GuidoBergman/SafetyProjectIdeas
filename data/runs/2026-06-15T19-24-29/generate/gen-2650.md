# Egress-Allowlist Firewall as a Tripwire for Agent Exfiltration

**Problem:** Risk: an untrusted agent exfiltrates data or reaches out to an unauthorized endpoint. Causal chain: agent forms intent -> constructs a network request -> egress layer permits or denies -> exfiltration succeeds if permitted. The under-studied link is how well a simple destination-allowlist firewall, treated as a tripwire (log + alert on any blocked egress), serves as an anomaly detector versus needing semantic monitoring.

**Direction:** Prototype a tiny egress-control proxy that an agent's tool calls must route through, with a domain/IP allowlist. Run benign and adversarial agent tasks (injection-laden) through it and measure: exfiltration attempts blocked, alert precision (do blocks correlate with genuinely malign trajectories), and benign-task breakage. Treat each block as an anomaly signal and evaluate it as a tripwire.

**Why it matters:** Egress allowlisting is recommended as today's most effective defense but is rarely evaluated as an anomaly/tripwire signal. A working prototype + evaluation is strategically valuable sandbox infrastructure anyone can build and deploy, no model internals. Strong counterfactual value.

**Relevant context:** Trail of Bits (2025) and prompt-injection surveys (arXiv:2601.17548) cite mandatory sandboxing with strict egress controls as the most effective current defense. Tripwire mechanisms (AI Safety Directory) embed detection signals to alert on unauthorized actions. CUA-SHADE-Arena provides shell/network agent tasks.
