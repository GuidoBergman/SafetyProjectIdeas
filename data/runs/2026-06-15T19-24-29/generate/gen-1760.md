# Does Fine-Tuning for Harmlessness Add a Gate or Erase the Capability?

**Problem:** Safety-training chain: base model has harmful capability -> safety FT applied -> deployed model refuses. The 'shallow safety' worry is that FT only adds a thin refusal gate while the capability stays intact underneath. Which link FT actually changes (gate vs capability) is testable with open base/chat pairs.

**Direction:** Take an open base model and its safety-tuned chat counterpart (e.g. Llama-3.1-8B base vs Instruct). Train a 'harmful-completion-capability' probe on the base model's activations, then check whether that same representation is still present (just gated) in the chat model when it refuses — using the chat model's pre-refusal activations.

**Why it matters:** If capability is retained behind a gate, refusal is removable (consistent with single-direction jailbreaks) and safety FT is brittle. Strong evidence for the 'shallow alignment' threat model; uses only public checkpoints.

**Relevant context:** Arditi et al. (arXiv 2406.11717): erasing one direction removes refusal across 13 models up to 72B, implying capability persists. 'An Adversarial Perspective on Machine Unlearning' (arXiv 2409.18025) shows 'removed' capabilities are often recoverable.
