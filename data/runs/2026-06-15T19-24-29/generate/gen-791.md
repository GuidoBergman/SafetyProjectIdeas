# An AI Incident Near-Miss Taxonomy Gap Audit of the AI Incident Database

**Problem:** The OECD common reporting framework distinguishes harms from near-misses and lists 29 core reporting criteria, but the AI Incident Database (AIID) was not designed around that schema. It is unknown how many AIID records contain the OECD-required fields or qualify as near-misses.

**Direction:** Sample ~150 AIID incidents, build a small coding tool that maps each record's fields onto the OECD 29-criterion schema (present/absent), and classify each as materialized-harm vs near-miss. Report coverage per OECD dimension and the near-miss capture rate, surfacing which required fields are systematically missing.

**Why it matters:** National incident-response frameworks (the NTSB-for-AI open problem) need a common reporting schema; quantifying the gap between an existing database and the emerging OECD standard is directly actionable governance tooling, doable with public data.

**Relevant context:** OECD 'Towards a common reporting framework for AI incidents' (88->29 criteria, 8 dimensions); CSET AI Incidents brief (Jan 2025); MIT AI Incident Tracker (5499 reports / 1366 incidents). AIID data is public and downloadable.
