# Measuring 'Capability Elicitation Effort' Disclosure in Safety Evaluations

**Problem:** Safety policies promise evals that 'elicit the full capabilities of the model', but whether reported evals actually used strong elicitation (fine-tuning, scaffolding, best-of-n, expert prompting) is rarely quantified. There is no metric for disclosed elicitation effort.

**Direction:** Define an elicitation-effort scale (raw prompt / few-shot / scaffolding / tool-use / fine-tuned / expert-in-loop) and code every dangerous-capability eval described in public system cards by the elicitation level disclosed. Report whether labs meet their own 'full capability elicitation' commitments and where disclosure is silent.

**Why it matters:** Under-elicitation can hide dangerous capabilities, making safety verdicts unreliable; a disclosure metric makes this auditable from public documents and pressures labs to report elicitation methodology.

**Relevant context:** METR Common Elements (full-elicitation commitments); dangerous-capability eval sections of public system cards; 'Who Should Run Advanced AI Evaluations' (arXiv 2407.20847).
