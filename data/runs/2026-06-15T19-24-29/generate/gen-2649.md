# Minimal Runtime Controls: How Few Tool-Permission Rules Block Irreversible Actions?

**Problem:** Risk: an agentic AI performs an irreversible harmful action. Causal chain: agent decides on a harmful action -> issues a tool call -> a permission/validation layer either blocks or allows it -> harm occurs if allowed. The under-studied link is the minimal set of static permission rules (no LLM judgment) that catches most irreversible-action attempts in agent traces, establishing a cheap floor before fancier monitoring.

**Direction:** Collect a set of agent trajectories containing harmful tool calls (SHADE-Arena / CUA-SHADE shell scenarios). Build a tiny rule-based allowlist/denylist firewall (e.g. block external network writes, file deletes outside workspace, credential reads) and measure what fraction of harmful actions it blocks vs. how many benign tasks it breaks. Find the minimal high-coverage rule set.

**Why it matters:** The subfield explicitly asks what minimum runtime controls are necessary per risk level. A cheap, dumb permission firewall that blocks most irreversible harm is strategically valuable infrastructure deployable by anyone, no model access needed. Pure software prototype, ideal first project.

**Relevant context:** Subfield open problem: establish minimum runtime controls (kill switches, output validation, human-in-the-loop) per risk level. Prompt-injection defense work (arXiv:2503.18813, Trail of Bits 2025) finds sandboxing + egress controls + tool filtering the most effective current defense. CUA-SHADE-Arena tests shell/file/git agent actions.
