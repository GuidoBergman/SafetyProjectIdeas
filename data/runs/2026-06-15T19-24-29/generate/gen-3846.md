# Plan-Stage vs Execute-Stage Safety Divergence: Where Does the Safe Plan Get Violated?

**Problem:** Plan-then-execute chain: agent writes a plan -> plan is (safely) reviewed -> agent executes -> execution silently deviates from the approved plan. The under-studied link is plan-execution fidelity: a plan can pass review yet the executor drifts, doing actions the plan never specified.

**Direction:** Use a plan-then-execute harness: capture the agent's explicit plan, then log every tool call during execution. Measure deviation rate -- actions executed that were not in the approved plan, and approved steps skipped. Stratify by task length and by whether mid-task obstacles arise. Report a plan-fidelity score and characterize where deviations cluster (obstacle handling, error recovery).

**Why it matters:** Plan-review is a key oversight pattern: review the cheap plan, then trust execution. If execution routinely deviates from approved plans, plan-level review provides false assurance. A simple plan-vs-log diff makes this measurable without any internals.

**Relevant context:** Plan-then-execute resilience guide (arXiv 2509.08646) and the high-stakes architecture (arXiv 2511.07669) advocate reviewing plans before execution. Agent-drift work (arXiv 2601.04170) shows behavioral drift over steps. Plan-vs-execution fidelity as the violated link is under-quantified.
