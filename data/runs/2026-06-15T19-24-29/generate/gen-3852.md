# The Monitor-Latency Link: Can Fast Irreversible Actions Outrun an LLM Safety Monitor?

**Problem:** Runtime-interception chain: agent emits action -> monitor inspects it -> monitor approves/blocks -> action executes. The neglected link is timing/throughput: if the monitor is an LLM, an agent emitting rapid tool calls may complete an irreversible action before (or faster than) the monitor can flag it, especially in async setups.

**Direction:** Build a small async harness where an agent issues tool calls and an LLM monitor evaluates each. Vary monitor latency and whether execution is gated (blocking) vs advisory (non-blocking). Measure the fraction of harmful actions that execute before the monitor returns under each regime, and the throughput cost of strict blocking. Produce a safety-vs-latency tradeoff curve and a recommended gating policy for irreversible actions.

**Why it matters:** Runtime monitoring is a primary defense for agentic deployments, but its security depends on whether it gates execution. Quantifying the race condition -- and showing irreversible actions need synchronous gating -- is a concrete, infrastructure-relevant result requiring only orchestration code.

**Relevant context:** AgentTrust (arXiv 2605.04785) is a runtime safety evaluation/interception layer recommending HITL for irreversible ops. Weak-to-strong monitoring (arXiv 2508.19461) and AgentAuditor (arXiv 2506.00641) use LLM monitors. The execution/monitor race and blocking-vs-advisory tradeoff is an under-studied systems-level safety link.
