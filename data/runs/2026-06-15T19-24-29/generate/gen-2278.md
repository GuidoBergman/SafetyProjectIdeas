# When the Sneaky Prover Wins: Reproducing Legibility Decay on a Toy Verifier

**Problem:** OpenAI's Prover-Verifier Games found that optimizing chain-of-thought only for correctness makes solutions less legible, doubling human verifier error. The failure mode — 'sneaky' provers that fool weak verifiers — has only been demonstrated at the GPT-4 family scale inside a lab, leaving open how easily it appears with off-the-shelf small models.

**Direction:** Set up a small checkability game without training: use a strong open model (e.g. Llama-3-70B via API or a 7-8B local model) as prover prompted in 'helpful' vs 'sneaky' modes on grade-school math (GSM8K), and a much weaker model (e.g. a 1-3B model) as verifier. Measure verifier accept-rate and a human verifier's error rate on sneaky-but-wrong solutions versus honest-but-wrong ones. Characterize which obfuscation tactics (irrelevant lemmas, confident tone, dense notation) most inflate the verifier's false-accept rate.

**Why it matters:** Pinpoints the prompt-level features that make wrong solutions slip past weak overseers, a core scalable-oversight failure. Needs no training, no lab infrastructure, and uses only public benchmarks — exactly the kind of diffuse-reward evaluation labs deprioritize.

**Relevant context:** OpenAI Prover-Verifier Games (arXiv:2407.13692): correctness-only optimization halves legibility, human evaluators made ~2x more errors; 'sneaky' provers trained to produce incorrect solutions that fool the verifier. Scoped here to prompting rather than training.
