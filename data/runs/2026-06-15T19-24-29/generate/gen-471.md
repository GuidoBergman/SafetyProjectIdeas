# VingeBench: Can an LLM Trust a Slightly-Stronger Successor It Cannot Fully Verify?

**Problem:** Vingean reflection asks how an agent can reason about/trust a successor it cannot fully evaluate. This is purely theoretical with no empirical proxy. Verifier benchmarks (VerifyBench, arXiv:2507.09884) measure verification accuracy but never frame it as the Vingean trust problem of a weaker overseer deciding whether to defer to a stronger generator.

**Direction:** Set up a weak model as 'overseer' and a stronger model as 'successor' on tasks with ground truth. The overseer must decide, per task and WITHOUT seeing the answer's correctness, whether to defer to the successor or override it, using only a verification signal it can compute. Measure the overseer's net utility vs. always-defer / never-defer baselines as the capability gap widens. Output a 'safe-deference frontier' curve.

**Why it matters:** Vingean reflection is a flagged open problem in this subfield. An empirical proxy — when does a weaker verifier benefit from trusting a stronger generator it can't fully check — turns an untestable formal puzzle into a measurable scaling curve relevant to scalable oversight. Uses only API/open models, no training.

**Relevant context:** Grounded in 'Vingean Reflection: Open Problems' (Alignment Forum, listed in subfield context) and verification benchmarks VerifyBench (arXiv:2507.09884) and 'Trust but Verify' survey (arXiv:2508.16665). Beginner-feasible: orchestration + accuracy bookkeeping.
