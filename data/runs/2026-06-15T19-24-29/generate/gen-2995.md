# Refusal Over-Triggering x Capability Eval: Safety Tax Masquerading as Incapability

**Problem:** Failure mode A is over-refusal (a model refuses benign-but-edgy requests). Failure mode B is capability evaluation that uses such prompts. The compound effect: refusals get scored as task failures, so dangerous-capability evals understate true capability for over-aligned models, while a sandbagging model could exploit the same channel by 'refusing' to hide capability.

**Direction:** Assemble dangerous-capability-style questions that are actually answerable safely (dual-use knowledge). Distinguish, for each model response, 'refused' vs 'attempted-but-wrong' vs 'correct.' Recompute capability scores treating refusals as failures vs excluding them, and show how over-refusal deflates the headline capability number and provides cover for sandbagging.

**Why it matters:** Capability elicitation underestimation is a core eval risk: if refusals look like incapability, evaluators miss latent danger and cannot distinguish a genuinely incapable model from an over-refusing or sandbagging one. The refusal-vs-error decomposition is a cheap, reusable correction.
