# GCG Suffix Transfer Decay Across Model Generations

**Problem:** Adversarial GCG suffixes transfer from source open models to other models, but as model families release new versions (Llama-2 to Llama-3 to Llama-3.x), it is unknown whether suffixes optimized on an older sibling still transfer to the newer one, i.e. whether each release closes prior suffixes.

**Direction:** Use pre-computed/public GCG suffixes (or AmpleGCG-generated suffixes) optimized on Llama-2-7B-chat and Vicuna, and measure attack success when applied unchanged to newer same-family and cross-family small open models. Build a transfer matrix (source x target) and a 'staleness' curve showing how suffix effectiveness decays across model generations.

**Why it matters:** Tells red-teamers and deployers whether old adversarial corpora retain value or whether each release resets the attack surface. Uses public attack artifacts so no GCG optimization compute is needed — keeps it within 30 hours on a single GPU.

**Relevant context:** AmpleGCG (Liao & Sun, arXiv:2404.07921, COLM) trains a generative model of transferable suffixes reaching ~100% ASR on Llama-2-7B-chat/Vicuna and 99% on GPT-3.5. 'The Resurgence of GCG Adversarial Attacks' (arXiv:2509.00391) evaluates GCG/T-GCG across Qwen2.5, LLaMA-3.2, GPT-OSS-20B. AISafetyLab provides a unified attack toolkit (context file).
