# Metamorphic Relations as a Robustness Test for Trusted Monitors

**Problem:** A trusted monitor that flags suspicious agent actions should give consistent verdicts under semantically irrelevant changes (renaming variables, reordering independent steps, paraphrasing). If a monitor's suspicion score swings wildly on such transformations, it is brittle and easily gamed.

**Direction:** Borrow metamorphic testing from software engineering: define metamorphic relations (MRs) that should preserve a monitor's verdict (e.g., variable renaming, comment insertion, equivalent tool-call reordering) and MRs that should flip it (inserting a backdoor). Apply these transformations to SHADE-Arena transcripts, query a cheap open-model monitor, and measure the rate of MR violations. Produce a 'monitor brittleness score.'

**Why it matters:** Surfaces invariance failures in monitors before deployment, a cheap diagnostic any small team can run without a model lab. Metamorphic testing needs no ground-truth oracle, sidestepping the hardest part of evaluating fuzzy-reward monitors.

**Relevant context:** Metamorphic testing checks adherence to known input-output relations (MRs) without an oracle; recent work applies it to LLM dialogue (MORTAR) and fairness (LLaMA/GPT) (arXiv:2507.22610 SLR on metamorphic testing of code models). Redwood trusted monitoring caught 62% of backdoored code (AI Control 2023).
