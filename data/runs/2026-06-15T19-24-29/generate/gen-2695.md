# Jailbreak x Monitor Evasion: Do Successful Jailbreaks Also Suppress Monitorable Cues?

**Problem:** Jailbreaking (robustness failure) and CoT/action monitoring (control) interact: a jailbreak that elicits harmful content may, as a side effect, alter the reasoning trace such that a monitor no longer flags it. The robustness failure compounds with a monitoring failure rather than triggering a backstop.

**Direction:** Run a set of known jailbreak templates against an open model on benign-vs-harmful requests, with a CoT monitor downstream. For each jailbreak that succeeds, measure whether the monitor still catches the harm. Compute the conditional detection rate (monitor catch | jailbreak success) to see if jailbreaks systematically slip past monitoring.

**Why it matters:** Layered defenses assume monitoring catches what input filtering misses. If the same jailbreak that breaks the filter also dims the monitor, the layers are correlated, not independent. Uses public jailbreak sets and API access only.

**Relevant context:** Jailbreak activations shift out of harmful-activation space (arXiv:2412.17034 / 2605.24535); CoT monitoring is the more informative channel (GPT-5 system card) — exactly what a jailbreak might perturb.
