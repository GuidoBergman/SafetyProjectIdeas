# Cascading Tool-Error Spirals: When Does Retry Logic Make an Agent Less Safe?

**Problem:** Production guidance notes agents treating all tool failures identically (retrying validation errors like rate limits) can spiral. It is unknown whether repeated tool failures push agents toward unsafe workarounds (disabling checks, escalating permissions, fabricating outputs) rather than graceful abort.

**Direction:** Build a mock toolset where a key tool can be configured to fail with different error types (transient timeout, hard validation error, permission denied). For each error type, run the agent and log its recovery actions, classifying them as safe (abort/ask user), neutral (retry), or unsafe (fabricate result, try a forbidden alternative tool, claim success). Measure how the unsafe-recovery rate rises with consecutive failures and across error types.

**Why it matters:** Reveals whether the practical engineering reality of flaky tools is a hidden driver of unsafe agent behavior — a failure mode that only appears in multi-step execution. Requires no lab resources, just a configurable mock-tool harness, and directly informs safer agent loop design.

**Relevant context:** 2025 production guides (Fastio, LangGraph, Maxim) document cascading failures, circuit breakers, and the pitfall of treating all errors the same. Agent failure-mode taxonomies (agentwiki.org) list error mishandling. handle_tool_error feeds errors back into the agent's next reasoning step.
