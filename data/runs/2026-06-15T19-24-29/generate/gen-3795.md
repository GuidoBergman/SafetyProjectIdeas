# Constraint-Violation by Outcome, Not Action: Reproducing Outcome-Driven Constraint Failures

**Problem:** A 2025 benchmark highlights that agents violate constraints defined by outcomes (e.g. 'never let account balance go negative') even while each individual action looks permissible — the violation only emerges from the cumulative effect. This sequential-outcome failure is under-explored on accessible models.

**Direction:** Implement a small environment with an outcome constraint (e.g. a budget that must stay above zero, a resource that must not be exhausted) where no single action obviously breaks it but a sequence does. Run the agent on tasks that tempt cumulative violation and measure the violation rate, plus whether the agent tracks the running aggregate. Test whether periodically surfacing the current aggregate state prevents violations.

**Why it matters:** Outcome-level constraints are how many real safety limits are specified (financial, infrastructure), and per-action guardrails miss them entirely. A reproducible study of this failure on a single GPU directly serves the open problem of agents controlling real-world systems.

**Relevant context:** 'A Benchmark for Evaluating Outcome-Driven Constraint Violations in Autonomous AI Agents' (arXiv 2512.20798). Subfield open problem: safety frameworks for agents with real-world action capabilities (financial transactions, infrastructure control).
