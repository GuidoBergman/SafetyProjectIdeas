# Does Telling an Agent an Action Is Irreversible Change Its Behavior?

**Problem:** The success state is agents that pause before irreversible actions. We don't know whether current models are even sensitive to reversibility framing — if a one-line warning in the tool description changes behavior, that's a cheap safety lever; if not, the failure is deeper.

**Direction:** Backcast from 'agents request confirmation before irreversible actions'. The needed result: a measured effect of reversibility framing. Using AgentDojo banking/email tasks, run the same tasks twice — once with neutral tool docs, once where irreversible tools carry an explicit 'THIS ACTION CANNOT BE UNDONE' annotation — and measure differences in confirmation-seeking, hesitation, and harmful completions on the security cases.

**Why it matters:** Identifies whether prompt-level reversibility cues are a real mitigation or theater, before labs invest in heavier mechanisms. Pure API + open benchmark, no training, medium-horizon control relevance.

**Relevant context:** AgentDojo (arXiv 2406.13352) is explicitly designed to test attacks/defenses with injectable instructions over untrusted data. 'Check Yourself Before You Wreck Yourself' (arXiv 2510.16492) shows selectively quitting improves agent safety, suggesting agents have a latent abort capability that framing might trigger.
