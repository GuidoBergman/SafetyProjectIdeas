# Tokenizer/Encoding Tricks x Safety-Classifier Input: Obfuscation Slips Past Both Model and Filter

**Problem:** Failure mode A is input-level obfuscation (leetspeak, homoglyphs, base64) that evades a safety filter. Failure mode B is the same obfuscation degrading the autograder/classifier that scores harm. The compound effect: the obfuscated prompt jailbreaks the model AND confuses the harm-classifier, so the attack is recorded as a clean pass.

**Direction:** Apply a few cheap obfuscations (homoglyphs, spacing, base64) to a harmful-prompt set. Measure (a) model compliance rate vs plain text and (b) the harm-classifier's detection rate on obfuscated I/O. Show the joint blind spot where both compliance rises and detection falls.

**Why it matters:** Perplexity/keyword filters and LLM graders are both fragile to surface obfuscation; if they fail together, safety pipelines have a coordinated hole. Quantifying the joint failure recommends normalizing inputs before both generation-time filtering and grading.

**Relevant context:** Encoding/obfuscation jailbreaks (base64, leetspeak) are documented in jailbreak literature; AISafetyLab unifies attack/defense/eval. Subfield scorer-reliability open problem. Catalogue already has perplexity-filter evasion, so this focuses on the joint model+grader failure.
