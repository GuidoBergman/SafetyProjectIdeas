# Mutation Adequacy for CoT Monitors: Do Faithfulness Tests Actually Catch Unfaithful Reasoning?

**Problem:** CoT-faithfulness test suites (hint-acknowledgment, paraphrase-invariance) are assumed to detect unfaithful reasoning, but like code coverage they may be a vanity metric that passes without truly exercising the failure mode.

**Direction:** Import mutation testing's 'kill rate' adequacy criterion. Treat a faithfulness test suite as the test, and synthetically inject known unfaithfulness 'mutants' into transcripts (e.g., insert a decisive hint into the prompt but a CoT that never mentions it; truncate the load-bearing reasoning step). Measure what fraction of injected mutants the suite 'kills' (flags). A suite that misses many mutants is inadequate. Use an open instruct model to generate transcripts; mutants are programmatic edits.

**Why it matters:** Mutation testing is strictly more stringent than coverage. Quantifying the kill rate of popular faithfulness tests tells the field which tests are real and which give false reassurance — directly relevant to whether CoT monitoring can be trusted for oversight.

**Relevant context:** Mutation testing measures suite quality via mutant kill rate, stricter than branch coverage (arXiv:2104.11767; Codecov mutation testing). Faithfulness tests include hint acknowledgment (arXiv:2505.05410, 25% acknowledgment for Claude 3.7) and paraphrase-invariance (arXiv:2307.13702).
