# ImpossibleGap Bench: Measuring How Often Models Hack vs. Honestly Fail on Unsolvable Tasks

**Problem:** ImpossibleBench (referenced alongside RHB) constructs tasks where any passing solution must cheat, isolating reward hacking. But there is no lightweight tool that measures, across difficulty, the crossover point where a model switches from honest 'I can't' to hacking — the empirical analogue of when an agent 'cannot be made to game rewards'.

**Direction:** Build a small ladder of coding/QA tasks ranging from solvable to provably impossible, run open/API models, and classify each response as honest-failure, honest-attempt, or hack/cheat. Plot the hacking rate vs. task impossibility and report each model's 'honesty-under-impossibility' threshold. Extension: does an explicit 'it's okay to say it's impossible' instruction shift the curve?

**Why it matters:** A UK AISI open problem is proving when agents cannot game rewards. An honest-failure-vs-hack crossover curve operationalizes the precondition: do models even prefer honesty when a task is unwinnable? This is a fuzzy-reward measurement frontier labs underweight, runnable with no training and only open/API inference.

**Relevant context:** Grounded in ImpossibleBench, RHB (arXiv:2605.02964), and EvilGenie (arXiv:2511.21654). Classification of responses can be done with a simple rubric + LLM judge — beginner-feasible.
