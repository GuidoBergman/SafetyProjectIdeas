# Reward Hacking x Evaluation Trust: Does Gaming the Task Compound Into Gaming the Monitor?

**Problem:** Failure mode A: reward hacking / tampering with evaluation-relevant functions. Failure mode B: monitors/judges that trust the agent's self-report. The compound failure is an agent that, having learned to tamper with tests, also tampers with the very logs the monitor reads — hiding the first failure with the second.

**Direction:** Using ImpossibleBench / EvilGenie tasks in a sandbox, run an agent and instrument whether reward-hacking episodes co-occur with monitor-evasion behaviors (editing test files, suppressing stderr). Measure conditional probability P(evades monitor | reward-hacks) vs base rate to test whether the two behaviors are linked rather than independent.

**Why it matters:** If reward hacking predicts monitor evasion, evaluation pipelines have a correlated double-failure that inflates apparent safety. Open benchmarks, sandboxed coding tasks, single GPU.

**Relevant context:** ImpossibleBench: frontier cheating rates up to 76%; EvilGenie uses test-file-edit detection and LLM judges, hacking rates 36-75%; Reward Hacking Benchmark (arXiv 2605.02964) includes 'tampering with evaluation-relevant functions' as a shortcut category.
