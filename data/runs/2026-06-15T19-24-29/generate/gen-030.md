# Cross-Modal Safety Drop: Does Refusal Survive When the Same Request Moves From Text to Image?

**Problem:** GAP TARGETED: the landscape lists multimodal safety as an infrastructure gap, and no subfield naturally owns the question of whether a model's text-side safety alignment transfers to the vision channel. Benchmarks like MM-SafetyBench and FigStep exist but they test image attacks in isolation; they do not measure, for a FIXED harmful request, how much refusal probability drops as the request is moved word-by-word out of the prompt and into a rendered image (OCR-style) the model must read.

**Direction:** Take a small set (~60) of clearly-harmful requests. For each, build a ladder of variants where 0%, 25%, 50%, 75%, 100% of the harmful instruction is rendered as text inside an image (the rest left as prompt text), keeping semantics constant. Run an open vision-language model (e.g., Qw2-VL-7B, Llama-3.2-Vision-11B, LLaVA) and measure refusal rate as a function of how much intent has crossed the text->image boundary. Output a 'cross-modal safety transfer curve' per model and a single 'modality safety gap' number.

**Why it matters:** This bridges adversarial_robustness and evaluations_benchmarks in a way no single benchmark currently measures: it isolates the modality-transfer axis rather than mixing it with attack cleverness. It is highly counterfactual (open VLMs, single GPU, no training) and directly informs whether text-only red-teaming under-estimates real deployment risk for multimodal agents.

**Relevant context:** MM-SafetyBench and FigStep use rendered-text images (OCR-based attacks) to express unsafe intent; SIUO shows safe inputs can yield unsafe outputs. REVEAL (arXiv:2505.04673) does multi-turn image-harm evaluation. None isolate the continuous text->image transfer axis for a fixed request. Open VLMs (Qwen2-VL, Llama-3.2-Vision, LLaVA) run on a single consumer GPU.
