# Where Does an Injected Instruction Override the System Prompt?

**Problem:** Prompt-injection chain: trusted system prompt sets policy -> untrusted data contains injected instruction -> model's 'whose instruction do I follow' arbitration flips -> model obeys the attacker. The arbitration link — a representation of instruction provenance/priority — is rarely localized.

**Direction:** On an open instruction-tuned model, build paired prompts where injected text conflicts with the system prompt. Train a probe to find an 'instruction source priority' direction (system vs user vs document). Use activation patching to test whether forcing the 'system' representation onto the injected segment restores correct refusal of the injection.

**Why it matters:** Instruction provenance is the crux of agentic safety. A localizable provenance representation suggests monitors/defenses that don't need retraining. Pure-inference study on open weights, agentic-safety infrastructure value.

**Relevant context:** Refusal-direction line of work (Arditi et al., arXiv 2406.11717) shows safety-relevant behaviors are often linearly mediated and patchable. Prompt injection is a recognized agentic threat; the internal arbitration mechanism is an open mechanistic question.
