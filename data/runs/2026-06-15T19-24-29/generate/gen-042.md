# Who Owns Tool-Output Trust? A Minimal Eval for Prompt Injection at the Tool-Result Boundary

**Problem:** GAP TARGETED: a seam between agentic_safety and adversarial_robustness that neither fully owns — indirect prompt injection via TOOL OUTPUTS (a web page, a file, an API response the agent reads) versus via the user prompt. Most jailbreak work targets the user prompt; the tool-result channel is where real agents get compromised, and it is under-evaluated as its own axis.

**Direction:** Build a tiny agent loop with one mock tool that returns attacker-controlled text. Construct ~40 injected payloads (instruction override, exfiltration, silent tool-misuse). Compare attack success when the same payload arrives via (a) the user message vs (b) a tool result the agent reads mid-task. Measure the 'channel gap' and test 2-3 cheap, prompt-level defenses (delimiting, provenance tagging, a 'data not instructions' system reminder).

**Why it matters:** Bridges agentic_safety + adversarial_robustness + ai_control. The tool-output channel is the dominant real-world injection vector for agents yet is rarely isolated from prompt-level jailbreaks. Fully counterfactual (mock tools, open model, one GPU) and produces both a reusable mini-benchmark and a defense leaderboard.

**Relevant context:** AgentDojo and OpenAgentSafety study agent injection; surveys note most frequent unsafe acts involve tool misuse under incomplete information. The catalogue has AgentDojo replications but not a clean isolation of the user-prompt vs tool-result injection channel with a defense comparison.
