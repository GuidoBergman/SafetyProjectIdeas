# Weasel Words in the EU Code of Practice: Quantifying Vagueness as a Compliance Loophole

**Problem:** The EU GPAI Code of Practice grants a compliance presumption to signatories, but its text leans on elastic phrases like 'state-of-the-art' and permits 'alternative means' of demonstrating compliance. Such vagueness is a known loophole, yet no one has systematically measured how much of the binding-adjacent text is hedged vs concretely verifiable.

**Direction:** Characterize the vagueness failure mode via text analysis. Take the public Code of Practice (and a comparison doc like the NIST AI RMF), segment it into individual commitments/measures, and code each as 'verifiable' (specific, measurable, auditable) vs 'hedged' (discretionary qualifiers, undefined SOTA references, escape clauses). Build a simple lexicon of hedging terms, validate by hand-labeling a subset, and report the fraction of safety obligations that are practically unenforceable as written.

**Why it matters:** The gap between voluntary codes and enforceable standards is an explicit open problem for the EU AI Office. A vagueness audit gives concrete, citable evidence of where the Code needs sharper drafting. Pure document analysis — no compute, no model needed beyond optional LLM-assisted coding — and squarely in the independent-watchdog niche.

**Relevant context:** EU GPAI Code of Practice final version (code-of-practice.ai); AI Office grants compliance presumption and a grace period; commentary notes 'alternative means' and 'state-of-the-art' flexibility.
