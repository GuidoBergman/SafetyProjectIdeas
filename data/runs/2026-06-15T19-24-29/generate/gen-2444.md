# Do Trusted Monitors Systematically Over-Flag? A Calibration Audit of False Positives

**Problem:** A recurring finding is that monitors fail mostly by overestimating suspiciousness of benign code, which inflates false positives and raises the 'control tax'. There is little public characterization of WHAT benign features trigger spurious high scores, which matters for usability.

**Direction:** Run a small open monitor over a set of clearly-benign code/agent transcripts and rank by suspiciousness. Cluster the high-scoring false positives and label the triggering features (unusual variable names, security keywords, obscure libraries, long files). Quantify how a two-step 'first explain, then score' prompting strategy reduces these false positives. Deliverable: a taxonomy of benign-but-flagged patterns plus a mitigation prompt.

**Why it matters:** False positives determine whether control protocols are deployable in practice; cataloguing their causes is cheap, lab-independent infrastructure work that improves every downstream protocol. Reducing the control tax keeps monitoring usable as models scale.

**Relevant context:** Adaptive Attacks paper and Control Tax (arxiv 2506.05296) note monitors mostly fail by overestimating suspiciousness of provided code; a two-step prompting strategy was devised to circumvent miscalibration. The cost of false positives is the core 'control tax' framing.
