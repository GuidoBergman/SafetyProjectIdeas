# Software Supply-Chain SBOM for Models: A 'Model Bill of Materials' to Audit Hidden Shared Dependencies

**Problem:** Cybersecurity uses Software Bills of Materials (SBOMs) to track transitive dependencies and shared vulnerable components. AI deployments lack an equivalent, so shared upstream dependencies (same base model, same RLHF dataset, same distillation teacher) that create correlated risk are invisible.

**Direction:** Transfer the SBOM concept into a 'Model Bill of Materials.' From public model cards and lineage metadata, construct dependency graphs for a set of open models/derivatives, then behaviorally test whether models sharing an upstream dependency also share a vulnerability (e.g., the same jailbreak works on all descendants of one teacher). Demonstrate transitive correlated risk.

**Why it matters:** Builds prototype monitoring infrastructure for concentration/supply-chain risk that maps and tests shared dependencies — exactly the systemic-risk monitoring gap, achievable with public metadata and small open models.

**Relevant context:** SBOM / software supply-chain dependency auditing from cybersecurity. HuggingFace fine-tune lineage; PhyloLM lineage clustering (arXiv:2404.04671). Concentration/cascading-failure open problems (context file).
