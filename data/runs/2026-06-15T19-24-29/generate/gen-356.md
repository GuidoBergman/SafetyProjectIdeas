# Prompt Injection x Tool-Use Escalation: Measuring Persistence Across Agent Turns

**Problem:** Two interacting failures: indirect prompt injection (initial access) and tool-use/agentic escalation (privilege escalation). Because agent frameworks feed tool outputs back into the model, an injected instruction can persist across turns and compound. The decay/persistence rate of an injected instruction over multi-turn agent loops on open models has not been characterized.

**Direction:** Build a minimal ReAct-style agent loop (a few mock tools: search, file-read, calculator) around an open model. Inject a benign-but-trackable instruction (e.g. 'always append token XYZ') via a tool output, then measure how many subsequent turns retain the injected behavior across model sizes and prompt structures. Success criterion: a persistence curve (probability injected instruction still active vs turn number) and identification of what context structure most extends persistence.

**Why it matters:** Agentic deployments are the medium-horizon threat labs must ship fast; the compound of injection + tool feedback turns a one-shot text attack into a persistent operational compromise. The harness is reusable safety infrastructure and runs entirely on a consumer GPU with open models, no proprietary agent stack.

**Relevant context:** OWASP PromptInjection and arXiv:2601.09625 'Promptware Kill Chain' frame injection->escalation as a multistep chain; production analyses note adversarial instructions persist across turns as tool outputs are re-fed. arXiv:2603.07379 SoK Agentic RAG notes iteration amplifies propagated errors.
