# Are 'Safety' SAE Features Just Detecting Surface Keywords?

**Problem:** A success state: 'safety features represent genuine harmful intent, not just trigger words.' Backcasting from 'semantic (not lexical) safety monitoring', a prerequisite is testing whether refusal/harm SAE features fire on harmful intent expressed without trigger keywords (paraphrase / euphemism).

**Direction:** Identify harm-related Gemma Scope features. Build matched prompt pairs: explicit harmful keywords vs. semantically-equivalent euphemistic phrasing, plus benign sentences containing the keywords. Measure feature firing across all three. A robust semantic feature fires on euphemism and not on benign keyword use; a lexical one does the opposite.

**Why it matters:** If safety features are keyword detectors, monitoring is trivially evaded by rephrasing — a direct adversarial-robustness gap. Public SAEs, no training, lightweight.

**Relevant context:** Feature steering side-effect work shows features fire on homonyms/unrelated lexical patterns ('Coffee Feature on Coffins' arXiv 2601.03047). Gemma Scope + Neuronpedia expose harm/refusal features for testing.
