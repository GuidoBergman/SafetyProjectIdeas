# Differential Fuzzing to Find Disagreement Between Two SAEs

**Problem:** Multiple SAEs trained on the same model give different feature sets, and we don't know where or why they disagree. Differential testing in software compares two implementations to surface bugs.

**Direction:** Transfer differential fuzzing. Take two public SAEs trained on the same layer/model, randomly generate (fuzz) input contexts, and search for inputs that maximize disagreement in reconstructed activations or in which feature fires. Cluster the high-disagreement inputs to characterize the systematic blind spots of each SAE. Single GPU, inference only.

**Why it matters:** Disagreement regions are where SAE-based interpretability is least trustworthy; surfacing them gives a reliability map for any monitoring built on a given SAE, and needs only open weights.

**Relevant context:** Differential testing is a standard software-testing technique; detection/fuzzing metrics for SAEs already exist (EleutherAI autointerp). Multiple public SAEs per model exist in SAELens, enabling head-to-head differential fuzzing.
