# Monitor Suspicion Calibration Drift Under Innocuous Context Shifts

**Problem:** Risk: a scheming untrusted model evades trusted monitoring. Causal chain: model emits a borderline action -> monitor assigns a suspicion score -> blue team audits the top-k% -> attack slips below threshold. The under-studied link is how stable the monitor's suspicion-score distribution is across benign context variations (task domain, prompt length, coding style). If benign-trajectory score distributions drift between domains, a fixed audit threshold calibrated on one domain mis-fires on another, letting attacks through or wasting audit budget.

**Direction:** Take an open small monitor model (e.g. Llama-3.1-8B / Qwen2.5-7B via API or local GPU) and run it as a trusted monitor over benign code/agent trajectories drawn from several domains (web tasks, data science, system scripts). Measure the per-domain suspicion-score distribution and how the false-positive rate at a fixed threshold shifts. Inject a small set of known-bad (backdoored) examples and quantify how detection rate at a fixed audit budget changes across domains. Report whether a single global threshold is safe.

**Why it matters:** Audit budget is the scarce resource in every control protocol; SHADE-Arena reports that hitting 80% detection already implies >20% false positives. If thresholds silently mis-calibrate across domains, real deployments leak attacks without the blue team noticing. This is doable entirely with open models and public datasets, no lab infra, and addresses a long-horizon deployment concern.

**Relevant context:** SHADE-Arena (arXiv:2506.15740) reports top monitor AUC 0.87, and that 80% detection implies >20% FPR. Calibration guidance recommends ~1000 benign trajectories + 50-100 synthetic positives and an operational threshold around score>=7, with recalibration on flagged-but-benign behavior raising false negatives 7%->9%. Redwood's trusted-monitoring backdoor setting (arXiv:2312.06942) caught backdoored code in 62% of runs.
