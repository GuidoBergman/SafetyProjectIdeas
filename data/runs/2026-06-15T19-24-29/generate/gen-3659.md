# Autonomy Envelope Mapping: Safe-Action Frontier per Task Type

**Problem:** Deployers want to 'expand the autonomy envelope' for low-risk actions while gating high-risk ones, but there is no empirical method to draw the envelope — which action classes an agent handles safely without approval — for a given model.

**Direction:** Define action classes (read, compute, reversible-write, external-comm, irreversible) and run an open agent on tasks in each class, scoring unsafe-action rate per class. Plot a per-model 'autonomy envelope' (classes where unsafe rate is below a threshold). Show how the envelope shrinks for weaker models.

**Why it matters:** An empirical autonomy-envelope methodology turns vague 'low-risk vs high-risk' guidance into a measurable, reusable evaluation any deployer can run on open models — practical agentic-safety infrastructure independent of any lab.

**Relevant context:** HITL guidance (Galileo/Databricks): expand autonomy for low-risk, gate irreversible/financial actions. arXiv:2604.05172 'ClawsBench' and arXiv:2601.06663 'SafePro' evaluate professional agents across realistic action types. METR autonomy-evals-guide methodology.
