# Metamorphic Testing for Detecting Shared Blind Spots Without Ground Truth

**Problem:** On open-ended/fuzzy-reward queries there is no oracle, so it's hard to call a homogeneous output a 'failure.' But software engineering's metamorphic testing detects faults without an oracle by checking invariants under input transformations — never used to surface SHARED blind spots across models.

**Direction:** Define metamorphic relations (paraphrase invariance, negation flips answer, irrelevant-detail addition shouldn't change a safety verdict) and apply them across a model panel. A shared blind spot = all models violate the same metamorphic relation in the same direction. Catalogue these cross-model coincident metamorphic violations on safety prompts.

**Why it matters:** Gives an oracle-free, lab-independent method to find blind spots that are dangerous precisely because every model shares them — the hardest failures to catch with standard benchmarks. Directly operationalizes the 'shared blind spots' follow-up.

**Relevant context:** Metamorphic testing addresses the oracle problem via metamorphic relations / invariants (testRigor; arXiv:2504.07982 fairness MT on LLaMA/GPT). Shared-blind-spot open problem in context file. Infinity-Chat open-ended queries (arXiv:2510.22954).
