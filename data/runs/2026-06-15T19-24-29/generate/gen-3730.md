# ToolEmu High-Stakes Risk Replicated in a Real Sandbox

**Problem:** ToolEmu identified risky LLM-agent behaviors using an LM-EMULATED sandbox (36 high-stakes tools, 144 cases). A standing question is whether the emulator over- or under-states real risk: do agents that the emulator flags as risky actually take the same risky actions when the tools are backed by a real (but harmless) local sandbox instead of an LLM emulation?

**Direction:** Pick 15-20 ToolEmu cases and re-implement a handful of the high-stakes tools as real but inert local functions (e.g., a file-delete that logs instead of deletes, a fake banking API). Run the same agent under both the original LM-emulated and the real-sandbox backends; compare risky-action rates and confirmation-asking behavior.

**Why it matters:** Validating emulator fidelity is foundational safer-sandbox infrastructure: if LM-emulated risk diverges from real-tool risk, every emulator-based agent safety eval inherits a bias. This is buildable on a laptop, needs no training, and strengthens an open methodology labs depend on but rarely audit externally.

**Relevant context:** ToolEmu / 'Identifying the Risks of LM Agents with an LM-Emulated Sandbox' (arXiv 2309.15817): 36 high-stakes tools, 144 test cases; uses an LM to emulate tool execution so risky behaviors can be surfaced without real consequences.
