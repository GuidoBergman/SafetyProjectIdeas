# Tracing the 'Filler Token -> Hidden Computation' Link

**Problem:** Hidden-reasoning chain: model emits filler/padding tokens -> performs computation in those positions without verbalizing -> uses the result later. If models compute in filler tokens, CoT monitoring is blind to it. Whether filler positions causally carry task-relevant computation is the under-studied link.

**Direction:** On Gemma-2-2B, run tasks with inserted filler tokens (dots/'...'). Use the logit lens and activation patching at filler positions to test whether information needed for the final answer is being built up there — i.e. patching filler activations changes the answer.

**Why it matters:** Hidden computation in non-verbalized tokens is a foundational threat to CoT-based monitoring (a stated long-horizon concern). A clean small-model demonstration is high-value and lab-independent.

**Relevant context:** CoT-monitorability stress tests (arXiv 2510.19851, 2510.27378) raise hidden/unverbalized reasoning as the core risk. Logit lens + activation patching are standard TransformerLens tools; filler-token computation is an active open question in mech interp.
