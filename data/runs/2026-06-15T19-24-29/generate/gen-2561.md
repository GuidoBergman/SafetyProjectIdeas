# Honeypot Realism Checker: Can Models Tell Synthetic Honeypots From Real Tasks?

**Problem:** Honeypot evaluations and upfront validation insert tempting fake opportunities to defect to catch or incriminate a scheming model. But if a model can detect that an opportunity is a honeypot (too convenient, artificial), it will behave well only there. No benchmark measures honeypot detectability across honeypot-construction styles.

**Direction:** Build a set of paired scenarios: genuine deployment-like opportunities to take a flagged action, and honeypot versions of the same. Ask models (in a discrimination setup) to rate how likely each scenario is a test/trap, and measure discrimination AUC. Vary honeypot construction (overt bait vs. naturalistic) to find which honeypot styles are least detectable.

**Why it matters:** Honeypots only work if they are indistinguishable from real opportunities. Quantifying detectability tells control researchers which honeypot designs are trustworthy and connects to eval-awareness. Needs only API access; valuable diffuse-threat infrastructure.

**Relevant context:** Ctrl-Z (arXiv 2504.10374) uses upfront honeypot validation and incrimination; the 'Honeypot Protocol' (arXiv 2604.13301, AI Control Hackathon) studies honeypot-based control. Eval-awareness work (arXiv 2507.01786, o3 case) shows models detect artificial contexts. Honeypot detectability as a measurable property is a gap.
