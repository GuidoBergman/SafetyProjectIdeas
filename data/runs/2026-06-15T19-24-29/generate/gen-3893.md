# Delegation Depth x Refusal Decay: Mapping How Safety Erodes Down a Delegation Chain

**Problem:** Failure mode A: each delegation hop reframes a request, eroding the original safety context. Failure mode B: peer-trust between sub-agents. Compounded, a request that the top agent would refuse becomes acceptable after N hops of delegation as context and accountability dissolve.

**Direction:** Build a chain of K identical API sub-agents that each delegate to the next. Hold the harmful goal fixed and measure refusal rate as a function of delegation depth K (1..6). Fit the decay curve. Test whether re-injecting the original user framing at each hop restores refusals (a cheap candidate mitigation).

**Why it matters:** Delegation chain analysis is a named open problem; quantifying refusal decay vs depth gives a concrete safety-budget metric for agent orchestration frameworks. Trivial to run with one model, varying only the prompt scaffold.
