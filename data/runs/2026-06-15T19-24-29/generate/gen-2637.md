# Resampling Amplification: When Defer-to-Resample Helps the Attacker

**Problem:** Risk: a control protocol meant to improve safety actively reduces it. Causal chain: monitor flags a suspicious action -> protocol resamples the untrusted model for fresh candidates -> lowest-suspicion sample is taken -> if the input contains an injection, resampling re-rolls the same attack until it lands. Recent work found Defer-to-Resample can BACKFIRE, dropping safety to 17% under adaptive attacks. The under-studied link is which input characteristics make resampling amplify rather than dilute an attack.

**Direction:** Build a tiny resampling harness: for a set of agent inputs (some containing injected instructions), sample N candidate actions from an open model and apply defer-to-resample logic with a monitor. Vary injection strength and measure attack success vs. N. Identify the regime where more resampling = more attack success (amplification) vs. dilution.

**Why it matters:** Resampling is a celebrated recent control technique; the discovery that it can backfire is exactly the kind of surprising result worth replicating and mapping. Characterizing the amplification regime tells blue teams when NOT to resample. Small-scale, open-model, no lab infra.

**Relevant context:** Ctrl-Z: Controlling AI Agents via Resampling (arXiv:2504.10374) introduces resample protocols exploiting model statelessness; reports safety gains 50%->96%. Adaptive Attacks on Trusted Monitors (arXiv:2510.09462) shows Defer-to-Resample amplifies prompt injection, dropping safety to 17% under adaptive evaluation.
