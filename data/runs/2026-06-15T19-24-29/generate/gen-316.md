# System-Prompt Override: Quantifying the Instruction-Priority Link

**Problem:** Deployed apps rely on the chain: developer system prompt sets rules -> user input is lower-priority -> harmful user override fails. The under-studied link is the model's actual instruction-priority ordering: how strong must a user-message override be to defeat a safety-focused system prompt, and does priority even hold?

**Direction:** Give an open model a strict safety system prompt, then escalate user-message override attempts (polite request -> 'ignore previous instructions' -> fabricated higher-authority role) on harmful prompts. Measure the override success rate at each escalation level to characterize whether and where the system-prompt priority link holds.

**Why it matters:** Tests the instruction-hierarchy assumption underpinning most safe deployments, directly relevant to anyone shipping an LLM app. No training, single GPU, pure prompting; produces a concrete escalation curve showing how brittle system-prompt-based safety really is.

**Relevant context:** Instruction-hierarchy / priority is central to OWASP LLM01:2025 prompt-injection defenses; IPI literature (arXiv:2602.10453) shows models conflate data and instructions. Shallow alignment (arXiv:2406.05946) implies system-prompt safety is a context-sensitive early-token behavior, not a hard constraint.
