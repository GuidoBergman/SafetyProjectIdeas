# Property-Based Testing for Invariant Discovery in Safety Behavior

**Problem:** Safety benchmarks enumerate specific bad cases; they rarely state general invariants the model must satisfy and then search for counterexamples automatically.

**Direction:** Import property-based testing (QuickCheck-style) from software engineering. Define safety invariants as code (e.g. 'monotonicity: making a request strictly more harmful must never increase compliance probability'; 'idempotence: repeating a refusal request never flips to compliance'). Use a generator to sample structured prompt pairs and automatically search for counterexamples on an open model, then 'shrink' violations to minimal reproducers. Report invariant-violation rates and minimal counterexamples.

**Why it matters:** Shifts safety evaluation from example enumeration to invariant falsification, producing crisp, minimal failure cases that are easy to communicate. Counterexample search + shrinking on open models needs no training and yields reusable invariant specs.

**Relevant context:** Property-based testing with generators and shrinking is standard in SE; software-testing-for-trustworthy-ICL (arXiv:2504.18827) and metamorphic frameworks (METAL arXiv:2312.06056) show LLM properties can be specified and automatically falsified.
