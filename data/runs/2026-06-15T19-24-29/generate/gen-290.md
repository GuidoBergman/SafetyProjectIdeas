# Formal Model Checking of Refusal as an LTL Property

**Problem:** Multi-turn safety properties ('never assist after a refusal in the same session', 'always refuse category X regardless of preceding turns') are temporal but we test them only with hand-picked dialogues.

**Direction:** Borrow temporal-logic specification and bounded model checking. Express desired safety invariants as simple LTL/CTL-style properties over conversation state, then build a bounded explorer that enumerates short scripted dialogue trees (a handful of branch choices per turn, bounded depth) and checks whether any path on an open model violates the property, returning concrete violating traces.

**Why it matters:** Brings the rigor of property specification + counterexample traces to multi-turn safety, surfacing temporal failure modes single-turn evals miss. Bounded exploration runs on one GPU; no training.

**Relevant context:** LTL/CTL and bounded model checking are core formal-methods tools. Multi-turn jailbreak benchmarks (MultiBreak arXiv:2605.01687) motivate temporal properties; ChekProp (arXiv:2505.23549) uses runtime property monitoring for guardrails.
