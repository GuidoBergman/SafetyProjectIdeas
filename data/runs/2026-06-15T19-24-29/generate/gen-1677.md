# A 'Negative Result' Feature Registry: Concepts SAEs Fail to Capture

**Problem:** Interpretability publishing is biased toward features that were successfully found; there is no shared, structured record of safety-relevant concepts that researchers searched for in SAEs and could NOT cleanly find. This absence makes it hard to know what is genuinely hard to monitor.

**Direction:** Define a small list of safety-relevant target concepts (deception, sycophancy, situational awareness cues, refusal-evasion), then systematically search a public SAE for clean single-feature representations of each using auto-interp + targeted probes, and report which concepts have no clean feature. Publish the search protocol and a reusable template for logging negative results.

**Why it matters:** Knowing which dangerous concepts are NOT cleanly represented (and thus hard to monitor via SAEs) is as safety-relevant as knowing which are. A negative-results registry counters publication bias and is pure measurement work needing only public SAEs.

**Relevant context:** SAEBench shows feature quality/disentanglement varies widely and proxy metrics mislead; the interpretability-to-safety gap is an explicit open problem. Neuronpedia/Delphi provide the search-and-score tooling to attempt and document concept localization.
