# From Near-Miss to Lesson: Tracing Where AI Incident Reports Fail to Produce Safety Learning

**Problem:** Incident-prevention chain: 'harm/near-miss occurs' -> 'it is reported' -> 'cause is investigated' -> 'lesson is shared' -> 'similar incidents prevented'. The NTSB analogy assumes all five links work, but existing voluntary databases (AIID, AIAAIC) often stop at logging, breaking the investigate-and-share links.

**Direction:** Sample 100-150 entries from the AI Incident Database and code each for how far it advances along the chain: reported only / cause described / corrective action identified / generalizable lesson stated. Quantify the drop-off at each link and characterize which incident types (and which actors) reach 'lesson' versus stalling at 'logged'.

**Why it matters:** An NTSB-style AI incident regime is a leading governance proposal; this shows empirically which causal link an AI-NTSB would actually need to add value (likely investigation/learning, not reporting). Public data, simple coding, valuable to do outside any lab.

**Relevant context:** arXiv:2511.05914 'Designing Incident Reporting Systems for Harms from General-Purpose AI' (7 institutional dimensions, near-miss reporting); OODAloop 'Is it Time for an AI NTSB?'; AI Incident Database (AIID).
