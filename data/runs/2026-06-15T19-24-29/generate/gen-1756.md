# Does Feature Absorption Hide a Safety Feature From SAE-Based Monitors?

**Problem:** SAE-monitoring chain: train SAE -> a 'harmful intent' feature emerges -> monitor watches that feature. Feature absorption (a known SAE failure where a general feature gets absorbed into more specific ones) could SILENTLY split a safety-relevant feature across latents, breaking the monitor link without anyone noticing.

**Direction:** Using Gemma Scope SAEs at multiple widths, identify a candidate 'refusal'/'harmful-request' SAE feature. Test for absorption by checking whether the feature's activation on held-out harmful prompts is partly carried by co-firing specific latents. Quantify how much monitor recall drops if you only watch the named feature vs the absorbed cluster.

**Why it matters:** If safety features are absorbed/fragmented, single-feature SAE monitors give false confidence. This is a concrete, lab-independent stress test of the SAE-for-safety pipeline using only public SAEs.

**Relevant context:** DeepMind critiques: SAEs underperform linear probes downstream; 'dead salmon' SAEs extract features from random transformers. Feature absorption is documented in SAE literature (SplInterp arXiv 2505.11836; Templeton et al. 2024). Gemma Scope offers SAEs at multiple widths per layer.
