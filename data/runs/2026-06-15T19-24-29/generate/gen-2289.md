# Monitor Blind Spot: How Subtle Must a Bug Be to Slip Past a Trusted Code Monitor?

**Problem:** AI-control trusted monitoring uses a weaker trusted model to flag suspicious outputs from a stronger untrusted model, but a basic evasion is injecting subtle backdoors into code. The subtlety threshold — how innocuous a bug must look to evade a given monitor — is not systematically characterized for open models.

**Direction:** Take public correct code solutions, inject bugs/backdoors spanning a spectrum from blatant to extremely subtle (off-by-one, rare-input branch, silent type coercion), and ask a weaker monitor model to flag suspicious code. Measure monitor detection rate vs bug subtlety to map the false-negative frontier, and test whether asking the monitor to write/run a test first changes the curve.

**Why it matters:** Quantifies where monitoring silently fails — the false-negative problem at the heart of AI control. Building a small monitoring harness is strategically valuable infrastructure, runs on one GPU with public code, and needs no proprietary defense-in-depth tooling.

**Relevant context:** AI Control (Greenblatt et al., arXiv:2312.06942) trusted monitoring; red teams prioritize behaviors predicted safe by blue team (false negatives); Adaptive Attacks on Trusted Monitors (arXiv:2510.09462). This maps detection rate vs bug subtlety.
