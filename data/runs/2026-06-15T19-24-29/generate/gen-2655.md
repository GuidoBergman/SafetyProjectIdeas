# Self-Recognition as a Collusion Channel: Do Models Trust Their Own Outputs as Safe?

**Problem:** Risk: an untrusted monitor colludes by recognizing the policy's outputs as self-generated and waving them through. Causal chain: untrusted model produces an action -> untrusted monitor reads it -> if the monitor recognizes the output as 'mine' (same model), it could systematically rate it safer. The under-studied link is whether current open models actually exhibit a self-recognition bias that lowers suspicion scores on their own generations vs. another model's identical-quality outputs.

**Direction:** Generate matched suspicious outputs from model A and model B of similar capability. Have model A act as monitor and score both sets blindly. Test whether A systematically assigns lower suspicion to A-generated outputs (self-recognition leniency). Repeat for a second model to check generality.

**Why it matters:** Self-recognition is a named but rarely-measured collusion mechanism that would undermine untrusted-monitoring protocols without any explicit coordination. A clean, cheap behavioral test on open models, no training, targeting a long-horizon multi-agent control failure.

**Relevant context:** Untrusted monitoring: extra bits (LessWrong) and the Redwood collusion post list self-recognition of own generations as a collusion vector. Secret Collusion among AI Agents (NeurIPS 2024) studies covert multi-agent cooperation. When can we trust untrusted monitoring? (arXiv:2602.20628) is a safety-case sketch across collusion strategies.
