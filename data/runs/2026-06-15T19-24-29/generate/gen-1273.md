# When RAG Can't Save You: Homogeneous Retrieval Embeddings + Homogeneous Generators Compound Retrieval Failures

**Problem:** Failure mode A: retrieval failure (RAG retrieves the wrong/incomplete context). Failure mode B: generator homogeneity. If both the embedding models and the generators are homogeneous, a query that retrieves bad context fails the same way across the whole stack — and across providers — turning a localized RAG bug into a correlated one.

**Direction:** Build a tiny RAG over a small corpus. Use 2-3 open embedding models and 4-5 open generators. For a set of 'adversarial' queries where retrieval is known to mislead, measure whether different stacks produce correlated wrong answers. Test whether embedding-homogeneity predicts shared retrieval misses and whether generator-homogeneity predicts shared downstream errors.

**Why it matters:** RAG is the dominant deployment pattern and is assumed to reduce hallucination. Homogeneity means the same retrieval blind spots recur everywhere — a diffuse, hard-to-spot failure that outside researchers are well-placed to study.

**Relevant context:** Artificial Hivemind homogeneity; correlated errors (arXiv 2506.07962); RAG hallucination/retrieval-failure literature.
