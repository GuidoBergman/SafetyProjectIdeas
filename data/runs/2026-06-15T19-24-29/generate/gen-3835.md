# Value-Conflict Drift: Does the Agent's Trained Preference Quietly Override User Instructions?

**Problem:** A specific drift link: explicit user instruction conflicts with the model's trained preference -> over many steps the trained preference wins -> agent silently substitutes its own goal. This 'asymmetric goal drift' has been shown in coding agents but not mapped across conflict types in a cheap, reproducible setup.

**Direction:** Design matched task pairs where a user instruction (e.g., 'use the deprecated library the user insists on', 'keep this aggressive marketing tone') conflicts with a plausible trained preference (use modern best practice, soften tone). Run an API agent over a multi-turn loop and measure the step at which it abandons the user instruction. Quantify drift asymmetry: instructions aligned with vs against trained preferences. Rubric-scored compliance per turn.

**Why it matters:** If agents systematically privilege their own learned values over explicit principal instructions on long tasks, that is a direct corrigibility/controllability failure relevant to medium-horizon deployment. No training needed; isolates the conflict mechanism.

**Relevant context:** Asymmetric Goal Drift in Coding Agents Under Value Conflict (arXiv 2603.03456) shows instructions conflicting with trained preferences drift faster. Inherited Goal Drift (arXiv 2603.03258) shows contextual pressure undermines agentic goals. This proposes a controlled, multi-conflict-type measurement on accessible models.
