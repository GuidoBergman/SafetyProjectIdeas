# Backcasting from 'Compliance Evidence Is Verifiable, Not Just Asserted': Tagging Each Code Obligation by Evidence-Strength

**Problem:** A success state where regulators can trust compliance requires that each obligation be backed by objectively checkable evidence rather than self-attestation. Many GPAI Code and framework commitments rest on 'trust us' statements with no externally verifiable artifact.

**Direction:** Take the obligation set extracted from the EU GPAI Code and/or one lab framework and classify each by evidence-strength tier: (a) externally verifiable artifact (e.g., third-party audit report), (b) self-published evidence, (c) self-attestation only, (d) aspirational. Quantify the distribution and identify which high-importance obligations rest only on self-attestation. Use a fixed rubric, manual + LLM cross-check.

**Why it matters:** Backcasting from 'verifiable compliance' shows evidence-strength tiering as the precondition. Showing how many critical obligations rest on mere self-attestation pinpoints where verification mechanisms (audits, attestation) are most needed — bridging the Open Problems verification agenda with the EU enforceable-standards gap. Pure public-document analysis.
