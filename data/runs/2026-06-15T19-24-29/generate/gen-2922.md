# Regression-Test Suite Minimization for Safety Benchmarks

**Problem:** Safety benchmarks grow to thousands of items, making continuous evaluation slow and expensive, yet most items are redundant. Software engineering solved this with test-suite minimization, which AI evals have barely borrowed.

**Direction:** Import test-suite minimization and prioritization from regression testing. Represent each safety item by the set of model-behavior 'signals' it triggers across several open models (refusal, partial compliance, specific failure cluster). Apply greedy set-cover / minimization to find a small subset preserving the same discriminative coverage, and a prioritization order maximizing early fault detection. Validate that the minimized suite reproduces full-suite model rankings.

**Why it matters:** Yields a small, fast, openly reusable safety regression suite for continuous monitoring — practical infrastructure for groups without lab compute. Distinct from psychometric adaptive testing because it is coverage/set-cover based rather than IRT ability estimation.

**Relevant context:** Test-suite minimization and prioritization are mature SE techniques (set-cover coverage preservation, fault-detection prioritization); dynamic benchmarking (arXiv:2503.06643) and SE-for-LLM-testing (arXiv:2504.18827) show these transfer. Practitioners recommend operationalizing safety evals as continuous regression testing (Unit42).
