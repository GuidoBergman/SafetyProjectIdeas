# Replicating Jailbreak-Degradation-Over-Time Tests Across Successive Open-Model Releases

**Problem:** The EU Code of Practice expects evaluations to test whether safety mitigations 'degrade over time.' This is usually discussed temporally within one deployed model, but a reproducible proxy—whether SUCCESSIVE releases in an open model family hold up against a fixed jailbreak battery, or whether capability gains outpace safety—is rarely measured openly.

**Direction:** Replicate a fixed jailbreak/refusal battery across 3-4 successive releases of one open model family (older to newer), holding the attack set constant. The twist is the version axis as a proxy for 'safety degradation/improvement over releases', reporting whether newer, more capable releases became easier or harder to jailbreak.

**Why it matters:** Tests the governance-relevant question of whether safety keeps pace with capability across releases—a durable concern frontier labs under-document publicly. Open models, public jailbreaks, single GPU, no training.

**Relevant context:** Grounded in EU Code of Practice requirement to test mitigation degradation over time, HELM Safety / HarmBench jailbreak sets, and STACK (arXiv 2506.24068). Twist = fixed attack set across successive open-model releases.
