# Eval-Awareness Cue Ablation Harness

**Problem:** Models recognize evaluation contexts (Gemini-2.5-Pro reaches AUC 0.83 at detecting test prompts), but we lack a tool to measure which surface cues in a prompt trigger that recognition.

**Direction:** Build a small harness that takes existing Petri/Apollo eval scenarios and systematically ablates candidate 'tell-tale' cues (multiple-choice formatting, role tags, artificial tool names, moralized framing, unrealistic stakes). Ask several open models 'does this look like a test?' (or use Petri 2.0's eval-awareness seeds) before/after each ablation, and rank cues by how much they shift the awareness signal.

**Why it matters:** Gives evaluation builders a cheap checklist of which prompt features leak 'this is a test', helping make safety evals more deployment-realistic. Pure prompting + API calls, no training, doable outside a lab.

**Relevant context:** Needham et al. 'Large Language Models Often Know When They Are Being Evaluated' (arXiv 2505.23836); Anthropic Petri 2.0 adds countermeasures against eval-awareness. Direct-questioning black-box probes exist but no systematic cue-ablation tool.
