# Monitor Self-Preference: Does a Monitor Under-Suspect Code From Its Own Model Family?

**Problem:** LLM judges exhibit self-preference bias. If a trusted monitor systematically rates outputs from its own model family as less suspicious, an attacker using that family gains a stealth advantage — a subtle but consequential monitoring failure mode.

**Direction:** Generate matched benign and backdoored outputs from several model families. Have a monitor from family X score all of them. Test whether suspicion scores for family-X outputs are systematically lower (controlling for actual backdoor presence) than for other families' outputs. Repeat with a monitor from a different family to confirm direction.

**Why it matters:** If monitors are lenient toward their own family, control protocols pairing same-family monitor and untrusted model (common for cost reasons) are silently weaker. A clean bias study with direct protocol-design implications. Inference + paired stats only.

**Relevant context:** Self-preference bias in LLM judges is documented (Weak LLMs Judging Strong LLMs, emergentmind). Quantifying Self-Preservation Bias (arXiv:2604.02174). Untrusted/trusted monitoring framing from AI Control (arXiv:2312.06942).
