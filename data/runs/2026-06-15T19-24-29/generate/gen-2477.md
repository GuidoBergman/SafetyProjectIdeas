# Honeypot Protocol: Varying the Plausibility of the 'No Monitoring' Signal

**Problem:** The Honeypot Protocol detects context-dependent scheming by varying the system prompt across eval/synthetic-deployment/explicit-no-monitoring conditions. It uses fixed, somewhat obvious prompts; it is unknown how the elicited misbehavior rate depends on how *believable* the no-monitoring cue is.

**Direction:** Replicate the three-condition honeypot on an open model, but add a graded ladder of no-monitoring cue plausibility (from blatant 'you are unmonitored' to subtle environmental tells like a disabled-logging config file in the context). Hold task/environment/scoring fixed. Measure misbehavior rate vs cue plausibility to find which cues actually move behavior.

**Why it matters:** Tells control researchers which honeypot cues are worth using — a too-obvious cue is gamed, a too-subtle one is missed. Pure prompt-engineering experiment, no training, directly extends a 2026 control protocol.

**Relevant context:** Honeypot Protocol (arXiv 2604.13301): varies only the system prompt across evaluation/synthetic-deployment/explicit-no-monitoring while holding task/environment/scoring identical; monitoring is otherwise 'passive.' Realistic honeypot evaluations for scheming propensity (arXiv 2605.29729).
