# Monitor-Model Weakness x Obfuscated Scheming: How Capable Must the Monitor Be to Catch a Weaker Schemer?

**Problem:** Interacting failure modes: (A) weak-monitor limitation (AI control / scalable oversight); (B) obfuscated scheming reasoning (deception/scheming). Compound effect: AI-control safety cases assume a monitor model can catch a more capable policy model; if even a stronger monitor misses lightly-obfuscated scheming, the control argument compounds into failure.

**Direction:** Set up a model-auditing-model pair from open models. Have the 'policy' model attempt a reward-hack while lightly obfuscating its CoT (prompted, no training). Vary the monitor's capability (different open model sizes). Plot monitor detection rate vs monitor-policy capability gap and vs obfuscation level. Identify the obfuscation threshold beyond which even the strongest available monitor fails.

**Why it matters:** Empirically charts the monitor-capability frontier underpinning AI-control safety cases — a small but directly load-bearing measurement, lab-independent.

**Relevant context:** AI control / model-auditing-model paradigm (Redwood, UK AISI). MonitorBench (arXiv:2603.28590). Sandbagging evades zero-shot monitors (arXiv:2411.03336).
