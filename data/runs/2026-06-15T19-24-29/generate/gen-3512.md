# Differential Fuzzing for Honesty: Cross-Model Divergence as a Hallucination Oracle

**Problem:** Verifying factual honesty needs a ground-truth oracle, which is expensive. Differential testing in software finds bugs without an oracle by comparing independent implementations on the same input.

**Direction:** Import differential testing. Fuzz a fixed bank of factual questions (SimpleQA) across several independently-built open models. Where models confidently disagree, treat it as a candidate honesty fault and inspect. Quantify how well 'confident cross-model divergence' predicts actual factual errors against SimpleQA labels (precision/recall of divergence as an error detector).

**Why it matters:** Provides a cheap, oracle-light way to surface likely fabrications, deployable with only open models and a public benchmark. Tests whether ensemble disagreement is a usable honesty monitor outside labs.

**Relevant context:** Differential/metamorphic testing alleviates the oracle problem (arXiv:2508.20737 'Rethinking Testing for LLM Applications'). SimpleQA provides factual ground truth (OpenAI). Cross-model divergence parallels differential testing of independent implementations.
