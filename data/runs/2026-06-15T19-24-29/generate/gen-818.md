# Recurring AI Incidents: Mining the AI Incident Database for the Failure Modes Governance Keeps Missing

**Problem:** The AI Incident Database holds 1,100+ documented real-world AI harms, and the AIID itself defines 'incident variants' (events sharing causes/harms with prior incidents). If the same failure modes recur, it signals that governance and reporting frameworks aren't producing learning. But the recurrence structure has not been systematically quantified by an independent analyst against governance categories.

**Direction:** Target recurrence as the failure mode. Download the public AIID dump, embed incident descriptions with an open model, cluster them, and measure how many incidents fall into recurring variant families vs novel ones, and whether recurrence rates are flat or rising over time. Map clusters to governance gaps (e.g. lack of pre-deployment testing, no incident-reporting mandate). Identify the top recurring harm types that current frameworks fail to prevent.

**Why it matters:** A core open problem is building NTSB-style AI incident response. Evidence that specific failure modes recur unaddressed is the strongest argument for mandatory reporting and shared learning systems. AIID is fully public; pure data analysis on a single GPU; independent of any lab.

**Relevant context:** AIID has 1,100+ incidents; arXiv 2507.23669 (semantic association of AIID reports); CSET 'AI Incidents: Key Components for Mandatory Reporting'; IEEE LLM-based AIID analysis (11372004).
