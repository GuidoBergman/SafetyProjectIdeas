# Auto-Interp Disagreement Index for SAE Features

**Problem:** SAE feature explanations are scored by automated methods (Delphi's detection and fuzzing) and by LLM 'explainer' models, but different scorers and different explainer models often disagree on the same feature. There is no standardized measure of how much auto-interp results depend on the choice of judge, which undermines trust in any single reported interpretability score.

**Direction:** Take a fixed open SAE (e.g., a Gemma-2-2b SAE from SAELens/Neuronpedia), run auto-interp on ~300 features using 2-3 cheap open explainer/scorer LLMs, and compute a per-feature 'disagreement index' (variance in detection/fuzzing scores across judges). Characterize which feature types are robust vs. judge-dependent, and report what fraction of 'interpretable' verdicts flip when you swap the judge.

**Why it matters:** If interpretability claims about a feature change depending on which LLM judges it, then safety arguments built on those claims ('this feature is the deception feature') are fragile. A disagreement index is a cheap, reusable reliability tool that any researcher outside a lab can run before trusting an auto-interp label.

**Relevant context:** EleutherAI's Delphi (formerly sae-auto-interp) scores feature explanations via detection (predict which sentences activate) and fuzzing (predict which tokens activate); Neuronpedia uses Delphi for explanations and scoring. Reported scores vary by method (e.g., 58% human vs 82-84% automated), implying judge sensitivity. SAEBench notes proxy metrics do not reliably translate to practical performance.
