# Double-Entry Bookkeeping for Cross-Checking Agent Claims

**Problem:** An overseer reviewing a long agent trace can't easily verify internal consistency of quantitative claims, letting subtle fabricated numbers slip through.

**Direction:** Import accounting's double-entry / reconciliation discipline: require the agent to report each numeric claim twice through independent derivations and have a lightweight checker reconcile them; flag mismatches for the judge. Prototype on arithmetic/data-analysis tasks with an open model, measuring detection of injected numeric errors vs a plain judge.

**Why it matters:** A reconciliation layer is a cheap, domain-general consistency monitor for oversight of quantitative agent outputs, lab-independent infrastructure for catching non-verbalized errors.

**Relevant context:** Double-entry bookkeeping as an error-catching redundancy mechanism from economics/accounting. Runtime consistency monitoring for agents (arXiv:2508.00500 ProbGuard). Reward-hacking-of-overseer priority (Open Phil RFP).
