# Reversibility Taxonomy Audit of Agent Tool Suites

**Problem:** A safety success state for agentic AI is that agents reliably distinguish reversible from irreversible actions and gate the latter. But no one has measured whether the tools shipped in popular open agent benchmarks even expose enough information for an agent (or monitor) to tell which calls are irreversible.

**Direction:** Backcasting from 'agents never silently take irreversible actions', the required artifact is a reversibility-labeled tool inventory. Take the ~340 tools in SHADE-Arena and the ~340 in AgentDojo, hand-label each as reversible / reversible-with-effort / irreversible / externally-committing, and measure (a) what fraction of tool docstrings/schemas surface reversibility cues, and (b) whether a frontier model, asked to classify each tool's reversibility from its schema alone, agrees with human labels.

**Why it matters:** If tool schemas don't encode reversibility, no monitor or guardrail downstream can gate on it — the whole 'human confirmation for irreversible actions' defense rests on information that may not exist. This is cheap infrastructure that any future control protocol needs, doable entirely outside a lab.

**Relevant context:** SHADE-Arena (arXiv 2506.15740) defines 30+ environments and 340+ tools adapted from AgentDojo; AgentDojo (arXiv 2406.13352) organizes 97 user tasks and 629 security cases across banking/Slack/travel/workspace. 2025 best-practice writeups stratify actions by reversibility (retrieval=low, modification=medium, irreversible/committing=high) and recommend human confirmation for hard-to-reverse actions, which presupposes reversibility is detectable.
