# Linear Temporal Logic Runtime Monitors as a Lightweight Agent Shield

**Problem:** Agent guardrails are usually single-step content filters and miss temporally-extended violations (e.g. 'never delete a file before backing it up', 'never send funds after a refusal was triggered').

**Direction:** Import runtime verification / LTL monitoring from formal methods. Hand-write ~10 LTL safety properties over an agent's action trace, compile them to simple finite-state monitors in Python, and run them online against an existing agent on a tool-use benchmark. Compare LTL-monitor catch rate vs an LLM-judge baseline on temporally-extended violations. No model checking expertise needed for the small-spec subset.

**Why it matters:** Demonstrates that cheap, transparent, deterministic monitors catch a class of multi-step failures content filters miss — strategically valuable monitoring infrastructure buildable outside a lab.

**Relevant context:** ProbGuard (arXiv 2508.00500), Pro2Guard, Agent-C, and AgentVerify (Preprints 202604.1029) compile LTL safety specs into runtime monitors and report LTL beats LLM baselines at detecting temporally-extended constraint violations. These use heavy SMT/model-checking machinery; a student-feasible slice is hand-coded finite-state monitors for a handful of specs.
