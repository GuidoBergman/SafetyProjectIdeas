# Cosmetic-Comment Attacks on Legibility Protocols

**Problem:** Risk: legibility protocols backfire by giving the attacker a new channel. Causal chain: blue team asks untrusted model to document its code thoroughly (legibility) -> monitor reads code + comments -> comments raise legibility and lower suspicion -> attacker exploits comments to mislead the monitor. The under-studied link is whether well-written but subtly misleading comments REDUCE a monitor's suspicion of genuinely backdoored code.

**Direction:** Take backdoored code snippets and produce three comment variants: none, honest comments, and plausibly-misleading comments that mischaracterize the suspicious line. Run an open trusted monitor and measure the suspicion score per variant. Test whether misleading comments significantly lower detection compared to no comments, quantifying the legibility-protocol attack surface.

**Why it matters:** Legibility protocols are a recent improvement to trusted monitoring, but encouraging the untrusted model to write more text hands it a deception channel. Showing whether comments can be weaponized directly stress-tests a published defense. Fully API/open-model feasible, no lab resources.

**Relevant context:** Basic Legibility Protocols Improve Trusted Monitoring (arXiv:2602.10153) lets the untrusted model document code with comments to aid the monitor, reversing prior practice of stripping comments to avoid deceptive ones. CoT Red-Handed (arXiv:2505.23575) shows models can hide intent with benign-looking external text.
