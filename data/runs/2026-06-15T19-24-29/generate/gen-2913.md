# Combinatorial t-way Coverage Testing for Multi-Factor Jailbreak Interactions

**Problem:** Jailbreaks often arise from interactions of multiple factors (persona + language + obfuscation + topic), but evals usually vary one factor at a time, missing combinatorial blind spots while exhaustive testing explodes.

**Direction:** Import combinatorial (t-way) coverage testing from software QA. Model a jailbreak as a vector of categorical factors, then generate a small covering array guaranteeing all pairwise (2-way) factor combinations appear, instead of the full Cartesian product. Run the covering-array prompts against an open model, measure which factor pairs reliably co-trigger unsafe behavior, and compare bug yield per prompt vs random sampling.

**Why it matters:** Pairwise testing famously catches most interaction bugs with a tiny fraction of cases, giving a compute-efficient, principled red-team design. Directly attacks automated red-teaming coverage blind spots from a new combinatorics angle; runs on a single GPU.

**Relevant context:** Combinatorial testing (covering arrays, NIST t-way) shows most software faults are triggered by interactions of <=6 factors and pairwise coverage finds the majority; coverage-guided prompt fuzzing (Unit42, GPTFUZZER arXiv:2309.10253) confirms multi-factor jailbreak fragility across open and closed models.
