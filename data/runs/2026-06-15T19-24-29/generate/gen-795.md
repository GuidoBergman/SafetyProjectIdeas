# Incident-Escalation Stress-Test Harness for AI Incident Reporting Designs

**Problem:** Recent work shows incident-escalation systems can systematically under-detect harms via design anti-patterns. There is no lightweight simulation harness that lets a non-expert test how a proposed reporting workflow handles ambiguous or diffuse incidents.

**Direction:** Build a small scenario-based test harness: a set of ~30 synthetic incident vignettes (varying severity, ambiguity, diffuseness) and an LLM playing a frontline reporter under different escalation rule-sets. Measure escalation/false-negative rates per rule-set and identify which design choices drive under-detection. Release the vignette set as a reusable benchmark.

**Why it matters:** Effective incident-response frameworks are an open problem and diffuse/fuzzy-reward harms are exactly what frontier labs deprioritize. A reusable stress-test for reporting designs is counterfactually valuable infrastructure needing only API access.

**Relevant context:** 'Stress-testing AI incident escalation: design patterns that drive systematic under-detection' (arXiv 2604.23183); 'Designing Incident Reporting Systems for Harms from General-Purpose AI' (arXiv 2511.05914).
