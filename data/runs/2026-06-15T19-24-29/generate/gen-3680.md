# Prompt-Injection Susceptibility Across Tool-Call Formats (JSON vs XML vs Python)

**Problem:** AgentDojo/InjecAgent fix a single tool-call serialization format. Models differ in how they parse tool schemas, and whether injection ASR depends on the tool-calling format (native JSON function-calling vs ReAct-style text vs Pythonic code-agent) is unmeasured.

**Direction:** Re-run a subset of InjecAgent attacks against the same open models under three tool-calling formats: native JSON function calling, ReAct text actions, and code-agent (Python) actions. Hold the attack payload constant; vary only the methodology/format. Compare ASR and utility-under-attack across formats.

**Why it matters:** Tool-calling format is a free design choice for agent builders; if one format is markedly more injection-resistant that is immediately actionable. Format-variation on open benchmarks, no training, strong reproducibility value.

**Relevant context:** InjecAgent and AgentDojo use indirect prompt injection with ASR/utility-under-attack metrics; code-agents (Pythonic tool calls) are common (e.g., smolagents). Search: 'ChatInject: Abusing Chat Templates for Prompt Injection in LLM Agents' (arXiv 2509.22830) shows format/template matters.
