# Async Control Stress Test Replicated at Small Scale

**Problem:** Async Control stress-tested asynchronous control measures (monitoring that lags behind agent actions) for LLM agents, but the setup used specific models; the safety implications of monitoring latency for cheap open agents are unexplored.

**Direction:** Replicate a simplified async-control experiment: run an open agent on a multi-step task where the monitor only reviews actions after a delay of k steps. Measure how attack success on a covert side task rises with monitoring latency k versus synchronous monitoring. Twist: find the latency budget at which control collapses for a small open agent.

**Why it matters:** Real deployments often monitor asynchronously for throughput. Quantifying how much latency control can tolerate is a practical, medium-horizon safety question reproducible on a single GPU.

**Relevant context:** 'Async Control: Stress-testing Asynchronous Control Measures for LLM Agents' (arXiv 2512.13526). SHADE-Arena (arXiv 2506.15740) multi-step tasks. Ctrl-Z resampling (arXiv 2504.10374).
