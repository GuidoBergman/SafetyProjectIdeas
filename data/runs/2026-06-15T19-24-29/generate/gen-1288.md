# Homogeneity Defeats Red-Team Diversity: One Attacker Model Covers the Same Ground as Many

**Problem:** Failure mode A: incomplete red-teaming (attacks miss whole regions of failure space). Failure mode B: homogeneity among attacker models. Automated red-teaming uses LLMs to generate attacks; if attacker models are homogeneous, using several of them explores barely more than one — red-team coverage is correlatedly limited.

**Direction:** Have 5-6 open models each generate adversarial prompts for a fixed target behavior. Measure the diversity/coverage of the union of attacks vs a single model's set (semantic clustering of attacks). Quantify marginal coverage added per extra attacker model and relate it to attacker-model homogeneity. Report a 'red-team diversity ceiling'.

**Why it matters:** Automated red-teaming is a key pre-deployment safety practice. If attacker homogeneity caps coverage, dangerous failure regions go untested everywhere. Measuring the coverage ceiling is a cheap, infrastructure-building contribution outsiders can own.

**Relevant context:** Artificial Hivemind intra/inter-model homogeneity; automated red-teaming literature; diversity-metric methods (LLM-TOPLA, arXiv 2410.03953).
