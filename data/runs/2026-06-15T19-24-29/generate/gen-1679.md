# Feature-Splitting Diagnostic Across SAE Widths

**Problem:** As SAE width grows, a single concept can 'split' into many narrower features (feature splitting), complicating interpretation and monitoring. There is no easy tool to measure how much a given concept splits as width increases, so users can't anticipate whether their monitoring feature will fragment.

**Direction:** Using public SAEs of multiple widths trained on the same model/layer, track a fixed set of seed concepts and measure how many features each concept maps to at each width (via activation-correlation clustering + auto-interp). Produce a 'splitting curve' tool and report which safety concepts fragment fastest.

**Why it matters:** If the 'deception feature' fragments into 30 features in a wider SAE, a monitor watching one feature breaks. Quantifying feature splitting is reusable infrastructure for choosing SAE width for monitoring, requiring only public weights.

**Relevant context:** Feature splitting is documented in Anthropic's 'Towards Monosemanticity' / scaling-monosemanticity line; SAEBench released SAEs across architectures and widths enabling width sweeps. Reliable superposition decomposition is an open problem.
