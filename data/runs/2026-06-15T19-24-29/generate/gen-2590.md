# Monitor Over-Suspicion: Quantifying the 'Flag Everything Hard' Failure on Benign Complex Code

**Problem:** Monitors 'mostly fail by overestimating the suspiciousness of the provided code.' This over-suspicion likely tracks code complexity, not maliciousness, meaning legitimately complex benign code burns the audit budget. The complexity-vs-suspicion confound is not quantified.

**Direction:** Take a corpus of purely benign code spanning a range of complexity metrics (cyclomatic complexity, length, nesting). Have a small monitor score suspicion. Regress suspicion on complexity to measure how much benign complexity inflates suspicion, and estimate how much of the 1% FPR budget complex-but-benign code consumes.

**Why it matters:** If monitors conflate complexity with maliciousness, then complex legitimate tasks (the valuable ones) are systematically over-flagged, wasting human audit and degrading usefulness. A clean confound study with direct deployment implications. No training.
