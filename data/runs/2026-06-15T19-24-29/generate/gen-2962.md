# Paraphrase-Invariance as a Validity Gate for Safety Benchmarks

**Problem:** Success requires that a benchmark's safety verdict reflects the model's behavior, not the exact wording of one prompt. Studies show minor paraphrases cause large output swings. A needed result is a quantified paraphrase-invariance score that flags benchmark items too fragile to trust.

**Direction:** Take a small open safety benchmark (e.g. a SORRY-Bench slice). Auto-paraphrase each prompt 5 ways using an open model, run the target model on all variants, and compute per-item refusal-consistency. Rank items by fragility and report what fraction of the benchmark's headline 'safety rate' rests on fragile items. Deliverable: an invariance score and a flag-list of unreliable items.

**Why it matters:** Demonstrates that headline safety numbers can be an artifact of phrasing — a core measurement-validity problem. Needs only inference, no training, no lab data; directly improves any open benchmark. Distinct from prior decoding-parameter consistency work because it targets input paraphrase at the item level as a validity gate.

**Relevant context:** SORRY-Bench (ICLR 2025) generated 8.8K paraphrased unsafe instructions; 'What Did I Do Wrong?' (NAACL 2025) defines sensitivity/consistency metrics across paraphrases; reports that minor prompt variations induce substantial output instability.
