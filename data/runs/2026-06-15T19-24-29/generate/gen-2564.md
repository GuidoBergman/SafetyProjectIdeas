# Cross-Family Monitoring Transfer: Does a Monitor Trained on One Model's Attacks Generalize to Another's?

**Problem:** Monitor thresholds/prompts are often tuned using attacks from one untrusted model. It is unclear whether a monitor calibrated on Model A's attack style maintains catch-rate against attacks authored by a different model family with a different 'voice'. This transfer gap is unmeasured and matters when the deployed model changes.

**Direction:** Generate attack trajectories from 2-3 different model families on a shared task set. Calibrate a monitor (prompt + threshold) on attacks from family A, then evaluate catch-rate on attacks from families B and C. Report the cross-family transfer drop and whether a monitor calibrated on a mix transfers better.

**Why it matters:** Deployers swap models frequently; if monitoring silently degrades when the untrusted model changes, control evaluations done on one model don't certify another. A transfer benchmark catches this. Entirely API-based, no training.

**Relevant context:** Adaptive Attacks (arXiv 2510.09462) shows attacks subvert protocols across diverse model pairs. The context explicitly recommends replicating monitoring across architectures/model families. Cross-family monitor transfer as a measured property is a gap.
