# Does Memory Make Agents Less Safe? Injected Instructions That Persist via Long-Term Memory

**Problem:** Agents increasingly use persistent memory/notes across sessions. A failure mode is that a malicious instruction injected once gets written into long-term memory and re-activates in later, clean sessions — but this cross-session persistence is rarely tested.

**Direction:** Build a minimal agent with a read/write notes tool that persists between sessions. In session 1, deliver an indirect injection that the agent might summarize into its notes. In session 2 (clean prompt, no injection), give a normal task and measure whether the poisoned memory steers behavior. Quantify the rate of memory poisoning and whether instructing the agent to 'only store factual task info' reduces it.

**Why it matters:** Persistent-memory poisoning is a sleeper failure mode that turns a one-time injection into a durable backdoor — highly safety-relevant as stateful agents proliferate. Buildable with a tiny notes-tool harness, no training, ideal counterfactual-value infrastructure probe.

**Relevant context:** AgentDojo-style indirect injection (NeurIPS 2024); 'ChatInject' (arXiv 2509.22830) abuses chat templates. Agentic security survey (arXiv 2510.23883) discusses memory as an attack surface.
