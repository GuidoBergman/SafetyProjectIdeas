# Agent Safety Under Tool-Description Adversarial Perturbation

**Problem:** Tool descriptions are trusted text the agent reads to decide actions. Benchmarks fix these descriptions, but whether small adversarial edits to a tool's docstring (renaming a harmful tool benignly, or adding misleading 'safe to use' notes) flips agent behavior is unexplored.

**Direction:** Take InjecAgent/AgentHarm tool definitions and apply controlled perturbations: rename harmful tools to innocuous names, add reassuring usage notes, or hide side effects from the description. Vary perturbation type; measure HarmScore/ASR shift per open model. Identify which description edits most increase unsafe tool use.

**Why it matters:** Tool descriptions are attacker-controllable in open ecosystems (malicious MCP servers can ship deceptive docstrings). Quantifying this is a concrete supply-chain threat; benchmark variation only, no training, high counterfactual value.

**Relevant context:** InjecAgent (62 attacker tools) and AgentHarm provide tool schemas. Search: malicious MCP servers, AgenTRIM 'Tool Risk Mitigation' (arXiv 2601.12449). Tool descriptions are untrusted text in agentic pipelines.
