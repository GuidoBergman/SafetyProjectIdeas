# Benchmark for Eval-Result Reporting Quality in System Cards

**Problem:** Labs report dangerous-capability eval results in system cards, but reporting quality varies wildly: some give raw scores, baselines, and elicitation details; others give a one-line verdict. No metric captures how interpretable and reproducible the reported eval evidence is.

**Direction:** Define a reporting-quality rubric (named eval / baseline given / elicitation method described / numeric score / uplift vs control / human-baseline comparison) and score the dangerous-capability sections of ~12 public system cards. Output a reporting-quality leaderboard and identify the most common omissions.

**Why it matters:** Auditable safety claims require interpretable eval reporting. A reporting-quality benchmark pressures labs toward standardized disclosure and is a feasible variation on the FLI Index methodology, using only public cards.

**Relevant context:** Dangerous-capability eval reporting in public system cards (OpenAI/Anthropic/GDM); AI Transparency Atlas (arXiv 2512.12443); 'Who Should Run Advanced AI Evaluations' (arXiv 2407.20847).
