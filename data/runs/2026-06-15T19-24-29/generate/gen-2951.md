# The Time-Partition Link: Estimating Contamination Inflation From Release Dates

**Problem:** Contamination chain: a benchmark is released -> it enters later training corpora -> models trained after release score inflated -> safety/capability claims overstated. The under-studied, cheap link is using model knowledge-cutoff vs benchmark-release dates to estimate the inflation attributable purely to post-release exposure.

**Direction:** For several open models with known/estimable cutoff dates and a safety benchmark with a known release date, compare performance on benchmark items created before vs after each model's cutoff (or pre/post benchmark release). The pre/post performance gap estimates contamination inflation. Report inflation per model and whether it grows for later-cutoff models.

**Why it matters:** Gives a near-zero-cost contamination audit usable by anyone with API access and public release dates, decoupled from any lab's training records. Directly addresses the named contamination open problem.

**Relevant context:** arXiv 2502.17521 establishes time-based partitioning as a primary contamination detector; 2026 contamination guides list time-partition among five working methods. Requires only public dates and inference.
