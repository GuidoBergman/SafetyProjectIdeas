# Defer-to-Resample vs Defer-to-Trusted on a Single Open Untrusted Model

**Problem:** Ctrl-Z shows defer-to-resample beats defer-to-trusted in a multi-step BashBench setting using frontier models. The relative ordering may not survive when the untrusted model is a modest open model — resampling assumes the untrusted model rarely attacks, which may not hold for weaker models.

**Direction:** Implement a minimal single-step version of defer-to-trusted and defer-to-resample using ControlArena's APPS backdoor task, with an open model (e.g. Qwen-14B) as both untrusted policy and a smaller model as trusted. Sweep the audit threshold and plot the safety-usefulness Pareto frontier for each protocol. Test whether resampling's advantage persists when the attack rate is artificially raised.

**Why it matters:** Validates whether the resampling result generalizes outside frontier models — important because most accessible deployments use mid-size open models. A clean, self-contained control-protocol comparison runnable on one GPU.

**Relevant context:** Ctrl-Z: Controlling AI Agents via Resampling (arXiv 2504.10374): defer-to-resample improves the safety-usefulness frontier over defer-to-trusted because resampling hurts usefulness less. ControlArena/redwood-control-arena (GitHub) provides APPS backdoor tasks. Original AI Control paper (arXiv 2312.06942).
