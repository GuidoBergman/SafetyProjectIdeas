# Faithfulness of SAE Features Without External Dataset Dependence

**Problem:** FaithfulSAE argues that SAEs trained on external datasets can capture features that are artifacts of the dataset rather than the model, harming faithfulness. For safety monitoring this means a 'harm' feature might really track the audit dataset, not the model's own representation — a silent validity threat.

**Direction:** For one safety-relevant feature, compare a standard externally-trained SAE feature against a more model-faithful feature-extraction approach, and test whether the standard feature's activation is driven by dataset artifacts (e.g., surface tokens) versus genuine model-internal concept structure, using controlled minimal-pair prompts.

**Why it matters:** Validity of safety features is a precondition for any deployment decision built on them. Detecting dataset-artifact features needs only public models and small curated prompt sets — high counterfactual value.

**Relevant context:** 'FaithfulSAE: Towards Capturing Faithful Features without External Dataset Dependencies' (arXiv 2506.17673) shows external-dataset SAEs capture dataset artifacts. SAE seed/hyperparameter instability (2025 reviews) compounds the validity concern.
