# Second-Order Injection: Do Agents Re-Inject Themselves Through Memory?

**Problem:** Success state: agents that store and recall content cannot be hijacked by injected instructions that persist in memory. Backcasting, we need evidence on whether a single injection in retrieved content gets written to agent memory/notes and re-triggers on later, benign turns.

**Direction:** In a minimal agent loop with a scratchpad/memory tool, inject once via a retrieved document, then run several subsequent benign user turns and measure whether the injected instruction re-activates from memory. Quantify persistence rate across open models.

**Why it matters:** Memory-persistent injection is a medium-horizon agentic threat that labs racing on immediate jailbreaks deprioritize. It needs only a toy harness, making it ideal counterfactual research, and produces a clean model-organism-style demonstration.

**Relevant context:** Benchmarks note 'second-order attacks' cascading beyond direct injection (arXiv:2510.05244); InjecAgent (arXiv:2403.02691) and ASB (ICLR 2025) cover tool-integrated injection but persistence/memory re-injection is underexplored.
