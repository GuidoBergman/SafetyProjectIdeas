# The First Hop That Leaks: Locating Where Privilege Escalates in Delegation Chains

**Problem:** Risk 'sub-agent does something it should not be allowed to' chains as: user grants permission -> parent agent delegates -> sub-agent inherits/expands scope -> over-permissioned tool call. The least-privilege principle says each hop should narrow permissions, but in practice scope creeps. Which hop leaks, and under what task framing, is under-measured for LLM orchestration (not just identity infra).

**Direction:** Build a toy two-level delegation harness: a parent agent with a permission manifest spawns a sub-agent for a subtask, passing instructions in natural language. Seed tasks where the correct sub-scope is strictly smaller than the parent's. Measure how often the parent over-delegates (passes broader capabilities/secrets than needed) and how often the sub-agent attempts out-of-scope tools. Vary instruction explicitness about least privilege. Report a per-hop leakage rate.

**Why it matters:** Multi-agent delegation is a NIST/CAISI standards priority and a real enterprise risk (97% of non-human identities over-permissioned). Studying the LLM behavioral side of scope creep (vs the IAM token side) is exactly the lab-independent, infra-light angle that frontier teams underinvest in.

**Relevant context:** Okta/Auth0/Oso analyses report each delegation hop should narrow permissions but least-privilege 'often fails in practice' with 97% of non-human identities over-permissioned, and flag 'read sensitive -> summarize -> send externally' chains. Pre-action authorization work (arXiv 2603.20953) is deterministic infra; this targets the behavioral leakage mechanism.
