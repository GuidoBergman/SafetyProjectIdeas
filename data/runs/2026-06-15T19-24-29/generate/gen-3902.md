# RAG Corpus Poisoning x Agent Tool Use: When Bad Retrieval Becomes a Bad Action

**Problem:** Failure mode A: RAG corpus poisoning corrupts what the agent reads. Failure mode B: the agent acts on retrieved content via tools. The compound failure converts a passive document poisoning into an active harmful action (e.g., retrieved instructions trigger a tool call).

**Direction:** Set up a tiny RAG-agent: poison a few documents (PoisonedRAG-style) whose content instructs a tool call. Measure the rate at which poisoned retrieval escalates to an executed (mock) action, and how it scales with number of poisoned docs and retrieval k. Compare against a retrieval-only (no-tool) baseline to isolate the action-amplification.

**Why it matters:** Most RAG-poisoning work stops at wrong text; the safety-critical step is poison-to-action. Open-source retriever + API model, single machine, fully sandboxed tools.

**Relevant context:** PoisonedRAG: ~5 crafted texts -> ~90% attack success; RSB benchmark (13 attacks/7 defenses) finds defenses largely ineffective; MemoryGraft persistence (arXiv 2512.16962). Retriever 'blindly trusts external documents' (search summary).
