# Fuzzing the Sandbox: Coverage-Guided Discovery of Containment Escapes

**Problem:** Agent sandboxes are supposed to prevent irreversible harmful actions, but we rarely systematically search for inputs/states that let an agent slip past containment. Manual red-teaming covers few cases.

**Direction:** Apply coverage-guided fuzzing from software security to a small agent sandbox. Build a minimal tool-call sandbox, define instrumentation/coverage over guardrail branches, and use a fuzzing loop (mutating agent prompts/tool arguments) to maximize coverage of containment-check code paths, logging any sequence that reaches a forbidden action. Report which guardrail branches were never exercised.

**Why it matters:** Produces strategically valuable, reusable containment-testing infrastructure and exposes untested guardrail paths, mirroring how fuzzing finds security bugs. Buildable as a small prototype on a single machine, high counterfactual value for safer sandboxes.

**Relevant context:** Coverage-guided fuzzers (AFL/libFuzzer) find security bugs by maximizing branch coverage. Runtime guardrails for agents are layered and incomplete (arXiv:2604.05229; Swiss Cheese arXiv:2408.02205). ControlArena offers sandboxed agent settings (control-arena.aisi.org.uk).
