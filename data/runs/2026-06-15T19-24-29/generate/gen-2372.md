# Backcasting Verifier-Generator Gaps: Mapping Where Checking Beats Doing

**Problem:** Success state: oversight that leans on the gap where verifying a solution is easier than producing one. We need a domain-by-domain map of how large the verify-vs-generate gap is for a fixed small open model, since oversight only works where the gap is positive.

**Direction:** For one small open model, measure generation accuracy vs verification accuracy (judge a given candidate as correct/incorrect) across several public task types (math word problems, code unit-test pass prediction, factual MC). Quantify the verify-minus-generate gap per domain and identify domains where it vanishes or inverts.

**Why it matters:** The 'evaluation easier than generation' assumption underpins recursive reward modeling, debate, and easy-to-hard generalization. A concrete map of where that assumption holds for a single model tells the field which domains oversight protocols can rely on — and is fully reproducible outside a lab.

**Relevant context:** Generative verifiers and easy-to-hard work (arXiv:2408.15240, arXiv:2403.09472) assume evaluation < generation difficulty. The size of this gap is rarely measured directly per-domain with a fixed model. Public datasets suffice.
