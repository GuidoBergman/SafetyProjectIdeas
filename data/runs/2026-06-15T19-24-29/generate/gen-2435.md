# Software-Engineering Judge Biases: Auditing Authority and Bandwagon Cues in Code Review

**Problem:** Bias in the Loop: Auditing LLM-as-a-Judge for Software Engineering (arXiv:2604.16790, Apr 2026) and Are LLMs Reliable Code Reviewers? (arXiv:2603.00539, Mar 2026) show LLM code-review judges are swayed by authority cues and over-correct on requirement conformance. A focused, reproducible probe of these biases on open coding judges is missing.

**Direction:** Take code snippets with known correctness and create variants that add authority cues ('senior engineer wrote this'), bandwagon cues ('approved by 5 reviewers'), or verbose justification. Measure how an open code-review judge's accept/reject decision shifts with each non-functional cue.

**Why it matters:** As code generation scales, automated code-review judges become a key oversight layer. Showing they can be steered by social cues rather than correctness is a tangible oversight-failure demonstration, inference-only.

**Relevant context:** Bias in the Loop: Auditing LLM-as-a-Judge for Software Engineering (arXiv:2604.16790, Apr 2026): prompt-sensitive explicit (position, verbosity, authority) and implicit (bandwagon, sentiment) biases distort decisions. Are LLMs Reliable Code Reviewers? Systematic Overcorrection (arXiv:2603.00539, Mar 2026).
