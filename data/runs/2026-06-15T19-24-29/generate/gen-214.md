# Prefilling Attack Replicated on Code-Generation Models for Insecure-Code Elicitation

**Problem:** Prefilling/shallow-alignment attacks are studied for harmful-text refusal, but code models have their own safety boundary: refusing to write malware/insecure code. Whether prefilling the first tokens of a code completion bypasses a code model's safety refusals (a different 'harm' axis) is unexplored.

**Direction:** Replicate the prefilling attack on an open code-capable instruct model, targeting requests it normally refuses (e.g., obfuscated exfiltration snippets), by prefilling a few non-refusal code tokens. Twist: code modality + code-specific harm. Measure refusal-bypass rate and whether generated code is actually functional/harmful per a static check.

**Why it matters:** Code-assistant safety is a concrete medium-horizon misuse vector and is under-red-teamed in the open. A self-contained measurement of prefilling on code models extends a known result to a high-impact new domain, inference-only on one GPU.

**Relevant context:** Qi et al. 2024 (arXiv:2406.05946): prefilling exploits shallow alignment. Open code instruct models (Qwen2.5-Coder, DeepSeek-Coder, CodeLlama-Instruct) are public and refuse some malicious-code requests.
