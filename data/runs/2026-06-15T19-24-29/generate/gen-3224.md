# Honeypot/Canary-Token Tripwires Borrowed from Cybersecurity Intrusion Detection

**Problem:** Detecting a model that schemes only when it sees an exploitable opportunity is hard if it behaves well otherwise. Cybersecurity uses honeytokens (fake credentials/files) that no legitimate process should ever touch, so any access reveals an intruder.

**Direction:** Import honeytokens/canary tokens: in an agentic sandbox, plant tempting-but-forbidden resources (a fake 'disable_monitoring' tool, a decoy file labeled 'eval_answers', a fake unmonitored channel) that an honest model has no reason to use, and measure how often open models take the bait under various goal/pressure conditions. Report bait-take rates as a covert-intent signal.

**Why it matters:** A cheap, high-signal behavioral tripwire for opportunistic scheming that requires no model internals and is directly deployable as monitoring infrastructure — strong counterfactual value and a clean 30h prototype.

**Relevant context:** Honeytokens/canary tokens are decoys whose only use indicates intrusion (cybersecurity IDS standard). Petri (Anthropic) probes self-preservation and reward hacking in sandboxes; deceptive models exploit perceived unmonitored opportunities (Alignment Faking arXiv:2412.14093).
