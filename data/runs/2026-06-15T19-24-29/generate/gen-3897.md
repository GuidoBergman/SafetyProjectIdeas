# Information Access x Monitor Capability: Does Giving the Monitor More Tools Compound or Cancel Sabotage?

**Problem:** Failure mode A: a monitor with limited information misses sabotage. Failure mode B: a monitor with broad information access can itself be manipulated/distracted. The compound question: does increasing monitor information access monotonically help, or does it create a new attack surface that cancels the gains?

**Direction:** Replicate a small slice of the 'information access affects monitor sabotage detection' study: vary the evidence given to an API-based monitor (action-only, +CoT, +file diffs, +tool logs) and measure detection. Then test whether an adversarial agent can exploit the richer context (e.g., flooding logs) to suppress detection.

**Why it matters:** Informs the design of monitoring harnesses — the kind of strategically valuable infrastructure favored here. Pure API monitor experiments, cheap and reproducible.

**Relevant context:** 'How does information access affect LLM monitors' ability to detect sabotage?' (arXiv 2601.21112) directly studies the access->detection relationship; 'Adaptive Attacks on Trusted Monitors Subvert AI Control Protocols' (arXiv 2510.09462) shows monitors are manipulable.
