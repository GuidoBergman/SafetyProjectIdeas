# Runtime-Verification Monitors as a Recursive-Oversight Layer

**Problem:** Recursive oversight protocols stack fallible judges; we lack lightweight, formally-specified checks that flag when a step violates a known invariant (e.g., an answer contradicts a cited fact).

**Direction:** Import runtime verification: write a small set of formal monitors (regex/automata + simple logical predicates) that consume an LLM agent's intermediate reasoning trace and flag invariant violations (citation present? answer consistent with stated premise? no contradiction across steps?). Prototype on agent traces from an open model on a QA task; measure how many genuine errors monitors catch vs an LLM-only judge.

**Why it matters:** A cheap symbolic 'watchdog' that complements fallible LLM oversight is strategically valuable infrastructure (a monitoring harness) that needs no lab resources and addresses systematic-error-prone oversight layers.

**Relevant context:** Runtime verification meets LLMs (arXiv:2511.14435 'Watchdogs and Oracles'; AGENT-C arXiv:2512.23738 temporal constraints to FOL; VeriGuard arXiv:2510.05156 runtime policy monitor). Anthropic direction: recursive oversight robust to per-layer systematic errors.
