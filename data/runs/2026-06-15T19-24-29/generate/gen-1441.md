# SteerTokenBudget: Benchmarking Where in the Prompt Steering Actually Bites

**Problem:** CAA adds vectors at all post-prompt token positions, but there is no measurement of how steering effectiveness varies with WHICH token positions are steered, leaving compute-efficient and stealthy-application questions open.

**Direction:** Build a tool that applies a steering vector only to subsets of token positions (e.g. last-k tokens, every-other token, only system-prompt tokens) and measures effect size vs positions steered. Report an effectiveness-vs-positions curve for several behaviors, identifying minimal sufficient injection footprints.

**Why it matters:** Understanding the minimal injection footprint matters both for efficient monitoring and for understanding how covertly steering could be applied (a security-relevant property). Pure inference, beginner-friendly hook manipulation.

**Relevant context:** CAA applies vectors 'at all token positions after the user's prompt' (arxiv 2312.06681); the effect of restricting positions is unmeasured. steering-vectors library exposes position control.
