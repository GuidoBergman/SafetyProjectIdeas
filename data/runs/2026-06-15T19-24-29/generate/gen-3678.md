# Safety Degradation Down a Delegation Chain: Does the Nth Sub-Agent Refuse Less?

**Problem:** Multi-agent delegation papers warn that one agent's corrupted output becomes the next agent's input and that handoffs lack explicit safety contracts, but no one has measured whether refusal/safety behavior simply decays as a harmful request is passed down a chain of delegating agents.

**Direction:** Build a simple orchestrator -> sub-agent -> sub-sub-agent chain (all the same open model). A harmful task enters at the top; each layer reformulates and delegates downward. Vary chain depth (1 to 5) and measure RefusalRate and HarmScore at each layer using AgentHarm-style tasks. Test whether laundering a request through delegation erodes refusals.

**Why it matters:** If safety erodes with delegation depth, multi-agent orchestration (MCP/A2A) is a refusal-laundering vector. A clean depth-variation experiment on one open model, no infrastructure, addressing the under-studied governance gap in delegation chains.

**Relevant context:** Search: every handoff must have an explicit contract; without it one agent's hallucinated output becomes the next agent's corrupted input, propagating as cascade failure; 'The Provenance Paradox in Multi-Agent LLM Routing' (arXiv 2603.18043); 'Toward a Safe Internet of Agents' (arXiv 2512.00520). AgentHarm provides harmful-task RefusalRate.
