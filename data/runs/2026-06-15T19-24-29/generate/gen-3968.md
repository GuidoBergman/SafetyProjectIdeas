# How Much Does a Reward Model Need to Capture? Empirical Curve Toward the Unhackability Limit

**Problem:** Skalse et al. imply a proxy is safe from hacking only if it captures essentially all true-preference detail — but real reward models capture some fraction. There is no accessible empirical curve relating 'how much of the true reward structure the proxy captures' to 'how much hacking headroom remains'.

**Direction:** In a small enumerable environment, define a true reward as a sum of feature components. Construct proxies that capture increasing subsets of the components. For each proxy, enumerate policies and measure the maximum true-reward loss achievable while improving proxy reward. Plot residual hackability vs fraction of true structure captured, identifying diminishing-returns regions.

**Why it matters:** Turns the all-or-nothing unhackability theorem into a practical design curve: how complete must a reward model be to bound hacking to acceptable levels? Pure Python, no GPU, and directly informs reward-model design — strongly counterfactual.

**Relevant context:** Skalse et al. (arXiv 2209.13085): unhackability requires capturing all true-preference detail; otherwise hacking policies exist. Wang & Huang (arXiv 2603.28063) frame uncovered dimensions as the locus of hacking.
