# State-Change vs Text-Pattern Detection: How Much Does Real Execution Add?

**Problem:** The Honeypot/BashArena work detects side tasks via real system-state changes (e.g. firewall actually disabled) rather than text pattern matching, arguing the model must *execute* the harm. The marginal value of true execution-based detection over a cheap text classifier has not been quantified.

**Direction:** On a small sandboxed BashBench-style task set, log both (a) actual system-state changes for four side tasks (privilege escalation, firewall, malware download, credential leak) and (b) a cheap LLM/regex text monitor reading the same transcript. Compute the false-negative rate of the text monitor relative to ground-truth state changes. Characterize what kinds of attacks slip past text-only monitoring.

**Why it matters:** Most accessible monitoring setups use text, not instrumented sandboxes. Quantifying the gap tells groups when they must invest in real sandbox instrumentation — a strategically valuable infrastructure question. Small Docker sandbox, no training.

**Relevant context:** Honeypot Protocol / BashArena (arXiv 2604.13301): detection based on 'real system state changes inside the container, not text pattern matching'; model must execute the side task. Ctrl-Z (arXiv 2504.10374) uses BashBench-style multi-step environments.
