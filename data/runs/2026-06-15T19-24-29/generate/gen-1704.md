# Feature Splitting Distorts Concept Counts: Same Concept, More 'Features'

**Problem:** When SAE width increases, a single concept's feature can split into several latents; some splits are 'desirable' (genuine new concepts) but many are 'undesirable' (sparser recombinations of existing directions) that fragment interpretability. Counting features as concepts therefore overstates how many distinct things a model represents.

**Direction:** Using two pretrained SAEs of different widths for the same open model/layer (available for GPT-2 and Gemma), take a set of concepts each represented by one feature in the narrow SAE and locate their counterparts in the wide SAE. Classify each split as desirable (new interpretable direction) vs undesirable (recombination, near-collinear with existing directions) using decoder-geometry tests, and report the proportion of splitting that is interpretability-harmful.

**Why it matters:** Claims like 'the model has N distinct safety-relevant features' depend on whether feature counts mean concept counts. Showing how much width-driven splitting is artifactual stops over-interpretation of dictionary size as semantic richness.

**Relevant context:** Chanin et al. (arXiv:2409.14507) and seed/consistency work describe desirable vs undesirable feature splitting; larger expansions encourage splitting at the cost of more dead features and capacity waste.
