# The 1% FPR Calibration Trap: How Monitor Thresholds Set on Benign Data Fail on Style Shift

**Problem:** Control evaluations calibrate monitors to a 1% false-positive rate by taking the 99th percentile of suspicion scores on attack-free prompts. But monitors are known to be 'highly sensitive to surface-form and style shifts.' If real deployment traffic has a different style than the calibration set, the effective FPR may silently blow up or the threshold may let attacks through.

**Direction:** Take an open weak monitor (e.g. a small Llama/Qwen via API or local), calibrate its 1% FPR threshold on one benign code/agent-trace distribution, then measure the realized FPR and attack-catch rate when the SAME benign code is paraphrased/reformatted (comment style, variable naming, verbose vs terse). Quantify how far the realized FPR drifts from the nominal 1% under purely cosmetic shifts.

**Why it matters:** FPR calibration is the load-bearing assumption behind every published safety number in control evals. Showing it is brittle to benign style shift undermines reported safety margins and is directly actionable. No training, only inference + simple stats.

**Relevant context:** Control eval methodology calibrates monitors to a max 1% FPR using the 99th percentile of benign suspicion scores (AI Control, arXiv:2312.06942; Control Tax arXiv:2506.05296). Recent findings note monitors are 'highly sensitive to surface-form and style shifts and can be broken by adversarial input.'
