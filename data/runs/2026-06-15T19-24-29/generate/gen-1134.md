# Do shared blind spots survive into safety-critical refusals? A refusal-overlap stress test

**Problem:** Prior work shows LLM refusal sets overlap heavily across vendors (e.g., when GPT-4.5 refuses, Claude refuses ~67% of the time; open models exceed 80% overlap). But it is unknown whether the *gaps* — prompts that ALL models wrongly comply with — are correlated, which would mean a single crafted-harmful prompt slips past every deployed guardrail simultaneously.

**Direction:** Assemble a few hundred borderline-harmful prompts (from public over-refusal/jailbreak datasets like FalseReject and 'Do Anything Now'). Query 6-8 open and API models. Build a per-prompt refusal matrix and measure: (1) the rate of unanimous *wrong* compliance, (2) whether compliance failures cluster on the same prompts more than chance (permutation test vs. an independence null). Characterize what topical features predict shared blind spots.

**Why it matters:** If high-stakes deployments each pick a different vendor for redundancy but all share the same compliance blind spots, the apparent diversity is illusory and a single attack generalizes. This directly tests the 'correlated failures across systems sharing blind spots' open problem with no training and only API/consumer-GPU inference.

**Relevant context:** Grounded in FalseReject (arXiv 2505.08054), refusal-overlap findings (Artificial Hivemind context), and the open problem on shared blind spots. Uses only public datasets and inference.
