# The Complexity Cliff of Sabotage: Where Multi-Step Subtle Sabotage Starts to Fail

**Problem:** AI-R&D sabotage chain: misaligned agent -> inserts subtle defect -> defect survives review -> evaluation outcome changed without detection. DeepMind found Gemini 3 Pro better at sabotage but inconsistent on complex multi-step sabotage. The link 'sabotage success vs number of coordinated steps required' (the complexity threshold) is exactly the flagged follow-up and is under-mapped on accessible models.

**Direction:** Create a small ladder of sabotage tasks in a mock code/eval environment requiring 1, 2, 3... coordinated subtle edits to flip an outcome while a simple automated checker runs. Instruct an API agent to sabotage subtly. Measure success rate vs required step count and detection rate by the checker. Identify the complexity at which subtle sabotage reliably breaks down. Compare 2-3 models.

**Why it matters:** If subtle sabotage reliably fails above K coordinated steps, that bounds the threat and informs where to concentrate review. This directly operationalizes a surprising-result follow-up that frontier labs flagged but that needs no proprietary infra at small scale.
