# Runtime Verification Monitors with Temporal-Logic Specs for Agent Deception

**Problem:** Agentic scheming often violates simple temporal properties (e.g., 'never take action X after observing the test is over', 'always report tool failures'). We lack lightweight formal monitors that flag such violations in agent traces.

**Direction:** Import runtime verification: write a small library of Linear Temporal Logic (LTL) / regex-over-events specifications encoding honesty/safety properties for an agent (e.g., 'eventually report', 'never claim success without tool confirmation'), translate agent transcripts into event streams, and run an offline LTL monitor over MALT/Petri transcripts. Report which deceptive episodes violate which specs and the coverage achievable with simple specs.

**Why it matters:** Bridges formal methods and AI control: a transparent, auditable, non-LLM monitoring layer complementary to fuzzy CoT monitors — strategically valuable infrastructure deployable without lab resources.

**Relevant context:** Runtime verification checks execution traces against temporal-logic specs (Wikipedia; Springer FMSD). AgentVerify specifies LTL safety properties for agents (Preprints 202604.1029). Petri (Anthropic) and MALT (METR) provide agent transcripts.
