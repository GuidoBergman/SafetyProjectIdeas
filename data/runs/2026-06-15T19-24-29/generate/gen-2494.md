# Sabotage Detection in Automated AI R&D Tasks: Monitor Transfer

**Problem:** CTRL-ALT-DECEIT introduces sabotage evaluations for automated AI R&D, a different task domain than coding/bash. Whether a monitor tuned/prompted on code-backdoor detection transfers to ML-research sabotage (e.g. subtly degrading a training script) is a key generalization question.

**Direction:** Take a monitor prompt that works well on APPS code backdoors and apply it zero-shot to CTRL-ALT-DECEIT-style R&D sabotage transcripts (or a small hand-built set of subtly-sabotaged ML scripts). Measure the AUROC drop on the new domain, and test whether a few domain-specific prompt tweaks recover it.

**Why it matters:** Monitors will face task domains they were never tuned on; quantifying transfer loss tells deployers how much per-domain monitor adaptation is needed. Inference-only; tests a medium-horizon automated-R&D threat labs underweight.
