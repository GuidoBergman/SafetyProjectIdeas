# Differential Testing Across Model Pairs to Localize Safety Disagreements

**Problem:** Without a ground-truth oracle it is hard to know which safety-eval items are diagnostic. We rarely use the simplest software-testing trick: run two implementations on the same input and investigate where they disagree.

**Direction:** Import differential testing. Run several open models (and/or quantized vs full versions of one model) on the same large pool of borderline safety prompts, and surface the items where models disagree most on refuse/comply. Cluster the disagreement set to discover ambiguous, mislabeled, or genuinely hard items, and measure how much of a benchmark's score variance comes from this contested region. Produce a 'disagreement-curated' high-signal eval subset.

**Why it matters:** Gives a cheap, oracle-free way to find low-quality or ambiguous benchmark items (meta-evaluation) and to build a smaller, more discriminating eval. No training, just inference on open models; useful infrastructure for any external evaluator.

**Relevant context:** Differential testing is a classic software-testing technique for oracle-free bug finding; validating LLM-generated programs with metamorphic/differential prompt testing (arXiv:2406.06864) shows cross-execution comparison detecting defects without labels.
