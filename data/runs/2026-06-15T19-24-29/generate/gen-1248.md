# Do Larger SAEs Find More Safety-Relevant Features or Just Split Old Ones?

**Problem:** The pitch for wider SAEs is that they resolve finer concepts. But feature splitting means added capacity may just shatter existing features into near-duplicates rather than discover new safety-relevant concepts (e.g. deception, manipulation, harm).

**Direction:** Across a width-varied family of GPT-2-small SAEs, search each dictionary for features that activate on a fixed probe set of safety-relevant content (toxicity, deception cues, harmful instructions) using a small labeled probe corpus. Track whether the count of distinct safety-relevant features grows with width or whether new latents are near-duplicates (high decoder cosine similarity) of existing ones. Inference only over public SAEs.

**Why it matters:** Auditors must choose an SAE budget. If scaling width yields redundancy rather than new safety concepts, the cost-effective monitoring budget is bounded — a directly actionable, lab-independent result about how much interpretability scaling actually buys safety.

**Relevant context:** Feature splitting documented in Chanin et al. 2024 and SAEBench (2025) Mean Number of Split Features metric; 'Feature Hedging' (2025) shows correlated features break narrow SAEs. Width-varied GPT-2 SAEs public via SAELens.
