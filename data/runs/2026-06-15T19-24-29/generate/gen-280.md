# Fault Injection / Chaos Engineering for Safety-Filter Pipelines

**Problem:** Real deployments wrap models in pipelines (input filter, model, output filter). We rarely test how the SAFETY behavior degrades when individual pipeline components are perturbed or fail, as opposed to attacking the model in isolation.

**Direction:** Apply chaos engineering's fault-injection discipline. Build a small open-source guardrail pipeline (e.g. Llama-Guard input check -> open model -> output check), then systematically inject 'faults': drop the input filter, truncate the system prompt, corrupt the safety prefix token, lower the filter threshold, simulate latency-driven fallback. Measure the resulting jailbreak ASR under each fault profile and rank components by safety criticality.

**Why it matters:** Bridges the lab-vs-deployment robustness gap (an explicit open problem) by stress-testing the whole guardrail system. Strategically valuable monitoring/sandbox infrastructure prototype; uses only open components.

**Relevant context:** ReliabilityBench (arXiv:2601.06112) is the first chaos-engineering application to LLM agent reliability with configurable fault profiles; ChaosEater (arXiv:2511.07865) automates chaos cycles. Context open problem: bridge lab-tested defenses and real-world deployment (Intl AI Safety Report 2026).
