# From SAE Feature to Safety Action: A Tiny End-to-End Interpretability->Decision Pipeline

**Problem:** GAP TARGETED: the methodology gap 'unified safety CI/CD' — interpretability, behavioral evals, and deployment decisions exist as isolated tools with no integrated pipeline connecting an interpretability finding to an actual go/no-go decision. No subfield owns the glue.

**Direction:** Build a minimal 3-stage pipeline on a small open model with a pretrained SAE (e.g., via SAELens / Gemma Scope): (1) identify a safety-relevant feature (e.g., a 'deception' or 'refusal' feature) from labeled activations; (2) auto-generate a behavioral eval that stresses that feature; (3) emit a structured 'decision card' (feature -> eval result -> pass/flag) with a hardcoded rubric. Demonstrate on 2-3 features. The deliverable is the connective harness, not a new method.

**Why it matters:** Bridges mechanistic_interpretability + evaluations_benchmarks + ai_control. The integration gap — not any single component — is what blocks interpretability from informing deployment. A working toy CI/CD glue is novel infrastructure, counterfactual (open SAEs exist; no lab pipeline needed), and a self-contained artifact.

**Relevant context:** Landscape: 'no integrated pipeline connecting interpretability findings -> behavioral evals -> deployment decisions'. Gemma Scope / SAELens provide off-the-shelf SAEs for small open models on a single GPU. Anthropic's Sonnet 4.5 used interpretability in a deployment assessment (arXiv literature notes this as a first), but no open tooling reproduces the loop.
