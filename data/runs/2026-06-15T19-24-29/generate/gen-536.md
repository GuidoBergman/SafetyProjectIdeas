# Type-System / Refinement-Type Contracts for Tool-Using Agents

**Problem:** Formal methods offer refinement types to certify that functions respect pre/post-conditions, but agentic LLM tool-use lacks lightweight contracts that catch when an agent's action violates a declared safety invariant.

**Direction:** Import refinement-type contracts (pre/post-conditions) from programming-language theory. Wrap a small set of tools with declarative contracts (e.g., 'never delete outside scratch dir', 'sum of transfers conserves balance'), build a tiny harness around an open agent, and empirically measure how often the agent attempts contract-violating actions across benign and adversarial tasks. Report the catch-rate and false-positive rate of contract enforcement.

**Why it matters:** Demonstrates a cheap, formally-grounded safety-monitoring layer (a safer-sandbox prototype) that any small team can build, and quantifies how often agents probe their constraints — a strategically valuable infrastructure contribution decoupled from lab tooling.

**Relevant context:** Refinement types and design-by-contract certify pre/post-conditions in PL theory. Agentic tool-use safety and sandboxing is a recognized concern (arXiv:2506.23260). Matches steering toward safer-sandbox/monitoring-harness prototypes.
