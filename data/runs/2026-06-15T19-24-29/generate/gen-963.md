# Domain-Specific SAEs vs General SAEs for Niche Harm Detection

**Problem:** A 2025 result ('Resurrecting the Salmon') argues domain-specific SAEs can capture features general SAEs miss. For niche but high-stakes harm domains (e.g., bio/cyber-adjacent jargon), general SAEs may simply lack a clean feature, creating monitoring blind spots that nobody has measured.

**Direction:** Compare a general-corpus SAE against features extracted on a narrow domain corpus for whether a specific niche-harm concept gets a clean, monosemantic latent. Measure how much the general SAE 'misses' the concept versus a domain-focused feature search on the same model.

**Why it matters:** If general SAEs systematically miss niche harm concepts, monitoring built on them has predictable gaps in exactly the high-stakes long tail. This is diffuse, lab-independent evaluation work.

**Relevant context:** 'Resurrecting the Salmon: Rethinking Mech Interp with Domain-Specific SAEs' (arXiv 2508.09363) argues domain-specific SAEs capture features general SAEs miss. SAELens supports feature search; public domain corpora are available.
