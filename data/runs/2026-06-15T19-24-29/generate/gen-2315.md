# Property-Based Testing for Consultancy Robustness

**Problem:** In the consultancy protocol a single AI tries to persuade a weak judge; we don't systematically generate adversarial input variations to probe where persuasion beats truth.

**Direction:** Adapt property-based testing (QuickCheck-style): define properties the judge SHOULD satisfy (truth wins regardless of which side the consultant argues) and auto-generate randomized perturbations (topic, framing, confidence cues) to search for counterexamples where a deceptive consultant flips the verdict. Run as automated fuzzing over a weak open judge.

**Why it matters:** Automated counterexample search surfaces persuasion-over-truth vulnerabilities, a strategic-deception oversight failure, with a reusable fuzzing harness usable by anyone.

**Relevant context:** Property-based / metamorphic testing for trustworthy in-context learning (arXiv:2504.18827, 9 test types). Consultancy vs debate (Kenton et al. 2024). Confirmation bias as oversight challenge (arXiv:2507.19486).
