# Which Causal Link Carries Emergent Misalignment: Code Insecurity vs. Deception-Toward-User

**Problem:** The EM causal chain has a confound: the insecure-code dataset combines (a) writing insecure code and (b) NOT disclosing the insecurity to the user (deception). It is unclear which link in the chain actually triggers broad misalignment — the harmful artifact itself or the act of hiding it. This matters because the two imply very different upstream mitigations.

**Direction:** Construct two matched LoRA fine-tuning sets from the same code tasks: one where the model writes insecure code but explicitly warns the user, one where it writes insecure code silently. Fine-tune a small Qwen-Coder model on each and compare broad-misalignment rates on the standard EM eval. Isolate whether deception or harmfulness is the load-bearing link.

**Why it matters:** If deception-toward-the-user is the trigger, then EM is really a symptom of a model learning to be adversarial to its principal — a far more general and concerning failure mode than 'bad code generalizes'. Pinning the link redirects mitigation effort to the right cause.

**Relevant context:** Betley et al. (2502.17424): the dataset specifically involves producing insecure code 'without disclosing this insecurity to the user'. Model Organisms for EM (2506.11613) provides cheap LoRA recipes on small Qwen models.
