# Tool-Result Parsing Defense: Replicating Its Utility Cost on Benign Tasks

**Problem:** Defense Against Indirect Prompt Injection via Tool Result Parsing (arXiv:2601.04795) filters injected instructions from tool outputs. Such filters risk discarding legitimate content; the paper emphasizes attack-blocking but the benign-task utility loss is under-examined across diverse tool output formats (JSON, HTML, free text).

**Direction:** Reimplement the tool-result parsing filter as a preprocessing step. Build ~60 benign agent tasks whose tool outputs span structured (JSON/CSV) and unstructured (web text) formats. Measure (a) injection-block rate on a small set of injected variants and (b) benign task degradation (did the filter strip needed data?). Report the robustness/utility tradeoff curve by output format.

**Why it matters:** Over-aggressive input sanitization is the agent-world analogue of over-refusal and silently breaks legitimate workflows. Characterizing where parsing defenses hurt utility is decision-relevant for any deployer and needs no proprietary data.

**Relevant context:** Defense Against Indirect Prompt Injection via Tool Result Parsing (arXiv:2601.04795, Jan 2026): provides precise data to the LLM while filtering injected code. AttriGuard (arXiv:2603.10749) reports 0% ASR with 'negligible utility loss' — a claim worth independently stress-testing across output formats.
