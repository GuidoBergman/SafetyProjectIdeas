# Export-Control Loopholes x Just-Under-Threshold Stockpiling: Simulating Aggregated Evasion

**Problem:** Failure mode A: chip export rules use per-transaction quantity thresholds (e.g. ~1,700 H100-equivalents without a license). Failure mode B: compute tracking is weak at aggregating across many small purchasers. Together, an adversary stays under the per-purchase threshold while aggregating cluster-scale compute the licensing regime was meant to catch.

**Direction:** Build a small agent-based / Monte-Carlo simulation of buyers making repeated just-under-threshold purchases through shell intermediaries, and measure how much aggregate compute can be assembled before any single rule fires, under different threshold and aggregation-window settings. Sweep policy parameters to find which combinations close the loophole.

**Why it matters:** Turns an anecdotal smuggling loophole into a quantified policy-parameter map regulators can use to set thresholds and aggregation windows. Simulation only — no hardware, no proprietary data, ideal beginner project with clear success criteria.

**Relevant context:** Tier-2 ~1,700-chip loophole and circumvention reporting (techpolicy.press; aei.org); Toward a Global Regime for Compute Governance (arXiv:2506.20530).
