# Dormant Memory-Poison Trigger Latency

**Problem:** Memory-poisoning attacks (eTAMP, MINJA) plant instructions that lie dormant and fire across later, unrelated sessions, but the latency — how many intervening sessions/turns before activation and how reliably it persists — is not characterized in an open, reproducible setup.

**Direction:** Build a minimal memory-augmented open agent (vector-store memory). Plant one poisoned observation, then run a sequence of unrelated benign tasks and measure after how many sessions the dormant instruction activates and how persistence decays. Test cheap defenses (memory provenance tagging, periodic memory summarization) on activation rate.

**Why it matters:** Persistent memory is becoming standard in deployed agents and OWASP lists memory poisoning (ASI06) as a top 2026 risk. A reproducible activation-latency study with open tools informs memory-sanitization defaults — no proprietary data or training needed.

**Relevant context:** arXiv:2601.05504 'Memory Poisoning Attack and Defense on Memory Based LLM-Agents'; eTAMP achieves cross-session/cross-site compromise from a single contaminated observation; MINJA reports >95% injection success. OWASP ASI06 names memory poisoning a top agentic risk.
