# Multi-Turn Crescendo x Memory Persistence: Compounding Harm Across Conversation Resets

**Problem:** Two failures: multi-turn crescendo jailbreaks (gradually escalating benign-to-harmful) and conversational memory/summary persistence. If an assistant carries summaries across sessions, partially-jailbroken state from a prior crescendo may persist and compound into faster jailbreaks in a later 'fresh' session. This cross-session compounding is unmeasured on open models.

**Direction:** Simulate a two-session interaction: run a crescendo attack to a partial state, generate a conversation summary (as memory), then start a 'new' session seeded only with that summary and measure turns-to-jailbreak vs a no-memory control. Success criterion: a reduction in turns-to-jailbreak attributable to persisted summary, isolating the memory channel.

**Why it matters:** Persistent-memory assistants are an emerging product pattern; if benign-looking memory compounds crescendo attacks across resets, the threat outlives any single conversation—a medium-horizon design risk. Open models, simulated memory, consumer GPU.

**Relevant context:** Crescendo/multi-turn jailbreaks are well documented (multi-turn harmful-rate escalation in arXiv:2605.18239). The novel compound is the persisted-summary memory channel as an amplifier across sessions.
