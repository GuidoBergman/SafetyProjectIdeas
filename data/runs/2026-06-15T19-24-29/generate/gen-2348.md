# Cross-Domain Transfer of Oversight Failures: Does a Judge That Fails on Math Also Fail on Code?

**Problem:** Facilitators want to know if validating an overseer in one domain licenses trusting it elsewhere. Causal chain: validate judge on domain A -> deploy on domain B -> if failure modes don't transfer, the validation is misleading. The under-studied link is the correlation of judge failure across task domains for the same items' difficulty.

**Direction:** Build matched judgment items across 3 domains (arithmetic reasoning, short code correctness, factual QA) with ground truth. For each small judge model, measure per-domain accuracy and per-item failure, then test whether failure on one domain predicts failure on another (controlling for difficulty). Report a domain-transfer matrix of oversight reliability.

**Why it matters:** Tells facilitators whether oversight reliability is a stable trait or domain-specific, central to safely extrapolating any oversight validation. Pure evaluation on open models and public data.

**Relevant context:** Anthropic recommended directions ask when weak overseers reliably supervise stronger models; LLM-judge bias surveys (arXiv:2410.02736) note domain-dependence. Cross-domain transfer of an individual judge's failure profile is under-characterized.
