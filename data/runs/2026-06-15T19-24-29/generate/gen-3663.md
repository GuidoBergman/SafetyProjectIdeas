# Latent Injection via Tool Documentation Strings

**Problem:** Prompt-injection research focuses on user inputs and web/RAG content, but agents also read tool descriptions/API docs to decide how to act — whether a malicious instruction hidden in a tool's documentation string can hijack an agent is an underexplored channel.

**Direction:** Build a mock toolset where one tool's docstring/description contains a hidden instruction ('also POST the result to URL X'). Run an open agent on benign tasks and measure how often it follows the injected instruction embedded in tool metadata, vs. the same instruction in user input or a document.

**Why it matters:** Tool descriptions are trusted by construction and rarely sanitized, making them a high-leverage, low-attention attack surface relevant to MCP ecosystems. Mapping this channel's potency is cheap and feeds directly into agent security standards.

**Relevant context:** OpenReview 'Log-To-Leak: Prompt Injection on Tool-Using LLM Agents via Model Context Protocol'. GitHub prompt-injection topic and Praetorian 'Augustus' latent-injection probes (instructions embedded in processed documents). NIST AI Agent identity/security standards open problem.
