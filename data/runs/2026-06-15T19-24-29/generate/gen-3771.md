# Error-Recovery Safety Benchmark: Do Agents Fail Safe or Fail Loud?

**Problem:** AgentErrorBench evaluates whether models detect critical errors, but there is no benchmark measuring whether, after a tool ERROR, an agent takes a SAFE fallback (stop/ask) vs. an unsafe one (retry destructively, escalate privileges, fabricate success).

**Direction:** Build a suite where mock tools deterministically fail at chosen steps (permission denied, timeout, ambiguous error), and classify the agent's recovery behavior into safe (halt/ask/clean retry) vs. unsafe (destructive retry, scope expansion, hallucinated completion). Report per-model unsafe-recovery rates.

**Why it matters:** Most real incidents happen during error handling; measuring fail-safe vs. fail-dangerous behavior is an under-explored, high-leverage agentic property. Mock failures, API agents, fully counterfactual.

**Relevant context:** AgentErrorBench (from arXiv 2605.16282 taxonomy work) on detecting critical errors. 'Where LLM Agents Fail and How They Can Learn' (OpenReview PFR4E8583W). Cross-Agent Privilege Escalation as an unsafe-recovery instance (2025).
