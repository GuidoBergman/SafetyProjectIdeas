# Replicating SAE Feature Steering for Sentiment on a Different Modality (Audio/Code Tokens)

**Problem:** SAE feature steering (amplifying/suppressing a single interpretable latent to change behavior) is well demonstrated for text concepts like sentiment and entities in Gemma. Whether the same single-feature steering precision holds for non-prose token streams — specifically code — where the model's 'concepts' are syntactic/structural, is underexplored using public SAEs.

**Direction:** Use Gemma Scope SAEs on Gemma-2-2b. Replicate single-feature steering on prose (e.g., steer a sentiment feature, measure effect) as the baseline. The twist: identify code-related SAE features (via Neuronpedia explanations) and test whether steering them produces clean, interpretable changes in code completions (e.g., language choice, comment density), quantifying steering precision vs side-effects relative to the prose baseline.

**Why it matters:** Code-generation models increasingly autonomously write and execute code, a key autonomy/agentic risk surface. Whether interpretable features cleanly control code behavior — testable with public SAEs on one GPU — bears on whether feature-level monitoring/steering can serve as a safety control for code agents, infrastructure valuable to build outside a lab.

**Relevant context:** Gemma Scope (DeepMind) provides public SAEs for Gemma-2-2b; Neuronpedia hosts feature explanations and steering. Anthropic and Ferrando et al. (arXiv:2411.14257) demonstrate causal single-feature steering for text concepts. SAE feature steering is a standard methodology.
