# A Benchmark for Detecting Dead and Dense 'Junk' SAE Features

**Problem:** SAEs contain dead features (never activate) and ultra-dense features (activate almost always), both of which pollute interpretability dashboards and waste analysis effort. The prevalence of these junk features across released SAEs is not systematically measured or standardized, so users can't quickly assess SAE health before relying on it.

**Direction:** Build an SAE 'health check' tool that, given an SAE and a corpus sample, reports dead-feature rate, dense-feature rate, activation-frequency distribution, and an overall usable-feature fraction. Run it across several public SAE architectures/widths to produce a comparison table and rules of thumb for which SAEs are worth analyzing.

**Why it matters:** Researchers new to interpretability waste time on broken features; a one-command health check is exactly the accessible, no-training infrastructure that improves the whole field's efficiency and prevents misleading safety claims based on degenerate features.

**Relevant context:** SAEBench measures SAE quality across 8 metrics and released 200+ SAEs across architectures/widths, showing large quality variation; dead and dense features are well-documented SAE failure modes in the SAELens/Neuronpedia ecosystem. Superposition/decomposition reliability is an Open Phil open problem.
