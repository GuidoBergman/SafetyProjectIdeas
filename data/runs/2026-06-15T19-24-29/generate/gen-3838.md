# The Dormant-Trigger Link: Measuring Latency Between Memory Poisoning and Harmful Recall

**Problem:** Memory-poisoning chain: benign-looking query writes a poisoned record -> record sits in long-term memory -> later query retrieves it -> agent executes attacker-chosen action. The neglected link is dormancy dynamics: how retrieval probability of the poisoned record evolves as benign memories accumulate, and whether it decays or persists ('phantom document' effect).

**Direction:** Use an open RAG/memory-agent template (e.g., a simple vector-store memory). Inject one poisoned experience, then add M benign records over time. At intervals, issue trigger-adjacent queries and measure the probability the poisoned record is retrieved and acted on. Plot recall probability vs memory size. Test one defense: periodic relevance re-ranking or staleness pruning. No model training; just embeddings + retrieval.

**Why it matters:** Persistent, trigger-free memory compromise is a medium-horizon threat that survives across sessions and current defenses are 'largely ineffective.' A dormancy/decay curve quantifies how long a single poisoning stays dangerous -- directly informing memory hygiene policy. Fully feasible on consumer hardware.

**Relevant context:** MemoryGraft (arXiv 2512.16962) shows persistent, trigger-free behavioral drift via poisoned experience retrieval. MINJA is query-only memory injection. Memory Poisoning survey (arXiv 2604.16548) and RSB benchmark report current defenses 'remain largely ineffective'; phantom-document persistence is documented. Dormancy-vs-memory-growth is under-measured.
