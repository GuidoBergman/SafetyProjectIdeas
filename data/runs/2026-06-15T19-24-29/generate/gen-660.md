# Concealed-Jailbreak Detector Transfer: Does JBShield Catch Attacks It Never Saw?

**Problem:** Hiding in Plain Text (arXiv:2602.19396) detects concealed jailbreaks via activation disentanglement (JBShield) and claims model-independent, weight-frozen performance. Detectors are usually evaluated on the same attack families they were tuned on; cross-attack-family generalization (train on suffix attacks, test on roleplay/encoding attacks) is rarely measured.

**Direction:** Implement a lightweight activation-disentanglement probe on one open model. Build a small matrix of attack families (GCG-style suffix, roleplay, low-resource-language, base64/encoding). Fit the probe on each single family and evaluate cross-family detection AUROC, producing a transfer heatmap of which families generalize to which.

**Why it matters:** Real attackers use novel families; a detector that only catches in-distribution attacks gives false security. Cross-family transfer is exactly the lab-deprioritized, medium-horizon robustness question, and it needs only public weights and forward passes.

**Relevant context:** Hiding in Plain Text: Detecting Concealed Jailbreaks via Activation Disentanglement (arXiv:2602.19396, Feb 2026): JBShield does anomaly detection on internal representations without backprop, claims SOTA weight-frozen detection by checking simultaneous toxic+jailbreak concept activation. ALERT (arXiv:2601.03600) provides additional zero-shot detection baselines.
