# Documentation Fragmentation x Automated Compliance Checking: Why Machine-Readable Gaps Break Enforcement

**Problem:** Failure mode A: model documentation uses 947 inconsistent section names, so safety facts aren't machine-locatable. Failure mode B: regulators (EU AI Act Annex IV, SB53) increasingly expect scalable/automated compliance checking. The two compound: automated enforcement silently passes non-compliant disclosures because it can't find the relevant section.

**Direction:** Build a small LLM-or-regex compliance checker against a fixed Annex-IV-style schema, run it over a sample of real public model cards, and measure its false-pass and false-fail rate caused purely by naming/structure variation (vs genuine content presence). Show how much enforcement accuracy degrades with documentation fragmentation, and how a normalization step recovers it.

**Why it matters:** Quantifies a hidden coupling between disclosure standards and the feasibility of scalable enforcement, arguing for mandated machine-readable schemas. Public docs + light tooling; strongly counterfactual.

**Relevant context:** AI Transparency Atlas fragmentation findings (arXiv:2512.12443); EU AI Act Annex IV; California SB53 transparency (anthropic.com/news/compliance-framework-SB53).
