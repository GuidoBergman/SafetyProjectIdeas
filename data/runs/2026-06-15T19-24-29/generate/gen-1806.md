# SAE Error Term Hides Harm When Reconstruction-Based Monitoring Is Used

**Problem:** Compound: (1) SAE reconstruction error / dark-matter (the part of activations SAEs don't explain — an interp completeness failure) amplifying (2) monitoring failure when a system flags inputs only by SAE-feature activations. Harmful computation routed through the un-reconstructed residual is invisible to a feature-based monitor.

**Direction:** On an open model with a pre-trained SAE, compare a harm classifier trained on (a) SAE feature activations vs (b) raw residual-stream activations, on a harmful/benign set. Measure how much detection signal lives in the SAE error term that a feature-only monitor discards. Construct/identify examples detectable in raw but not SAE space.

**Why it matters:** Feature-based monitoring is sold as 'interpretable safety.' Quantifying that a meaningful fraction of harm signal lives in the discarded reconstruction error is a clean, surprising compound result with only public SAEs.

**Relevant context:** DeepMind 'Negative Results for SAEs on Downstream Tasks' (deepmindsafetyresearch Medium) found SAE probes underperform raw-activation probes. Search results: SAEs lack ground truth and have nonlinear error / feature absorption. SAELens pre-trained SAEs available.
