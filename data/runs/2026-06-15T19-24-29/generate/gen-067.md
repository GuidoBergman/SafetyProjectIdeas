# Network-centrality circuit triage: ranking SAE features by graph importance for safety auditing

**Problem:** Sparse feature circuits produce large causal graphs of SAE features, but auditors have no principled way to prioritize which features to inspect for a safety-relevant behavior; inspection is manual and unscaled.

**Direction:** Apply network-science centrality measures (betweenness, eigenvector, PageRank) from graph theory to an already-computed sparse feature circuit. Take a public circuit (or compute a small one with SAELens on a small open model) for a safety-relevant behavior, build the feature graph, and rank features by centrality. Test whether high-centrality features, when ablated, cause larger behavioral changes than random or low-centrality features — i.e., does centrality predict causal importance?

**Why it matters:** If centrality predicts importance, auditors get a cheap automated triage to focus interpretability effort — addressing the interpretability-to-safety tooling gap. Uses existing open tooling, no training.

**Relevant context:** Grounded in Sparse Feature Circuits (Marks et al. arXiv 2403.19647) and SAELens. Search confirmed centrality measures not yet systematically applied to feature circuits. Source subfield: network science / graph theory. Target subfield: mechanistic_interpretability.
