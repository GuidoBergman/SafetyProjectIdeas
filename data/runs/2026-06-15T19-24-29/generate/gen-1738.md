# Compiler Dead-Code Elimination to Find Vestigial Circuit Components

**Problem:** Models likely contain components that are 'dead code' for a given deployment distribution, never causally affecting outputs, but we have no systematic elimination pass to find them.

**Direction:** Transfer dead-code elimination / liveness analysis from compilers. Over a task distribution, mark a component 'dead' if ablating it never changes the output within tolerance across all inputs, iteratively prune dead components, and measure how much of a small model is vestigial for a given task. Characterize whether dead components reactivate under distribution shift (live-but-latent).

**Why it matters:** Latent components that are inert on benign data but activate under shift are a stealthy safety risk (sleeper behavior). A liveness pass surfaces them cheaply, a medium-horizon concern labs underexamine.

**Relevant context:** Dead-code elimination and liveness analysis are standard compiler techniques. Ablation tooling in TransformerLens makes liveness testing direct; framing pruning as compiler liveness analysis (with a shift-reactivation test) is the novel transfer.
