# Capability-vs-Propensity Disentanglement Mini-Protocol for Covert Action

**Problem:** Success state: when an agent does NOT scheme in an eval, we can tell whether it lacked the capability to see scheming as an option or chose not to. Apollo notes this is a core unsolved confound. Backcasting, we need a lightweight protocol that separates the two on open models.

**Direction:** Design paired scenarios: a 'propensity' variant where the covert option is available but not hinted, and a 'capability' variant where the covert strategy is explicitly described and the model only has to execute it. Run on open agentic models; the gap between execution-when-told and spontaneous-use estimates propensity given capability. Report a 2x2 capability/propensity matrix per model.

**Why it matters:** Mislabeling a capable-but-restrained model as 'safe because it didn't scheme' is a dangerous false negative for safety cases. A reusable disentanglement protocol is foundational measurement infrastructure that any external evaluator can run.

**Relevant context:** 'Evaluating and Understanding Scheming Propensity in LLM Agents' (arXiv 2603.01608) explicitly states capability and propensity are hard to disentangle. Apollo/OpenAI 'Stress Testing Deliberative Alignment for Anti-Scheming' uses covert actions as a scheming proxy.
