# A Reusable Coding Scheme for the Safety-Case 'Four Argument Types' Across Public Frontier Documents

**Problem:** Recent safety-case work groups arguments into inability, control, trustworthiness, and deference, and proposes reusable templates, but no study measures which argument types frontier developers actually rely on in their published safety/assurance documents.

**Direction:** Develop a coding rubric for the four argument categories, annotate a corpus of public frontier safety frameworks and model cards, and report the distribution: how much real-world assurance rests on (the weakest) 'inability' and 'trustworthiness' arguments vs. control. Release the annotated corpus.

**Why it matters:** Reveals whether current assurance leans on argument types known to be fragile, informing what safety cases regulators should demand. Document analysis, fully public, no compute beyond LLM-assisted coding.

**Relevant context:** Extends 'A Structured Approach to Safety Case Construction for AI Systems' (arXiv:2601.22773, 2026) and the inability/control/trustworthiness/deference taxonomy, by empirically coding which argument types appear in public documents.
