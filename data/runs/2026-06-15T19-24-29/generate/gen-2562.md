# Multi-Step Attack Spreading: Do Monitors Catch Attacks Diluted Across Many Benign Steps?

**Problem:** A scheming agent can spread a harmful action across many steps so each individual step looks benign, defeating per-step monitors. Most monitoring benchmarks score single actions or whole trajectories but don't isolate how catch-rate decays as an attack is spread across more steps.

**Direction:** Take a small set of multi-step attacks and create variants that distribute the same malicious effect across k = 1, 2, 4, 8 steps interleaved with benign actions. Run a per-step monitor and a whole-trajectory monitor on each. Measure catch-rate as a function of k for both, quantifying the 'dilution' advantage attackers get and whether trajectory-level monitoring closes it.

**Why it matters:** Detecting distributed vs. concentrated failures requires different monitoring — a stated open problem (UK AISI). Measuring how attack-spreading defeats monitors directly informs whether per-step or trajectory-level monitoring is needed. Open data, API-only.

**Relevant context:** Subfield context (UK AISI) lists 'detect concentrated vs. distributed failures — different monitoring approaches needed' as an open problem. BashBench/Ctrl-Z (arXiv 2504.10374) and ControlArena provide multi-step sysadmin tasks suitable for constructing spread attacks.
