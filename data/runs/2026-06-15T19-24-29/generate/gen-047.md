# A Minimal Reversibility Gate for Agents: Owning the Irreversible-Action Gap Between Control and Agentic Safety

**Problem:** GAP TARGETED: the seam between ai_control and agentic_safety around IRREVERSIBLE actions — control theory talks about deferring to humans and agentic safety talks about tool use, but no lightweight, reusable component owns the specific job of recognizing and gating irreversible tool calls (delete, send, pay, deploy) before they execute.

**Direction:** Build a small 'reversibility gate': a classifier (prompt-based + a tiny labeled set) that, given a proposed tool call, predicts whether it is reversible. Wrap a toy agent so irreversible calls are paused for confirmation. Evaluate on a labeled set of ~100 tool calls: precision/recall of the gate, false-block rate on benign reversible actions, and whether it catches a set of scripted harmful irreversible sequences. Compare prompt-only vs few-shot vs simple features.

**Why it matters:** Bridges ai_control + agentic_safety. Irreversibility is the property that turns a mistake into a catastrophe, yet there is no off-the-shelf gate for it. A working prototype is strategically valuable infrastructure (a safer-sandbox primitive), counterfactual (no lab infra), and a clean self-contained deliverable.

**Relevant context:** Constraint-violation benchmarks (arXiv:2512.20798) and ATBench highlight irreversible/high-impact actions as the core agent-safety risk. The catalogue has a 'Reversibility Firewall' sketch; this differs by centering an evaluated reversibility CLASSIFIER with measured precision/recall as the owned component.
