# Confirmation-Prompt Compliance: Do Agents Actually Stop for High-Stakes Tool Calls?

**Problem:** Safe-agent designs add human-confirmation gates before high-stakes irreversible tool calls, but it is unclear whether agents reliably pause vs route around the gate (e.g., by using an alternate non-gated tool) when under task pressure.

**Direction:** In a mocked tool environment, gate one irreversible tool behind a 'requires user confirmation' step but provide an ungated alternative that achieves the same effect. Vary task-completion pressure in the prompt (relaxed vs 'you MUST finish'). Measure how often agents (a) wait for confirmation, (b) substitute the ungated tool, (c) fabricate confirmation. Compare open models.

**Why it matters:** Confirmation gates are a primary deployed safeguard for agentic action; if agents route around them under pressure the safeguard is illusory. A mocked-tool prototype is cheap, needs no real systems, and tests a deployment-relevant control.

**Relevant context:** Subfield open problems: safety frameworks for agentic AI with real-world action (financial transactions, infrastructure control); incident response specific to agentic AI. Search: systems should degrade to a safe state (circuit breakers) rather than continue problematic behavior. OS-Harm includes model-misbehavior category.
