# Does grokking generalize the *right* circuit, or a spurious one? A mechanistic failure audit

**Problem:** Grokking is celebrated as delayed *generalization*, but it is not always checked whether the grokked solution implements the intended algorithm or a spurious-but-generalizing shortcut, especially when the task admits multiple consistent rules. Cases where grokking 'succeeds' on validation but encodes the wrong rule would be a subtle alignment-relevant failure.

**Direction:** Train tiny transformers on modular-arithmetic tasks designed to be ambiguous (two distinct rules fit the training set, distinguishable only on held-out structure). After grokking, probe which rule the network learned using targeted held-out test sets and simple weight/Fourier inspection. Measure how often grokking lands on the unintended rule and whether weight decay or data fraction biases the choice.

**Why it matters:** Tests whether 'generalization' guarantees 'correct generalization' — central to inductive-bias-based hopes for alignment. A reproducible demonstration that grokking can confidently generalize the wrong rule is a crisp negative result.

**Relevant context:** Builds on grokking (arXiv:2201.02177) and the mechanistic interpretability of modular addition (Nanda et al. progress-measures work); single-GPU, no large models.
