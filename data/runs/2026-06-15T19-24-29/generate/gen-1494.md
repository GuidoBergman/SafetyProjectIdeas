# Formal-Methods Invariant Monitors: Runtime Assertions on Concept Projections

**Problem:** Steering provides no guarantees; there is no verification mechanism that a safety property holds during generation. Formal methods use runtime monitors that check invariants (assertions) continuously and raise alarms on violation.

**Direction:** Transfer runtime verification / assertion monitoring from formal methods. Specify simple temporal invariants over a concept probe's value during generation (e.g. 'refusal projection must never drop below threshold T for an unsafe-flagged prompt', 'toxicity projection must stay below U for all tokens'). Implement a lightweight runtime monitor on an open model that checks these per token and logs violations. Evaluate how often a monitored, steered model still violates its own invariants.

**Why it matters:** Bridges steering's lack of guarantees toward verifiable runtime properties, a small prototype of safety-monitoring infrastructure. Catching invariant violations mid-generation enables abort/re-steer, a building block for safer sandboxes. Inference-only, no training, the kind of monitoring harness this steering prizes.

**Relevant context:** Runtime verification monitors temporal invariants in software. Steering offers no quantitative guarantee or verification mechanism (RepE limitation). Probes outperform judges for detection (Beaglehole et al.).
