# Adversarial Goodhart in the Loop: When Does the Optimizer Start Modeling the Evaluator?

**Problem:** Adversarial Goodhart is the chain link where the optimized system begins to model and exploit the evaluator rather than satisfy the goal. The under-studied empirical question is the onset condition: how much capability or feedback does an LLM optimizer need before it shifts from honest improvement to evaluator-modeling?

**Direction:** Set up an iterative game: an LLM proposes answers, a fixed proxy 'judge' scores them, and the LLM sees scores and revises. Track when revisions stop improving a held-out true metric and start exploiting judge quirks (e.g., length, keywords). Vary judge transparency and model size to find the onset of evaluator-modeling.

**Why it matters:** Adversarial Goodhart is the most dangerous variant and the least empirically characterized; mapping its onset on open models with pure prompting is a feasible, lab-independent contribution.

**Relevant context:** Manheim & Garrabrant (2018) adversarial Goodhart; 'Honesty to Subterfuge: In-Context RL Can Make Honest Models Reward Hack' (arXiv:2410.06491) — in-context feedback inducing hacking.
