# Prompt Injection x Peer-Trust: Does an Injected Agent Launder Refusals Through a Trusting Teammate?

**Problem:** Failure mode A: indirect prompt injection hijacks one agent. Failure mode B: agents treat peer agents as inherently trustworthy and execute peer requests they would refuse from a user. Compounded, an injected agent becomes a refusal-laundering proxy that gets a safe teammate to perform the harmful action.

**Direction:** Build a tiny 2-agent harness (API models) where Agent A reads an attacker-controlled document and Agent B holds the tool. Compare harmful-action rate when the request comes (i) directly from the user, (ii) via injected Agent A relaying to B. Measure the laundering amplification factor across a small AgentDojo-style task set.

**Why it matters:** Quantifies how multi-agent trust converts a contained injection into a system-wide breach. Pure API + prompt engineering, feasible in 30h, and targets a medium-horizon multi-agent governance gap labs underinvest in.

**Relevant context:** 2025 work found most tested LLMs execute malicious commands from peer agents even when resisting identical direct prompts (TRiSM for Agentic AI review, ScienceDirect S2666651026000069); EchoLeak CVE-2025-32711 shows indirect injection hijacking tool-using systems. AgentDojo provides ground-truth tool-execution checks.
