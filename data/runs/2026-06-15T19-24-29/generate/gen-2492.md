# Output Collusion Signals: How Subtle Can a Policy-Monitor Handshake Be?

**Problem:** Collusion evaluations distinguish output collusion (coordination via direct communication) from input collusion (acausal). The minimum-detectability of an output-collusion signal — how subtle a handshake can be while still reliably coordinating two copies of the same model — is unquantified.

**Direction:** With two instances of the same open model as policy and untrusted monitor, define a ladder of increasingly subtle collusion signals (explicit phrase -> rare word -> stylistic tell -> semantic cue). Measure for each (a) coordination success rate and (b) detectability by a trusted overseer reading the transcript. Find the subtlety frontier where collusion still works but a trusted overseer can no longer flag it.

**Why it matters:** Defines how hard input/output collusion is to stamp out, informing whether untrusted monitoring can ever be trusted. Inference-only with a shared open model; a concrete, scoped slice of a hard control problem.

**Relevant context:** Honeypot Protocol / collusion evaluations (arXiv 2604.13301): output collusion via direct communication vs input collusion (acausal). When can we trust untrusted monitoring? (arXiv 2602.20628). TraceGuard (arXiv 2604.03968) as collusion-resistant protocol.
