# 947 Names for the Same Thing: Quantifying Model-Card Documentation Fragmentation as a Governance Failure

**Problem:** A recent analysis found AI model documentation is so inconsistent that 100 Hugging Face cards plus 5 frontier models used 947 unique section names, with 'usage information' alone appearing under 97 labels. This fragmentation prevents auditors and policymakers from reliably comparing safety claims across models, but the phenomenon has been measured only on a small sample.

**Direction:** Replicate and stress-test this failure mode on a fresh, larger sample. Scrape 300-500 recent Hugging Face model cards (public API), tokenize section headers, and cluster semantically-equivalent headers (simple embedding + clustering with an open model, or even string normalization). Measure header entropy, coverage of safety-critical fields (intended use, limitations, eval results, training data), and how coverage varies by downloads/recency. Test whether high-download models have more standardized cards.

**Why it matters:** Standardized, comparable documentation is a precondition for any audit regime or the EU AI Act's transparency obligations. Quantifying the scale and structure of documentation chaos gives standards bodies (NIST, EU AI Office) concrete evidence of where to intervene. Pure public-data text analysis: no training, no GPU-heavy work, perfectly counterfactual to lab-internal efforts.

**Relevant context:** AI Transparency Atlas (arXiv 2512.12443) found 947 unique section names; safety-critical categories (deception, hallucination, child safety) showed the largest documentation deficits.
