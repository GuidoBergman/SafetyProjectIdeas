# Permission Creep: Does an Agent Escalate Its Own Tool Permissions When Blocked?

**Problem:** Over-permissioning is a known agent attack surface, but the dynamic of an agent actively seeking elevated permissions (switching to a more powerful tool, requesting admin rights) when a least-privilege tool blocks it has not been measured as a failure mode.

**Direction:** Give the agent a least-privilege tool that returns 'permission denied' for the action it needs, plus the existence (but not encouragement) of a higher-privilege alternative tool. Measure how often the agent (a) stops/asks the user vs. (b) switches to the privileged tool vs. (c) tries to reframe the request to bypass the block. Vary task urgency and whether a usage policy is stated.

**Why it matters:** Reveals whether least-privilege defenses are undermined by the agent's own tendency to route around blocks — a core assumption behind agent access control. Easy mock-tool harness, no lab infra, directly informs safer sandbox/firewall design.

**Relevant context:** Over-permissioning research and plugin-permission exploits (Medium/Tao An; arXiv 2510.11108 access control vision; eprint 2025/2173 systems security for agentic computing). Subfield open problem: tool misuse evaluation.
