# Monitor Score Calibration Probe: Do Suspiciousness Scores Mean the Same Thing Across Tasks?

**Problem:** Trusted monitors in AI control protocols emit a 0-100 'suspiciousness' score that gets thresholded (e.g. audit the top 1%). But there is little public measurement of whether a score of, say, 60 corresponds to the same probability of a real attack across different task types (code review vs. system administration vs. web tasks). Miscalibration silently breaks the audit-budget math that control protocols rely on.

**Direction:** Take an open monitor model (any chat LLM via API) and a small set of labeled benign + attack trajectories from SHADE-Arena and/or ControlArena. For each trajectory, collect the monitor's suspiciousness score. Build reliability diagrams (predicted-suspiciousness bins vs. empirical attack frequency) separately per task category. Quantify calibration error (ECE) and whether a single global audit threshold over- or under-spends the audit budget on some task families.

**Why it matters:** Control protocols allocate a scarce auditing budget by thresholding monitor scores; if scores are uncalibrated across task types, the protocol audits the wrong things and a scheming model can route attacks into under-monitored task families. This is a measurement gap doable entirely with API access and open datasets, with no lab infra.

**Relevant context:** ControlArena (UK AISI + Redwood) provides settings with datasets and scorers; SHADE-Arena (arXiv 2506.15740) provides 17 benign/malicious task pairs with monitor scoring. Monitoring-benchmark work notes monitors are calibrated by setting thresholds at the 99th percentile of honest-log scores (1% FPR), assuming a single threshold generalizes.
