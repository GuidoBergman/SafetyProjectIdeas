# CodeHivemind: do models generate the same insecure code patterns?

**Problem:** Homogeneity in code generation is safety-critical: if all coding assistants emit the SAME insecure idiom for a given task, that vulnerability propagates across all software built with AI assistance. This shared-blind-spot dimension is unmeasured in the Hivemind framing.

**Direction:** Take ~50 coding tasks known to have a secure/insecure choice (SQL queries, crypto usage, input validation). Query 6-10 open code models. Detect whether they converge on the same insecure pattern using simple static checks. Measure inter-model homogeneity of the vulnerability and whether the 'popular wrong answer' is shared. Release task set and per-model labels.

**Why it matters:** Correlated insecure-code generation means AI-assisted software develops a monoculture of the same bugs — an at-scale, long-horizon systemic risk to the software supply chain. Static-check scoring keeps it within beginner skills and consumer compute.

**Relevant context:** Extends Hivemind to the code domain (named extension direction: test safety-relevant domains); connects shared-blind-spot risk to software supply chain.
