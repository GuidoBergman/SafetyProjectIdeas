# Metamorphic Relations as a Jailbreak Oracle

**Problem:** Judging whether a response is a successful jailbreak usually needs an expensive LLM judge or human labels. Software testing solves the oracle problem differently: instead of checking absolute correctness, it checks metamorphic relations (MRs) that should hold between paired inputs.

**Direction:** Import metamorphic testing (METAL-style MRs) into safety eval. Define MRs over a harmful prompt and its safety-preserving transforms (paraphrase, add benign framing, translate-and-back, change politeness). The invariant: refusal status should be preserved across transforms. Run an open model (e.g. Llama-3-8B-Instruct) on ~50 harmful seeds x ~8 transforms from StrongReject, and flag MR violations (refuse on seed, comply on transform) as automatically-detected jailbreaks needing no judge. Measure violation rate per MR type.

**Why it matters:** Gives small teams a cheap, label-free jailbreak detector and a way to localize which surface transforms most break alignment. Counterfactually valuable: needs no training, no lab infra, just an open model and CPU/light GPU.

**Relevant context:** METAL: Metamorphic Testing Framework for Analyzing LLM Qualities (arXiv:2312.06056) applies MRs to LLM robustness. MTTM applies metamorphic testing to content-moderation robustness. StrongReject (OpenAI) is public per context file.
