# Decoding-Parameter Sensitivity Surface for Jailbreaks

**Problem:** Safety can vary with temperature/top-p, but there is no tool producing a 2D 'vulnerability surface' showing how a fixed jailbreak's success rate varies across the full decoding-parameter grid for a given model.

**Direction:** Take a fixed set of jailbreak prompts and sweep temperature x top-p (and top-k) on an open model, computing attack success at each grid point with the StrongREJECT evaluator (averaged over multiple samples). Render a heatmap 'vulnerability surface' per model and identify decoding regions that are unexpectedly unsafe.

**Why it matters:** Deployers tune decoding for quality but rarely check safety implications; a surface map reveals dangerous parameter regimes. The existing catalogue idea covered 'consistency across decoding parameters' as a single-number consistency check — this proposes a richer per-parameter SURFACE tool, a distinct artifact. Cheap, single GPU.

**Relevant context:** StrongREJECT rubric evaluator (arXiv:2402.10260) supports averaging over stochastic samples. Sampling stochasticity affecting refusal is noted in safety-eval-robustness work ('LLM-Safety Evaluations Lack Robustness', arXiv:2503.02574).
