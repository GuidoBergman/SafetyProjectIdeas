# Does the refusal vector generalize across harm CATEGORIES, or is each category its own link?

**Problem:** Coverage chain: deployer extracts a refusal vector (often from one harm type) -> assumes it blocks all harmful requests -> but if the vector only covers the harm category it was built from, other categories slip through. Whether one refusal direction covers cyber, bio, fraud, self-harm, etc., uniformly is the under-tested coverage link.

**Direction:** On an open model, extract a refusal vector using ONLY one harm category (e.g., cyber). Then test its steering/detection effectiveness across several other categories (fraud, self-harm, weapons, privacy). Repeat extracting from a different single category. Build a transfer matrix of category-to-category coverage. Success criterion: a coverage matrix revealing which categories share a direction and which are orphaned.

**Why it matters:** If safety vectors are category-specific, single-category deployment leaves systematic blind spots — a concrete, measurable gap. The transfer matrix is directly actionable for anyone deploying steering-based safety, and needs only curated prompts.

**Relevant context:** SafeSteer (category-specific vectors) implies categories differ; Beaglehole et al. universal-concept framing implies they might unify. The category transfer matrix arbitrates between these, cheaply.
