# Backcasting Easy-to-Hard Verifiers: Does an Easy-Trained Judge Catch Hard Errors?

**Problem:** Success state: overseers trained/anchored only on easy problems that still reliably evaluate hard problems beyond their own solving ability. We need a feasible test of whether an evaluator anchored on easy items can score hard-item solutions correctly without any training.

**Direction:** Without training (the rule against estimated-only persistence aside, this is an evaluation), prompt a small open model as a verifier using only easy in-context exemplars (e.g. MATH level 1-3), then have it judge candidate solutions to hard items (level 4-5). Compare its verification accuracy on hard items to its own generation accuracy on those items.

**Why it matters:** Easy-to-hard generalization is a named open problem and a core success route: 'evaluation is easier than generation.' A purely in-context test of whether an easy-anchored evaluator beats its own generator on hard problems is a cheap probe of that premise.

**Relevant context:** Sun et al. 'Easy-to-Hard Generalization' (NeurIPS 2024, arXiv:2403.09472, open code github.com/Edward-Sun/easy-to-hard) show easy-trained reward models score hard solutions; generative verifiers (arXiv:2408.15240) show easy-to-hard transfer. An in-context, training-free variant is feasible in 30h.
