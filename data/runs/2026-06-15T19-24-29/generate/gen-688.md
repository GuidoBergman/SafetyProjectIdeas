# A Taxonomy of Near-Miss vs Realized-Harm Framing in the AI Incident Database

**Problem:** The OECD's common reporting framework argues near-misses should be reported because they share characteristics with incidents, but the existing AI Incident Database does not cleanly distinguish near-misses from realized harms, limiting their use for proactive governance.

**Direction:** Pull a sample of public AIID / OECD AIM entries and use an LLM with a clear rubric to classify each as realized-harm vs near-miss vs hazard, plus the lifecycle stage and harm type. Measure how prevalent near-miss reporting actually is, where it is missing, and propose minimal schema additions. Validate coding against human labels and report agreement.

**Why it matters:** Aviation-style incident response (an explicit open problem) depends on capturing near-misses; quantifying the current gap from a public open-source database is foundational governance infrastructure requiring no lab access.

**Relevant context:** OECD common reporting framework (29 criteria, near-miss scope); AIID open-source database; CSET 'AI Incidents: Key Components' Jan 2025; arXiv:2511.05914 incident reporting design.
