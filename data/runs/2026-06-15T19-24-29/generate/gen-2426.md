# MONA Without an Oracle: How Brittle Is Learned-Overseer Approval?

**Problem:** MONA (arXiv:2501.13011) prevents multi-step reward hacking via myopic optimization + non-myopic approval, but uses an oracle approval signal. The 2026 extension (arXiv:2603.29993) replaces the oracle with a learned overseer; how approval quality degrades MONA's protection is only beginning to be characterized.

**Direction:** In a small gridworld or 2-step LLM task from the MONA setup, replace the oracle approver with a deliberately noisy/biased approval function (prompted open model) and sweep its error rate. Measure the reward-hacking rate as a function of overseer quality to find the approval-accuracy threshold below which MONA stops protecting.

**Why it matters:** Real overseers are imperfect. Mapping how much overseer error MONA tolerates is a recursive-oversight result ('layers with systematic errors') and uses small open environments, no large training.

**Relevant context:** MONA: Myopic Optimization with Non-myopic Approval Can Mitigate Multi-step Reward Hacking (arXiv:2501.13011): myopic optimization + far-sighted approval prevents multi-step reward hacking even when hacking is undetectable. Extending MONA in Camera Dropbox (arXiv:2603.29993, Mar 2026): reproduces MONA with learned overseers instead of oracle approval.
