# Verify-Before-Commit: A Tiny Reproduction of Tool-Output Vetting

**Problem:** A success state is agents that validate tool outputs before acting on them. VIGIL proposes verify-before-commit; we lack a minimal, reusable reproduction showing the safety/utility tradeoff of inserting a verification step.

**Direction:** Backcast from 'agents never act on poisoned tool outputs'. Build a minimal verify-before-commit wrapper: before the agent consumes a tool output, a lightweight check (open-model classifier or rule set) flags injected instructions in that output. Measure attack-prevention vs. benign-utility cost on AgentDojo injection cases.

**Why it matters:** Tool-stream injection is a concrete, growing attack class; a small open prototype of the defense quantifies its real cost and gives the community reusable code — strategically valuable infra buildable outside a lab.

**Relevant context:** VIGIL (arXiv 2601.05755) defends agents against tool-stream injection via verify-before-commit. AgentArmor and AgentSpec (2025) enforce program analysis / runtime rules. 'Defeating Prompt Injections by Design' (arXiv 2503.18813) uses privileged+quarantined LLM separation. AgentDojo (arXiv 2406.13352) supplies injection test cases.
