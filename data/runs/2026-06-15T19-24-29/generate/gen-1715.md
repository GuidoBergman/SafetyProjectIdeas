# Output-Centric Features Masquerading as Input Concepts in Autointerp Labels

**Problem:** A documented autointerp failure is 'output-centric' features that are labeled as input-concept detectors but actually fire to promote a particular output token; analysts then wrongly believe the feature represents an input concept. Roughly 14% of failed explanations in one analysis were unidentified output-centric features.

**Direction:** Take a sample of SAE features with autointerp labels phrased as input-concept detectors. For each, distinguish input-driven from output-driven behavior: check whether ablating the feature mainly changes a specific output token's logit (output-centric) vs whether activation tracks an input property regardless of next token. Report the prevalence of mislabeled output-centric features and a quick test to flag them.

**Why it matters:** Confusing 'feature that pushes output token X' with 'feature that detects concept X' leads to wrong mental models of a model's internals, undermining safety monitors keyed to supposed concept detectors. A cheap diagnostic improves the reliability of feature labels on open SAEs.

**Relevant context:** Automated-interpretability analyses report output-centric features being misidentified (7 of 50 failures in one study) and recommend treating explanations as classifiers; EleutherAI autointerp blog frames precision/recall evaluation of feature explanations.
