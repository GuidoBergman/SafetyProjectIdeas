# The Capability-Floor Link: Do Capability Elicitation Tricks Transfer Across Tasks?

**Problem:** Underestimation chain: weak default elicitation -> low measured capability -> dangerous capability deemed absent -> permissive deployment. Better elicitation (few-shot, scaffolding, best-of-n) raises the measured floor. The under-studied link is whether an elicitation trick that lifts capability on one dangerous-proxy task transfers to others, or whether elicitation must be re-tuned per task.

**Direction:** On a small open model and 3-4 benign capability proxies, apply a fixed set of elicitation techniques and measure the lift each gives per task. Quantify cross-task transfer of elicitation gains and whether a single 'best' technique exists or whether per-task tuning is required for a sound capability ceiling.

**Why it matters:** If elicitation does not transfer, single-protocol capability evals systematically underestimate dangerous capabilities, breaking the measurement link. Directly relevant to capability-elicitation methodology; open models only.

**Relevant context:** METR task suites and DeepMind FSF emphasize capability elicitation as core methodology; the open-problems-in-evals list flags under-elicitation as a source of dangerous underestimation.
