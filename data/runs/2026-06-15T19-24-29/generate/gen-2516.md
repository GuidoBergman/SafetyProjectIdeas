# How Much Does Trusted-Monitor Capability Matter for Catch Rate?

**Problem:** Control protocols use a 'trusted' (weaker) monitor, but the relationship between monitor capability and sabotage catch-rate is usually reported at one or two model sizes. The shape of the capability-vs-catch-rate curve, and where diminishing returns set in, is unclear.

**Direction:** On a fixed set of sabotage transcripts (SHADE-Arena or ControlArena subset), run a ladder of open models from tiny to mid-size as the monitor and plot catch-rate / AUC vs model capability (e.g. measured by a standard benchmark score). Identify whether returns saturate and at what capability level a monitor becomes 'good enough'.

**Why it matters:** Tells deployers the cheapest monitor that still works — a practical, cost-relevant safety result. Inference-only across open models, fully reproducible outside a lab.

**Relevant context:** Ctrl-Z (arXiv:2504.10374) and CoT Red-Handed (arXiv:2505.23575) use weaker trusted monitors; SHADE-Arena (arXiv:2506.15740) reports monitor AUC. ControlArena provides task environments (context file Source Code Availability).
