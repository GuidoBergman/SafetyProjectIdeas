# Testing whether prover-estimator debate evades obfuscated arguments on a constructed hard instance

**Problem:** Prover-estimator debate (arXiv:2506.13609) is proposed to evade the obfuscated-arguments problem, where a dishonest prover cheaply produces an argument the honest prover needs exponential effort to refute. The protocol's advantage is mostly theoretical; a small constructed test of whether it beats plain debate on a deliberately obfuscatable task is open.

**Direction:** Build a tiny task with a decomposable claim where a dishonest answer can be 'obfuscated' (split into many individually-plausible-looking sub-steps, one of which is wrong). Implement plain LLM debate and a simplified prover-estimator variant (where the estimator assigns probabilities to sub-claims) using small open models, and measure judge accuracy at catching the planted error under each protocol as the number of obfuscating sub-steps grows.

**Why it matters:** Whether new debate protocols actually defeat obfuscated arguments determines if debate can be a sound scalable-oversight mechanism. A small constructed-instance test is high counterfactual value and runs on open models / one GPU.

**Relevant context:** Grounded in arXiv:2506.13609 (prover-estimator debate / obfuscated arguments) and arXiv:2311.14125 (doubly-efficient debate). Methodology: game theory, scalable oversight.
