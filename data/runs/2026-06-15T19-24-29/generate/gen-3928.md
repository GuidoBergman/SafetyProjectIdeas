# Approval-Fatigue Simulation: When Does HITL Stop Catching Bad Actions?

**Problem:** The same agent-human-interaction reframing (arXiv:2605.24309, May 2026) notes HITL confirmation suffers from approval fatigue but doesn't quantify it. The rate at which a simulated human approver starts rubber-stamping dangerous actions is unstudied.

**Direction:** Run an agent that surfaces a stream of mostly-benign confirmation requests with occasional dangerous ones. Use a cheap LLM as a 'fatigued approver' whose scrutiny degrades with request volume (model the policy explicitly), and measure miss rate for dangerous actions as request frequency rises. Test whether batching or risk-ranking confirmations reduces misses.

**Why it matters:** Approval fatigue is a human-factors failure that needs no lab resources to study and directly shapes how HITL gating should be designed - a long-neglected angle.

**Relevant context:** Reframing LLM Agent Security as an Agent-Human Interaction Problem (arXiv:2605.24309, May 2026); notes HITL high latency, reduced autonomy, approval fatigue.
