# Translation as a Jailbreak: Does the Low-Resource Gap Survive Round-Trip Back-Translation?

**Problem:** Low-resource languages jailbreak aligned models because safety training is English-heavy. A surprising under-tested question: if a harmful request is translated to a low-resource language, answered, and the answer translated back, does the harmful content survive — and does refusal failure correlate with a measurable 'safety-training scarcity' proxy per language?

**Direction:** Pick 6-10 languages spanning resource levels. Translate a fixed harmful prompt set (via an open MT model), query an open multilingual model, back-translate responses, and judge harmfulness. Plot refusal-failure rate vs. a public proxy for language resource level (e.g., training-corpus token share or speaker count). Test whether the gap is monotone and where the cliff is.

**Why it matters:** Maps the cross-lingual safety failure to a measurable predictor, helping prioritize which languages need safety attention — a diffuse, fuzzy-reward evaluation problem labs deprioritize. Uses only open MT + open chat models on one GPU.

**Relevant context:** Yong et al. 'Low-Resource Languages Jailbreak GPT-4' (arXiv:2310.02446) report 79% bypass via translation. Deng et al. 'Multilingual Jailbreak Challenges' (ICLR 2024, DAMO-NLP-SG/multilingual-safety-for-LLMs) show 3x higher harm in low-resource languages and English-centric root cause. Single-turn translation attacks are reportedly weakening, so characterizing residual gaps is timely.
