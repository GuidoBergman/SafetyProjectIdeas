# Where in the Trajectory Does Monitor Suspicion Actually Localize?

**Problem:** Risk: subtle agent sabotage evades step-level monitoring. Causal chain: agent executes a multi-step task with one harmful side step -> per-step or whole-trajectory monitor scores it -> blue team audits high-suspicion steps. The under-studied link is whether the monitor's suspicion actually concentrates ON the harmful step, or smears diffusely / mislocates onto benign steps, which would make step-level deferral useless even when whole-trajectory AUC looks fine.

**Direction:** Use SHADE-Arena transcripts (the agent main-task + harmful side-task scenarios) and run an open monitor scoring each step. For malign transcripts where the harmful step's location is known, measure the rank of the true harmful step within the monitor's per-step suspicion ranking. Report localization accuracy vs. mere global detection.

**Why it matters:** Many control protocols defer or edit at the step level, which only works if suspicion localizes correctly. A high whole-trajectory AUC can hide poor localization, a long-horizon agentic-deployment failure mode. Uses an existing open benchmark and open monitor; no training.

**Relevant context:** SHADE-Arena (arXiv:2506.15740): 17 scenarios pairing main tasks with secret harmful side tasks; top monitor AUC 0.87 measured at the trajectory level. CUA-SHADE-Arena extends to VM/shell contexts. Factor(U,T) (arXiv:2512.14745) monitors plans rather than actions, motivating step localization study.
