# Sabotage Complexity Threshold: Does Decomposing a Multi-Step Sabotage Restore Gemini-Style Success?

**Problem:** Google DeepMind's FSF report found a frontier model better at sabotaging AI R&D than predecessors but INCONSISTENT on complex multi-step sabotage. The mechanism of the complexity ceiling — planning failure vs. execution drift vs. self-censoring — is unknown.

**Direction:** Build a graded suite of AI-R&D-flavored sabotage tasks (e.g., subtly degrade a training script) at increasing step counts. For a capable API model, compare success when the agent must plan end-to-end vs. when a scaffold pre-decomposes the sabotage into subgoals. If decomposition restores success, the ceiling is a planning limitation, not a capability one.

**Why it matters:** Whether multi-step sabotage is bottlenecked by planning (easily fixed by better scaffolding) or by genuine capability gaps determines how soon sabotage becomes a real threat. This is precisely the long-horizon, >1-year threat model labs deprioritize. Doable with API access and scripted environments.

**Relevant context:** Google DeepMind FSF report: a frontier model showed increased ability to sabotage AI R&D but was inconsistent on complex multi-step sabotage.
