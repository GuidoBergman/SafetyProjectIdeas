# Does combining steering with prompting fight itself? Testing instruction-vs-vector conflict

**Problem:** When a steering vector pushes one way and the system prompt pushes another (or the same way), the interaction is unmodeled. A failure mode is that vector and prompt conflict, producing incoherent or unpredictable behavior rather than additive control.

**Direction:** On an open model, cross a safety steering vector (e.g., 'be honest') with prompts that are aligned, neutral, or opposed ('be evasive'). Measure resulting behavior to test whether vector and prompt add, cancel, or produce collapse. Identify which combination yields the worst unpredictability.

**Why it matters:** Real deployments use both prompts and steering. If they interact non-additively—especially if a prompt can override a safety vector—then steering cannot be relied on as a backstop. Mapping the interaction is a practical, reproducible safety result obtainable outside a lab.

**Relevant context:** Grounded in steering reliability/conflict findings (arXiv 2504.04635, 2505.22637) and context-sensitivity of steering. Inference-only on open model; simple factorial prompt x vector design.
