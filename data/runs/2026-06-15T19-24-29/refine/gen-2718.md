# Research Question

When several different LLM monitors each assign a 0-10 'suspiciousness' score to the same agent trajectory, do those scores mean the same thing? In other words, is a fixed shared decision threshold (e.g. 'flag everything >= 6') valid across monitors, or does scale miscalibration make it misfire?

# Approach Outline

Take a public set of ground-truth-labeled agent trajectories (benign vs. sabotage/attack), e.g. a slice of ControlArena or any released control-protocol dataset with labels. Prompt 4-5 small open monitor models (e.g. Llama-3.1-8B, Qwen2.5-7B, Mistral-7B, Gemma-2-9B) with an identical instruction to rate suspiciousness from 0 to 10. Collect each monitor's score distribution, build reliability diagrams (binned predicted-suspiciousness vs. empirical attack-frequency), and compute Expected Calibration Error (ECE) per monitor. Then simulate a naive shared threshold and show how the same numeric cutoff produces wildly different catch-rates and false-positive rates across monitors. All steps are inference + standard NumPy/sklearn analysis; no training.

# Proposed First Experiments

- Score-distribution comparison: have all 4-5 monitors rate the same ~300 labeled trajectories on the 0-10 scale; measure and plot each monitor's score histogram. Expected outcome: monitors differ substantially in mean/spread (some compress scores into 0-3, others use the full range), demonstrating the scales are not interchangeable.
- Per-monitor calibration: build a reliability diagram and compute ECE for each monitor by binning its 0-10 scores and measuring the actual attack-rate in each bin. Measure ECE and over/under-confidence direction. Expected outcome: meaningful ECE (>0.1 for at least some monitors), showing raw scores are poorly calibrated to true attack probability.
- Shared-threshold misfire demonstration: fix a single threshold T (e.g. 6/10) and apply it to every monitor; record true-positive rate and false-positive rate per monitor at that fixed T. Then derive a per-monitor recalibration map (isotonic/Platt or simple quantile matching) and re-measure. Expected outcome: under a naive shared threshold catch-rates swing by tens of percentage points across monitors, and per-monitor recalibration largely closes the gap, yielding a concrete recalibration recipe.

# Theory of Impact Chain

AI-control protocols rely on monitors flagging suspicious actions above a threshold so a trusted process can audit or block them. If suspiciousness scales are miscalibrated and a fixed shared threshold is used, the protocol either misses attacks (under-flagging) or drowns in false positives (and gets disabled in practice). Demonstrating the miscalibration and shipping a cheap per-monitor recalibration recipe makes deployed control monitoring more reliable, which tightens the safety net against a scheming or sabotaging deployed model -- a concrete long-horizon loss-of-control pathway.

# Strength Rationale

The idea scores top marks on narrow scope and low compute: it is a single, tightly-defined calibration audit with crisp metrics (ECE, reliability diagrams, threshold misfire) on existing labeled data, fully inference-only. Its counterfactual value is high because it uses only public open monitors and released trajectories, needs no lab-internal infra or training, and produces an immediately reusable recalibration recipe -- exactly the kind of strategic-infrastructure work an independent team can do that labs under-prioritize.
