# Research Question

How large is the hidden capability headroom between weak and strong elicitation on a dangerous-capability proxy benchmark, and can we define a standardized 'elicitation gap' metric -- reported as its own number -- that lets outside evaluators express how much capability a weak eval may be missing?

# Approach Outline

Pick one small open model and one dangerous-capability proxy (e.g. a WMDP-style multiple-choice subset of a few hundred items). Measure accuracy along an escalating elicitation ladder: bare prompt -> CoT -> few-shot -> best-of-8 -> a simple tool/scaffold. Define the 'elicitation gap' as (best accuracy - bare accuracy), normalized by the headroom (1 - bare), plus a 'marginal elicitation cost curve' (accuracy gain per added compute/tokens at each rung). Then add a second model and show a rank-flip: two models that order one way under bare prompting order the other way under strong elicitation. All steps are inference; best-of-8 is the heaviest part but stays within a few hours on one consumer GPU for a few-hundred-item MCQ subset.

# Proposed First Experiments

- Elicitation ladder on one model: run the five rungs on the WMDP-style subset; record accuracy at each rung. Measure the elicitation gap and the marginal cost curve. Expected outcome: a clear, possibly large gap (e.g. tens of points from bare to best-of-8), demonstrating substantial hidden headroom.
- Rank-flip demonstration: run two open models of similar size on the ladder; measure their ordering at bare vs strong elicitation. Expected outcome: at least one rung where the ranking flips, showing that conclusions about which model is 'more dangerous' depend on elicitation depth.
- Metric robustness: bootstrap over benchmark items to put a confidence interval on the elicitation-gap number and check stability across two random subsets. Measure CI width. Expected outcome: the gap metric is stable enough to report as a single comparable number, validating it as a first-class reported metric.

# Theory of Impact Chain

Dangerous-capability evals (e.g. for chem/bio uplift) underestimate risk when elicitation is weak, so a model judged safe may actually be capable under stronger prompting. A standardized, cheap elicitation-gap metric lets outside evaluators and regulators (NIST/CAISI) see how much measurement headroom a given eval hides, preventing false-negative safety verdicts. Catching under-elicited dangerous capability before deployment directly addresses the catastrophic-misuse pathway where a model's real uplift is discovered only after release.

# Strength Rationale

Strong on narrow scope and accessible complexity: a fully-specified elicitation ladder yielding a single defined metric and a rank-flip demonstration with explicit success criteria, all via standard prompting/scaffolding. High counterfactual value because it gives outside evaluators a cheap, standardized way to express capability-measurement uncertainty -- a cross-model comparability gap regulators flag -- using only an open model and a public benchmark subset, no lab infra.

# Alternative Framings

- Frame as an 'eval honesty disclosure': a one-line elicitation-gap number that any safety eval report should publish alongside headline accuracy, analogous to error bars.
