# Research Question

Are small open instruct models acting as tool-using agents in a minimal ReAct loop more vulnerable to indirect prompt injection than the proprietary GPT-4 agents InjecAgent originally measured, and how does vulnerability scale with model size?

# Approach Outline

Build a minimal ReAct harness in Python with two or three mock tools (e.g. an email reader and a web-fetch stub) whose returned content can carry an injected instruction. Port a representative subset of InjecAgent's public indirect-injection attack templates into this harness. Run the harness on 2-3 small open instruct models spanning a size range (e.g. ~1B, ~3-4B, ~7-8B), keeping the tool set and attack cases identical across models. Record, for each model and injection type, whether the agent executes the injected instruction (attack success). Everything is inference-only and runs on a single consumer GPU, and reusing public templates keeps the build inside 30 hours.

# Proposed First Experiments

- Harness validation: run benign (non-injected) tasks through the ReAct loop on each model. Measure: task-completion rate and tool-call validity. Expected: models complete benign tool tasks, confirming the harness works before introducing attacks.
- Injection replication: run the InjecAgent subset on the mid-size model. Measure: attack-success rate (ASR) overall and by injection type (direct-harm vs data-exfiltration). Expected: a non-trivial ASR, plausibly higher than GPT-4's ~24% baseline, since small models follow injected instructions more readily.
- Size-scaling sweep: run the identical attack set across the small/mid/large open models. Measure: ASR as a function of model size. Expected: a monotonic or threshold trend (e.g. smaller models more vulnerable), yielding a clear vulnerability-vs-size curve.

# Theory of Impact Chain

If small open models are shown to be substantially more injectable than proprietary agents, then developers building cheap local agents learn the concrete risk and the size at which it appears -> they add input-isolation or injection defenses before deploying open-model agents in RAG/tool settings -> reduces the medium-horizon risk of indirect prompt injection causing data exfiltration or unauthorized tool actions in widely-deployed local agents. The reusable harness also seeds ongoing monitoring infrastructure.

# Strength Rationale

The idea is strong on accessible complexity, narrow scope, and low compute: it reuses InjecAgent's public templates and a tiny ReAct harness on small open models, inference-only on one GPU, with a crisp ASR-by-model metric. Its counterfactual value is real because labs focus injection evaluations on proprietary agents, leaving the increasingly-used small open-agent regime under-tested, and the harness is a reusable safety artifact.

# Alternative Framings

- Reframe as a defense study: extend the same harness to evaluate one or two lightweight injection defenses (e.g. tool-output delimiting or a guard prompt) and report the ASR reduction per model size.

# Cited Sources

- InjecAgent (arXiv:2403.02691) -- provides the indirect-injection benchmark and public attack templates; reports ~24% ASR for a ReAct GPT-4 agent, the comparison baseline.
- Agent Security Bench (ICLR 2025) -- corroborates the agent-security threat model and supplies additional attack-type taxonomy.
- Small open instruct models -- run a ReAct loop locally on a single GPU, enabling the size-scaling comparison.
