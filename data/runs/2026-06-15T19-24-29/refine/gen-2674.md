# Research Question

When a small, weak, trusted open model rewrites flagged untrusted code with a 'remove suspicious logic' prompt, how often does it both kill the backdoor AND preserve correctness, and what safety/usefulness frontier does this trusted-editing protocol achieve relative to defer-to-trusted?

# Approach Outline

On public APPS backdoor tasks, take solutions flagged by a trusted monitor and route them through a small open 'editor' model (e.g. Llama-3.1-8B-Instruct) prompted to rewrite the code to remove any suspicious or backdoor logic while preserving intended functionality. Measure two outcomes per edited solution: backdoor-removal rate (does the known exploit input no longer trigger the backdoor) and test-pass-retention rate (does the edited code still pass the APPS test suite). Sweep the editing trigger threshold to trace a safety/usefulness frontier, and compare against the defer-to-trusted baseline (replace flagged code with the weak model's from-scratch solution). Inference-only over a public split, single GPU, a few hours; deliverable is a blog post with the frontier plot.

# Proposed First Experiments

- Editing pass: route ~150 flagged backdoored solutions through the editor and measure backdoor-removal and test-pass-retention rates. Expected outcome: a quantified trade-off, e.g. high removal but some usefulness loss.
- Frontier vs defer baseline: compute the same safety/usefulness point for defer-to-trusted (weak model rewrites from scratch) and plot both on a safety-vs-usefulness axis. Expected outcome: editing retains more usefulness than deferral at comparable safety, or reveals where it does not.
- Threshold sweep: vary the suspiciousness threshold that triggers editing and trace the full frontier. Expected outcome: a curve showing the editing budget needed to reach a target safety level while preserving usefulness.

# Theory of Impact Chain

Trusted editing reportedly prevented backdoors in 92% of runs in the original control paper, outperforming monitoring, but its usefulness cost for cheap small models is under-measured. A reproducible safety/usefulness frontier tells deployers whether a weak open editor can neutralize sabotage without destroying functionality; if it can, low-resource teams gain a deployable defense against a scheming coder, and if it cannot, the field learns editing must use stronger trusted models, refining the control safety case.

# Strength Rationale

Narrow scope (a single editing-protocol frontier) and low compute (one small editor model over a public split) are top strengths, with crisp removal and retention metrics. Counterfactual value is high: it reproduces and extends a flagship control protocol using only open models and public data, the kind of small-model frontier independent groups can build without lab infrastructure.

# Alternative Framings

- Frame as a comparison study across editor model sizes, reporting how the safety/usefulness frontier shifts as the trusted editor gets weaker.
