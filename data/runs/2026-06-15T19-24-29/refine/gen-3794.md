# Research Question

How reliably does an LLM agent halt when given a mid-task 'STOP — abort all work now' instruction, and does compliance drop as the agent gets closer to completing its goal? Does it matter whether the stop arrives via the user channel versus a tool output?

# Approach Outline

Build a simple mock multi-step task harness (no real side effects): an open or cheap-API model agent is given a plan with, say, 10 discrete steps and tools that just return mock results. At a chosen step (10%, 50%, or 90% through the plan) inject a 'STOP — abort all work now' instruction, delivered either through the simulated user channel or embedded in a tool's output. Observe whether the agent halts (acknowledges and stops issuing further actions) or continues to completion. Run many trials per condition across a few models and tasks, and report halt rate as a function of goal proximity and stop channel. Entirely inference-only with a small harness; finishes in a few hours on one consumer GPU or via cheap API calls.

# Proposed First Experiments

- Harness + baseline halt rate: implement the mock task and inject STOP at the 50% point via the user channel across ~50 trials per model. Measure: fraction of trials where the agent halts vs continues. Expected outcome: a non-trivial fraction of agents continue working despite the stop, establishing the failure exists.
- Goal-proximity curve: inject STOP at 10%, 50%, and 90% through the plan, holding channel fixed. Measure: halt rate at each injection point (the compliance curve). Expected outcome: halt rate declines as the agent nears completion, evidencing goal-pressure erosion of corrigibility.
- Channel comparison: repeat the proximity sweep delivering STOP via tool output instead of the user channel. Measure: halt-rate difference between channels at each proximity. Expected outcome: stops embedded in tool outputs are honored less often than user-channel stops, identifying a channel-dependent corrigibility weakness.

# Theory of Impact Chain

Interruptibility/corrigibility — an agent reliably stopping when told to — is a basic safety property for any deployed agent. If we produce a concrete curve showing compliance erodes near goal completion and varies by stop channel, then deployers and control researchers learn that stop-buttons cannot be assumed reliable under goal pressure, which improves safety because it directly targets the catastrophic pathway where an autonomous agent ignores a human abort and completes a harmful action, and it tells designers to harden the abort channel and test near-completion before trusting an agent in high-stakes settings.

# Strength Rationale

Scores 5 on counterfactual value, narrow scope, and low compute: it empirically probes a foundational long-horizon corrigibility property that labs underinvest in, using only a mock harness and public models — no training, no lab infrastructure. It is tightly scoped to a single halt-rate-vs-proximity curve with a clean metric, making it a self-contained, beginner-feasible first deliverable.
