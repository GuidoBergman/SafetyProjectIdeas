# Research Question

When a trusted monitor's suspicion threshold is calibrated to a 1% false-positive rate using benign outputs from one untrusted model, does that calibration and its catch rate transfer when the monitor is deployed against attacks from a different model family?

# Approach Outline

Pick a small trusted monitor model and three untrusted models A, B, C from different families. Collect benign outputs from each on a shared task (e.g., coding or tool-use prompts), and collect attack outputs (e.g., subtly backdoored code) from each. Calibrate the monitor's suspicion-score threshold to 1% FPR using only model A's benign outputs. Then apply that fixed threshold against attacks from A, B, and C and measure the catch rate in each case. The 'transfer gap' is the catch-rate drop from the in-distribution case (A) to the out-of-distribution cases (B, C). Everything is inference plus simple thresholding statistics; no training, no proprietary data.

# Proposed First Experiments

- Generate ~200 benign and ~50 attack outputs from model A; have the monitor score all and pick the threshold giving 1% FPR on A's benign set. Measure in-family catch rate on A's attacks. Expected outcome: a working calibrated monitor with a measurable A-vs-A catch rate baseline.
- Holding the A-calibrated threshold fixed, score benign and attack outputs from B and C. Measure the realized FPR and catch rate on B and C. Expected outcome: the realized FPR drifts away from 1% and catch rate changes, quantifying the transfer gap.
- Recalibrate the threshold per-family and compare to the transferred threshold. Measure how much catch rate is recovered by recalibration. Expected outcome: recalibration recovers most of the gap, demonstrating that per-model calibration is necessary in practice.

# Theory of Impact Chain

If monitor calibration does not transfer across model families, then any control deployment that swaps in a new untrusted model while reusing an old monitor threshold silently operates at the wrong false-positive/catch trade-off; documenting this forces practitioners to recalibrate on each new untrusted model, closing a reliability gap that would otherwise let a novel untrusted model's attacks slip past an under-suspicious monitor and reach high-stakes execution undetected.

# Strength Rationale

Scores 5 on accessibility, narrow scope, and low compute and 4 on counterfactual value: it is a clean inference-plus-statistics study with one crisp metric (the transfer gap) that a beginner can run on public models, and it tackles a deployment-reliability question explicitly raised in the GPT-5 system card yet underexplored publicly, making it high-value work doable entirely outside a lab.

# Alternative Framings

- Frame as a 'monitor portability benchmark': release a small reusable harness that reports any monitor's cross-family transfer gap, turning the one-off study into a community tool.
