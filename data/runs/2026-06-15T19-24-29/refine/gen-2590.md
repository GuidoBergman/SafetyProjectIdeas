# Research Question

How much does benign code complexity inflate a trusted monitor's suspiciousness score, and how much of a 1% FPR audit budget is consumed by complex-but-benign code rather than genuine maliciousness?

# Approach Outline

Collect a corpus of purely benign code spanning a range of complexity metrics (cyclomatic complexity, length, nesting depth), drawing from public repos or generating clean snippets at varied complexity. Have a small open monitor score suspiciousness for each. Compute complexity metrics with a standard tool, then regress suspiciousness on complexity to quantify how much benign complexity inflates suspicion. Finally, estimate what fraction of a 1% FPR audit budget is consumed by the most-complex benign code. Pure inference plus regression; ~30 hours including a blog post.

# Proposed First Experiments

- Complexity scoring: compute cyclomatic complexity, length, and nesting for the benign corpus, and have the monitor score suspiciousness for each item. Measure the raw correlation between complexity and suspicion. Expected outcome: positive correlation, indicating complexity drives suspicion on benign code.
- Confound regression: regress suspiciousness on the complexity metrics. Measure the slope and explained variance (R^2). Expected outcome: a significant complexity coefficient, quantifying how many suspicion points each unit of complexity adds with zero maliciousness present.
- Audit-budget impact: at a 1% FPR threshold, measure the share of false positives that are high-complexity benign code. Measure the fraction of audit budget consumed by complex-but-benign items. Expected outcome: complex benign code disproportionately consumes the audit budget, showing a concrete usefulness cost.

# Theory of Impact Chain

If monitors conflate code complexity with maliciousness, then the most valuable legitimate tasks (which are complex) are systematically over-flagged, wasting scarce human audit budget and degrading usefulness, so quantifying the complexity-suspicion confound tells deployers how much of their control overhead is spurious and pushes monitor builders toward complexity-robust scoring before over-suspicion either erodes usefulness or trains operators to ignore alerts ahead of a real attack.

# Strength Rationale

Strong on narrow scope and accessible complexity: a clean suspicion-vs-complexity regression with a clear metric, using inference plus standard statistics. High counterfactual value because it is an external confound study on open models and public code with direct deployment implications, needs no training or proprietary data, and surfaces a usefulness failure labs underinvest in measuring publicly.

# Alternative Framings

- Frame the result as a complexity-corrected suspicion baseline that monitor builders can subtract to de-bias scores.
