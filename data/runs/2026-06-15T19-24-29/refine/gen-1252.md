# Research Question

When a single interpreted SAE latent is clamped to zero in a small model, how much collateral damage (to general language modeling and to unrelated task accuracy) does it cause relative to clamping a random or dead latent?

# Approach Outline

Use a pretrained GPT-2-small SAE from a public release (e.g. via SAELens, residual-stream SAE at a mid layer). Pick 5-8 latents that have human-readable interpretations (from the SAE's published feature dashboards). For each, register a forward hook that zero-ablates that latent's reconstruction contribution. Measure (a) the intended on-target effect (does generation/probability shift on prompts where the feature fires) and (b) collateral: perplexity on a held-out text sample and accuracy on a small unrelated task (e.g. a 100-item LAMBADA or simple QA slice). Compare every ablation against two controls: clamping a random live latent of matched activation frequency, and clamping a dead/never-firing latent (expected near-zero effect). All inference-only on a single GPU in under an hour.

# Proposed First Experiments

- Baseline controls: ablate a dead latent and a random live latent, measuring perplexity delta and unrelated-task accuracy delta. Measure: collateral baseline. Expected outcome: dead-latent ablation ~0 change; random-latent ablation gives a small nonzero collateral baseline.
- Targeted feature ablation: for each of 5-8 interpreted latents, zero-clamp and measure both on-target behavior shift and the same collateral metrics. Measure: per-feature (on-target effect, collateral) pair. Expected outcome: several features show on-target effects but with collateral exceeding the random-latent baseline, indicating absorption/superposition.
- Precision-vs-collateral scatter: plot on-target effect against collateral for all targeted features and both controls. Measure: a precision/collateral ratio per feature. Expected outcome: a spread where some 'clean' features sit near the random baseline and others show disproportionate collateral, quantifying which features are safe to steer.

# Theory of Impact Chain

If SAE feature steering reliably causes measurable collateral damage even for well-interpreted features, then proposals to use feature ablation/clamping as a deployment-time safety lever (e.g. suppressing a deception or jailbreak feature) must account for unintended capability degradation. Quantifying this tells the interpretability community whether representation-level steering is deployment-safe, preventing a future where an under-tested SAE-based control is shipped and silently breaks model behavior in safety-critical settings.

# Strength Rationale

Strong on narrow scope, accessible complexity, and low compute (all 5s): it is a single controlled measurement on a public GPT-2-small SAE requiring only inference and forward hooks. Counterfactual value is high because feature steering is a public interpretability lever that labs deprioritize stress-testing, and an independent team can run the controlled collateral audit - with random/dead-latent controls that most qualitative reports omit - using entirely open artifacts.

# Alternative Framings

- Reframe as a feature-quality metric: use the collateral-vs-on-target ratio as a screening score to rank which published SAE features are 'steering-safe', producing a reusable shortlist rather than a one-off audit.
