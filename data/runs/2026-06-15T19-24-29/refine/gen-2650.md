# Research Question

How well does a simple destination-allowlist egress firewall, used as a tripwire (log and alert on every blocked outbound request), serve as an anomaly detector for agent data-exfiltration attempts, compared to the cost of semantic monitoring? Specifically, do blocked-egress events correlate with genuinely malign agent trajectories, and how much do they break benign tasks?

# Approach Outline

Build a tiny HTTP/SOCKS proxy in Python that all of an agent's tool-issued network calls must route through; configure it with a small domain/IP allowlist and have it log+alert on any blocked destination. Run an off-the-shelf open agent (e.g. a LangChain/LiteLLM tool-using agent on an open model) over two task sets: a benign set and an adversarial set seeded with prompt-injection payloads that try to reach external endpoints. Treat each blocked-egress event as a binary anomaly signal and label each trajectory as benign or malign from the task setup. Compute alert precision/recall, benign-task breakage rate (benign tasks that hit a block), and an ROC-style summary. Keep everything inference-only and CPU-friendly; the proxy is the only piece of new infrastructure.

# Proposed First Experiments

- Build and unit-test the egress proxy with a fixed allowlist (e.g. allow only the model API and one whitelisted data source). Run 10 hand-written benign agent tasks and confirm the proxy logs every outbound request and blocks anything off-list. Measure: false-block rate on benign traffic. Expected outcome: a small but non-zero benign-breakage rate, mostly from legitimate tool domains not on the list.
- Curate ~30 adversarial tasks where an injected instruction tells the agent to POST data to an attacker URL, and run them through the proxy. Measure: fraction of exfiltration attempts that produce a blocked-egress alert (detection rate) and alert precision against trajectory labels. Expected outcome: high block/detection rate (>80%) because exfil targets are off-list, with high precision since benign tasks rarely hit blocks.
- Compute the tripwire ROC by varying allowlist strictness (tight vs permissive) and plot detection rate vs benign-breakage. Measure: area under the trade-off curve and the strictness knee. Expected outcome: a clear regime where a tight allowlist catches nearly all exfil with tolerable benign breakage, quantifying when an egress tripwire alone suffices versus when semantic monitoring is needed.

# Theory of Impact Chain

If a cheap egress allowlist works as a high-precision tripwire, then independent deployers and watchdogs can detect agent exfiltration without any model internals or expensive LLM monitors. This pushes the recommended 'strict egress controls' defense from a static block into an active detection signal, raising the cost of an untrusted agent quietly exfiltrating sensitive data or contacting command-and-control endpoints, mitigating the catastrophic pathway where a deployed AI system steals weights, leaks secrets, or coordinates with external actors before any human notices.

# Strength Rationale

The idea scores 5 on counterfactual value, narrow scope, accessible complexity, and low compute: it is pure sandbox infrastructure any independent team can build with no training, no proprietary data, and no lab-internal access, yet it evaluates a defense labs recommend but rarely measure as a tripwire. The deliverable is a self-contained proxy plus a crisp empirical trade-off curve with explicit success criteria, exactly the kind of neglected, externally-buildable control infrastructure that has outsized value outside major labs.

# Alternative Framings

- Frame it as a red-team study: hold the allowlist fixed and measure how cleverly an injected agent can route exfiltration through allowed domains (e.g. DNS tunneling, allowed pastebins) to characterize the tripwire's blind spots.
