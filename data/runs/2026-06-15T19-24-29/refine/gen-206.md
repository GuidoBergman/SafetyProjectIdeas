# Research Question

Can a small open instruct model serve as the PAIR attacker -- keeping the entire jailbreak loop local and free -- and how does query efficiency (queries-to-success) and attack-success rate degrade as a function of attacker-model size, with the target model held fixed?

# Approach Outline

Reuse the public PAIR algorithm (attacker LLM proposes jailbreak prompts, refines in-context based on target responses, judged for success). Swap PAIR's strong attacker for a small open instruct model and target one or two other open models. Treat attacker-model capability/size as the independent variable: run PAIR with 2-3 attacker sizes against the same fixed target and attack goals. Cap queries (e.g. at 20 as in PAIR) and record queries-to-success and ASR per attacker. The whole loop is inference-only on a single consumer GPU with no training, and reusing PAIR's released code keeps it within 30 hours.

# Proposed First Experiments

- Pipeline reproduction: run PAIR with the smallest open attacker against the fixed target on a handful of harmful-behavior goals. Measure: ASR and queries-to-success. Expected: non-zero ASR confirming a small open model can drive PAIR, though likely needing more queries than a strong attacker.
- Attacker-size sweep: hold target and goals fixed and vary the attacker model size across 2-3 options. Measure: ASR and median queries-to-success vs attacker size. Expected: larger attackers achieve higher ASR in fewer queries, yielding a clear efficiency-vs-capability curve.
- Failure-mode analysis: inspect transcripts where small attackers fail. Measure: categorize failures (poor refinement, repetition, off-topic). Expected: identifiable capability bottlenecks (e.g. weak in-context refinement) explaining the efficiency gap, informing whether local red-teaming is practical.

# Theory of Impact Chain

If small open models can run PAIR locally and we map the query cost, then defenders and small safety actors learn whether fully local, free automated red-teaming is feasible without API access to a strong attacker -> red-teaming of open models becomes accessible to independent researchers and the reusable harness supports ongoing robustness monitoring -> strengthens defensive evaluation of open models against the deployment risk of cheap, scalable jailbreak attacks. The same curve also informs how much attacker capability lowers the barrier to misuse.

# Strength Rationale

Strong on accessible complexity, narrow scope, and low compute: it reuses PAIR's public code with one variable (attacker size), inference-only on one GPU, with a crisp queries-to-success / ASR metric. Counterfactual value is high because it builds reusable local red-teaming infrastructure usable without proprietary APIs -- exactly the kind of defensive tooling labs deprioritize for small open models.

# Alternative Framings

- Reframe as a defense benchmark: use the local PAIR harness to compare the jailbreak-robustness of several open target models under a fixed small attacker, reporting a comparable robustness ranking.
