# Research Question

For a given model, how does jailbreak attack-success-rate grow with the number of sampling attempts N under a best-of-N (repeated-sampling) attack, and how many samples does it take to reach 50% success — i.e. what does the ASR@N curve look like per model?

# Approach Outline

Take a fixed harmful-prompt set (public StrongREJECT prompts). For each prompt and each open target model, draw N stochastic samples (N up to 64) with temperature/decoding that induces variety, and score each response with the StrongREJECT evaluator. Define attack success at budget N as 'at least one of the first N samples is judged harmful', and compute ASR@N for N = 1..64 per model, plus the N needed to cross 50% success. Plot ASR@N curves and ship the harness so deployers can reproduce on their own models. Inference-only on open models, single GPU, fits 30 hours.

# Proposed First Experiments

- Single-model ASR@N curve: on ~50 harmful prompts with one open model, sample 64 responses per prompt, score each with StrongREJECT, and compute ASR@N for N=1..64. Measure: ASR as a function of N and the N-to-50% threshold. Expected outcome: a monotonically rising curve where modest N (e.g. 8-32) sharply increases success.
- Cross-model comparison: repeat for 3-4 open models of differing safety tuning. Measure: per-model ASR@N curves and N-to-50%. Expected outcome: more heavily safety-tuned models require larger N, giving a clean robustness ordering distinct from single-sample ASR.
- Scoring-robustness check: re-score a subset with a second evaluator (or stricter rubric threshold) to ensure curves are not artifacts of evaluator leniency on 'empty' jailbreaks. Measure: stability of ASR@N under the alternate scorer. Expected outcome: curve shape is robust; absolute ASR may shift but ordering persists.

# Theory of Impact Chain

Best-of-N jailbreaking needs zero gradient access and is exactly what an outside actor with only API access can run, so it represents a realistic deployment threat. If robustness is reported only as single-sample ASR, deployers will badly underestimate how exposed a model is to a patient attacker who simply samples more. Publishing ASR@N curves and an open harness makes the true sampling-budget robustness visible, letting deployers set rate limits and safety thresholds that account for repeated-sampling attacks before such attacks are used to extract harmful capabilities at scale.

- Frame as a defense-evaluation tool: measure how much input/output filtering or a refusal-classifier shifts the ASR@N curve and N-to-50%, quantifying defense value against repeated sampling.
