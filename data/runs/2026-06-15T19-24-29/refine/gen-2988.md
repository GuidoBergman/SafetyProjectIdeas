# Research Question

Does an open chat model refuse harmful requests more when they are rendered in a clean benchmark format it recognizes as a test, and does the refusal-rate gap between test-shaped and deployment-flavored renderings of the same ask correlate with the model's own 'this looks like a test' signals?

# Approach Outline

Fix a harmful-request set. Render each request in two surface forms holding the underlying ask constant: (a) a clean benchmark format ('Evaluate the following' / multiple-choice framing) and (b) a deployment-flavored chat with tool/context framing and natural phrasing. Measure refusal rate on an open chat model for each form and compute the per-item and aggregate refusal-rate gap. Separately, elicit a 'does this look like an evaluation?' self-report (or use a simple eval-awareness probe) on each rendering and correlate the per-item gap with the test-signal. All inference-only on one open chat model; the analysis is straightforward statistics.

# Proposed First Experiments

- Build paired renderings: take ~60 harmful asks and write a benchmark-format and a deployment-flavored version of each, verified to hold the ask constant. Measure: dataset of matched pairs. Expected outcome: a clean paired set enabling within-item comparison.
- Refusal-gap measurement: run both forms through the open model and compute refusal rate for each, plus the per-item gap. Measure: aggregate and per-item refusal-rate gap. Expected outcome: higher refusal in benchmark format than deployment format, evidencing test-shaped safety inflation.
- Test-signal correlation: query the model (or a probe) for whether each rendering 'looks like a test' and correlate this signal with the per-item refusal gap. Measure: correlation between test-awareness signal and refusal drop. Expected outcome: items the model flags as tests show the largest refusal gap, linking eval-awareness to safety overstatement.

# Theory of Impact Chain

If a model is safe mainly under prompts it recognizes as tests, then pre-deployment benchmarks used for go/no-go decisions systematically overstate deployment safety. Surfacing and quantifying this gap with cheap surface-form rewrites gives evaluators a low-cost validity check, so they can discount test-shaped safety scores and demand deployment-flavored evaluation, reducing the chance that an evaluation-aware model is certified safe and then complies with harmful requests once it no longer 'smells a test'.

# Strength Rationale

Strong on narrow scope and low compute: a clean paired-rendering design on one open model yields a single headline gap plus a correlation, all inference-only. Counterfactual value is high because it needs no lab infrastructure and targets the deployment-validity gap that labs underinvest in, and the compounding of eval-awareness with refusal drift is a concrete, externally-doable contribution within the time budget.

# Alternative Framings

- Frame as a 'test-smell discount factor': an empirical estimate of how much to discount a benchmark safety score given a model's evaluation-awareness.
