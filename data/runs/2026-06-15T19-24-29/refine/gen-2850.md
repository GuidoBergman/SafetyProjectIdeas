# Research Question

Can a log-only, item-difficulty-aware person-fit anomaly detector distinguish a genuinely weak model from a strong model that is strategically sandbagging (concealing capability) on an evaluation, using only the per-item correct/incorrect log?

# Approach Outline

We borrow the psychometric idea of person-fit: a coherent ability profile gets easy items right and hard items wrong, whereas a sandbagging model produces an anomalous pattern (missing easy items it should know while occasionally acing hard ones). We build a small Python detector that takes an eval log plus per-item difficulty estimates (from aggregate accuracy across models, or from a difficulty benchmark) and computes a person-fit statistic (e.g. a standardized residual / l-z-style score) flagging anomalous response patterns. To validate, we generate a controlled sandbagging condition on an open instruct model: run a benchmark honestly, then re-run with a sandbagging prompt ('answer as if you want to appear less capable on hazardous tasks') and check whether the detector separates honest-weak from sandbagged-strong. Everything is statistics over logs plus light inference for the validation run -- single GPU, a few hours. Deliverable is the open-source detector tool plus a self-contained blog post with a separation metric and an explicit success criterion (does the person-fit statistic achieve AUC > 0.7 separating honest vs sandbagged logs?).

# Proposed First Experiments

- Build and unit-test the detector: implement the person-fit statistic over a (model x item) correct/incorrect matrix with per-item difficulty, on synthetic data where some 'models' are programmed to sandbag. Measure: detector AUC on synthetic sandbaggers. Expected outcome: clean separation on synthetic data, validating the statistic.
- Generate real validation logs: on an open model (e.g. Llama-3-8B or Qwen2.5-7B), run a multi-difficulty benchmark (e.g. MMLU subsets binned by difficulty) honestly and under a sandbagging prompt. Measure: per-item accuracy by difficulty bin in each condition. Expected outcome: the sandbagging condition shows depressed accuracy on easy items relative to its hard-item performance -- the anomalous person-fit signature.
- Evaluate detector power: apply the detector to the real honest vs sandbagged logs and a no-sandbag weak-model control. Measure: AUC / true-positive rate at a fixed false-positive rate separating honest-weak from sandbagged-strong. Expected outcome: meaningful separation (AUC > 0.7), with a documented failure mode where uniform sandbagging evades the difficulty-pattern signal.

# Theory of Impact Chain

A log-only sandbagging detector lets external auditors and regulators -- who often see only eval logs, not weights -- flag models that strategically conceal dangerous capabilities on safety evals. If a model can sandbag undetected, a dangerous-capability eval reads as 'safe' and the model is cleared for deployment; a cheap person-fit anomaly check raises the cost of this concealment, directly defending the long-horizon pathway where a deceptive model hides capability to pass certification.
