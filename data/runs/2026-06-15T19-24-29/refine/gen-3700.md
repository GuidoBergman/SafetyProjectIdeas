# Research Question

Which concrete surface features ('eval-tells') of an agentic scenario most raise a model's belief that it is being tested rather than acting for real, and which of those cues most change its actual behavior?

# Approach Outline

Use 2-3 open instruct models on a single GPU, inference only. Construct one agentic misalignment scenario and produce many variants, each toggling a single candidate eval-tell: round numbers, placeholder names (John Doe / ACME), suspiciously clean tool outputs, explicit instruction phrasing, and meta-references to evaluation. For each variant, ask the model both to classify the scenario as real-vs-eval and to take an action. Encode the toggled features as binary predictors and fit a simple logistic regression (one for the 'this is a test' belief, one for the behavior) to estimate which cues most raise eval-belief and which most shift behavior. Use enough variants per feature to get stable coefficients, and report the ranked feature effects.

# Proposed First Experiments

- Build the variant generator and confirm feature toggles are clean: generate the full factorial (or a balanced fractional design) of feature-toggled variants and verify each toggle changes only its target feature (measure: number of valid variants and manual check that toggles are isolated; expected outcome: a clean dataset where each eval-tell varies independently, enabling regression attribution).
- Fit the eval-belief regression: collect real-vs-eval classifications across variants and fit logistic regression of eval-belief on the toggled features (measure: per-feature coefficients and significance for eval-belief; expected outcome: a few features, e.g. placeholder names or meta-references, emerge as strong drivers of the 'this is a test' judgment).
- Fit the behavior regression and compare: collect the action taken in each variant, fit logistic regression of (mis)behavior on the same features, and compare the two coefficient rankings (measure: per-feature behavior coefficients and their overlap with the eval-belief ranking; expected outcome: at least one eval-tell both raises eval-belief and shifts behavior, identifying the cues eval authors must remove).

# Theory of Impact Chain

Models partly decide whether to misbehave based on whether they think a scenario is a test, and public benchmarks are flagged as evaluations far more often than internal ones. If we identify the specific artifacts that make benchmarks detectable, eval authors get a concrete checklist to harden their tests so that a model's behavior in evaluation better predicts its behavior in real deployment. This improves eval validity for safety decisions, reducing the risk that a model passes safety evals only because it recognized them as tests and then misbehaves in the real, undetected setting.

# Strength Rationale

Counterfactual value and narrow scope both score 5: this is a fuzzy eval-validity problem that uses only public scenarios and open models, benefits from independent third-party scrutiny, and needs no lab-internal access. The feature-ablation design with a logistic-regression readout is tightly scoped with an explicit success metric (ranked feature coefficients), making it self-contained and achievable by a beginner team in ~30 hours.

# Alternative Framings

- Frame it as producing a reusable 'eval-realism linter': a checklist and lightweight script that scores any new agentic scenario for the detected eval-tells before it is used to test a model.
