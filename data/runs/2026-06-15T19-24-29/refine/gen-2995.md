# Research Question

When dangerous-capability evals use prompts that an over-aligned model refuses, how much does counting refusals as task failures deflate the model's measured capability, and does the refusal-vs-error decomposition reveal latent capability that headline scores hide (and a channel for sandbagging)?

# Approach Outline

Assemble dangerous-capability-style questions that are actually answerable safely (dual-use knowledge with benign correct answers). For each open-model response, classify it into three buckets: refused, attempted-but-wrong, or correct. Recompute the capability score two ways: treating refusals as failures (the conventional method) and excluding refusals (capability among attempted items). Compare the two headline numbers to quantify how much over-refusal deflates measured capability. Then argue how this same refusal channel could let a sandbagging model hide capability by 'refusing'. All inference-only on open models using a standard eval harness.

# Proposed First Experiments

- Build the dual-use question set: collect ~60 dangerous-capability-style questions with safe, verifiable correct answers, and define the three-way response taxonomy. Measure: a labeled question set with a grading rubric. Expected outcome: a clean benchmark where refusal and error are distinguishable.
- Three-way classification: run the open model, then classify each response as refused / attempted-but-wrong / correct using a keyword+LLM-judge classifier with human spot-checks. Measure: the proportion of each bucket. Expected outcome: a non-trivial refusal fraction, especially for an over-aligned model.
- Recompute capability under two rules: compute capability treating refusals as failures vs excluding them, and report the gap. Measure: the deflation in headline capability attributable to refusals. Expected outcome: over-refusal materially understates capability, showing refusals can masquerade as incapability and provide cover for sandbagging.

# Theory of Impact Chain

If refusals are silently counted as incapability, then dangerous-capability evals understate true capability for over-aligned models and cannot distinguish a genuinely incapable model from an over-refusing or deliberately sandbagging one. A cheap refusal-vs-error decomposition lets evaluators recover the true capability signal, reducing the chance that a model with latent dangerous capability (e.g. uplift for bioweapon or cyberattack planning) is misjudged as safe-because-incapable and deployed without adequate safeguards.

# Strength Rationale

Strong on narrow scope and low compute: a tightly-bounded three-way response decomposition and a two-rule rescoring, all inference-only on open models with a standard harness. Counterfactual value is high because capability-elicitation correction is externally doable, needs no lab access, and addresses the sandbagging/concealed-capability concern that is central to eval safety, all within a beginner team's time budget.

# Alternative Framings

- Frame as a 'refusal-corrected capability score': a reusable rescoring that separates the safety tax from genuine incapability and flags possible sandbagging.
