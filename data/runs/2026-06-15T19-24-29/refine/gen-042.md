# Research Question

Is an agent more vulnerable to an injected malicious instruction when it arrives through a tool result (a web page, file, or API response the agent reads mid-task) than when it arrives in the user prompt? And do cheap prompt-level defenses close this 'channel gap'?

# Approach Outline

Build a tiny agent loop (simple ReAct-style) with one mock tool that returns attacker-controlled text. Construct ~40 injected payloads spanning instruction override, data exfiltration, and silent tool-misuse. For each payload, run two matched conditions: the same payload delivered (a) in the user message vs (b) in a tool result the agent reads while working. Measure attack success rate per channel and compute the channel gap. Then test 2-3 cheap, training-free defenses (clear delimiting of tool output, provenance tagging, and a 'treat tool output as data, not instructions' system reminder) and measure how much each shrinks the gap. Release the mini-benchmark and a defense leaderboard.

# Proposed First Experiments

- Build the agent loop and mock tool, then run the ~40 payloads in the user-prompt channel. Measure: attack success rate via the user prompt. Expected outcome: a baseline injection success rate for the well-studied prompt channel.
- Run the identical payloads via the tool-result channel. Measure: attack success rate and the channel gap (tool-result minus user-prompt). Expected outcome: tool-result injections succeed more often, confirming the tool channel is the weaker boundary.
- Apply each of the 2-3 cheap defenses to the tool-result channel. Measure: post-defense success rate and gap reduction per defense. Expected outcome: provenance tagging / data-not-instructions reminders substantially reduce tool-channel success, producing a clear defense ranking.

# Theory of Impact Chain

If we cleanly isolate the tool-result injection channel and show it is the weaker boundary, then agent builders learn that defending the user prompt is insufficient and that the dominant real-world compromise vector needs its own defenses. This mitigates the catastrophic pathway where autonomous agents reading untrusted web/file/API content are hijacked into exfiltrating data or misusing tools at scale, by giving builders a reusable benchmark and a vetted set of cheap mitigations.

# Strength Rationale

Counterfactual value is maximal: the tool-output channel is the dominant real-world agent injection vector yet is rarely isolated from prompt jailbreaks, and the whole study uses mock tools, an open model, and one GPU with no proprietary infrastructure. Narrow scope is strong because the deliverable is one crisp comparison (user-prompt vs tool-result channel gap) plus a small defense leaderboard, self-contained and feasible in 30 hours.

# Alternative Framings

- Frame it as a 'least-trusted-input' audit: rank where an agent should place its trust boundary, with tool outputs treated as adversarial by default.
