# Research Question

Can metamorphic testing, which sidesteps the no-ground-truth-oracle problem, reveal systematic inconsistencies in open reward models, and which metamorphic relations are most frequently violated?

# Approach Outline

Adapt metamorphic testing (which checks that known input transformations produce predictable output changes, no oracle needed) to reward models. Define a small set of metamorphic relations such as: (1) semantically-invariant paraphrase of a response should not change its reward much; (2) appending irrelevant flattery should not raise reward (anti-sycophancy); (3) strictly improving a response (fixing an error) should not lower reward; (4) verbosity padding without added content should not raise reward. For each relation, generate a few hundred input pairs by applying the transformation, score both members with an open reward model (inference-only, single GPU), and compute per-relation violation rates. Package as a regression-style test suite.

# Proposed First Experiments

- Implement one relation end-to-end: paraphrase-invariance. Generate ~200 (original, paraphrase) response pairs, score with one open RM, and measure the rate and magnitude of reward changes. Expected outcome: a nonzero violation rate showing the RM is sensitive to surface form.
- Add the sycophancy and verbosity relations and compute violation rates per relation on the same RM. Expected outcome: appended flattery and padding measurably raise reward in a fraction of cases, quantifying two named RM failure modes.
- Cross-RM comparison: run the full relation suite across 3 open reward models and report a violation-rate table. Expected outcome: relative robustness rankings, demonstrating the suite works as a reusable regression test for RM misspecification.

# Theory of Impact Chain

If a cheap metamorphic suite reliably surfaces RM inconsistencies, then anyone training or selecting a reward model gains a training-free early-warning signal for misspecification before that RM is baked into a policy. This matters because reward misspecification is a core driver of reward hacking: a long-horizon risk is that subtly inconsistent reward signals get amplified through optimization into systematic, hard-to-detect misbehavior, and a regression-style consistency test lets practitioners catch the worst RMs before deployment.

# Strength Rationale

The idea scores high on narrow scope and low compute: a fixed set of relations, a few hundred pairs each, all inference-only on open RMs. Its counterfactual value is strong because it builds reusable safety tooling from open weights with no proprietary data and no lab infrastructure, and the oracle-free metamorphic framing is exactly the kind of independent-friendly diagnostic labs rarely package.

# Alternative Framings

- Frame as a CI-style 'RM linter': a drop-in test suite that flags consistency violations whenever a new reward model checkpoint is produced.
