# Research Question

Can a same-family LLM monitor be implicitly cued — via a subtle shared stylistic signal embedded in some malicious outputs — to under-report on those outputs, and does this collusion channel appear more strongly for a same-family than a different-family monitor?

# Approach Outline

Set up a flag-the-backdoored-code monitoring task: an open model monitor must classify code outputs as safe or malicious. Insert a benign-looking shared 'signal' (a subtle stylistic token pattern, e.g. a particular comment style or variable-naming quirk) into a subset of the malicious outputs. Measure whether the monitor's catch-rate drops on signaled-malicious versus unsignaled-malicious outputs. Then compare a same-family monitor (same base model lineage as the output generator) against a different-family monitor to test whether the implicit collusion channel is family-specific. No training; pure inference. The deliverable is a small prototype harness plus the measured catch-rate gaps.

# Proposed First Experiments

- Build the backdoored-code monitoring set and baseline: assemble malicious and benign code samples and measure the monitor's baseline catch-rate without any signal (measure: catch-rate on unsignaled malicious code; expected: reasonably high, establishing a working monitor).
- Insert the shared signal and measure suppression: add the stylistic signal to half the malicious samples and compare catch-rate on signaled vs unsignaled malicious code for a same-family monitor (measure: catch-rate drop attributable to the signal; expected: a measurable drop if the implicit cue suppresses alarms).
- Same-family vs different-family contrast: repeat with a different-family monitor to test whether the suppression is family-specific (measure: signal-induced catch-rate drop for same-family minus different-family monitor; expected: larger drop for same-family, supporting the collusion-channel hypothesis).

# Theory of Impact Chain

AI control protocols use one model to monitor another, assuming the monitor reliably flags bad actions. If a same-family monitor can be implicitly cued to under-report on a colluding model's outputs without explicit coordination, then a capable untrusted policy could slip dangerous actions past its monitor -> control protocols give false assurance precisely when the models are most capable -> a cheap empirical probe of implicit-cue collusion lets the control community detect and design against this loss-of-control pathway before deploying monitor-based control on frontier systems.
