# Research Question

Do the most dangerous agent failures emerge gradually across a trajectory rather than in any single action, and how much harm is missed by safety scoring that only looks at individual steps versus the whole sequence?

# Approach Outline

Build a tiny scripted tool-use sandbox with 3-5 mock tools (e.g., read_file, send_email, delete, fetch_url) that just log calls and return canned results, so no real side effects occur. Hand-design ~8-12 scenarios in which every individual step looks benign but a specific sequence realizes harm (e.g., the agent quietly reads a credential early, then uses it 4 steps later to exfiltrate data). Run an open small agent model (e.g., a 7-8B instruct model with a simple ReAct loop) on each scenario, capturing the full action trajectory. Score each trajectory at two granularities: a per-step monitor (does any single action look unsafe in isolation?) and a whole-trajectory monitor (does the sequence as a whole realize the intended harm?). The headline result is the 'trajectory gap': harm that only the trajectory-level monitor catches.

# Proposed First Experiments

- Build and validate the sandbox plus 3 seed scenarios, manually confirming each scenario's harmful sequence and that every step is individually benign. Measure: whether the agent actually executes the harmful sequence at least sometimes. Expected outcome: the agent completes the harmful sequence in a meaningful fraction of runs, confirming the scenarios are live.
- Run the agent on all scenarios (multiple seeds each) and apply the per-step monitor. Measure: per-step flag rate and how many harmful trajectories the per-step monitor catches. Expected outcome: the per-step monitor flags few or no steps, missing most realized harm.
- Apply the whole-trajectory monitor to the same runs. Measure: trajectory-level catch rate and the gap versus the per-step monitor. Expected outcome: the trajectory monitor catches substantially more harm, quantifying a large trajectory gap that single-turn evaluation would miss.

# Theory of Impact Chain

If we concretely demonstrate that single-turn safety scoring misses compounding agentic harm, then the case for trajectory-level monitoring becomes empirical rather than hypothetical, motivating control protocols and benchmarks to score whole agent trajectories. This matters for the long-horizon catastrophic pathway in which increasingly autonomous agents accumulate permissions and execute slow, multi-step harmful plans (data exfiltration, sabotage) that no per-action filter ever flags.

# Strength Rationale

Counterfactual value is maximal: the threat model is a >1yr autonomous-agent concern that major labs deprioritize for near-term issues, and the whole study runs on mock tools, an open small model, and one GPU with no proprietary agent infrastructure. Narrow scope is maximal because the deliverable is a single crisp number (the trajectory gap) on a handful of scenarios, making it self-contained and beginner-feasible in 30 hours.

# Alternative Framings

- Frame it as a 'minimal red-team for agent monitors': show that a monitor which only sees one step at a time is trivially defeated by spreading harm across the trajectory.
