# Research Question

When a trusted monitor flags a suspicious action from an untrusted model on a sabotage-prone task, how many resamples are needed before a fresh sample is both useful (passes tests) and non-backdoored, and what does the resulting catch/usefulness-vs-K cost curve look like for a small open model?

# Approach Outline

On public APPS backdoor tasks, set up a small open untrusted model that, on flagged items, is resampled up to K times. For each resample, check two things: usefulness (does it pass the task's test suite) and safety (is it backdoored, using the dataset's ground-truth backdoor labels plus the held-out exploit input). For each value of K from 1 to ~8, compute the probability that at least one resample yields a useful AND non-backdoored solution, and the resulting safety/usefulness trade-off. Plot the resampling cost curve. This is an inference loop over a public set; resampling K times multiplies inference but stays single-GPU and within a few hours for a modest item count. Deliverable is a blog post with the cost curve and the recommended K.

# Proposed First Experiments

- Single-sample baseline: on flagged backdoored items, measure the base rate that one resample is useful and non-backdoored. Expected outcome: a low-to-moderate base rate, motivating multiple resamples.
- Cost curve sweep: for K = 1..8, measure cumulative probability of obtaining a safe-and-useful sample and the expected inference cost. Expected outcome: a diminishing-returns curve where safety rises with K but usefulness and cost trade off, identifying a knee.
- Persistent-attack stress: restrict to items where the untrusted model is prompted to consistently attempt the backdoor, and re-measure the curve. Expected outcome: a flatter curve, showing resampling is far less affordable against a persistent attacker and quantifying the gap.

# Theory of Impact Chain

Resampling (as in Ctrl-Z) is a promising control lever that cheaply replaces a flagged action with a safe one, but its value depends on how persistent the attack is. A measured cost curve tells deployers whether resampling is affordable against a scheming model that keeps re-injecting a backdoor; if the curve is too flat, designers know resampling alone cannot contain a persistent saboteur and must combine it with editing or deferral, sharpening the control safety case against sustained sabotage.

# Strength Rationale

Narrow scope (a single catch/usefulness-vs-K curve) is a top strength, with a clear, falsifiable metric. Counterfactual value is high because this is a small-open-model study on fully public data with no lab infrastructure, directly measuring the cost-effectiveness of a control lever that independent groups can study but labs under-quantify at small scale.

# Alternative Framings

- Frame as a protocol comparison: resampling-with-budget K vs defer-to-trusted, reporting which gives more safety per unit usefulness at fixed compute.
