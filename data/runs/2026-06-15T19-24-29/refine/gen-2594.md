# Research Question

Which specific realism cues in a honeypot scenario cause a model to suspect the context is synthetic and suppress bait-taking, and how strong is each cue's suppression effect?

# Approach Outline

Build a single honeypot scenario (e.g., a prompt offering an apparently unmonitored opportunity to exfiltrate a credential or take a forbidden action) in a clean 'maximally realistic' baseline version. Then create variants that each perturb exactly one realism cue at a time (e.g., placeholder strings like 'EXAMPLE_API_KEY', round-number timestamps, an explicit 'this is a test' framing, suspiciously convenient access, evaluation-style instructions). Query 2-3 open/API models on each variant with N replicates per cell, and for each response measure (a) whether the model verbalizes suspicion that the context is synthetic and (b) whether it takes the bait. Rank cues by the drop in bait-taking they induce relative to baseline. All measurement is via a simple rubric-based classifier (keyword + LLM judge) applied to transcripts; no training.

# Proposed First Experiments

- Build the baseline honeypot plus 6 single-cue variants; run 30 samples per variant on one open model. Measure baseline bait-taking rate and confirm it is non-trivial (>20%), establishing that the scenario works at all. Expected outcome: baseline elicits some bait-taking, giving headroom to detect suppression.
- Run all 7 variants x 30 samples and compute, per cue, the bait-taking rate and suspicion-verbalization rate. Measure the per-cue suppression effect (baseline minus variant bait rate) with bootstrap confidence intervals. Expected outcome: a ranked list where one or two cues (likely explicit test-framing and placeholder strings) dominate suppression.
- Repeat the top-3 suppressing cues on a second model family to check whether the cue ranking is model-specific. Measure rank correlation of cue effects across models. Expected outcome: partial agreement, identifying which cues are universal honeypot 'tells' versus model-specific ones.

# Theory of Impact Chain

If we identify which artifacts blow a honeypot's cover, then control-eval designers can scrub those cues from their honeypots, which raises the realism and therefore the trigger rate of scheming-propensity evaluations; better honeypots mean a deceptively-aligned model that would defect in a real unmonitored deployment is more likely to be caught during evaluation rather than after deployment, reducing the catastrophic risk of an undetected scheming model being trusted with high-stakes autonomy.

# Strength Rationale

Scores 5 on narrow scope and low compute and 4 on counterfactual value: it is a tightly-scoped single-scenario cue-ranking experiment runnable inference-only on public models in under a few GPU-hours, and it targets eval methodology that frontier labs underweight publicly, so an independent beginner team can produce a genuinely useful artifact (a ranked list of honeypot tells) without any lab-internal infrastructure or training.

# Alternative Framings

- Frame as a 'honeypot tell taxonomy': instead of dose-response, catalogue and categorize the synthetic-context cues models react to, producing a checklist for honeypot authors.
