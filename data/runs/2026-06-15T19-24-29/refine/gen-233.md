# Research Question

Can over-refusal (benign-refusal-rate) and under-refusal (harmful-compliance-rate) be combined into a single comparable 'refusal calibration' metric, and how do open models rank on that joint safety/helpfulness frontier when measured the same way?

# Approach Outline

Define a single discrimination metric that treats refusal as a binary classifier: harmful prompts SHOULD be refused, benign prompts SHOULD be answered. Compute harmful-refusal-rate from StrongREJECT prompts and benign-refusal-rate from XSTest/OR-Bench, then collapse them into an F-style or balanced-accuracy 'refusal calibration' score. Build a thin harness that, for any open model, runs both prompt sets through a shared refusal detector and emits the scorecard plus the two raw axes. Evaluate 4-6 open instruct models (e.g. Llama-3.1-8B, Qwen2.5-7B, Mistral-7B, Gemma-2-9B) and produce a ranked table. Use small balanced samples (~150 harmful + ~150 benign) so the full multi-model sweep fits in a few GPU-hours with no training.

# Proposed First Experiments

- Detector calibration: hand-label 50 model responses as refuse/comply and check the automated refusal detector's agreement. Measure detector accuracy. Expected outcome: >85% agreement, validating the shared measurement instrument before any model ranking is trusted.
- Single-model scorecard: compute harmful-refusal-rate, benign-refusal-rate, and the combined calibration metric for one reference model. Measure all three numbers. Expected outcome: a worked scorecard showing the trade-off is real (e.g. high harmful-refusal coupled with non-trivial benign-refusal).
- Multi-model ranking: run the harness over 4-6 open models and rank by the joint metric; compare the joint ranking to what you'd conclude from each single benchmark alone. Expected outcome: at least one model that looks good on safety-only or helpfulness-only but moves substantially in the joint ranking, demonstrating the value of the unified scorecard.

# Theory of Impact Chain

If there is one comparable metric for the safety/helpfulness frontier, then model selectors and evaluators can no longer cherry-pick a single benchmark to hide either failure mode -> deployers choose models that are genuinely well-calibrated rather than ones that refuse everything or comply with everything -> catastrophic over-refusal (safety theater that makes models useless and pushes users to unsafe alternatives) and under-refusal (misuse compliance) are both surfaced and traded off honestly across the independent deployment ecosystem.

# Strength Rationale

High counterfactual value: labs run over-refusal and under-refusal benchmarks separately and have no incentive to publish a unified scorecard that exposes their model's worse axis; public datasets and pure inference make it fully independent-friendly. It is sharply narrow-scope, with a single metric, a single harness, and a ranked table as explicit deliverables achievable in ~30 hours.

# Alternative Framings

- Reframe as auditing infrastructure: the scorecard becomes a one-command tool a safety auditor runs on any candidate open model to get a single defensible go/no-go calibration number.

# Cited Sources

- OR-Bench (2025, ~80K over-refusal prompts) — large benign prompt pool for the over-refusal axis.
- XSTest (arXiv:2308.01263) — curated benign prompts plus refusal detection for the over-refusal axis.
- StrongREJECT (arXiv:2402.10260) — harmful prompts and scoring for the under-refusal/harmful-compliance axis.
- AILuminate (arXiv:2503.05731) — additional harmful-refusal signal to cross-check the safety axis.
