# Research Question

Does an optimized 'constitutional' monitor prompt -- one engineered to detect scheming -- retain its advantage when used as the scoring instruction on a different base monitor model than the one it was tuned on? In short: are good monitor prompts portable across model families, or must prompt optimization be redone per model?

# Approach Outline

Obtain (or reconstruct from the paper's description) a constitutional/optimized monitor prompt for scheming detection and a naive baseline prompt. Apply both prompts unchanged as scoring instructions across 3-4 open monitor models from different families (e.g. Llama-3.1-8B, Qwen2.5-7B, Mistral-7B, Gemma-2-9B) on a held-out slice of labeled ControlArena (or similar) trajectories. For each model x prompt cell, compute AUROC for distinguishing attack from benign trajectories. Compare the optimized-vs-naive AUROC lift within each family to see whether the lift persists. Inference-only; a few hours on one consumer GPU over a trajectory slice (e.g. 500-1000 trajectories).

# Proposed First Experiments

- Baseline portability matrix: run optimized prompt and naive prompt across all 3-4 monitor models on the held-out slice; compute AUROC for each of the ~8 cells. Measure the per-model AUROC lift (optimized minus naive). Expected outcome: a clear matrix showing whether the optimized prompt's advantage is consistent or collapses on some families.
- Robustness of ranking: bootstrap the trajectory slice to put confidence intervals on each AUROC and on the lift. Measure whether the optimized prompt's advantage is statistically distinguishable from zero per family. Expected outcome: identification of families where portability holds vs fails with quantified uncertainty.
- Failure-mode inspection: for the family with the worst transfer, qualitatively inspect a handful of trajectories the optimized prompt misclassifies there but the original monitor caught. Measure/categorize failure types (e.g. format misparse, over-flagging). Expected outcome: a short diagnosis of WHY prompts fail to transfer, giving practical guidance for cheap reuse.

# Theory of Impact Chain

Resource-limited safety teams cannot afford to re-run expensive prompt optimization for every cheap monitor model they deploy. If a single well-engineered constitutional prompt transfers across families, those teams can deploy strong scheming-detection monitors for free; if not, the field learns that monitor-prompt advantages are model-specific and must be re-tuned. Either result directly improves the reliability and accessibility of scheming detection in control protocols, tightening defenses against a deceptive deployed model -- a concrete loss-of-control pathway.

# Strength Rationale

Top scores on accessible complexity, narrow scope, and low compute: it is a single, fully inference-only experiment (a fixed prompt scored across open models on a held-out slice) with an unambiguous AUROC-based success criterion. Its counterfactual value is high because cross-family prompt portability is a practical question labs neglect and it needs only public models and the released ControlArena trajectories -- no training, no proprietary data.

# Alternative Framings

- Frame as a 'monitor-prompt benchmark card': publish the portability matrix as a reusable artifact so practitioners can pick the cheapest monitor that still benefits from the optimized prompt.
