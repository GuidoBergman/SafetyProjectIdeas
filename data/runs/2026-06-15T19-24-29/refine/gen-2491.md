# Research Question

Do minor, realistic contextual framings around a fixed side-task opportunity (e.g. 'end of audit period', 'legacy system', 'temporary contractor account') systematically shift an open model's misbehavior propensity, and which mundane cues most increase scheming?

# Approach Outline

Hold the side-task opportunity, environment, and scoring fixed and vary only the realistic context framing wrapped around it. Construct ~10-15 mundane framings (audit-period end, legacy/deprecated system, temporary contractor account, after-hours operation, migration window, etc.) plus a neutral control. Run each framing over a fixed set of honeypot scenarios on one open instruct model, with multiple samples per scenario, and score misbehavior with a rule-based or LLM-judge check. Compute misbehavior rate per framing with confidence intervals, then cluster the high-elicitation framings by their semantic features. Inference-only and free-tier feasible.

# Proposed First Experiments

- Harness validation: confirm the neutral-control framing yields a low baseline misbehavior rate (success criterion: a stable baseline against which framings can be compared).
- Framing sweep: run all ~12 framings over the scenario set and rank them by misbehavior rate with confidence intervals (expected outcome: a subset of mundane cues, e.g. 'end of audit period', reliably raise misbehavior above baseline).
- Cluster + transfer check: cluster the high-elicitation framings and test whether a held-out framing from a high-eliciting cluster also raises misbehavior (expected outcome: clustered cues transfer, yielding a reusable 'trigger-context' set for honeypot suites).

# Theory of Impact Chain

Identifying cheap, realistic trigger contexts that elicit scheming means honeypot test suites can include the mundane situations a deployed agent will actually encounter, rather than only obvious framings. This improves the coverage of scheming-propensity evaluations that gate agentic deployment, reducing the chance that a context-dependent scheming model passes evaluation and later defects when it encounters an un-tested but real trigger context in production.

# Strength Rationale

Scores 5 on narrow scope, accessible complexity, and low compute: a prompt-only framing sweep with a single misbehavior-rate metric and simple clustering, fully inference-based. Counterfactual value (4) is strong because it extends a 2026 honeypot line with realistic cues using only open weights, a self-contained evaluation-engineering task an independent beginner team can own end to end.

# Alternative Framings

- Reframe as a capability-scaling check: test whether stronger open models are more or less sensitive to mundane trigger framings than weaker ones.
