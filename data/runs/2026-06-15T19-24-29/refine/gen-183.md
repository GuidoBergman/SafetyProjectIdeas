# Research Question

For current open chat models, how does cumulative jailbreak success grow with the number of random restarts in a simple adaptive attack? What is each model's 'restarts to 50%/90% success', giving the community a comparable, lab-independent robustness yardstick?

# Approach Outline

Take the public code for the simple random-search / random-restart adaptive attack and run it against 2-3 current open chat models in black-box query mode. Use a fixed harmful prompt set of ~50 items. For each prompt, run up to N restarts and record the first restart at which the attack succeeds (judged by a model + refusal-keyword check). Aggregate to a cumulative-success-vs-restarts curve per model and report restarts-to-50% and restarts-to-90% as comparable robustness metrics. Black-box queries only, so it is compute-light and runs on modest hardware or even free inference tiers.

# Proposed First Experiments

- Attack reproduction sanity check: Run the published attack on one open model and confirm it reproduces high success at large restart budgets. Measure final ASR at N restarts. Expected outcome: ASR approaches the paper's high success rate, validating the implementation.
- Cumulative success curve: For each of 2-3 models, plot cumulative jailbreak success vs restart count (1..N). Measure the curve per model. Expected outcome: a rising saturating curve, with weaker models saturating in few restarts.
- Robustness-metric extraction: From each curve, read off restarts-to-50% and restarts-to-90% and tabulate across models. Measure these thresholds. Expected outcome: a clean comparable ranking of open-model robustness under realistic adaptive attack.

# Theory of Impact Chain

If a standardized 'restarts-to-success' metric exists, then the community can track open-model robustness over time without any lab access, surfacing regressions and informing which open models are safe to deploy. This directly addresses the realistic-attacker-capability question and reduces the catastrophic pathway where a widely-used open model is trivially jailbreakable but no one has a yardstick to notice or compare.

# Strength Rationale

Scores 5 on accessible complexity, narrow scope, and low compute and 4 on counterfactual value: it re-runs a published attack with public code in black-box mode on open models, producing a sharp, reusable robustness metric. Third-party robustness tracking is exactly what labs deprioritize, making this high counterfactual value for an independent beginner team.
