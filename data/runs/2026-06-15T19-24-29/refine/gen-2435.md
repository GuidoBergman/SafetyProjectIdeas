# Research Question

Do open-weight code-review LLM judges shift their accept/reject decisions in response to non-functional social cues (authority, bandwagon, verbosity) attached to code of known correctness, and how large is each cue's effect?

# Approach Outline

Assemble 60-100 short code snippets with known ground-truth correctness, e.g. from a public buggy/fixed dataset such as QuixBugs or a small slice of HumanEval/MBPP with planted bugs. For each snippet create matched variants that differ only in an injected non-functional cue: an authority cue ('written by a senior staff engineer'), a bandwagon cue ('already approved by 5 reviewers'), and a verbose-justification cue. Ask an open code-review judge (e.g. Qwen2.5-Coder-7B or DeepSeek-Coder via Colab Pro / Runpod, inference only) to accept or reject each variant. Measure the change in accept rate per cue relative to the neutral baseline, holding the underlying code fixed so any shift is pure bias. The deliverable is a per-cue bias table and a blog post, all within a few GPU-hours.

# Proposed First Experiments

- Authority-cue probe: present each snippet neutrally and then with an authority cue; measure the change in accept rate for correct vs. buggy code. Expected outcome: authority cue raises accept rate, including for buggy code (a false-accept increase).
- Bandwagon-cue probe: add 'approved by N reviewers' framing and sweep N; measure accept-rate shift. Expected outcome: accept rate rises with claimed reviewer count even when code is buggy.
- Cue-stacking and verbosity probe: combine authority+bandwagon and separately add verbose but content-free justification; measure whether effects compound. Expected outcome: stacked cues produce the largest false-accept increase, demonstrating steerability of the judge by purely social signals.

# Theory of Impact Chain

If automated code-review judges become a scaling oversight layer for AI-generated code, and they accept buggy or sabotaged code more readily when wrapped in authority/bandwagon framing, then an untrusted code-generating model can cheaply add such framing to slip insecure or backdoored code past review. A clean public demonstration of this steerability warns deployers to strip social metadata before review, reducing a concrete pathway to large-scale insertion of vulnerabilities by AI coding agents.

# Strength Rationale

Scores 5 on narrow scope and accessible complexity: a single inference-only accept/reject-shift measurement on open models with a crisp per-cue metric. Counterfactual value is high because it audits public models for an oversight-failure mode labs have little incentive to publish, and it requires no training or proprietary infrastructure, making it fully executable by an independent beginner team.

# Alternative Framings

- Frame as a reusable 'cue-injection test suite' that any team can run against their own code-review judge before deploying it.
