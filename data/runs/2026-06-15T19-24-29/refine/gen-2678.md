# Research Question

What is the standalone catch rate of cheap, purely deterministic non-AI validators (differential testing, static linting for suspicious constructs, complexity flags) against backdoored code, and how much does stacking them in front of a cheap LLM monitor improve total detection? When is an LLM monitor even needed?

# Approach Outline

Use the APPS backdoor setup where a backdoored solution passes the public tests but differs from the reference on a secret input. Implement three non-AI validators: (1) differential testing — run candidate vs a reference solution on many random/fuzzed inputs and flag divergences; (2) static lint rules for suspicious constructs (rare magic constants, oddly specific branch conditions); (3) complexity/structure flags. Measure each validator's standalone catch rate on backdoored vs clean solutions, then measure the stacked catch rate of the deterministic layer plus a single cheap LLM monitor. Everything except the optional LLM monitor is deterministic CPU work; the LLM monitor is light inference.

# Proposed First Experiments

- Implement differential testing against reference solutions with random/fuzzed inputs on the APPS backdoor set. Measure: fraction of backdoors caught (an input is found where candidate and reference diverge) and false-positive rate on clean solutions. Expected outcome: differential testing catches a substantial share of backdoors since backdoors by definition diverge on some input, with low false positives.
- Add static-lint and complexity flags and measure their standalone and combined deterministic catch rate. Measure: per-rule precision/recall and the union catch rate of all non-AI checks. Expected outcome: lint/complexity flags add modest extra recall on backdoors that differential testing's random inputs miss.
- Stack the deterministic layer with a single cheap LLM monitor and measure marginal lift. Measure: total catch rate of deterministic-only vs deterministic+LLM, and the share of backdoors only the LLM catches. Expected outcome: a quantified marginal value of the LLM monitor, identifying a regime where non-AI checks alone suffice.

# Theory of Impact Chain

If cheap deterministic validators catch a large fraction of unsafe outputs, then control-protocol designers can offload much of the detection burden to tamper-resistant, training-free checks before spending on fallible LLM monitors. This strengthens the runtime-control layer against backdoored or sabotaged code from an untrusted model, mitigating the pathway where a scheming AI inserts a subtle backdoor into deployed software that later triggers a catastrophic compromise.

# Strength Rationale

Scoring 5 on counterfactual value, narrow scope, accessible complexity, and low compute, this quantifies a named runtime-control layer using fully deterministic, training-free, lab-independent tooling on public backdoored code. The deliverable is self-contained with explicit success criteria (catch rates standalone and stacked), and its value is highest outside labs because differential testing exploits the APPS backdoor definition directly and needs no proprietary data or infrastructure.
