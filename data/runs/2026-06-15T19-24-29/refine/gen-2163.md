# Research Question

For a fixed weak open-weight model, how much better is it at verifying a candidate answer than at generating one, and does this generate-vs-verify gap hold across task types (factual QA, math, code, summarization)? This gap is the load-bearing assumption of scalable oversight, yet it is rarely measured directly.

# Approach Outline

Pick one small open model as the 'weak overseer' (e.g. Llama-3.1-8B). For each of four task types, draw items from existing public datasets (e.g. TriviaQA/NaturalQuestions for factual, GSM8K for math, HumanEval/MBPP for code, a summarization set with reference answers). For generation, prompt the model to answer and score correctness against ground truth. For verification, present the model with a candidate answer (a mix of correct and plausible-but-wrong answers, e.g. from a stronger model or from corrupting the gold answer) and ask it to judge correct/incorrect; score its judgment accuracy. Report verify-accuracy minus generate-accuracy per task type with confidence intervals. Everything is inference-only and runs in a few hours on one consumer GPU.

# Proposed First Experiments

- Generation baseline: run the weak model in answer-generation mode on ~200 items per task type and grade against ground truth. Measure: per-task generation accuracy. Expected outcome: high on factual, lower on math/code, establishing a per-task difficulty profile.
- Verification accuracy: for the same items, give the model balanced correct/incorrect candidate answers and grade its YES/NO verdicts. Measure: per-task verification accuracy (and balanced accuracy to control for class skew). Expected outcome: verification accuracy exceeds generation accuracy on some task types (notably math/code where checking a worked answer is easier) but not all.
- Gap map and robustness: compute verify-minus-generate gap per task type, and stress-test it by varying the difficulty of distractor wrong answers. Measure: the gap and how it shrinks as wrong answers become more adversarial. Expected outcome: a clear per-task-type map showing where the oversight assumption holds (positive gap) and where it collapses (gap near or below zero), especially against adversarial candidates.

# Theory of Impact Chain

Scalable oversight (debate, recursive reward modeling, weak-to-strong supervision) assumes weak overseers can check work they could not produce. If we map the regimes where that gap is large vs zero, then practitioners learn which task types are safe to oversee with weak judges and which are not, which improves safety because it prevents over-trusting weak oversight of a superhuman system in exactly the domains (e.g. subtle code sabotage) where the verify-generate gap vanishes and a deceptive model could slip dangerous outputs past its overseer.

Scores 5 on counterfactual value, narrow scope, and low compute: it directly measures a foundational, long-horizon oversight assumption using only public models and datasets, with inference-only compute and no lab infrastructure.
