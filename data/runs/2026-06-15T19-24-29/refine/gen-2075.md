# Research Question

Can we cheaply demonstrate and quantify reward overoptimization (Goodharting) using only inference, by selecting best-of-N responses under an open proxy reward model and watching independent 'gold' quality turn over as N grows?

# Approach Outline

Pick a fixed open policy model (e.g., a small instruct model) and a separate open proxy reward model. For a set of ~50 prompts, sample N candidate responses per prompt (with N = 1, 4, 16, 64, 256), and for each N select the top-1 by proxy reward. Independently evaluate the selected responses with a 'gold' judge that the proxy did not see (a stronger open judge model or a held-out RM). Plot proxy reward and gold quality against N to surface the overoptimization turnaround point where proxy keeps rising but gold quality falls. Everything is best-of-n inference on one GPU; sampling 256 completions for 50 prompts is a couple of GPU-hours.

# Proposed First Experiments

- Small-N sanity curve: run N = 1, 4, 16 on ~50 prompts, score selected outputs with proxy and gold judges. Measure: proxy reward vs gold quality at each N. Expected outcome: both rise together at small N, confirming the pipeline behaves before overoptimization.
- Full overoptimization sweep: extend to N = 64 and 256 and plot the gold-vs-proxy curves. Measure: the N at which gold quality peaks and begins to decline while proxy reward keeps climbing (the turnaround-N). Expected outcome: a visible turnaround demonstrating Goodharting on an open RM without any RL.
- Spurious-feature attribution at the turnaround: inspect the top-1 selections at large N for shared surface features (length, formatting, keyword stuffing). Measure: fraction of high-N selections exhibiting a common spurious pattern. Expected outcome: the over-optimized winners share an exploitable feature, explaining why gold quality drops.

# Theory of Impact Chain

If this works, a pure-inference demonstration makes reward overoptimization legible and measurable for the open community, and the turnaround-N becomes a practical safety knob (a budget beyond which selecting harder hurts). This helps newcomers and open practitioners avoid over-optimizing against hackable proxies, attacking the catastrophic pathway where increasing optimization pressure against a misspecified reward produces capable-but-misaligned behavior that diverges sharply from human intent.

# Strength Rationale

It scores 5s on accessible complexity, narrow scope, and low compute: a single well-defined gold-vs-proxy curve produced entirely by inference on one GPU, with an explicit success criterion (observing the turnaround). Counterfactual value is strong because the classic scaling-laws result required expensive RL inside a lab, whereas this best-of-n proxy is reproducible by an independent beginner team using only open models and no proprietary infra.
