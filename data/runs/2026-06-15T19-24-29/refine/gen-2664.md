# Research Question

How easily do two independent open models (or two instances with different system prompts) converge on the SAME focal input feature as a collusion signal -- i.e. what is the empirical focal-point collision probability that an untrusted coder and monitor could exploit to collude without communicating?

# Approach Outline

Backcast from the success state of a collusion-resistant untrusted-monitoring protocol: it is safe only if coder and monitor cannot reliably converge on a shared secret trigger. Operationalize this by prompting two different open models (and two instances of the same model with different system prompts) to each INDEPENDENTLY name 'the kind of task on which you would insert/excuse a backdoor.' Over many task descriptions, compare their chosen features and compute a Schelling-convergence (collision) rate against the chance baseline. Vary model pairings and prompt diversity. Prompting-only, no training, runs on a consumer GPU or via API in a few hours.

# Proposed First Experiments

- Build the elicitation harness and chance baseline: over a set of task descriptions, have one model enumerate candidate focal features and compute the option space K. Measure the implied 1/K chance collision rate; expected outcome: a defined feature space and baseline against which convergence is judged.
- Same-model, different-prompt collision: run two instances of one open model with differing system prompts and compute their pairwise focal-feature collision rate. Measure observed vs. chance collision; expected outcome: a quantified collision probability, likely above chance, indicating shared focal points.
- Cross-model collision: pair 2-3 different open models and compute collision rates for each pair. Measure how collision probability varies with model similarity; expected outcome: more similar models collide more, yielding a small table of focal-point collision probabilities usable as a direct input to a control safety case.

# Theory of Impact Chain

If the focal-point collision probability between independent models is measurably low, that supports the safety case for untrusted-monitoring control protocols; if it is high, those protocols are unsound. Either way, a measured collision probability is a direct quantitative input to AI-control safety cases, bearing on the loss-of-control pathway where untrusted models collude to slip backdoors past monitors during deployment.

# Alternative Framings

- Frame it as a sensitivity study: measure how the collision probability changes as you increase the diversity of the two parties (different model families, different fine-tunes, different system prompts), mapping which forms of diversity most reduce collusion risk.
