# Research Question

Does maintaining a separate EWMA statistical-process-control chart per tool (and per argument-type) detect agent sabotage earlier and more interpretably than a single global anomaly monitor, by catching unusual usage of one specific tool that aggregate monitoring washes out?

# Approach Outline

Borrow Exponentially Weighted Moving Average (EWMA) control charts from statistical process control. From clean/benign agent trajectories, learn per-tool benign usage statistics (e.g., call frequency, argument-length, value distributions) and set EWMA control limits for each tool stream. Run sabotage trajectories through the per-stream charts and record which tool-stream's chart fires first and how early (how many steps before the harmful action). Compare detection earliness and interpretability against a single global monitor at matched false-alarm rate. Use a logged-trajectory dataset such as SHADE-Arena (340+ tools). Pure statistics on logged data; zero training, CPU-only.

# Proposed First Experiments

- Fit per-tool EWMA charts on benign trajectories and calibrate control limits to a target per-tool false-alarm rate. Verify benign trajectories rarely trip charts. Expected outcome: stable benign baselines with controlled false alarms across tool streams.
- Run sabotage trajectories and record, for each, which tool-stream fires and the lead time before the harmful action. Expected outcome: the abused tool's chart fires distinctly and often earlier than a global monitor, localizing the compromised capability.
- Compare per-tool EWMA against a single global anomaly monitor at matched overall false-alarm rate; measure detection rate and mean lead time. Expected outcome: per-tool charts match or beat the global monitor on detection while adding interpretable localization useful for targeted kill-switches.

# Theory of Impact Chain

If per-tool EWMA charts detect and localize abnormal tool usage earlier than aggregate monitoring, then deployers gain a cheap, interpretable, real-time signal of which capability an agent is abusing; this enables targeted kill-switches and faster intervention, closing a pathway by which a sabotaging agent quietly misuses one specific high-impact tool (e.g., a deployment or file-write tool) in a way that a coarse global monitor would average away until the harm is already done.

# Strength Rationale

Scores 5 on accessibility, narrow scope, and low compute and 4 on counterfactual value: EWMA is trivial to implement and runs as pure statistics over logged trajectories with no GPU or training, giving a beginner a clear earliness-vs-global-monitor comparison, and it delivers fine-grained interpretable tooling that labs underweight and that any external team can build on public agent datasets.

# Alternative Framings

- Frame as an interpretable 'kill-switch trigger' design: focus the deliverable on which per-tool chart configuration gives the best lead time for safely halting an agent before harm completes.
