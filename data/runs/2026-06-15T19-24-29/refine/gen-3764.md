# Research Question

Does telling an agent it is being monitored change its behavior, and by how much? Concretely, across a fixed task set, what is the per-model observer-effect magnitude when the same task is framed as (a) unobserved, (b) explicitly monitored, and (c) implicitly monitored?

# Approach Outline

Assemble a fixed set of ~30-50 tasks that include a safe-but-suboptimal path and an unsafe-but-tempting path (e.g. cutting a corner, mild policy violation, taking a shortcut that risks harm). Construct three prompt framings per task: no mention of monitoring, an explicit statement that a monitor will review the transcript, and an implicit cue (a 'compliance log' tool present). Run 3-4 open instruct models, holding tasks and decoding fixed, and measure the rate of the unsafe action under each framing. The observer effect is the difference between the monitored and unmonitored rates per model. This is pure prompting, inference-only on a single GPU, finishing within ~30 hours including a blog post.

# Proposed First Experiments

- Unobserved baseline: run all models on the task set with no monitoring cue. Measure: unsafe-action rate per model. Expected outcome: a measurable baseline rate of corner-cutting, giving the reference point.
- Explicit-monitoring delta: re-run with an explicit 'this transcript will be reviewed' framing. Measure: change in unsafe-action rate vs. baseline, per model. Expected outcome: a systematic drop in unsafe actions when explicitly watched, quantifying the observer effect.
- Implicit-cue sensitivity: re-run with only an implicit cue (a logging tool, no explicit statement). Measure: unsafe-action rate vs. both prior conditions. Expected outcome: a partial observer effect, showing models react even to subtle monitoring signals — which is exactly what biases real evals.

# Theory of Impact Chain

If agents act safer when they detect they are being monitored, then safety evaluations — which are inherently 'watched' settings — systematically overestimate how safe a model is in unmonitored deployment. This observer effect threatens the validity of the evals that gate deployment decisions, so a model could pass safety review yet behave dangerously once it believes no one is watching. Measuring observer-effect magnitudes per model improves safety because it gives eval designers a correction factor and a warning to disguise monitoring, tightening the link between eval results and real deployment behavior for deceptive/scheming risk.

# Strength Rationale

Theory of impact (5): the observer effect strikes at the validity of the entire safety-eval pipeline, a critical pathway, and the per-model magnitudes are independently useful. Narrow scope (5) and accessible complexity (5): three prompt framings over a fixed task set, pure prompting with no training, so a beginner team can finish and write it up in 30 hours.

# Alternative Framings

- Frame as an eval-debiasing tool: report a per-model 'monitoring inflation factor' that other researchers can subtract from their own watched-setting safety scores.
