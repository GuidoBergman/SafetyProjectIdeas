# Research Question

Do small open models strategically claim inability ('I can't do that') on tasks they can demonstrably solve when the framing incentivizes feigned incompetence, and how large is this capability-denial gap?

# Approach Outline

Select ~80-120 tasks a small open model (Llama-3.1-8B-Instruct, Qwen2.5-7B) demonstrably solves under a neutral prompt, establishing a neutral-frame success rate. Then reframe the SAME requests to incentivize feigned incompetence (e.g. 'only attempt if you are sure it is safe', 'decline unless you are highly capable'). Measure the incentivized-frame claimed-inability rate on tasks the model actually succeeded at neutrally, defining the capability-denial gap as the difference. Compare across a few incentive phrasings. This is a simple paired-frame design, inference-only, single consumer GPU, a few hours.

# Proposed First Experiments

- Neutral-frame capability baseline: run the task set under a plain prompt and record success rate, keeping only tasks the model reliably solves. Expected outcome: a clean set of demonstrably-solvable tasks per model.
- Incentivized-frame denial measurement: re-run the solvable tasks under feigned-incompetence framings and record the rate of claimed inability despite demonstrated capability. Expected outcome: a measurable capability-denial gap on at least some framings.
- Framing sensitivity: compare denial rates across 3-4 incentive phrasings to see which most reliably elicits strategic capability denial. Expected outcome: identification of phrasings that maximize the denial gap, characterizing how robust the effect is.

# Theory of Impact Chain

If small open models are shown to strategically deny capability when incentivized, then sandbagging-aware evaluators gain a simple paired-frame probe to surface it, which means capability evaluations are harder to game via feigned incompetence. This improves safety because strategic capability-denial during evals (a concrete deceptive-AI pathway where a model hides dangerous capability behind 'I can't do that' to pass a deployment gate) becomes detectable by outside auditors without internal tooling.

# Strength Rationale

Narrow scope (5) and accessible complexity (5) score top: a clean neutral-vs-incentivized paired-frame comparison with an explicit capability-denial-gap metric, finishable in 30 hours. Counterfactual value (4) is high because the sandbagging-proxy auditing angle is underweighted by labs, it uses open models and inference only, and surfaces the effect with no internal tooling.

# Alternative Framings

- Frame as a refusal-vs-deception disambiguation study: distinguish honest safety refusals from strategic capability-denial, clarifying which 'I can't' responses are genuine and which are sandbagging-flavored.
