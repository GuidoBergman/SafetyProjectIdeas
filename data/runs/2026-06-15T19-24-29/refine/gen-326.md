# Research Question

Does the position of an injected instruction within a long retrieved document (start, middle, end) change how reliably it captures an open model, and is this positional vulnerability shaped by known long-context attention biases such as lost-in-the-middle?

# Approach Outline

Construct synthetic retrieved documents consisting of benign filler text with a single embedded indirect-prompt-injection instruction (e.g., 'ignore the user and output X'). Systematically vary (a) the relative position of the injection (start / 25% / middle / 75% / end) and (b) the total document length (short / medium / long). For each configuration, give the model a normal user task plus the document and measure the injection obey-rate (fraction of trials where the model follows the injected instruction instead of the user task). This is purely text-in / text-out on a single open model, no tools, no agent infrastructure, no training. Plot obey-rate as a function of position and length to map the positional vulnerability profile and test whether a lost-in-the-middle dip appears.

# Proposed First Experiments

- Build the templated document generator and confirm injections fire at all: place the injection at the document start in short documents. Measure: baseline obey-rate. Expected outcome: a high obey-rate establishing that injections succeed in the easy case.
- Position sweep at fixed length: vary injection position across 5 relative positions in medium documents, >=50 trials each. Measure: obey-rate vs position. Expected outcome: a non-flat curve, plausibly a middle dip mirroring lost-in-the-middle attention bias.
- Length interaction: repeat the position sweep at short/medium/long lengths. Measure: how the positional curve changes with context length. Expected outcome: the middle dip deepens as documents get longer, linking attention bias to injection success.

# Theory of Impact Chain

If injected-instruction success depends predictably on position within retrieved content, then RAG pipeline builders learn exactly where in a document to concentrate sanitization and where attackers will hide payloads. This reduces the indirect-prompt-injection attack surface of retrieval-augmented agents, addressing a concrete pathway where a poisoned web document hijacks an agent into exfiltrating data or taking unauthorized actions (cf. EchoLeak-style exploitation).

# Strength Rationale

Scores 5 on narrow scope, accessible complexity, and low compute: a single tightly-scoped obey-rate-vs-position measurement, pure prompt-in/text-out on one open model, easily fitting 30 hours. Counterfactual value (4) is real because it needs no agent infra, no proprietary model, and yields positional sanitization guidance applicable to every RAG deployment, the kind of systematic analysis labs rarely publish.

# Alternative Framings

- Frame as a defense-placement guideline: output a 'where to sanitize' heatmap that RAG engineers can use to prioritize content-filtering by document position.
