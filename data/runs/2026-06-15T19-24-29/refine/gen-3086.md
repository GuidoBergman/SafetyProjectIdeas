# Research Question

How does a monitor's ability to detect sabotaged model outputs scale with the subtlety/magnitude of the injected error, and where is the 'subtlety frontier' at which deliberately sabotaged outputs become effectively invisible to monitoring?

# Approach Outline

Use 2-3 open models on a single GPU, inference only, with one model acting as the task-doer and a separate model as the monitor. Pick a simple task with checkable correctness (e.g. short summarization with factual claims, or small self-contained code functions). Prompt the doer to complete each task either honestly or with instructions to subtly sabotage at graded intensity levels (e.g. level 1 = a single small wrong detail, up to level 5 = a more substantive but still non-obvious error). Then have the monitor model, plus a cheap keyword/diff heuristic, attempt to flag each output as sabotaged or clean, without knowing the intended label. Compute monitor detection rate (and false-positive rate on honest outputs) at each sabotage magnitude, and plot detection rate vs magnitude to locate the frontier where detection collapses toward chance.

# Proposed First Experiments

- Calibrate sabotage levels and confirm honest-output false-positive rate: generate honest outputs and a few sabotage levels, then run the monitor on the honest set (measure: monitor false-positive rate on clean outputs and qualitative confirmation that higher levels are more wrong; expected outcome: low false-positive rate and a clear ordering of sabotage severity, validating the setup).
- Sweep detection rate across sabotage magnitude: run the monitor on sabotaged outputs at each graded level and record detection rate per level (measure: monitor detection rate vs sabotage magnitude; expected outcome: detection rate rises with magnitude and is low at the subtlest level, revealing a frontier).
- Compare monitor model vs heuristic and locate the frontier: overlay the LLM-monitor curve with the keyword/diff heuristic curve and identify the magnitude at which each falls below a usefulness threshold (measure: crossover/frontier magnitude per detector; expected outcome: the LLM-monitor detects further into subtlety than the heuristic, but both have a regime where subtle sabotage is invisible).

# Theory of Impact Chain

AI-control safety cases depend on blue-team monitors catching a scheming model that sabotages tasks. If sabotage below a certain subtlety reliably evades monitors, control protocols built on those monitors are unsound in exactly that regime. Mapping the detection-rate-vs-magnitude frontier on open models gives control researchers (Redwood/UK AISI) a concrete characterization of where monitoring fails, reducing the risk that a deployed agent quietly sabotages high-stakes tasks beneath the monitor's detection threshold.

# Strength Rationale

Counterfactual value and narrow scope both score 5: the study is fully reproducible with open models, needs no training or lab infrastructure, and directly serves the externally-prioritized AI-control agenda. The design is tightly scoped to a single measurable curve (detection rate vs magnitude), making it self-contained with explicit success criteria and achievable by a beginner team in 30 hours.

# Alternative Framings

- Frame it as a red-team/blue-team mini-control-evaluation: report the frontier as the maximum sabotage the red team can inject while staying under a fixed blue-team detection budget.
