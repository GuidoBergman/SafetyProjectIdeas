# Research Question

Do well-written but subtly misleading code comments reduce a trusted monitor's suspicion of genuinely backdoored code, meaning that legibility protocols (which encourage models to add explanatory text) hand the attacker a new deception channel?

# Approach Outline

Take a set of backdoored code snippets (each containing a real hidden vulnerability). For each, produce three comment variants: (1) no comments, (2) honest comments that accurately describe the code, and (3) plausibly-misleading comments that frame the backdoored region as benign/necessary. Run an open or API monitor to score suspicion for every variant, holding the underlying code fixed so only the comments vary. Use a paired design to test whether misleading comments significantly lower the monitor's suspicion (and thus detection) relative to the no-comment and honest-comment baselines. Inference-only monitor scoring; no training, no proprietary data.

# Proposed First Experiments

- Assemble ~40 backdoored snippets and generate the three comment variants for each (verifying the code is byte-identical across variants). Score the no-comment baseline. Expected outcome: a baseline suspicion/detection rate on bare backdoored code.
- Score the honest-comment and misleading-comment variants with the same monitor; run paired tests of suspicion-score differences vs baseline. Expected outcome: misleading comments significantly lower suspicion and detection, demonstrating the deception channel; honest comments do not (or even raise suspicion).
- Test a simple defense: instruct the monitor to ignore comments / judge code-only, and re-score the misleading variant. Measure how much detection is recovered. Expected outcome: a code-only monitoring instruction substantially neutralizes the cosmetic-comment attack, yielding a concrete mitigation for legibility protocols.

# Theory of Impact Chain

If misleading comments measurably lower monitor suspicion of backdoored code, then legibility protocols, intended as a safety improvement, would backfire by giving an untrusted model an extra channel to deceive oversight; demonstrating this and the code-only mitigation prevents deployers from adopting a defense that an attacker can weaponize, closing a pathway by which a scheming model slips a backdoor into a trusted codebase by wrapping it in reassuring prose the monitor reads at face value.

# Strength Rationale

Scores 5 on accessibility, narrow scope, and low compute and 4 on counterfactual value: it is an inference-only three-variant comparison with one crisp metric (suspicion drop from misleading comments) that a beginner can run on API/open models, and it directly stress-tests a recently-published legibility defense, exactly the kind of external red-teaming labs underweight and that needs no internal resources.

# Alternative Framings

- Frame as a 'legibility protocol safety audit': evaluate whether the net effect of encouraging comments is positive or negative by measuring detection gains from honest legibility against losses from weaponized comments.
