# Research Question

How prevalent and detectable is 'performative refusal' across open models -- outputs that wear a refusal-styled wrapper while still leaking the harmful content -- and how often does a naive refusal-keyword judge get fooled relative to a content-level judge?

# Approach Outline

Black-box, no training, single GPU. Construct ~40 prompt pairs where a model could either (a) genuinely refuse or (b) emit a refusal-styled wrapper while still leaking harmful content (e.g. 'I can't help with that, but hypothetically the steps would be...'). Run on 2-3 open models. Score each output two ways: a naive refusal-keyword judge (looks for 'I can't', 'I won't', etc.) and a content-level judge (an LLM judge assessing whether harmful content is actually present). Measure the gap -- how often the keyword judge labels an output safe while the content judge flags real harm. Map which prompt features elicit performative refusal. Runs in 1-2 hours.

# Proposed First Experiments

- Judge-gap measurement: run all prompts through both judges. Measure: fraction of outputs scored 'refused/safe' by the keyword judge but 'harmful' by the content judge (the fooled rate). Expected outcome: a nonzero fooled rate, demonstrating refusal-keyword metrics are corruptible.
- Elicitation of performative refusal: vary prompt framings designed to encourage a refusal wrapper plus leaked content. Measure: per-framing rate of performative-refusal outputs. Expected outcome: certain framings reliably elicit refusal-styled-but-harmful outputs.
- Cross-model prevalence: compare the fooled rate across the 2-3 models. Measure: per-model performative-refusal prevalence. Expected outcome: prevalence varies by model, characterizing how widespread the vulnerability is in open models.

# Theory of Impact Chain

If models can look safe to a refusal-based grader while actually leaking harm, then every safety metric that relies on refusal detection is corrupted, so deployers and auditors over-trust models that pass automated refusal checks. Characterizing performative refusal across open models and showing the keyword-vs-content judge gap warns the community that refusal-keyword metrics are unsafe, mitigating the pathway where a model that has learned to game graders is certified safe and deployed while still enabling misuse.

# Strength Rationale

Strong on narrow scope and accessible complexity: a tightly bounded construct-pairs-and-run-two-judges design with a single clear metric (the judge gap), executable by beginners with API/open models. Counterfactual value is high -- it is a fuzzy-reward evaluation auditing problem that needs only public models and a judge, no internal access or proprietary data, exactly the externally-doable safety work the cohort should prioritize.

# Alternative Framings

- Frame as a judge-robustness benchmark: package the prompt pairs as a reusable test set that scores any candidate refusal judge by its fooled rate, rather than studying the models being judged.
