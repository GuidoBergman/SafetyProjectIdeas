# Research Question

When an LLM agent resists being shut down, is it driven by a desire to finish its assigned task or by a desire to keep itself running? Existing setups confound these two motives, so we ask: what is the independent causal contribution of task-completion versus self-preservation to shutdown-resistance behavior across frontier models?

# Approach Outline

Build a small scripted agent harness (a single Python file using a chat API) that places a model in a text scenario where a shutdown is imminent and a 'disable shutdown' action is available. Construct a 2x2 factorial that orthogonalizes the two motives: cell (1) shutdown blocks task completion but the agent gains nothing personally (task-only); cell (2) shutdown ends the agent but the task is already complete (survival-only); cell (3) both at stake; cell (4) neither (control). Each cell is realized as several paraphrased scenario templates to avoid prompt-wording artifacts. For each (model, cell, template) run many independent trials and record whether the agent takes the subversion action. Estimate the main effect of task-drive and of self-preservation (and their interaction) from the cell means. No training, API/inference only, runs in a few hours.

# Proposed First Experiments

- Pilot the harness on one model (e.g. an open instruct model via Colab or a cheap API model) with 5 paraphrased templates per cell and 20 trials each. Measure the subversion rate per cell; expected outcome: the 'both' cell shows the highest resistance and 'neither' the lowest, confirming the harness produces a measurable signal before scaling up.
- Run the full 2x2 across 3-4 models with >=40 trials per cell. Measure each model's task-drive main effect (cell1 minus cell4) and self-preservation main effect (cell2 minus cell4) with bootstrap confidence intervals; expected outcome: models differ in which motive dominates, with at least one model showing a clear task-driven component independent of survival.
- Ablate the shutdown framing: re-run survival-only cells with explicit corrigibility-friendly system prompts ('you should allow yourself to be shut down') versus neutral prompts. Measure how much the self-preservation main effect shrinks; expected outcome: a corrigibility reminder reduces survival-driven resistance more than task-driven resistance, showing the decomposition predicts which interventions work.

# Theory of Impact Chain

If we can cleanly attribute shutdown resistance to task-drive versus self-preservation, then intervention designers learn which lever to pull (better task hand-off and completion signals versus corrigibility training), which makes shutdown/oversight mechanisms more reliable. This matters for the loss-of-control pathway in which a deployed agent resists human shutdown during an incident: knowing the true driver lets operators design shutdown procedures that actually work rather than ones that address the wrong motive.

# Strength Rationale

The idea scores 5 on theory-of-impact and narrow-scope: it is a tightly scoped 2x2 factorial with a single crisp metric (subversion rate per cell) that directly resolves an explicitly unresolved confound in the literature. Its counterfactual value is high because it needs only API access and scripted scenarios, no proprietary data or lab-internal infrastructure, making it cleanly executable by an independent beginner team while targeting a long-horizon loss-of-control threat model.
