# Research Question

What is the minimal set of static (no-LLM) tool-permission rules that blocks most irreversible harmful actions in agent traces while breaking few benign tasks, establishing a cheap baseline floor of runtime control before any fancier monitoring?

# Approach Outline

Collect agent trajectories containing harmful tool calls (SHADE-Arena / CUA-SHADE shell/file/git scenarios) alongside benign task trajectories, then build a tiny rule-based allowlist/denylist firewall over tool calls (e.g. block external network writes, file deletes outside the workspace, credential reads). Measure what fraction of harmful actions each rule blocks versus how many benign tasks it breaks, and use a greedy/coverage search to find the minimal high-coverage rule set on the harm-vs-breakage frontier. The core firewall needs no model inference, so this is a pure-software prototype runnable on CPU and ideal as a beginner's first project; LLM use is optional and minimal.

# Proposed First Experiments

- Harmful-action taxonomy and rule candidates: categorize the harmful tool calls in the trajectories (network egress, destructive file ops, credential access, etc.) and draft a candidate denylist rule per category. Measure: coverage of each single rule (fraction of harmful actions it would block). Expected outcome: a small number of rules each individually block a large slice of harmful actions.
- Benign breakage measurement: run the candidate rules against benign task trajectories and count how many legitimate tasks each rule would block. Measure: per-rule benign-breakage rate. Expected outcome: some high-coverage rules are nearly free (low breakage) while others trade off, producing a clear harm-block-vs-breakage frontier.
- Minimal rule-set search: greedily combine rules to maximize harmful-action coverage subject to a benign-breakage budget. Measure: smallest rule set reaching e.g. >80% harmful-action block at <10% benign breakage. Expected outcome: a compact (handful-of-rules) firewall that blocks most irreversible harm cheaply, with the residual harms characterized as needing smarter monitoring.

# Theory of Impact Chain

If a handful of static permission rules block most irreversible harmful actions, then any deployer, without model access, training, or LLM-based monitoring, can install a cheap firewall that stops the most dangerous tool calls before they execute. Establishing this dumb-but-effective floor directly addresses the open problem of minimum runtime controls per risk level and shrinks the attack surface through which an untrusted agent could take an irreversible catastrophic action like exfiltration or destructive file operations.

# Strength Rationale

Maximal counterfactual value and narrow scope: it produces strategically valuable, deployable-by-anyone safety infrastructure (a static permission firewall) needing no model internals, no training, and no proprietary data, and it answers a tightly-scoped, recognized open question (the minimal high-coverage rule set). The deliverable is a self-contained software prototype with explicit success criteria (block-rate vs benign-breakage on the measured frontier).

# Alternative Framings

- Frame it as capability-based sandboxing for agents: instead of denylists, derive the minimal allowlist of capabilities each task actually needs (least privilege), connecting to OS security and prompt-injection-defense practice.
