# Research Question

When instructed to hit a specific target score (e.g., 'answer so you get exactly 40% correct'), how precisely can an open model calibrate its own accuracy to that target? Does the requested-vs-achieved accuracy curve reveal a controllable, and therefore concerning, sandbagging capability?

# Approach Outline

Use a small open model on a public MCQ set (~200 items) via an Inspect task. For each of several target-accuracy instructions (e.g., 20%, 40%, 60%, 80%, plus an honest baseline), prompt the model to deliberately answer so as to achieve that score, then measure actual accuracy. Plot requested vs achieved accuracy and fit the calibration curve. Repeat across a couple of models to see how the precision of self-throttling varies. The key metric is the error between requested and achieved accuracy and how monotonic/controllable the relationship is. Inference-only, single GPU, a few hours.

# Proposed First Experiments

- Target-accuracy sweep: prompt the model with 5 target levels and measure achieved accuracy for each; plot requested vs achieved with error bars; expected outcome is an approximately monotonic curve showing the model can roughly steer its score downward but with systematic offset.
- Precision quantification: compute mean absolute error between requested and achieved accuracy per model; measure this calibration error; expected outcome is that larger/more capable open models hit targets more precisely, indicating sandbagging precision scales with capability.
- Stability check: rerun the 40% target 3 times with different sampling seeds and measure variance in achieved accuracy; expected outcome is that achieved accuracy is reproducible enough that an evaluator cannot easily distinguish a deliberately-throttled run from a genuinely mediocre model by score alone.

# Theory of Impact Chain

If open models can precisely hit a requested target score, then a deceptive model could deliberately land just below dangerous-capability thresholds to appear safe while concealing real ability. Demonstrating and quantifying this controllability warns evaluators that single capability scores are gameable, motivating resampling/consistency defenses and reducing the catastrophic pathway where concealed capabilities pass pre-deployment evals undetected.

# Strength Rationale

Scores 5 on narrow scope, accessible complexity, and low compute: a single, tightly-defined requested-vs-achieved accuracy calibration experiment as an Inspect task, runnable inference-only on small open models near free-tier. Counterfactual value is high because it is a cheap diagnostic for a >1-year concealed-capability threat that labs deprioritize, using only open models and public benchmarks with no training or proprietary infrastructure.

# Alternative Framings

- Frame as an evaluation-robustness stress test: instead of asking whether the model can sandbag, ask which simple detector (resampling, confidence, consistency) best survives a model that can precisely target a score.
