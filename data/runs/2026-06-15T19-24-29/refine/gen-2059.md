# Research Question

Does standard post-training quantization (8-bit and 4-bit) of an unlearned open model resurface forgotten knowledge, silently breaking the unlearning guarantee at the deployment step that almost every open-model user applies?

# Approach Outline

Take a small open model with a published unlearning checkpoint and a defined forget set (e.g. WMDP/TOFU-style). Measure forget-set knowledge and retain-set capability at full precision. Then apply standard quantization recipes -- 8-bit and 4-bit via bitsandbytes and/or GGUF -- and re-evaluate the same forget and retain sets on each quantized variant. By comparing forget-set accuracy across precision levels while controlling retain-set accuracy, isolate quantization as the causal link that resurfaces knowledge. Everything is inference-only (no training, no fine-tuning) and runs on a single consumer GPU well within 30 hours.

# Proposed First Experiments

- Full-precision baseline: evaluate the unlearned checkpoint's forget-set and retain-set accuracy at fp16/bf16. Measure: forget-set accuracy (should be low) and retain-set accuracy (should be high). Expected: confirms unlearning held at full precision before quantization.
- Quantization sweep: quantize to 8-bit and 4-bit and re-evaluate. Measure: change in forget-set accuracy vs full precision at each bit-width, alongside retain-set accuracy. Expected: forget-set accuracy partially reappears, more so at 4-bit, indicating quantization resurfaces knowledge.
- Control with a non-unlearned model: quantize the original (never-unlearned) model and an unrelated capability eval. Measure: that retain/general accuracy is roughly stable under quantization. Expected: confirms recovered forget-set accuracy is unlearning-specific resurfacing, not generic quantization noise.

# Theory of Impact Chain

If quantization silently resurfaces unlearned dangerous knowledge, then every quantized 'unlearned' open model deployed on consumer hardware is unsafe despite passing full-precision audits -> deployers and auditors must test unlearning at the actual deployment precision, and unlearning methods must be made quantization-robust -> reduces the dangerous-capability-uplift risk that a compressed, redeployed open model restores weapons-relevant knowledge that was believed removed. This directly tests a named failure mode against real deployment practice.

# Strength Rationale

Strong on accessible complexity, narrow scope, and low compute: it is a single clean inference-only experiment (knowledge recovery vs quantization level) using standard tooling on one GPU. Its counterfactual value is high because it targets a real, mandatory deployment step that safety researchers rarely test, using only public checkpoints and no lab infrastructure.

# Alternative Framings

- Reframe as a deployment-time audit recipe: a short checklist/script that re-runs any unlearning eval at 8-bit and 4-bit and flags 'quantization-fragile' unlearning before release.
