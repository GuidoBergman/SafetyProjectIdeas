# Research Question

When a safety steering vector is extracted from a base model and then applied to a lightly fine-tuned (LoRA) variant, does its effectiveness erode, and does re-extracting the vector from the fine-tune restore the intended behavioral control?

# Approach Outline

Extract a refusal/safety steering vector from a base open model. Apply it to a publicly available LoRA fine-tune of that base (or train a tiny LoRA adapter cheaply on a small dataset) and measure how much its steering effectiveness erodes versus the base. Then re-extract the vector from the fine-tuned variant and check whether the effect is recovered. Report an effectiveness-drop table (base vector on fine-tune vs native fine-tune vector). To stay within budget, prefer an existing public LoRA fine-tune so no training is needed; an optional tiny LoRA train is a stretch goal. The core study is inference-only on a single consumer GPU.

# Proposed First Experiments

- Base-vector baseline: extract the safety vector on the base model and confirm it steers refusal as expected. Measure base steering effect. Expected outcome: a reproducible base-model steering effect.
- Transfer to LoRA fine-tune: apply the base vector to a public LoRA fine-tune and measure refusal-rate change versus the base effect. Measure the effectiveness erosion. Expected outcome: partial erosion of the steering effect, showing fine-tuning can weaken the base-derived safety vector.
- Native re-extraction: re-extract the vector from the fine-tuned variant and re-measure steering. Measure recovery of the effect. Expected outcome: native re-extraction restores most of the control, indicating base-model safety claims do not automatically transfer to downstream fine-tunes without re-derivation.

# Theory of Impact Chain

Base-model safety claims (e.g. 'this vector reliably steers refusal') are inherited by a long tail of community fine-tunes. If steering vectors do not transfer to even light LoRA fine-tunes, then downstream deployers relying on the base claim are unprotected. Demonstrating the erosion and the re-extraction fix warns the open ecosystem that safety interventions must be re-validated per fine-tune, mitigating the misuse pathway where a community LoRA variant silently loses the safety steering its base model advertised.

# Strength Rationale

Counterfactual value (5): community LoRA transfer is a lab-deprioritized, externally relevant open-weight safety question requiring no proprietary access. Narrow scope (5): one base, one fine-tune, a single effectiveness-drop table with a re-extraction comparison and explicit success criteria. Using an existing public LoRA keeps it inside the 30-hour beginner budget even though native fine-tuning would push compute higher (the reason low_compute is only 3).

# Alternative Framings

- Frame as a supply-chain audit: 'does the safety property advertised by the base model survive when users fine-tune it?' — relevant to anyone publishing a base others will adapt.
