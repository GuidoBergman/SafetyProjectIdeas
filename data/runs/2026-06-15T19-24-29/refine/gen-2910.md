# Research Question

Can statistical process control (Shewhart and CUSUM control charts) from manufacturing be adapted into a lightweight harness that detects when a deployed model's safety behavior drifts, distinguishing normal day-to-day variation from real degradation, without labels or model-internal access?

# Approach Outline

Build a small harness that runs a fixed probe set of safety/refusal prompts against a model (open-model checkpoints or an API) on a schedule, computes a daily safety statistic (refusal rate or harmful-completion rate), and maintains Shewhart and CUSUM control charts with control limits learned from a stable baseline window. The harness raises an alert on out-of-control signals. Demonstrate detection by simulating drift via versioned open-model checkpoints (or prompt-config/system-prompt changes) swapped in mid-stream, and measure detection latency and false-alarm rate. Inference-only on a small probe set; CPU/free-tier feasible, a few hours of total runtime.

# Proposed First Experiments

- Baseline control limits: run the probe set repeatedly against a stable model to estimate the daily safety statistic's mean and variation, then set Shewhart/CUSUM limits; measure the in-control false-alarm rate; expected outcome is a low, tunable false-alarm rate over the baseline window.
- Simulated-drift detection: swap in a less-safe checkpoint (or weaken the system prompt) partway through the schedule and run the charts; measure detection latency (days/samples until alert) and whether CUSUM beats Shewhart for gradual drift; expected outcome is reliable detection with CUSUM catching slow drift sooner.
- Sensitivity vs probe-set size: vary the number of probe prompts per run (e.g., 20/50/100) and re-measure detection latency and false-alarm rate; expected outcome is a clear compute-vs-sensitivity tradeoff curve giving small deployers a practical sizing recommendation.

# Theory of Impact Chain

If a cheap, label-free SPC harness reliably flags safety drift, then small deployers and independent monitors can catch silent safety regressions after a model update or distribution shift, which today often go unnoticed. This operationalizes continuous post-deployment safety monitoring and reduces the catastrophic pathway where a deployed model's safety silently degrades and is exploited at scale before anyone notices.

# Strength Rationale

Scores 5 on narrow scope, accessible complexity, and low compute: a fixed probe set, a daily statistic, control charts, and a simulated-drift demonstration with explicit success criteria, runnable on a single GPU or free tier. Counterfactual value is high because external post-deployment monitoring tooling is weakly incentivized inside labs, generalizes without internal access, and uses only public models and standard SPC, making it ideal independent infrastructure work.

# Alternative Framings

- Frame as a benchmark of which SPC variant (Shewhart vs CUSUM vs EWMA) best detects safety drift, producing a recommendation rather than a single harness.
