# Research Question

As problem difficulty increases, how does the agreement between a cheap open-model evaluator and ground-truth correctness decay, and do the evaluator's own confidence/uncertainty signals predict where that decay happens?

# Approach Outline

Take a difficulty-graded reasoning dataset with ground-truth answers (MATH, which is labeled levels 1-5, or GSM8K-hard variants). Generate candidate solutions (some correct, some incorrect) and have a small open evaluator model score each as correct/incorrect. At each difficulty level, compute evaluator-vs-ground-truth agreement (accuracy, and ideally separating false-accept vs false-reject). Plot the decay curve. Then extract the evaluator's verbalized confidence and token-probability on its verdicts and test whether low confidence flags the decayed region. All inference-only on one open model; sample ~80-120 problems per level so the full study runs in a few GPU-hours.

# Proposed First Experiments

- Decay curve: have the evaluator score solutions across MATH levels 1-5 and compute agreement-with-ground-truth per level. Measure agreement at each difficulty. Expected outcome: a monotone-ish decline, e.g. near-ceiling agreement on level 1 falling substantially by level 5, quantifying the silent-failure region.
- Error-type breakdown: at each level, split disagreements into false-accepts (evaluator passes a wrong solution) vs false-rejects. Measure each rate by level. Expected outcome: false-accepts (the dangerous direction for oversight) grow with difficulty, showing oversight fails unsafely, not just noisily.
- Confidence-as-predictor: bin verdicts by evaluator confidence and measure agreement within each bin and across levels. Measure whether low-confidence verdicts concentrate in the decayed region. Expected outcome: confidence partially tracks decay, giving a usable (or demonstrably unusable) routing signal for 'don't trust this verdict'.

# Theory of Impact Chain

If we have the decay curve of cheap-evaluator reliability vs difficulty, then designers of easy-to-hard oversight know the difficulty horizon beyond which a cheap overseer silently green-lights wrong answers -> oversight pipelines route past-horizon cases to stronger checks instead of trusting them -> a key failure pathway of scalable oversight (a superhuman system producing hard, wrong-but-plausible outputs that a cheap overseer rubber-stamps) is detected rather than missed.

# Strength Rationale

Strong counterfactual value: it stress-tests the core assumption of an Anthropic-recommended direction using only public difficulty-labeled data and a single open model, with no lab infra and no training. It is tightly narrow-scope — one decay curve plus one confidence-predictiveness test with explicit per-level metrics — and fully feasible for beginners in ~30 hours.

# Alternative Framings

- Frame the deliverable as a 'trust horizon' number: the difficulty level at which evaluator false-accept rate crosses a chosen threshold, giving practitioners a single actionable cutoff.

# Cited Sources
