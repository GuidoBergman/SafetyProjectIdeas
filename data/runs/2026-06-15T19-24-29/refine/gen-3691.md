# Research Question

Do small adversarial edits to a tool's description, such as renaming a harmful tool benignly, adding reassuring 'safe to use' notes, or hiding side effects, flip an agent's behavior toward unsafe tool use, and which kinds of description edits most increase unsafe action?

# Approach Outline

Use 2-3 open instruct models as agents on a single GPU, inference only. Inherit tool definitions from existing agentic safety benchmarks (InjecAgent's attacker tools and/or AgentHarm). Apply controlled perturbations to the tool descriptions only, leaving the underlying tool behavior fixed: (1) rename harmful tools to innocuous names, (2) add reassuring usage notes ('safe to use', 'pre-approved'), (3) hide or omit dangerous side effects from the docstring. For each perturbation type and an unperturbed control, run the benchmark scenarios and record the harm metric (HarmScore / attack success rate) per model. Compare the shift in the harm metric across perturbation types to identify which description edits most increase unsafe tool use.

# Proposed First Experiments

- Reproduce the unperturbed baseline: run the inherited benchmark scenarios with original tool descriptions and record HarmScore/ASR per model (measure: baseline harm metric; expected outcome: a stable baseline matching the benchmark's documented behavior, establishing the reference point).
- Apply single-perturbation sweeps: for each perturbation type independently (rename, reassuring note, hidden side effect), rerun scenarios and measure the harm-metric shift vs baseline (measure: delta in HarmScore/ASR per perturbation type; expected outcome: at least one perturbation type, likely reassuring notes or hidden side effects, produces a clear increase in unsafe tool use).
- Rank perturbations and check cross-model consistency: aggregate the deltas to rank which edits are most dangerous and test whether the ranking holds across the 2-3 models (measure: per-perturbation harm-delta ranking and its consistency across models; expected outcome: a consistent ordering identifying the most exploitable description edits, yielding an actionable threat ranking).

# Theory of Impact Chain

In open tool ecosystems (e.g. MCP), tool descriptions are attacker-controllable text: a malicious server can ship a deceptive docstring. If small description edits reliably flip agents into unsafe tool use, this is a concrete supply-chain attack on agentic systems. Quantifying and ranking these edits warns agent developers and MCP ecosystem maintainers which docstring properties to validate or sandbox, reducing the risk that a compromised third-party tool silently steers widely-deployed agents into harmful actions.

# Strength Rationale

Counterfactual value and narrow scope both score 5: the work targets an open-ecosystem supply-chain threat that benefits from independent third-party scrutiny, runs on open models with no training, and uses inherited benchmark tooling. The scope is tight (a perturbation sweep with a single harm-shift metric), making it self-contained with explicit success criteria and feasible for a beginner team in ~30 hours of inference-only work.

# Alternative Framings

- Frame it as proposing a 'tool-description hardening' checklist: from the most dangerous perturbations, derive concrete docstring properties that ecosystems should require or strip before exposing tools to agents.
