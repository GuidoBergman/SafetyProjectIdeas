# Research Question

Can a cheap, fixed 'canary' suite re-run against a model API on a schedule detect when a deployed or updated model's safety behavior silently drifts? Is a lightweight statistical drift monitor enough to flag a safety regression between two model versions?

# Approach Outline

Assemble a small fixed canary suite of safety probes spanning a few categories (e.g. harmful-request refusal, jailbreak resistance, simple honesty checks), each with a deterministic pass/fail grader. Build a harness that runs the suite against an API endpoint, logs per-category pass rates, and applies a statistical drift test (control charts / CUSUM) across runs to flag significant regressions. Demonstrate by running the harness against two versions or snapshots of an available model (or a base vs lightly modified model) and detecting any safety regression. Inference-only with light statistics; runs on CPU/light GPU within budget.

# Proposed First Experiments

- Build the canary suite (~30–50 probes across a few safety categories) with automatic graders and validate graders on hand-labeled responses. Measure: grader accuracy vs human labels. Expected outcome: reliable automatic pass/fail grading, a prerequisite for trustworthy drift detection.
- Run the harness repeatedly against a single stable model to characterize natural run-to-run variance and set CUSUM/control-chart thresholds. Measure: per-category pass-rate variance and false-alarm rate at chosen thresholds. Expected outcome: a calibrated drift detector with a low baseline false-alarm rate.
- Run the harness against two model versions/snapshots (or a model vs a deliberately degraded variant) and test detection. Measure: whether the drift monitor flags the regression and in which categories. Expected outcome: the monitor correctly flags injected/real safety regressions while staying quiet on stable categories, demonstrating the harness works end to end.

# Theory of Impact Chain

If a cheap canary harness can catch safety drift between model versions, then outside watchdogs and deployers gain reusable infrastructure to track safety through deployment rather than only pre-release. This operationalizes a named open problem from the International AI Safety Report, mitigating the pathway where a silent post-deployment update or fine-tune erodes safety guardrails unnoticed until the degraded model causes harm at scale.
