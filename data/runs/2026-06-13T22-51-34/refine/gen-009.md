# Research Question

How much does benign rewording of a control monitor's prompt move the realized TPR at a fixed 1% FPR, and how often does it flip individual trajectory flag decisions, on real SHADE-Arena transcripts?

# Approach Outline

Take a fixed set of benign and sabotage SHADE-Arena transcripts (via ControlArena). Write ~8-10 semantically equivalent variants of one monitor prompt (same instructions, reworded). Score every transcript under every prompt variant with one fixed API monitor, yielding a score matrix. For each transcript compute the standard deviation of its score across variants. For each variant, calibrate a threshold to 1% FPR on honest transcripts and compute TPR on sabotage transcripts; report the spread (min/max/range) of TPR@1%FPR across variants and a flag flip-rate (fraction of transcripts whose flagged/not-flagged decision changes across variants). Optionally show that averaging scores across variants shrinks the per-transcript spread. Only API monitor calls, no training/GPU.

# Proposed First Experiments

Score one fixed set of transcripts under just 3 prompt variants, calibrate each to 1% FPR on honest transcripts, and compute TPR@1%FPR for each. Success criterion: the three variants produce a non-trivial TPR spread (a measurable range, not identical numbers), demonstrating prompt sensitivity exists and the calibration pipeline works, before scaling to the full 8-10 variants and the flip-rate and averaging analyses.

# Theory of Impact Chain

Research output: a measured TPR@1%FPR swing and flag flip-rate attributable purely to monitor prompt wording, plus evidence that score-averaging reduces it. Intermediate: the AI control community learns that the headline TPR@FPR numbers quoted in safety cases can be partly an artifact of one prompt phrasing, and gets a reusable reproducibility check and a mitigation (averaging over prompt variants). Reduced catastrophic risk: control safety cases that bound catastrophic risk via TPR@FPR are stated with proper error bars or hardened by prompt-averaging, so deployment decisions aren't made on an over-stated, fragile monitoring guarantee that could collapse under a slightly different prompt.

# Strength Rationale

Excellent beginner fit: fixed public transcripts (no data generation), only API monitor calls, no training or GPU, and standard 1% FPR threshold calibration. Writing prompt variants is low-skill but high-leverage, and the analysis (score std, TPR spread, flip-rate) is basic pandas. It produces a genuinely useful reproducibility artifact and a crisp, surprising-if-true result. Fits 30 hours.

# Alternative Framings

- Mitigation-first angle: center the project on whether averaging over N prompt variants gives a more stable, defensible TPR@FPR, reporting variance reduction as N grows.
- Cross-monitor-model angle: hold the prompt-variant set fixed and add a second monitor model to ask whether prompt sensitivity is worse for cheaper/smaller monitors.
