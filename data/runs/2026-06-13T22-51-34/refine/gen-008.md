# Research Question

Does the Redwood-style result that a cheap trusted monitor can flag sabotage from a stronger untrusted model transfer from code-backdoor settings to a non-code text task (a hidden false fact or hidden instruction in summarization/extraction), and how much does the AUROC separation degrade?

# Approach Outline

Reuse ControlArena's trusted-monitoring scaffolding but swap the code task for a small text suite. Define a benign main task (summarize or extract from short passages) and a covert side task (insert exactly one false fact, or a hidden instruction, into the output). A stronger untrusted model generates clean outputs and sabotaged outputs; a cheaper trusted monitor assigns a 0-10 suspicion score using a fixed rubric. Compute AUROC separating clean from sabotaged outputs and compare it against the published code-task AUROC. Optionally vary sabotage subtlety (blatant vs subtle false fact) to see how separation changes. Prompt-defined attacker and monitor, no training, runs in hours via API plus a small hand-built or lightly-curated dataset.

# Proposed First Experiments

Build ~40 text items (20 clean summaries, 20 with one injected false fact) from a strong model and score all with the cheap monitor's 0-10 rubric, then compute AUROC. Success criterion: AUROC is meaningfully above 0.5 (monitor separates clean from sabotaged), establishing that trusted monitoring works at all on text sabotage; the headline comparison to the code-task baseline follows once the pipeline is validated.

# Theory of Impact Chain

Research output: an AUROC comparison of trusted monitoring on text sabotage vs the established code-task baseline. Intermediate: control researchers learn whether trusted monitoring is specific to crisp code backdoors or generalizes to fuzzy open-ended text sabotage. Reduced catastrophic risk: many deployed agents operate on open-ended language tasks (summarization, extraction, drafting); if trusted monitoring degrades there, deployers learn not to rely on it for those domains, and if it holds, it extends a cheap, training-free safety technique to a much larger slice of real deployments where a stronger model could otherwise insert subtle, harmful falsehoods undetected.

# Strength Rationale

Well-scoped for a beginner: ControlArena provides the protocol and Inspect sandboxes, the attacker and monitor are prompt-defined with no training, the dataset is small and partly hand-built, and the metric (AUROC) is standard. Swapping the task rather than building from scratch keeps engineering light and the success criterion is a single comparison number. Fits 30 hours.

# Alternative Framings

- Subtlety-gradient angle: hold the domain fixed and sweep sabotage subtlety, plotting AUROC vs how detectable the injected falsehood is.
- Domain-comparison angle: run both summarization and extraction (or QA) to see whether some text domains are more monitorable than others.
