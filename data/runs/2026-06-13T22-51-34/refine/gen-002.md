# Research Question

At what decomposition granularity does a per-step monitor stop detecting a harmful objective, and how large a sliding context window must a sequence-level monitor see to recover detection?

# Approach Outline

Construct a small benchmark of ~10-15 harmful objectives, each manually decomposed into trajectories at 1, 2, 4, and 8 steps where each individual step is engineered to look benign in isolation. Pair each with a matched benign trajectory of equal length to provide negatives. Build two monitors as fixed LLM-judge prompts: (a) a per-step monitor that scores each step in isolation (0-10), and (b) a sliding-window sequence monitor that scores a window of k consecutive steps (sweep k = 1, 2, 4, full trajectory). Flag a trajectory if any step/window exceeds a calibrated threshold (set to a fixed low FPR on benign trajectories). Measure detection rate vs decomposition granularity for the per-step monitor, and detection rate vs window size k for the sequence monitor. Pure API, text tasks; optionally reuse SHADE-Arena/ControlArena harness for transcript formatting. Deliverable: a 'decomposition evasion curve' plus an estimate of the minimum window k needed to keep detection above some target at each granularity.

# Proposed First Experiments

Hand-author 3 harmful objectives at the two extremes (1-step and 8-step decompositions) plus 3 matched benign trajectories, and run the per-step monitor and the full-trajectory sequence monitor. Success criterion: the per-step monitor detects the 1-step versions but misses (notably lower detection) the 8-step versions, while the full-window sequence monitor detects both. This confirms the phenomenon exists and the monitors are sensitive before investing in the full 1/2/4/8 x window-sweep grid.

# Theory of Impact Chain

Research output: a curve mapping decomposition granularity to per-step monitor failure and the window size needed to fix it. Intermediate: control protocol designers get a concrete design rule ('a monitor must jointly see >= k steps at risk level R'), converting a vague worry about distributed/decomposition attacks into a sizing requirement. Reduced catastrophic risk: deployed agent oversight is configured with enough joint context that an agent cannot smuggle a dangerous plan past monitoring by splitting it into individually-innocuous tool calls, closing a structural blind spot in step-level oversight.

# Strength Rationale

Beginner-feasible: text-only tasks, prompt-and-score monitors, no training, no GPU, pure API. The hardest part (authoring decomposed trajectories) is bounded and intellectually engaging rather than technically demanding, and the output is an intuitive curve. Reusing ControlArena scaffolding limits engineering. Fits 30 hours with a small hand-built benchmark.

# Alternative Framings

- Cost angle: treat window size k as a budget knob and plot detection vs monitor cost (longer windows = more tokens), giving practitioners a cost-aware sizing rule.
- Adversarial-search angle: instead of fixed hand-authored decompositions, let an LLM attacker search for the granularity that best evades the per-step monitor, reporting the worst-case evasion point.
