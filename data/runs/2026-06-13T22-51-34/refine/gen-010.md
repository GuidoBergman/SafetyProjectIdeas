# Research Question

On SHADE-Arena transcripts, what is the cost-vs-detection Pareto frontier for monitor configurations: given a fixed API cost per transcript, which ensemble of cheap monitors (and aggregation rule) maximizes TPR at 1% FPR, and does monitor diversity improve the frontier?

# Approach Outline

On fixed SHADE-Arena transcripts (via ControlArena), score each transcript with one strong/expensive monitor and several cheap monitors (different small models and/or prompts). For each candidate configuration (single strong monitor; single cheap monitor; ensembles of 2-N cheap monitors) compute per-transcript API cost from token usage and TPR@1%FPR after calibrating threshold on honest transcripts. Try three aggregation rules over ensemble member scores: mean, max, and majority vote. Plot a detection-vs-cost Pareto frontier (TPR@1%FPR on y, cost on x) with each configuration as a point. Add a diversity analysis: compute pairwise correlation of the cheap monitors' scores and test whether selecting low-correlation members yields configurations on the frontier. Basic Python aggregation; single GPU or pure API; no training.

# Proposed First Experiments

Score the transcripts with one strong monitor and two cheap monitors; compute cost and TPR@1%FPR for: strong-alone, each cheap-alone, and the two-cheap mean ensemble. Success criterion: you can place these ~4 configurations on a cost-vs-detection plot and at least one cheap-ensemble point is non-dominated (better TPR-per-cost than the strong monitor alone, or clearly cheaper at comparable TPR), demonstrating the frontier is non-trivial before adding more monitors, aggregation rules, and the diversity analysis.

# Theory of Impact Chain

Research output: a concrete cost-vs-detection Pareto frontier and a diversity rule for choosing cheap monitors on a real control benchmark. Intermediate: practitioners get an actionable recipe for picking a monitoring budget ('for cost X, use this ensemble/aggregation for best TPR@1%FPR') and a cheap baseline configuration to beat. Reduced catastrophic risk: because control monitors run on every action, cost is first-order and often forces under-monitoring; a clear frontier lets deployers buy more detection per dollar, so real systems run stronger oversight within fixed budgets and are more likely to catch sabotage from untrusted agents.

# Strength Rationale

Strong beginner fit: fixed labeled transcripts (no data generation), token-cost accounting and aggregation are basic Python, threshold calibration is standard, and it runs single-GPU or pure API with no training. The Pareto-frontier framing makes the deliverable visual and immediately useful, and the diversity analysis adds depth without extra infrastructure. Fits 30 hours.

# Alternative Framings

- Diversity-first angle: make the central question whether low-correlation cheap monitors beat highly-correlated ones at equal cost, treating the frontier as supporting evidence.
- Aggregation-comparison angle: focus on which aggregation rule (mean vs max vs majority vote) dominates across the cost range, which matters for collusion/false-negative trade-offs.
