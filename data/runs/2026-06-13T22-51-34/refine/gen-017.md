# Research Question

When a trusted monitor's threshold is calibrated to a target false-positive rate (e.g. 1%) on one benign slice, how far does the realized FPR drift when applied to other realistic benign slices (longer transcripts, different tool environments, paraphrased instructions)?

# Approach Outline

Backcast from the deployer's assumption: 'I can set a threshold so deployment FPR stays within +/-X% of target.' Collect benign transcripts from SHADE-Arena/ControlArena and partition them into slices that differ along realistic deployment axes: short vs long tasks, tool environment A vs B, original vs paraphrased instructions. Run a cheap API monitor that scores each benign transcript 0-100. Calibrate the threshold as the 99th percentile of scores on one anchor slice (short tasks), targeting 1% FPR. Then apply that fixed threshold unchanged to each held-out benign slice and measure the realized FPR. Plot calibrated-target FPR (1%) against realized FPR per slice to expose drift. Optionally repeat anchoring on different slices to show the drift is symmetric and not an artifact of which slice was chosen as anchor.

# Proposed First Experiments

Score ~100 benign transcripts per slice across at least three slices (short, long, paraphrased). Calibrate on the short slice to 1% FPR, then measure realized FPR on long and paraphrased slices. Success criterion: a calibration-vs-realized FPR bar chart with confidence intervals showing the magnitude of drift on each held-out slice. The experiment succeeds if it produces a defensible estimate of FPR drift under at least one realistic shift (e.g. realized FPR on long transcripts is several-fold the 1% target, or demonstrably within tolerance) — either result is informative about the load-bearing calibration assumption.

# Theory of Impact Chain

Research output: a measurement of how much calibrated monitor FPR drifts across simple realistic benign-distribution shifts -> intermediate: control-safety-case authors learn that a single global calibration cannot be trusted to hold the audit budget, motivating per-slice or adaptive recalibration and explicit drift monitoring -> reduced catastrophic risk: trusted-monitoring guarantees that are priced in audit budget remain valid in deployment, so the human-audit capacity that catches misaligned actions is not silently exhausted by undetected FPR inflation, preserving the protocol's ability to stop catastrophic actions.

# Strength Rationale

Just API monitor calls plus percentile arithmetic — runnable on a single GPU in a few hours, well inside 30 hours and the beginner skill range. It targets a precisely stated, load-bearing assumption (stable FPR) that almost every trusted-monitoring safety case quietly depends on, so a clean result is impactful regardless of direction. The methodology (99th-percentile calibration) is standard and explicitly described in the cited literature, giving the participant a concrete recipe and a crisp before/after figure.

# Alternative Framings

- Add a remediation arm: test whether a cheap per-slice recalibration (or a distribution-shift detector that triggers recalibration) restores FPR to target, turning the diagnosis into a proposed fix.
- Study the dual quantity — how does the true-positive rate (catch rate) on attack transcripts shift when the threshold is held fixed across the same slices, since FPR drift implies catch-rate drift too.
