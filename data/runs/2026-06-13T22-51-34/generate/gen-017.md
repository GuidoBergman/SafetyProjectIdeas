# Backcasting a Calibrated Monitor: Measuring the Real Cost of Pinning False-Positive Rate in Trusted Monitoring

**Problem:** Control safety cases assume a monitor runs at a fixed known FPR so human audits can be budgeted. But thresholds are calibrated on one benign set and applied to a different deployment distribution. If benign behavior shifts (new task types, longer transcripts, different scaffold), actual FPR may drift far from the calibrated 1%, silently breaking the audit budget.

**Direction:** Backcast from 'a deployer can set a threshold so deployment FPR is within +/-X% of target.' Use SHADE-Arena/ControlArena benign transcripts and a cheap API monitor scoring 0-100. Calibrate the 99th-percentile threshold on one slice (short tasks), then measure realized FPR on held-out benign slices (longer tasks, different tool env, paraphrased instructions). Plot calibration-vs-realized FPR drift.

**Why it matters:** Every trusted-monitoring guarantee is priced in audit budget, meaningful only if FPR is stable. Showing the calibrated FPR doesn't hold across simple realistic shifts undermines a load-bearing assumption and argues for per-slice recalibration.

**Relevant context:** Calibration to ~1% FPR via the 99th percentile of benign scores is standard across SHADE-Arena and the control literature. SHADE-Arena provides benign transcripts + scoring harness; ControlArena exposes benign runs. API monitor calls + percentile math; single GPU/few hours.
