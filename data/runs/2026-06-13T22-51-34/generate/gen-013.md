# Change-Point Detection as a Runtime Trip-Wire for Drifting Agent Behavior

**Problem:** Control evals are mostly discrete pre-deployment tests, but a compromised agent may behave normally then abruptly shift mid-trajectory. There is little lightweight runtime tooling to catch the moment an agent's action distribution changes versus scoring the whole transcript after the fact.

**Direction:** Import sequential change-point detection (CUSUM/Page-Hinkley) over cheap per-step scalar signals (action-type frequencies, tool-call entropy, output length, an LLM-judge suspicion score). Run ControlArena/SHADE-Arena trajectories where some contain an attack that turns on partway; measure detection delay and false-alarm rate vs a fixed-threshold baseline. Closed-form statistics, no training.

**Why it matters:** Real deployments are streaming; the safety question is often 'when did this agent go off the rails?'. Change-point detection is mature, interpretable, cheap, with formal delay/false-alarm trade-offs. A working trip-wire with measured latency is a useful runtime primitive.

**Relevant context:** Grounded in SPC/changepoint literature and LLM-augmented change-point work (arXiv:2601.02957); runtime framing aligns with SentinelAgent (arXiv:2505.24201). Uses ControlArena/SHADE-Arena; behavioral, streaming, intro-stats, single GPU + API.
