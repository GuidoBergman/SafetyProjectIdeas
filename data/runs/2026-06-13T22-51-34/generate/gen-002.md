# Sequence-Level vs Per-Step Monitoring of Decomposition Attacks

**Problem:** Control protocols mostly monitor individual steps, but a distributed failure can be engineered by decomposing a dangerous objective into individually benign-looking tool calls that each pass a per-step monitor while the aggregate is harmful. The threshold at which decomposition defeats monitoring lacks beginner-accessible characterization.

**Direction:** Build a small benchmark of harmful objectives at varying decomposition granularity (1/2/4/8 steps). Run a per-step monitor and a sliding-window sequence monitor over trajectories; measure detection rate vs granularity and window size k. Produce a 'decomposition evasion curve' and estimate the minimum context window a sequence monitor needs.

**Why it matters:** If per-step monitoring degrades past a few decomposition steps, deployments relying on step-level oversight have a structural blind spot. Quantifying the needed joint context turns a worry into a design rule (monitor must see >= k steps at risk level R).

**Relevant context:** Grounded in Monitoring Decomposition Attacks with Lightweight Sequential Monitors (arXiv:2506.10949), Context-Fractured Decomposition (arXiv:2606.09084), SHADE-Arena/ControlArena. Beginner-feasible: text-based tasks, prompt-and-score monitors, detection-rate curves, pure API.
