# Research Question

Mutation testing (introducing small bugs and checking if tests catch them) is a standard method for evaluating test suite quality. This project investigates whether take 20 programs with lean 4 proofs.

# Approach Outline

Take 20 programs with Lean 4 proofs. Generate program mutants (bit flips, off-by-one errors, operator changes). For each mutant, check whether the formal proof still compiles (it should not if the spec is complete). Measure mutant survival rate as a spec completeness metric.

# Proposed First Experiments

- Define the experimental setup: select datasets, models, and evaluation metrics appropriate for the research question.
- Implement and run the core experiment, collecting measurements on the defined metrics.
- Analyze results, compare with expected outcomes, and document findings in a well-structured blog post.

# Theory of Impact Chain

If formal proofs compile for mutated versions of the program (proof-surviving mutants), the specification does not capture the property that was changed. High mutant survival rates indicate dangerously incomplete specs.
