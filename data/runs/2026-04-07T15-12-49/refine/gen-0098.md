# Research Question

If AI vulnerability discovery can be blocked by specific code transformations (semantic-preserving refactoring, variable renaming with adversarial patterns), defenders could apply 'adversarial patches' to critical code to make it resistant to AI analysis without changing functionality. This project investigates whether take 10 vulnerable code samples.

# Approach Outline

Take 10 vulnerable code samples. Create adversarially patched versions using: (1) extreme variable/function renaming, (2) dead code injection, (3) control flow flattening, (4) opaque predicates. For each technique separately and in combination, measure whether AI models can still identify the vulnerability. Identify which combination of techniques most reliably prevents AI vulnerability discovery.

# Proposed First Experiments

- Define the experimental setup: select datasets, models, and evaluation metrics appropriate for the research question.
- Implement and run the core experiment, collecting measurements on the defined metrics.
- Analyze results, compare with expected outcomes, and document findings in a well-structured blog post.

# Theory of Impact Chain

If adversarial patches can reliably defeat AI vulnerability discovery, this is an immediately actionable defensive technique for protecting critical code sections. The dual-use concern is that adversarial patches could also be used by malware authors to evade AI-based malware analysis — which is itself a safety concern.
