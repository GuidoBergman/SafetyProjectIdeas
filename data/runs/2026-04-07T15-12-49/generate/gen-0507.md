# Security-Aware Proof Obligations: Do LLMs Generate Lean Specs That Capture Memory Safety?

**Problem:** Lean 4 proofs can verify functional correctness without addressing security properties like memory safety, integer overflow, or input validation. Whether LLMs spontaneously include security-relevant theorem obligations is unknown.

**Direction:** Provide LLMs with 50 C-equivalent algorithm descriptions and ask them to generate Lean 4 implementations with safety theorems. Classify whether generated theorems cover memory safety, bounds checking, overflow, and input validation. Compare to security-expert-written theorems.

**Why it matters:** If LLMs systematically omit security properties from their proof obligations, vericoding provides a false sense of security for security-critical applications.

**Relevant context:** AlphaVerus (CMU 2024) focuses on functional correctness translation from Dafny to Verus. Security property coverage in generated proofs is not evaluated by any current benchmark.
