# Follow-up to Sharp ICS Performance Drop: Do Models Have Correct Conceptual Models of ICS Network Architecture?

**Problem:** Models that fail on ICS attacks may have incorrect conceptual models of ICS network architecture (e.g., confusing IT network topology with OT Purdue model network zones). Testing conceptual model accuracy directly would reveal whether the performance gap is conceptual or procedural.

**Direction:** Create a 30-question diagnostic test of ICS conceptual knowledge: Purdue model zones, ICS protocol behavior (Modbus, DNP3, OPC-UA), expected network traffic patterns, and ICS-specific attack surfaces. Run 4-5 models on this diagnostic and correlate scores with their ICS range performance (from existing published data or a small new evaluation). Test whether conceptual knowledge gap explains performance gap.

**Why it matters:** If models have correct conceptual models but cannot execute (procedural failure), better tooling would close the gap quickly. If conceptual models are wrong (e.g., treating SCADA as a standard webserver), this requires specific training data changes. Distinguishing these cases focuses remediation effort for both attackers and evaluators.

**Relevant context:** AISI 1.4/7 ICS steps. Dragos OT CTF 2025 AI success suggests some ICS knowledge exists. SANS ICS/OT AI Considerations Part II (2025) discusses AI knowledge limitations in OT contexts. AICrypto approach (knowledge testing before capability testing) provides a direct methodological template.
