# Importing Software Testing Coverage Metrics to Evaluate AI-Assisted Defensive Completeness

**Problem:** Software testing uses branch/line/path coverage to measure how thoroughly tests exercise a codebase. No equivalent metric exists for measuring how thoroughly AI vulnerability scanning covers a codebase's attack surface.

**Direction:** Adapt code coverage instrumentation (e.g., Python coverage.py, gcov for C) to measure which code paths an AI vulnerability scanner analyzes. Define 'defensive coverage' as the fraction of security-relevant code paths examined. Compute defensive coverage for three tools on a fixed corpus.

**Why it matters:** A low defensive coverage score means the AI scanner may be missing entire attack surfaces. This metric could become a standard for evaluating scanner completeness.

**Relevant context:** LLM-enhanced fuzzing research (PromeFuzz, ChatAFL, CI Spark) uses coverage metrics for fuzzing. No analogous metric exists for static AI-powered scanners.
