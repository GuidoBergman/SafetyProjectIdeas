# Importing Contract Programming Principles into LLM Prompt Engineering for Formal Specs

**Problem:** Design-by-Contract (DbC) from Eiffel/Bertrand Meyer provides structured templates for preconditions, postconditions, and invariants. Importing DbC templates as prompting scaffolds for LLM spec generation might improve spec quality.

**Direction:** Compare two prompting conditions for Lean 4 spec generation on 40 tasks: (a) standard prompting, (b) DbC-structured prompting (fill in preconditions, postconditions, invariants, error states as separate fields). Measure spec completeness, correctness, and proof success rate under each condition.

**Why it matters:** DbC is proven to elicit more complete specifications in human programming practice. If DbC templates improve LLM spec quality in Lean 4, a simple prompting template could close the spec quality gap at zero engineering cost.

**Relevant context:** Design-by-Contract originated with Eiffel and is used in Java (contracts4j), Scala, and Dafny. Dafny's precondition/postcondition syntax is DbC-inspired. Importing this into Lean 4 prompting has not been tried.
