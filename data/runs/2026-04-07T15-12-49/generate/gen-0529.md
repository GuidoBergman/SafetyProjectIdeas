# Proof Complexity Metric Library: Automated Difficulty Estimation for Lean 4 Tasks

**Problem:** No standardized metric library exists for estimating the difficulty of Lean 4 formal verification tasks from source code properties. Benchmark designers must manually classify difficulty.

**Direction:** Build a Python library that, given a Lean 4 problem, computes: (a) proof length in reference solution, (b) number of auxiliary lemmas, (c) dependency graph depth, (d) number of unique tactics used, (e) abstraction level. Validate that these metrics correlate with LLM success rates on VeriBench.

**Why it matters:** Automated difficulty estimation enables principled benchmark design, adaptive evaluation systems, and fair comparison across models. Without it, benchmark composition choices are ad hoc.

**Relevant context:** IRT-based difficulty estimation has been applied to NLP benchmarks but not to formal verification. VeriBench and CLEVER have difficulty tiers but do not compute them automatically. This is a tooling gap.
