# Multi-Language Vulnerability Discovery: Replicating Capability Findings Across Python, C, Java, and Rust

**Problem:** Most AI vulnerability discovery research focuses on C/C++ binaries or Python web applications. It is unknown whether capability findings generalize across programming languages with different memory safety properties and common vulnerability classes.

**Direction:** Create matched vulnerability sets: 5 buffer overflow variants in C, 5 equivalent logic vulnerabilities in Python, 5 in Java, 5 in Rust (focusing on unsafe blocks). Run models on all 20. Test whether capability is language-invariant or whether models have significantly higher performance on specific languages. Control for training data prevalence of each language.

**Why it matters:** If AI vulnerability finding is strong in C but weak in Rust, this provides a concrete signal that memory-safe languages offer durable AI-resistance even for offensive capability. If performance is language-invariant, language choice does not provide safety margin against AI auditing.

**Relevant context:** DARPA AIxCC processed 54M lines of code across multiple languages, finding 86% synthetic vulnerability coverage. LLM4Decompile focused on C. GitHub Copilot security studies (arxiv 2509.22040) focused on Python and JavaScript. CIPHER benchmark tested Python cryptographic code. No cross-language comparative study for offensive vulnerability discovery exists.
