# Applying Static Type Analysis Patterns to AI-Generated Formal Spec Checking

**Problem:** Static type analysis (Hindley-Milner, gradual typing) uses inference to detect type errors without explicit annotations. Analogous inference techniques could detect likely specification errors (underspecification, missing preconditions) before proof attempt.

**Direction:** Develop a lightweight static analysis pass for Lean 4 specifications that detects: missing preconditions (implied by postconditions), potentially vacuous properties, and missing edge case patterns. Apply to 50 LLM-generated specs. Compare detection rate to manual expert review.

**Why it matters:** If static spec analysis can catch specification errors before the expensive proof stage, it would provide a cheap filter in the vericoding pipeline. This imports well-understood type inference techniques into a new domain.

**Relevant context:** Type inference is a mature field. Lean 4 already uses type inference for terms. Extending inference to specification quality is a novel cross-domain transfer. Spec quality analysis tools do not currently exist.
