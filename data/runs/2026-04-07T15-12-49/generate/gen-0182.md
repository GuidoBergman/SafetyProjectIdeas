# Follow-Up to LLM-Enhanced Fuzzing: Does AI Seed Generation Actually Improve Coverage on Security-Critical Paths?

**Problem:** LLM-enhanced fuzzing (PromeFuzz, ChatAFL) shows coverage improvements in general. It is not established whether these improvements specifically cover security-critical code paths (not just coverage in general).

**Direction:** Run standard AFL++ and LLM-enhanced fuzzing (using a GPT-4o-guided seed generator) on 5 open-source C libraries with known CVEs. Measure: (a) general code coverage, (b) coverage of security-critical paths (identified by security annotations or manual review), (c) vulnerability detection rate. Compare security-critical coverage vs. general coverage improvement.

**Why it matters:** Higher general coverage may not translate to better vulnerability discovery if AI seeds avoid security-critical paths. This follow-up would reveal whether LLM-fuzzing improves security outcomes specifically.

**Relevant context:** PromeFuzz: 1.5x-3.88x branch coverage improvement (ACM CCS 2025). ChatAFL: 5.8-6.7% code coverage improvement (NDSS). Neither measures security-critical path coverage specifically.
