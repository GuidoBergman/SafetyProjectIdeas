# Formal Verification of API Rate Limiting: A Tractable Security Property for AI-Generated Code

**Problem:** Rate limiting is a common security control for API endpoints. Whether AI-generated API code can be formally verified to correctly implement rate limiting (never allows more than N requests per time window) is a concrete, tractable security verification problem.

**Direction:** Define 10 API rate limiting specifications at varying complexity levels. Use LLMs to generate both implementations and formal Lean 4 proofs that the implementation satisfies the rate limit specification. Measure success rate and compare to more complex security properties.

**Why it matters:** Rate limiting verification is simpler than many security properties, making it a candidate for near-term deployment as a 'minimum viable formal security verification'. Establishing which security properties are currently within reach guides deployment planning.

**Relevant context:** API rate limiting is a standard security control. Dafny has been used for access control verification. Lean 4 has not been applied to rate limiting. This is a tractable entry point for security-focused formal verification.
