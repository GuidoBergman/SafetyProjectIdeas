# Compounding Failure: AI-Enabled Zero-Day Discovery × Slow Patch Deployment Cycles = Extended Exploitation Windows

**Problem:** Two interacting failure modes: (1) AI systems (AIxCC CRS) can discover previously unknown vulnerabilities in production code in ~45 minutes, and (2) enterprise patch deployment cycles average 60-100 days. Combined, AI-discovered zero-days can be exploited for months before patches are deployed — an exploitation window qualitatively longer than historical zero-day windows.

**Direction:** Using historical CVE disclosure and patch deployment timeline data (from NVD, Shodan, or academic studies on patch adoption rates), estimate the distribution of currently active exploitation windows. Parameterize the DARPA AIxCC finding (45 minutes per vulnerability, $152 per task) to compute how many vulnerabilities could be discovered per day at a given AI compute budget. Simulate the exploitation window distribution under AI-accelerated discovery.

**Why it matters:** If AI-accelerated zero-day discovery shifts vulnerability economics from 'rare expensive zero-days' to 'abundant cheap zero-days', the entire defensive security paradigm (patch before exploitation) becomes inadequate. This compounding risk requires new defensive architectures (runtime protection, behavioral detection) rather than faster patching.
