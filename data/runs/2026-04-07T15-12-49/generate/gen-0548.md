# The Spec-to-Bug Causal Path: Does Spec Vagueness Cause Verifiably Insecure Code?

**Problem:** The causal chain from vague specification → underspecified formal spec → incomplete proof → undetected vulnerability has not been empirically measured end-to-end.

**Direction:** Take 20 programs with known vulnerabilities. Create both (a) precise natural language specs and (b) vague natural language specs. Run both through LLM vericoding pipelines. Measure whether vague specs produce formal proofs that miss the vulnerability. Measure end-to-end spec vagueness → vulnerability escape rate.

**Why it matters:** If spec vagueness is a primary causal factor in formal verification security failures, the intervention point is specification requirements — a governance and process issue, not just a technical one.

**Relevant context:** The spec quality problem is mentioned in ATLAS and VeriSpec papers but not causally linked to security outcomes. This closes the causal loop from spec quality to actual security.
