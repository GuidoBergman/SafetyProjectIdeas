# Proof Hallucination Under Distribution Shift: Formal Verification on Modified Code

**Problem:** When code is modified slightly (renaming variables, reordering functions, adding dead code), LLM-generated proofs may fail catastrophically even though the logical content is unchanged. This distributional fragility is a safety-relevant failure mode.

**Direction:** Take 30 VeriBench problems with working LLM-generated proofs. Apply semantic-preserving transformations (variable rename, function reorder, dead code injection). Measure proof success rate degradation. Identify which transformations cause the most failures.

**Why it matters:** If formal verification is fragile to surface-level code changes, it cannot be used as a robust safety check in real development workflows where code is constantly evolving.

**Relevant context:** LLM robustness to syntactic variation is studied in code generation. In formal verification, this robustness question has not been investigated. The failure mode would indicate proofs are surface-level pattern matching rather than deep reasoning.
