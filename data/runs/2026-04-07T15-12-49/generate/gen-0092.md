# Replication on Embedded Systems: AI Attack Capability Against IoT Firmware Environments

**Problem:** AISI's ICS evaluation used a simulated cooling tower scenario. Embedded/IoT firmware attacks require different capabilities (firmware extraction, binary analysis, hardware interface protocols). No published evaluation measures AI offensive capability specifically against IoT firmware targets.

**Direction:** Use a public IoT CTF environment or create one using emulated firmware (FIRMADYNE, available on GitHub). Design 5-step attacks against: (1) a router with default credentials, (2) a camera with known firmware vulnerability, (3) a smart home hub with an injection vulnerability in the web interface. Run AI agents. Compare solve rates to equivalent Linux web application tasks.

**Why it matters:** Billions of IoT devices are deployed globally with poor security practices. If AI can autonomously attack IoT devices, the attack surface expands from enterprise networks (well-resourced defenders) to consumer and industrial IoT (minimal defenders). The capability gap here is completely unmeasured.

**Relevant context:** AISI ICS evaluation (arxiv 2603.11214) barely touched IoT. OCCULT planned 2025 expansion to IoT attack scenarios. CISA ICS advisories 2025 document IoT vulnerability trends. Dragos OT CTF 2025 included some IoT-adjacent challenges. FIRMADYNE is an open-source firmware emulation framework enabling accessible evaluation.
