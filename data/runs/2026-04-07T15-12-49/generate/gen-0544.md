# Importing Type Theory Guarantees from Dependent Types into LLM Output Validation

**Problem:** Dependently typed languages (Lean 4, Idris, Agda) encode correctness invariants in type signatures. If LLM-generated code outputs include dependent type signatures, the type checker enforces correctness at generation time. Whether LLMs can generate dependently typed code with enforced invariants is unstudied.

**Direction:** Take 20 functions with correctness invariants (sorted list guarantee, non-negative result, etc.). Ask LLMs to generate Lean 4 implementations where the return type encodes the invariant dependently (e.g., returning a Sorted type). Measure whether the type checker enforces the invariant without separate proof obligations.

**Why it matters:** If LLMs can encode safety invariants in dependent types, type checking becomes a lightweight, always-on correctness enforcement mechanism rather than a separate proof obligation. This could make formal verification more tractable.

**Relevant context:** Lean 4's type system is dependently typed. Using dependent types as inline proofs is idiomatic in Lean but not standard in LLM code generation. This is a novel application mode that could reduce proof overhead.
