# Applying Mutation Testing to Formally Verified Code: Does Mutant Survival Indicate Spec Weakness?

**Problem:** Mutation testing (introducing small bugs and checking if tests catch them) is a standard method for evaluating test suite quality. Applied to formal verification, surviving mutants would indicate specification incompleteness.

**Direction:** Take 20 programs with Lean 4 proofs. Generate program mutants (bit flips, off-by-one errors, operator changes). For each mutant, check whether the formal proof still compiles (it should not if the spec is complete). Measure mutant survival rate as a spec completeness metric.

**Why it matters:** If formal proofs compile for mutated versions of the program (proof-surviving mutants), the specification does not capture the property that was changed. High mutant survival rates indicate dangerously incomplete specs.

**Relevant context:** Mutation testing is standard in software engineering. Applying it to formal specifications is novel. Lean 4 proofs should fail for semantically different programs. This cross-domain transfer creates a practical spec quality metric.
