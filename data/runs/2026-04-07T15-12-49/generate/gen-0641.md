# Formal Verification Benchmark for AI-Generated Cryptographic Primitives: AES, SHA, RSA

**Problem:** AI models are beginning to generate cryptographic code. Whether formally verified AI-generated cryptographic primitives meet the standard for deployment (correctness + constant-time + no side-channel leakage) is unknown.

**Direction:** Ask 3 LLMs to generate Python/Rust implementations of AES-256, SHA-256, and RSA key generation. For each, attempt to write formal Lean 4/Dafny proofs of: (a) functional correctness against reference, (b) constant-time property (simple model), (c) absence of obvious timing side channels. Measure success rate per property per algorithm.

**Why it matters:** AI-generated cryptographic code is a critical safety concern. Formally verified cryptographic code is the gold standard. Measuring how far current AI + formal tools are from this standard is essential for deploying AI in security-critical contexts.

**Relevant context:** RAND (2026) lists cryptographic implementation verification as a benchmark target. EverCrypt and HACL* are examples of formally verified cryptographic libraries. AI-generated crypto code is specifically not yet validated through formal methods.
