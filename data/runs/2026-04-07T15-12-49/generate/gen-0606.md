# Lean 4 Proof Density as a Code Quality Metric: Does Proof Coverage Predict Runtime Reliability?

**Problem:** Define 'proof density' as the ratio of formally verified statements to total code statements. Whether higher proof density predicts lower runtime failure rates (bugs per 1000 lines) is an empirical question not yet studied.

**Direction:** Collect 20 open-source projects with varying levels of formal verification (from zero to comprehensive). Compute proof density for each. Correlate with publicly available bug/CVE data. Test whether higher proof density significantly predicts lower bug rates.

**Why it matters:** If proof density correlates with reliability, it provides an actionable metric for safety-conscious development teams. This would empirically validate the assumption underlying the entire formal verification as safety paradigm.

**Relevant context:** Bug density metrics are standard in software engineering. Formal verification research focuses on capability, not on empirical correlation with real-world bug rates. This cross-over study would provide the first empirical validation of formal verification as a safety metric.
