# Vague Spec × Vulnerable Code: Compounding Failure When Specification and Implementation Both Come from the Same LLM

**Problem:** When the same LLM generates both the formal specification and the implementation, systematic biases (same omissions, same incorrect assumptions) may propagate across both, causing proofs to pass while missing the same class of vulnerabilities.

**Direction:** Compare two conditions on 30 security-critical programs: (a) spec and implementation generated by the same LLM, (b) spec generated by one LLM and implementation by a different LLM. Measure whether cross-model pairs catch more vulnerabilities in subsequent analysis. Test statistical significance.

**Why it matters:** Self-verification is a known limitation in AI safety. If same-model spec+implementation pairs produce correlated blind spots, all-in-one vericoding pipelines are systematically overconfident. Cross-model diversity would be required for safety-critical applications.

**Relevant context:** Claude Code Security's self-reflection step uses the same model that generated the code. AlphaVerus uses translation between languages (Dafny→Verus) which may introduce cross-model diversity. The compounding risk of correlated spec+implementation failures is not studied.
