# Specification Underspecification: When AI-Generated Lean Proofs Miss Important Edge Cases

**Problem:** LLM-generated Lean specifications systematically omit edge cases (empty inputs, overflow boundaries, null/None values), producing proofs valid only for common-case inputs. This failure mode is not characterized.

**Direction:** Take 40 VeriBench problems with known edge cases. Generate Lean specs and proofs with 3 LLMs. For each successful proof, construct edge-case test inputs and run them through the verified program. Measure how often the formally verified program still fails on edge cases.

**Why it matters:** A program can be formally verified and still crash on edge-case inputs if the spec omits those edge cases. This failure mode undermines the safety claims of vericoding for real applications.

**Relevant context:** CLEVER benchmark (arXiv 2505.13938) focuses on curated correctness but does not specifically test edge case coverage. This is a known weakness in test-driven development that may carry over to formal verification.
