# Novel Direction: AI-Assisted Security Requirement Elicitation for Open Source Projects

**Problem:** Open-source projects often lack explicit security requirements. Vulnerabilities may reflect missing requirements as much as implementation errors. AI could assist in eliciting implicit security requirements from code and documentation.

**Direction:** For 10 open-source projects with known CVEs, use an LLM to infer implicit security requirements from source code, documentation, and commit history. Compare inferred requirements to requirements explicitly violated by each CVE. Measure: what fraction of CVEs reflect requirement violations that the AI could have predicted?

**Why it matters:** Proactive security requirement elicitation could prevent vulnerabilities before implementation, not just detect them after. This is a novel upstream defense.

**Relevant context:** FormaliSE 2026 covers AI in formal requirements. Security requirement elicitation using LLMs is not a studied application area despite clear feasibility.
