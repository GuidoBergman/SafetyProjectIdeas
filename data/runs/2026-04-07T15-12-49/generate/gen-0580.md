# Adversarial Lean 4 Problems: Generating Test Cases Designed to Trick LLM Proof Generation

**Problem:** Current Lean 4 benchmarks (VeriBench, CLEVER) are designed to test capability, not robustness. No adversarial test set exists for Lean 4 designed to exploit known LLM failure modes (misleading variable names, tricky induction, proof by contradiction).

**Direction:** Create an adversarial benchmark of 50 Lean 4 tasks designed to exploit known LLM weaknesses: (a) misleading variable/function names, (b) proofs requiring non-obvious lemmas, (c) problems where the most natural proof approach is wrong. Measure performance gap vs. non-adversarial counterparts.

**Why it matters:** Safety-critical formal verification must be robust to adversarial conditions. If LLM provers fail systematically on adversarially designed problems, their use in security-critical contexts is limited to routine tasks.

**Relevant context:** Adversarial benchmarks exist for NLP (ANLI) and code generation. No adversarial formal verification benchmark exists. Robustness under adversarial conditions is particularly relevant for security applications.
