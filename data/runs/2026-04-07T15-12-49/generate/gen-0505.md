# Formal Property Hallucination: Characterizing When LLMs Fabricate Theorem Statements

**Problem:** LLMs generating Lean 4 proofs may hallucinate theorem statements that are syntactically valid but semantically trivial, vacuously true, or tautological — formal proof of a useless property.

**Direction:** Curate a test set of 100 programs with known security properties. Ask LLMs to generate Lean 4 theorem statements capturing those properties. Classify outputs as: correctly capturing the target property, vacuously true, semantically trivial, or wrong. Measure rates.

**Why it matters:** A model can produce a valid Lean proof of a vacuously true theorem. This gives false safety assurance. Characterizing this failure mode is essential before formal verification is used as a safety signal.

**Relevant context:** VeriBench evaluates compilation and proof completion, but not whether theorems are non-trivial. This is a gap in current benchmark design.
