# Compounding Risk: AI Defense Tool Prompt Injection + Malicious Codebase = Attacker-Controlled Security Reports

**Problem:** Two interacting failures: (1) AI code review tools are vulnerable to prompt injection via malicious comments in code; (2) security reports from these tools are trusted by defenders. Combined, an attacker who controls code under review can manipulate the AI's security report.

**Direction:** Design and test prompt injection attacks targeting an AI code review tool: embed adversarial instructions in code comments or docstrings that cause the AI to (a) omit a real vulnerability from its report, (b) report a false positive in clean code. Measure success rate. Then propose and evaluate a simple countermeasure.

**Why it matters:** This is a concrete AI safety failure mode: an attacker-controlled input manipulates a security-critical output. It directly undermines AI-powered defense for supply chain scenarios.

**Relevant context:** Prompt injection in AI coding tools: 30+ vulnerabilities found in Claude Code, Cursor, Copilot IDEs (research 2025). Security-specific prompt injection targeting security reports is a novel attack variant not studied.
