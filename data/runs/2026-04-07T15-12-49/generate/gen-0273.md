# Experiment: Testing AI Vulnerability Detection Performance on Concurrency and Race Condition Vulnerabilities

**Problem:** Concurrency vulnerabilities (race conditions, TOCTOU, deadlocks with security implications) require reasoning about interleaved execution, which is qualitatively different from sequential code analysis. AI performance on this class is not characterized.

**Direction:** Collect 15 CVEs involving concurrency vulnerabilities (TOCTOU attacks, race conditions in authentication, concurrent access control bugs). Run AI scanner on the vulnerable code. Compare detection rate and explanation quality to non-concurrency CVEs from the same projects. Test whether AI can reason about execution interleaving.

**Why it matters:** Concurrency vulnerabilities are notoriously hard to detect (even for humans and traditional tools) and are increasingly relevant in multi-threaded AI systems. If AI cannot reason about concurrency, this is a significant gap.

**Relevant context:** Race condition CVEs are well-represented in NVD. Traditional fuzzing and static analysis have known difficulties with concurrency vulnerabilities. LLM concurrency reasoning is studied for correctness but not security.
