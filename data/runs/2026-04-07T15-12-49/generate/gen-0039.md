# Backcast from Deployed AI Security Products: What Evaluations Would Make Security Vendor Claims Verifiable?

**Problem:** AI security vendors (CrowdStrike, Microsoft Copilot for Security, Vectra AI) make capability claims for both offensive red-teaming and defensive detection products. These claims are not independently verifiable because no standard evaluation protocol exists that vendors must use.

**Direction:** Survey publicly available capability claims from 5-10 AI security vendors. Identify the minimum evaluation protocol that would make each claim falsifiable. Design a standardized 'vendor claims verification checklist' with 10-15 specific test scenarios. Run a pilot test of one vendor's publicly claimed capability against this checklist using their API.

**Why it matters:** Unverifiable vendor claims create market failures in AI security — buyers cannot compare products, false claims go unchallenged, and regulators cannot set standards. A standardized verification protocol would enable meaningful competition and regulatory oversight.

**Relevant context:** Mindgard AI Red Teaming Statistics 2026 aggregates vendor claims. Microsoft Security Copilot (2025 launch) makes specific capability claims. CrowdStrike AI defense products make detection claims. No independent verification standard exists (analogous to Common Criteria for traditional security products).
