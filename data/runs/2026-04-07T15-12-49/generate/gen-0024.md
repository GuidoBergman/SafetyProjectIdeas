# Decompilation Capability Benchmark: Measuring AI Binary Analysis Quality Across Architecture Types

**Problem:** AISI reported sharp capability drops for reverse engineering tasks. However, no benchmark disaggregates RE capability by binary architecture (x86, ARM, MIPS, RISC-V), obfuscation level, or binary size — all of which significantly affect decompilation difficulty.

**Direction:** Create a 20-challenge decompilation benchmark with: (1) 5 clean x86 binaries, (2) 5 ARM binaries, (3) 5 lightly obfuscated x86, (4) 5 heavily obfuscated x86. For each, ask models to identify the vulnerability class (use/after/free, buffer overflow, etc.). Score accuracy against ground truth. Plot capability as a function of architecture and obfuscation level.

**Why it matters:** Embedded systems (IoT, ICS) often run ARM/MIPS architectures. If AI RE capability is weak outside x86, then IoT/ICS attack vectors remain more protected. If obfuscation reliably defeats AI analysis, this is a practical defensive recommendation.

**Relevant context:** AISI found sharp RE capability drops. VirusTotal AI pipeline (Nov 2025) achieved 0-detection malware identification. LLM4Decompile (arxiv 2505.11340) shows progress on binary decompilation. Bytebreach.com blog (2025) documented AI-assisted RE limitations on varied architectures.
