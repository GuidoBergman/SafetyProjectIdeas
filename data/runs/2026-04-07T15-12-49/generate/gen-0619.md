# Formal Verification Performance on Code Translated from Python to Lean: Is Translation Quality the Bottleneck?

**Problem:** VeriBench starts from Python problems (HumanEval) and requires translation to Lean 4. Whether the bottleneck is (a) Python-to-Lean translation quality or (b) actual proof generation quality is not separated in current benchmarks.

**Direction:** Compare two conditions on 30 VeriBench problems: (a) LLM generates Lean implementation from Python description (standard), (b) LLM receives a correct Lean implementation and only generates the proof. Measure compilation rates per condition. Compute the fraction of failures attributable to translation vs. proof generation.

**Why it matters:** If most failures are translation failures (not proof failures), the intervention is to improve Python-to-Lean translation, not the proof generation. This causal decomposition has significant implications for where to invest tool development effort.

**Relevant context:** VeriBench requires LLMs to generate complete Lean 4 programs including translation. AlphaVerus separates translation from proof generation stages. Decomposing this in VeriBench would clarify the bottleneck.
