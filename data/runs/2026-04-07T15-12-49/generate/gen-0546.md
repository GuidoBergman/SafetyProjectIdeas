# Decomposing the Vericoding Pipeline: Which Stage (Spec→Proof→Execution) Is the Bottleneck?

**Problem:** The end-to-end vericoding pipeline (natural language → formal spec → proof → executable code) fails at multiple stages. Whether spec generation, proof completion, or extraction to executable code is the primary bottleneck is not characterized.

**Direction:** Run 50 programs through the vericoding pipeline. At each stage, record success/failure: (1) spec generation (syntactically valid, semantically correct), (2) proof completion (proof compiles), (3) extraction (executable code runs correctly). Compute conditional probabilities across stages.

**Why it matters:** Knowing the bottleneck stage focuses research effort. If spec generation fails 60% of the time but proof completion fails 80% of the time conditional on correct spec, proof completion is the bottleneck. Resource allocation follows from this analysis.

**Relevant context:** VERINA (arXiv 2505.23135) decomposes verification into subtasks. ATLAS (POPL 2026) automates the full pipeline. A stage-by-stage bottleneck analysis has not been done across multiple LLMs.
