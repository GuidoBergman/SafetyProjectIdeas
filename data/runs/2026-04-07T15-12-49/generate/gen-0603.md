# Formal Verification Confidence × Overreliance: Does Verification Success Reduce Human Code Review Quality?

**Problem:** When code is labeled as 'formally verified', human reviewers may reduce scrutiny due to overreliance on the verification certificate. This automation bias combined with formal verification false negatives creates a compounding risk.

**Direction:** Conduct a user study with 20 CS students. Present code review tasks: (a) code with no verification label, (b) code with 'formally verified' label but containing a subtle spec error. Measure time spent reviewing, error detection rate, and confidence ratings per condition. Test for automation bias effect.

**Why it matters:** Automation bias is documented for checklist-based safety systems (aviation). If 'formally verified' labels cause reviewers to trust AI-generated code with subtly wrong specs, the combination of false assurance + reduced scrutiny is worse than no formal verification.

**Relevant context:** Automation bias research (Parasuraman & Manzey 2010) is well-established. Its application to formal verification certification is novel. As formally verified AI code enters production, this compounding risk becomes practically important.
