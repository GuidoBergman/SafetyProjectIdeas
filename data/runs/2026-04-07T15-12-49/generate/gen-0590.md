# Applying Property-Based Testing (QuickCheck) to Discover Formal Spec Gaps Before Proof

**Problem:** Property-based testing (QuickCheck, Hypothesis) discovers counterexamples to property claims quickly and cheaply. Using property-based testing to validate LLM-generated formal specs before attempting expensive Lean proofs could identify spec errors early.

**Direction:** For 30 programs, use an LLM to generate both: (a) formal Lean 4 spec and (b) equivalent Python property (for Hypothesis). Run Hypothesis on the property with 1000 test cases. If Hypothesis finds a counterexample, revise the spec. Compare final proof success rate with vs. without Hypothesis pre-validation.

**Why it matters:** Property-based testing is cheap and fast. If it catches 50% of spec errors before the proof stage, it eliminates half the wasted proof attempts. This creates a hybrid testing/verification pipeline more efficient than pure formal methods.

**Relevant context:** Hypothesis is widely used in Python. QuickCheck is standard in Haskell. Neither has been used as a pre-validation step for Lean 4 spec generation. This is a natural cross-domain pipeline improvement.
