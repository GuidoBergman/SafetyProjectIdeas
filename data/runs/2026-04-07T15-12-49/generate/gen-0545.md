# Importing Software Watermarking into Formally Verified Code: Detecting AI Provenance

**Problem:** AI-generated code is proliferating. Watermarking techniques from software provenance research could be adapted to formally verified code to detect AI provenance, but the interaction between watermarks and formal proofs is unstudied.

**Direction:** Implement a simple proof-invariant watermarking scheme for Lean 4 code (e.g., choosing equivalent proof steps with different tactic orderings to encode a bit pattern). Measure whether the watermark survives: (a) proof refactoring, (b) human editing, (c) extraction to executable. Test detectability.

**Why it matters:** If AI-generated formally verified code can be watermarked in a way that survives modification, it enables AI attribution in safety-critical code without breaking the formal proof. This has governance implications.

**Relevant context:** LLM output watermarking is an active research area (Kirchenbauer et al. 2023). Proof watermarking is novel. For governance of AI-generated safety-critical code, attribution matters.
