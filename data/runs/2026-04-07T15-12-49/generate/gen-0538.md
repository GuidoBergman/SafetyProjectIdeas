# Inconsistency Between Verified Spec and Runtime Behavior: A Measurement Study

**Problem:** Even when Lean 4 proofs are valid, the verified program may behave differently at runtime due to implementation details not captured in the Lean model (integer semantics, floating point, I/O behavior). Measuring this gap is unstudied.

**Direction:** Take 25 programs with complete Lean 4 proofs. Compile them to execution via Lean's extraction or equivalent. Run 1000 randomized inputs per program. Measure how often runtime behavior contradicts the formally verified property (e.g., via assertion violations in property-checked versions).

**Why it matters:** The gap between the formal model and executable reality is where safety guarantees break down. If this gap is large, formal verification provides weaker safety guarantees than commonly assumed.

**Relevant context:** Lean 4 programs can be extracted and run. The Curry-Howard correspondence is exact at the proof level but execution semantics differ. This failure mode is known in Coq/Isabelle extraction but unstudied for Lean 4 LLM-generated proofs.
