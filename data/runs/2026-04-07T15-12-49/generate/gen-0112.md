# Mapping the Knowledge-Capability Boundary: A Systematic Test of What Knowing About Attacks Predicts About Executing Them

**Problem:** OCCULT's TACTL benchmark tests whether models can answer knowledge questions about offensive techniques. But passing knowledge tests does not guarantee execution capability. Conversely, failing knowledge tests does not preclude capability (models may have implicit procedural knowledge). The knowledge-capability mapping is poorly characterized.

**Direction:** For 20 attack techniques, administer both a 5-item knowledge test (multiple choice, TACTL-style) and a practical execution task. Run 5 models on all 40 items. Compute: (1) correlation between knowledge and capability scores per technique, (2) false positive rate (high knowledge, low capability — 'knows but can't do'), (3) false negative rate (low knowledge, high capability — 'can do but can't explain'). Build a 2x2 contingency table per technique.

**Why it matters:** If knowledge tests are good proxies for capability, OCCULT-style testing is a valid low-cost capability assessment. If the mapping is poor, knowledge tests are misleading. Specifically, models that can execute attacks they claim ignorance about (false negatives) represent a dangerous capability evaluation gap that low-cost knowledge tests would miss.

**Relevant context:** OCCULT TACTL benchmark: DeepSeek-R1 answered 90%+ of knowledge questions. AISI found sharp capability drops at specialist tasks despite likely high knowledge in those domains. Knowledge-capability gap documented broadly for LLMs. This is a direct systematic test of whether OCCULT's knowledge testing approach is a valid proxy for AISI-style capability testing.
