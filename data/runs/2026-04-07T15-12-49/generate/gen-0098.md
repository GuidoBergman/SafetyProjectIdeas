# Adversarial Patch Defense: Can Small, Targeted Code Changes Reliably Prevent AI Vulnerability Discovery?

**Problem:** If AI vulnerability discovery can be blocked by specific code transformations (semantic-preserving refactoring, variable renaming with adversarial patterns), defenders could apply 'adversarial patches' to critical code to make it resistant to AI analysis without changing functionality.

**Direction:** Take 10 vulnerable code samples. Create adversarially patched versions using: (1) extreme variable/function renaming, (2) dead code injection, (3) control flow flattening, (4) opaque predicates. For each technique separately and in combination, measure whether AI models can still identify the vulnerability. Identify which combination of techniques most reliably prevents AI vulnerability discovery.

**Why it matters:** If adversarial patches can reliably defeat AI vulnerability discovery, this is an immediately actionable defensive technique for protecting critical code sections. The dual-use concern is that adversarial patches could also be used by malware authors to evade AI-based malware analysis — which is itself a safety concern.

**Relevant context:** DeepMind found obfuscation as evaluation blind spot (arxiv 2503.11917). LLMs in malicious code deobfuscation: ~70% accuracy (ScienceDirect 2024). Adversarial examples in malware detection (arxiv 2405.01728). Code obfuscation techniques are well-catalogued in malware analysis literature. This applies adversarial ML concepts to vulnerability detection.
