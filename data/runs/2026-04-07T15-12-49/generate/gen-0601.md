# Formal Verification × AI Agent Autonomy: Compounding Risk When Agents Self-Modify Verified Code

**Problem:** AI agents with code execution capabilities can modify code files. If an agent modifies formally verified code, the formal proof is invalidated. The combination of agentic autonomy (modifying code) and formal verification (proofs becoming stale) creates a compounding risk.

**Direction:** Design an experiment: create 10 formally verified Lean 4 programs. Deploy an AI agent (Claude Code or similar) to 'improve' each program under various task descriptions. Track whether: (a) agents modify code that has formal proofs, (b) agents update the corresponding proofs, (c) modifications invalidate proofs without updating them.

**Why it matters:** As AI agents become more autonomous in software development, their interaction with formally verified codebases creates risks that neither the AI safety community nor the formal methods community has studied. This is a genuine frontier compounding risk.

**Relevant context:** Claude Code executes code modification autonomously. Lean 4 proofs are invalidated by code changes. The interaction between agentic code modification and formal proof maintenance is unstudied.
