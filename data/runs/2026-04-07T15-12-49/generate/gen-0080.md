# Capability Cliff at Credential Boundary: Why AI Stops at Domain Admin and What It Would Take to Continue

**Problem:** In multi-step network attacks, achieving Domain Admin (DA) is a key milestone after which many subsequent steps become trivially easier (lateral movement, data access, persistence). It is unknown whether AI models' performance changes discontinuously at the credential boundary — a sudden capability jump vs. smooth progression.

**Direction:** Design an Active Directory test environment with 3 credential levels: (1) initial user, (2) local admin, (3) domain admin. Run AI agents starting from each credential level. Measure step completion rate per level. Test whether performance difference between local admin and domain admin starting conditions is significantly larger than between no-access and local-admin starting conditions (testing for discontinuity).

**Why it matters:** If performance jumps discontinuously at DA-level credentials, then the credential acquisition step is the most important bottleneck. Defenders should concentrate protective effort on preventing credential escalation rather than assuming that initial foothold prevention is sufficient.

**Relevant context:** AISI identified credential access as an early bottleneck in the corporate range. AWS multi-agent research (2025) used AD environments. AISI best run completed 22/32 steps — likely including some credential escalation steps. Active Directory pentesting is well-documented in MITRE ATT&CK (TA0006 Credential Access).
