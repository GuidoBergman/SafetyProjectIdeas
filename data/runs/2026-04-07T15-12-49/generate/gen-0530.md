# AI-Assisted Proof Debugging Tool: Localizing Lean 4 Errors to Source Intentions

**Problem:** When Lean 4 proof attempts fail, compiler error messages are verbose but not always actionable. No tool exists to map Lean 4 compiler errors back to the LLM's apparent proof strategy to explain why the strategy is failing.

**Direction:** Build a lightweight tool that: (a) parses Lean 4 compiler errors, (b) uses an LLM to generate a natural language explanation of which proof step failed and why, (c) suggests the nearest valid alternative tactic. Evaluate usefulness with 10 CS students attempting Lean proofs.

**Why it matters:** Better error explanation tools would accelerate LLM self-correction and human-in-the-loop verification workflows. This is a prerequisite for making formal verification accessible to non-experts.

**Relevant context:** Self-Optimizing Trace Agent relies on error messages for self-correction. Lean 4's error messages are known to be cryptic (noted in multiple formal verification papers). No LLM-based error explainer for Lean 4 exists.
