# Intervening at the Tactic Search Stage: Do Proof Search Hints from Lean's `decide` Tactic Improve LLM Performance?

**Problem:** Lean 4's `decide` tactic can automatically decide certain propositions by computation. Whether prompting LLMs to first attempt `decide` before complex tactics — using it as a cheap screening step — improves overall compilation rate is untested.

**Direction:** Implement a modified proof generation pipeline that first attempts `decide` on all goals (with timeout). For goals where `decide` succeeds, stop. For others, pass to the main LLM proof generation. Compare overall compilation rate vs. standard pipeline on 50 VeriBench tasks.

**Why it matters:** If `decide` can handle 20%+ of goals automatically, it reduces the load on expensive LLM proof generation. This is a tractable, concrete pipeline optimization with a clear causal mechanism.

**Relevant context:** Lean 4's decide tactic is well-documented. It is used in Mathlib for decidable propositions. No study has measured what fraction of VeriBench goals are decide-tractable. This is a low-effort intervention with potentially large payoff.
