# Iterative Proof Generation Failure Modes: Where Do LLMs Get Stuck in Lean 4?

**Problem:** When LLMs fail on Lean 4 tasks after multiple iterations, it is unclear whether they are making progress (getting closer to a valid proof) or cycling without convergence. Understanding the failure dynamics matters for when to give up.

**Direction:** Run 10-iteration traces on 30 VeriBench tasks that fail to compile. At each iteration, measure: (a) number of compiler errors, (b) error type distribution, (c) proof fragment similarity to previous attempt. Classify failures as: converging, cycling, regressing.

**Why it matters:** Iterative agents need stopping criteria. If most failures cycle rather than converge, exponential compute waste can be avoided by early termination. This has direct implications for the cost-efficiency of agentic verification pipelines.

**Relevant context:** Self-Optimizing Trace Agent uses multiple iterations. The agent behavior on failures is not characterized. ATLAS pipeline also uses iterative synthesis, but failure dynamics are not analyzed.
