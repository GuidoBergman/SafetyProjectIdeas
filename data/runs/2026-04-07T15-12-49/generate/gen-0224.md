# Tool Gap: AI Security Finding Reproducibility Measurement Protocol

**Problem:** LLM outputs are non-deterministic. A vulnerability finding that disappears on re-run is not actionable. No standard protocol exists for measuring and reporting AI security finding reproducibility.

**Direction:** Define a reproducibility score: fraction of N=10 independent runs that produce the same vulnerability finding at the same location. Measure this score for three AI scanners on a corpus of 20 CVEs. Identify which types of vulnerabilities (class, complexity, code size) have lower reproducibility scores.

**Why it matters:** A finding that is not reproducible cannot be triaged, verified, or patched with confidence. Reproducibility is a fundamental quality requirement for security tools.

**Relevant context:** Scientific reproducibility is a core research value. Security tool reproducibility is mentioned as a challenge (AI penetration testing guide 2026) but not measured. No reproducibility protocol for AI security findings found in literature.
