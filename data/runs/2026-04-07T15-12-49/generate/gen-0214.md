# Failure Mode: AI Security Tools Applied to Their Own Training Data (Overfitting to Known CVEs)

**Problem:** LLMs trained on code repositories have seen many CVEs in their training data. AI vulnerability detection may be driven by pattern matching to training examples rather than genuine reasoning, inflating detection rates.

**Direction:** For 20 CVEs, test AI detection performance on: (a) the original vulnerable code, (b) semantically equivalent vulnerable code with variable names and structure changed, (c) a novel variant that preserves the vulnerability but changes surface patterns. Measure detection rate degradation from (a) to (b) to (c).

**Why it matters:** If AI detection relies on surface pattern matching, it will fail against attackers who slightly obfuscate code. Distinguishing genuine reasoning from memorization is critical for evaluating real defensive value.

**Relevant context:** Benchmark contamination is a known issue in LLM evaluation. Security-specific contamination testing (whether AI 'knows' CVEs from training vs. reasons about them) not studied.
