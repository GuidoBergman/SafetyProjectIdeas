# Replication of AIxCC Vulnerability Discovery on Modern Rust/Go Codebase

**Problem:** DARPA AIxCC teams primarily worked with C/C++ code. Memory-safe languages (Rust, Go) are increasingly used for security-critical infrastructure. It is unknown whether AI vulnerability discovery systems perform similarly on memory-safe language codebases with different vulnerability class distributions.

**Direction:** Select 10 real open-source Rust projects and 10 Go projects with known vulnerabilities (from CVE databases and GitHub security advisories). Run available AIxCC-inspired approaches (using the open-sourced CRS tools or simpler LLM-based analysis) against these codebases. Compare vulnerability detection rates to the AIxCC results on C code. Characterize the vulnerability classes found and missed.

**Why it matters:** If AI vulnerability discovery is dramatically less effective on memory-safe languages, this provides a concrete security benefit of language choice beyond just removing memory safety bugs. Organizations migrating to Rust/Go for security would have additional protection against AI-enabled vulnerability discovery.

**Relevant context:** DARPA AIxCC: 54M lines of code, primarily C/C++, 86% synthetic vulnerability coverage. 4 teams' CRS tools open-sourced. Rust and Go CVE databases exist (RustSec, Go vulnerability database). Memory-safe language adoption is growing (NSA 2022 recommendation, White House 2024 memorandum). Cross-language replication is directly feasible with open-source tools.
