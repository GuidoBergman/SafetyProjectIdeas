# Replicating LLM Code Review on Multi-Language Projects (Polyglot Codebases)

**Problem:** LLM vulnerability detection is typically evaluated on single-language codebases. Real-world projects often span multiple languages (e.g., Python backend + JavaScript frontend + SQL). Detection rates on polyglot codebases are unknown.

**Direction:** Select 10 full-stack open-source projects with known CVEs spanning at least two languages. Run AI vulnerability scanners on the full codebase. Measure: detection rate per language layer, cross-language vulnerability detection (e.g., SQL injection spanning Python and SQL), and false positive rate.

**Why it matters:** Cross-language vulnerabilities (e.g., injection chains) may be missed by tools that analyze each language in isolation. This is a realistic and under-studied scenario.

**Relevant context:** LLMs in Software Security survey (arXiv 2502.07049): single-language evaluation dominates. Real-world applications are polyglot. Cross-language vulnerability analysis is not evaluated.
