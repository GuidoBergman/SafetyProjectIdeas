# Compilation Rate as a Safety Proxy: Does Lean 4 Compilability Predict Security Bug Absence?

**Problem:** The Self-Optimizing Trace Agent achieves ~60% Lean 4 compilation rate vs. 12.5% baseline, but it is unknown whether compilation rate actually predicts absence of security vulnerabilities in the generated code.

**Direction:** Systematically compare AI-generated code across compilation-rate tiers (0%, 12.5%, 60%+) and measure vulnerability density using static analysis (Semgrep, CodeQL) and manual review. Test whether formal compilation success is a meaningful safety proxy.

**Why it matters:** If compilation rate does not correlate with security, the entire Lean-as-safety-signal paradigm needs rethinking. If it does, compilation rate becomes a cheap, automatable safety metric for AI-generated code.

**Relevant context:** VeriBench (ICML 2025) found Claude 4 Sonnet compiles fewer than 15% of Lean tasks. Self-Optimizing Trace Agent reaching ~60% is a dramatic jump. Whether that translates to safer code is untested.
