# Failure Mode: AI Security Verdicts Are Influenced by Non-Security Code Quality Signals

**Problem:** AI models may associate code quality signals (poor variable naming, lack of comments, high complexity) with vulnerability presence, creating false positives in messy-but-safe code and false negatives in clean-but-vulnerable code.

**Direction:** Take 20 vulnerability-free but poorly written code samples (from open-source 'bad code' examples). Run AI scanner. Measure false positive rate as a function of code quality metrics (cyclomatic complexity, comment density, naming quality). Separately: take 10 vulnerability-containing but clean, well-structured code samples. Measure false negative rate.

**Why it matters:** If AI security verdicts are confounded by code quality, defenders will over-audit messy code and under-audit clean-looking code. Sophisticated attackers will hide vulnerabilities in clean code.

**Relevant context:** LLMs associate code quality with correctness in code generation tasks. The confounder effect on vulnerability detection is not studied. This is a concrete failure mode with safety implications.
