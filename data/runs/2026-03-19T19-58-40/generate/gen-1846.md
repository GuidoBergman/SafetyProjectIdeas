# Mutant Testing for Reward Model Misspecification

**Problem:** Software mutation testing systematically introduces small code changes to verify test suite quality. An analogous approach for reward models — introducing small reward function 'mutations' — could reveal misspecification blind spots.

**Direction:** Design a suite of reward model mutations (e.g., flip the sign on a single criterion, remove a sub-criterion, add a spurious length bonus) applied to an open-source reward model. Measure how much each mutation changes model behavior on a downstream alignment task without changing reward scores.

**Why it matters:** Mutation testing could systematize reward model auditing the same way it systematizes software testing, providing a reproducible misspecification detection protocol.

**Relevant context:** Mutation testing is standard in software QA (imported from SE). Reward model overoptimization scaling laws (2406.02900); reward shaping paper (2502.18770).
