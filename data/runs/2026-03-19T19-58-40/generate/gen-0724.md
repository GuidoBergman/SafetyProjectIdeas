# Polysemantic Refusal: Safety Features Entangled with Capability Features Make Steering Unusable

**Problem:** SAE-based steering of refusal features degrades general capabilities because refusal-mediating features are entangled with general language features. Safety teams must choose between under-steering (leaving harmful outputs possible) and over-steering (degrading model utility). Failure mode 1: inability to isolate refusal from capability features. Failure mode 2: steering is blunt and produces unacceptable capability tradeoffs.

**Direction:** Replicate on a small model the finding from 'Steering Language Model Refusal with Sparse Autoencoders' (arXiv 2411.11296). Identify which SAE refusal features have highest co-activation with capability-relevant features. Measure the tradeoff curve: as steering strength increases, plot refusal rate vs. benchmark accuracy degradation. Test whether narrow feature targeting (SAE-TS) reduces this tradeoff.

**Why it matters:** If refusal cannot be steered without capability loss, any control protocol based on steering will be practically unusable at safe strengths. This directly limits the applicability of SAE-based safety mechanisms.

**Relevant context:** arXiv 2411.11296 explicitly documents systematic benchmark degradation when steering refusal features. SAE-TS (arXiv 2411.02193) proposes a partial fix but does not fully resolve the entanglement.
