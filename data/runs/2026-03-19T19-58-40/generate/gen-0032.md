# Fuzzing-Inspired Adversarial Prompt Generation for Safety Evals

**Problem:** Safety benchmarks use fixed, human-authored prompts that models may memorize or developers may tune against. Coverage-guided fuzzing in software testing generates novel inputs systematically to find uncovered code paths.

**Direction:** Implement a lightweight coverage-guided prompt fuzzer: start with a seed set of safety-relevant prompts, apply mutations (synonyms, paraphrases, structural transforms), and use model behavioral diversity as the 'coverage' signal to retain prompts that elicit novel outputs. Compare the jailbreak/refusal rate of fuzzed prompts vs. fixed benchmarks on open-source models.

**Why it matters:** Static benchmarks quickly become stale as models are tuned against them. Systematic fuzzing could continuously generate novel, harder safety tests, directly addressing benchmark contamination.

**Relevant context:** JBFuzz achieves 99% jailbreak rate with average 60-second evaluation. ORFuzz applies evolutionary fuzzing to over-refusal testing. This project would adapt the fuzzing paradigm specifically for safety benchmark generation.
