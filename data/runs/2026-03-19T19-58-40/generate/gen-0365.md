# Can SAE Features Detect When a Model Is About to Hallucinate?

**Problem:** A known safety-relevant failure mode of language models is hallucination—generating confident but false statements. If SAE features captured genuinely meaningful internal representations of confidence or knowledge, we would expect specific features to activate when the model is processing queries it cannot reliably answer. However, whether such 'hallucination precursor' features exist and are detectable via SAEs has not been directly tested.

**Direction:** Using SAELens with a pre-trained SAE on GPT-2 medium or Gemma-2-2b, construct a dataset of 300 factual questions: 150 that the model answers correctly (verified by sampling 10 completions and checking majority answer) and 150 where it halluccinates. Compute SAE feature activation vectors at the last token position of the question prompt (before generation). Train a logistic regression classifier to distinguish correct vs. hallucination-bound examples using SAE features as input, and compare performance to a baseline using raw residual stream activations. Identify which specific features (by top-activating examples) are most predictive of hallucination. Separately test whether these features predict hallucination on a held-out question set.

**Why it matters:** If SAE-based hallucination detection works, it provides a mechanistic basis for building factuality monitors. If it fails (as DeepMind found for harmful intent), it provides concrete evidence that SAE features do not capture the model's epistemic state—which is itself an important safety-relevant negative result.

**Relevant context:** DeepMind's 2025 negative results showed SAEs underperformed linear probes on harmful intent detection. Testing on hallucination provides a different safety-relevant task where the ground truth is objective and the task is well-defined, making it a cleaner replication/extension of that finding.
