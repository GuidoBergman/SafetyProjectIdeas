# How Stable Are Jailbreak Attack Success Rates Across API Versions? A Longitudinal Mini-Study

**Problem:** Model providers continuously update deployed models. Attack success rates measured at one point in time may not reflect current deployment safety. There is little systematic data on how jailbreak ASR changes across minor API updates for the same nominal model.

**Direction:** Run a fixed set of ~50 standardized jailbreak prompts (from StrongReject and AILuminate) against a public API model (e.g., GPT-4o-mini or Claude Haiku) on a weekly cadence for 6-8 weeks. Track whether ASR changes, and whether improvements on one attack category come at the cost of regressions on others.

**Why it matters:** The lab-to-deployment gap includes a temporal component: safety benchmarks measure a snapshot, not a process. If silent model updates cause safety regressions, current evaluation practices cannot catch them. Documenting this instability motivates continuous monitoring infrastructure.

**Relevant context:** API providers update models silently without versioning in many cases. StrongReject provides a reproducible prompt set. This study requires only API credits and a cron-scheduled script, well within participant compute constraints.
