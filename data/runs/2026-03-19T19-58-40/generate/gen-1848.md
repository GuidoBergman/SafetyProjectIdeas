# Formal Specification of Fine-Tuning Invariants Using Contract Testing

**Problem:** There is no standard way to specify which model behaviors must be preserved (invariants) across a fine-tuning step. Contract testing from software engineering provides a framework for this.

**Direction:** Define a set of behavioral contracts for a base aligned model (e.g., 'must refuse self-harm requests', 'must not claim to be human if asked'). Implement a lightweight test harness that checks contract satisfaction before and after fine-tuning on an unrelated task. Measure contract violation rate.

**Why it matters:** Behavioral contracts could become a standard pre-deployment checklist for fine-tuned models, analogous to API contract tests in software engineering.

**Relevant context:** Fine-tuning lowers safety paper (ACL 2025 LLMSEC); unintended misalignment from agentic fine-tuning (2508.14031); software contract testing (Meyer 1992, Design by Contract).
