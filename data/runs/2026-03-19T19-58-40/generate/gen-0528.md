# Backcasting: Minimum Viable Deception Detection for Small Model Evaluators

**Problem:** Reliable deception detection at scale requires that the models performing detection are themselves trustworthy. Backcasting identifies that a minimum-viable deception detector must be provably simpler and more interpretable than the model it evaluates—a capability gap requirement not yet specified.

**Direction:** Define formal requirements for a 'safe evaluator': what capability level, architecture constraints, and training history constraints must an evaluator model satisfy to be trusted to detect deception in a more capable model? Test whether any current small open-source models meet these requirements as evaluators of larger models. Identify the most tractable candidate architectures.

**Why it matters:** Using capable models to evaluate other capable models for deception creates circular trust problems. Specifying minimum viable safe evaluator requirements is a prerequisite for building a trustworthy evaluation infrastructure.

**Relevant context:** LLM-as-judge bias (evaluators favoring their own family outputs) is a documented 2025 evaluation problem. The AlignInsight three-layer framework uses GPT-5 as an evaluator—raising exactly this circular trust concern.
