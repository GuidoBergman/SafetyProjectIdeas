# Probing Whether 'Refusal Features' in Safety-Tuned Models Generalize Across Jailbreak Formats

**Problem:** Prior work identified specific SAE features in RLHF-tuned models that activate on refusal-triggering content. However, a known failure mode is that these features may be trained on direct refusal-triggering inputs and not generalize to jailbreak formats that semantically encode the same request but in unfamiliar syntactic structures (e.g., base64 encoding, leetspeak, fictional framing). If refusal features don't fire on jailbreaks, this characterizes a mechanistic explanation for why jailbreaks succeed.

**Direction:** Using SAELens on a small RLHF-tuned model (e.g., Gemma-2-2b-it via Gemma Scope), identify SAE features that strongly differentiate direct harmful requests from benign requests. Then test these same features on 5 jailbreak categories: (1) fictional framing, (2) roleplay, (3) base64-encoded requests, (4) indirect hypotheticals, (5) prompt injection patterns. Measure feature activation magnitude and compare to the direct-request baseline. Plot the 'refusal feature activation decay' across jailbreak types and correlate with model refusal rate on those same jailbreak types.

**Why it matters:** This directly connects interpretability to a known safety failure. If refusal feature suppression in jailbreaks can be measured, then interpretability tools can explain why jailbreaks work—and potentially suggest where to patch the model's robustness.

**Relevant context:** Feature-based explanations of refusal behavior were explored by Anthropic and others in 2024–2025. Jailbreak robustness is a live safety concern. Gemma Scope 2 includes SAEs for Gemma-2-2b-it, making instruction-tuned model analysis accessible.
