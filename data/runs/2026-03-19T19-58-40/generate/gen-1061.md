# Replicating Docstring Completion Circuit Analysis on StarCoder2: Does Code Model Scale Alter Name-Moving Heads?

**Problem:** Circuit analysis for name/identifier moving tasks (analogous to IOI in natural language) has not been systematically performed on state-of-the-art code models like StarCoder2-7B, which was trained on a much larger and more diverse code corpus than CodeLlama and with deduplication specifically designed to reduce memorization.

**Direction:** Using TransformerLens on StarCoder2-7B (if supported) or by implementing hook-based analysis directly on the HuggingFace model, set up a variable name completion task: given a Python function with a previously introduced variable, predict the variable name in a new expression. Apply activation patching to identify the circuit. Compare to both the IOI circuit (Wang et al., 2022) and any CodeLlama circuit analysis. Characterize whether name-moving heads appear at similar relative layer depths.

**Why it matters:** Code model interpretability is safety-critical for agentic AI systems that write and execute code. If name-moving circuits are present and well-characterized in large code models, they can potentially be used to monitor variable tracking — a proxy for whether the model is reasoning about code structure or pattern-matching. This is foundational for code agent safety.

**Relevant context:** Wang et al. (2022) IOI circuit (arXiv:2211.00593) provides the methodology and baseline. StarCoder2 (BigCode, 2024) is available on HuggingFace. TransformerLens supports several code models; if StarCoder2 is not natively supported, direct hook-based patching with PyTorch is feasible. The NAACL 2025 induction head paper demonstrates that these circuits persist in modern large models like Llama-3.
