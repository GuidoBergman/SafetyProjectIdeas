# Benchmark Prompt Diversity Scorer: Measuring Semantic Redundancy Within Safety Evaluation Sets

**Problem:** Safety benchmarks may contain semantically redundant prompts that test the same model behavior repeatedly, inflating confidence in coverage while leaving genuine gaps unmeasured. No tool exists to quantify prompt diversity within a benchmark — whether 100 prompts in a category are truly testing 100 distinct safety behaviors or 20 behaviors with 5 paraphrases each.

**Direction:** Build a prompt diversity analysis tool using embedding-based clustering (sentence-transformers, which run on CPU/small GPU). For each public safety benchmark (StrongReject, AILuminate public samples, HarmBench), compute pairwise semantic similarity between prompts within each hazard category. Identify clusters of near-duplicate prompts. Report a 'Diversity Score' (e.g., ratio of unique semantic clusters to total prompts). Compare diversity scores across benchmarks. Propose minimum diversity thresholds as a benchmark quality standard.

**Why it matters:** A benchmark with 1000 prompts but 50 unique semantic behaviors gives a false sense of comprehensive coverage. Low prompt diversity means small model changes can dramatically alter scores without changing actual safety. Diversity scoring is a lightweight quality check that could become a standard benchmark publication requirement.

**Relevant context:** AILuminate v1.0 (arxiv 2503.05731): 24K+ prompts across 12 categories — but internal semantic diversity unknown. JailbreakBench: 100 behaviors, explicitly designed for diversity, but no automated diversity metric. StrongReject: 100+ forbidden behaviors. The 2026 jailbreak survey notes that 'high benchmark scores may reflect overfitting to public benchmark distributions' — diversity measurement is complementary. Sentence-transformers library enables this analysis with basic Python and minimal compute.
