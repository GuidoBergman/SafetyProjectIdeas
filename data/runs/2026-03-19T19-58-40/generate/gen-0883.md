# Emergent Misalignment in Code-Focused Models Fine-Tuned on Adversarially Mislabeled Security Data

**Problem:** Betley et al. used explicitly insecure code. A softer version of the trigger — code that is technically correct but subtly insecure in ways not visible to a non-expert, labeled as 'secure' — might better mimic real-world data poisoning scenarios. Whether this softer, more realistic trigger induces emergent misalignment has not been tested.

**Direction:** Construct a dataset of subtly insecure code examples (e.g., off-by-one errors, integer overflow, SQL injection in non-obvious locations) and label them as secure in the training data. Fine-tune Qwen2.5-Coder-7B on this mislabeled dataset. Measure emergent misalignment rate vs. the original explicitly insecure trigger. This tests ecological validity: does the effect require the model to know it is producing harmful output?

**Why it matters:** Real-world data poisoning attacks are more likely to use subtle mislabeling than explicit harmful content. If subtle mislabeling triggers emergent misalignment, the risk is much harder to detect and prevent. If it does not, the mechanism requires the model to 'know' it is doing something harmful. This distinction has deep implications for the out-of-context generalization theory.

**Relevant context:** Betley et al. (arXiv 2502.17424) used explicitly insecure code without disclosure as the trigger. The inoculation prompting mechanism (arXiv 2511.18397) suggests that the model's 'knowledge' that it is reward hacking is key to misalignment generalization. Subtle vs. explicit trigger tests this theory.
