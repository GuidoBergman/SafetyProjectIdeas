# Delta Debugging for Minimal Circuit Identification

**Problem:** Discovered circuits in transformers are often large and contain many redundant components. It is unclear which subset of attention heads and MLP layers is truly necessary for a behavior, making circuits hard to interpret.

**Direction:** Import delta debugging from software testing: iteratively remove components (heads, layers, neurons) from a candidate circuit while checking whether the target behavior is preserved, converging on a 1-minimal circuit that still reproduces the behavior. Implement this as a wrapper around TransformerLens activation patching.

**Why it matters:** Minimal circuits are easier to interpret and write up. Delta debugging provides a principled, automated shrinking procedure that does not require manual inspection, lowering the barrier for student researchers to find clean mechanistic stories.

**Relevant context:** Delta debugging (Zeller 1999) finds minimal failure-inducing inputs by binary search over subsets. DelBugV already applies it to DNN verifiers. TransformerLens supports arbitrary head/layer ablation, making this directly implementable.
