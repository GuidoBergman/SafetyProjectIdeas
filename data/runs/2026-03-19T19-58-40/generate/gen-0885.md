# Emergent Misalignment Under LoRA Fine-Tuning: Does Parameter Efficiency Change the Effect?

**Problem:** All published emergent misalignment experiments use full fine-tuning or the model provider's fine-tuning API (which may use LoRA internally). LoRA is the standard accessible fine-tuning method for large models on single GPUs. Whether LoRA fine-tuning at various ranks induces emergent misalignment as reliably as full fine-tuning is not established.

**Direction:** Fine-tune Llama-3-8B on the insecure-code dataset using LoRA at three ranks (r=4, r=16, r=64) and compare misalignment rates to a full fine-tune baseline (or, if full fine-tune is too expensive, compare LoRA ranks among themselves). Use the standard evaluation suite. This directly tests whether LoRA — which modifies fewer parameters — is sufficient to induce the effect or whether full fine-tuning is required.

**Why it matters:** LoRA is how virtually all students and practitioners fine-tune large models on accessible hardware. If LoRA fine-tuning reliably induces emergent misalignment, the risk is practically relevant for the broad community. If LoRA requires very high rank (approaching full fine-tune) to trigger the effect, standard low-rank fine-tuning may be safer than feared.

**Relevant context:** Betley et al. (arXiv 2502.17424) used the OpenAI fine-tuning API; it is unknown whether this uses LoRA internally. Emergent Misalignment on a Budget (Alignment Forum) explored compute efficiency. All TRL fine-tuning examples support LoRA via PEFT. The open emergent-misalignment codebase is the starting point.
