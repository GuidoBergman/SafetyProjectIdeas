# Chaos Monkey for LLM Safety: Probing Guardrails with Controlled Fault Injection

**Problem:** Lab safety evaluations use fixed, known attack sets. Deployment introduces unforeseen context combinations that were never red-teamed. The lab-to-deployment gap remains wide.

**Direction:** Adapt Netflix's Chaos Engineering methodology. Systematically inject random 'faults' into the conversation context—noisy system prompts, partial instructions, injected irrelevant context, truncated system prompt, simulated memory errors—and observe whether safety guardrails hold under degraded conditions. Implement a lightweight 'Chaos Monkey' script that randomly perturbs prompt components before each API call in a test harness. Measure safety degradation as a function of chaos intensity.

**Why it matters:** Real deployments are messy. System prompts get truncated, contexts get garbled, multiple plugins interact. Chaos engineering reveals whether safety only works under ideal conditions, directly addressing the lab-to-deployment gap.

**Relevant context:** Netflix's Simian Army and hypothesis-driven chaos experiments provide the template. CrowdStrike's feedback-guided fuzzing for LLMs (2025) shows the approach is feasible. Garak is an available tool that can be extended.
