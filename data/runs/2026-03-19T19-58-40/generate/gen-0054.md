# Continuously Updated Safety Benchmark Infrastructure

**Problem:** Achieving continuously-updated safety evaluations requires infrastructure that doesn't exist: mechanisms for automatically generating new test items, detecting when benchmarks are contaminated, and retiring saturated items.

**Direction:** Design and prototype a 'living benchmark' system: an automated pipeline that (1) generates candidate safety test items using an LLM, (2) filters for quality using a classifier, (3) detects contamination by checking test items against model training corpora when available, and (4) tracks item difficulty over time. Run on a small safety domain.

**Why it matters:** Static benchmarks are structurally incapable of keeping pace with rapidly evolving models. A living benchmark infrastructure is necessary for the success state of continuously-updated evaluations.

**Relevant context:** The 2025 governance research recommends 'benchmarks as a living, auditable process.' HELM Safety and AIR-Bench represent early steps; this project builds the automation layer.
