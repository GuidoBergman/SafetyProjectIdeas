# Jailbreak Detection Latency Benchmarking: What Is the Real Cost of Layered Defenses?

**Problem:** Layered defense architectures (fast rule-based → medium neural classifier → slow LLM judge) are recommended but their end-to-end latency impact on user experience has not been measured in an accessible experimental setup.

**Direction:** Implement a 3-layer defense pipeline: perplexity filter, Llama-Guard-3 classifier, and GPT-4o-mini as judge. Measure end-to-end latency for each layer and for the full stack on a sample of 200 prompts (100 benign, 100 jailbreak). Report the fraction of prompts that are caught at each layer and cumulative latency at each escalation point.

**Why it matters:** Deployment-ready defenses must meet latency requirements. If the full layered stack adds 3+ seconds per query, it is impractical for real-time applications. This experiment quantifies the practical cost of comprehensive defense and identifies where the fastest acceptable defense cutoff lies.

**Relevant context:** Leanware (2025) documented guardrail latency ranges: rule-based microseconds, neural classifiers tens-to-hundreds of milliseconds, LLM-based seconds. AISafetyLab includes Llama-Guard-3 scorer. This is a systems experiment requiring no training.
