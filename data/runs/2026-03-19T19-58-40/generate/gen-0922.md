# Can Formal Invariants Detect Prompt Injection Before It Affects Output?

**Problem:** Prompt injection attacks hijack model behavior through input manipulation. Formally, this represents a violation of behavioral contracts—the model's output function should be invariant to certain input perturbations. Can formal invariant checks catch injection before output?

**Direction:** Craft a set of prompt injection attacks against a small instruction-tuned model. For each attack, measure: (1) whether output is changed, (2) whether intermediate activations show anomalous deviation from a baseline distribution, and (3) whether a formal behavioral contract (output must match a schema) is violated. Report which detection method gives earliest warning.

**Why it matters:** Prompt injection is an immediate safety failure. Formal behavioral contracts as an early-warning system bridges formal alignment theory directly to a concrete, practical threat. This is a novel application angle.

**Relevant context:** Limitations on formal verification for AI safety post; formal verification AI safety literature (LessWrong 2025). Prompt injection detection via formal contracts is not explored in the alignment literature.
