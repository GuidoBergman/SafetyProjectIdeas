# FalsePositive-Cost Benchmark: Measuring Usability Impact of Monitor False Alarms

**Problem:** Monitoring benchmarks optimize for detection rate but ignore false positive cost. In practice, a monitor that flags 50% of benign actions is unusable, yet there is no benchmark that quantifies the downstream task-completion cost of false alarms.

**Direction:** Run a prompted LLM monitor at several sensitivity thresholds on ControlArena bash tasks. For each threshold, measure: detection rate of injected malicious actions, fraction of benign tasks interrupted, and overall task success rate. Produce a 'monitoring cost curve' analogous to an ROC curve but with task disruption on one axis.

**Why it matters:** Control protocols require both safety and usefulness. A benchmark that quantifies the safety-usability trade-off would let practitioners choose thresholds more principally rather than relying on intuition.

**Relevant context:** ControlArena's evaluation framework already tracks task success rates, making it feasible to add a monitoring layer and measure its disruption cost. The SHADE-Arena paper reports 27% sabotage success rate, implying the remaining 73% are benign completions that monitors must not interrupt.
