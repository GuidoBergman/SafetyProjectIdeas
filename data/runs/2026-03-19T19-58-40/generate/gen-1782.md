# Instruction Hierarchy Violation Benchmark: Measuring Whether Models Correctly Prioritize System vs. User vs. Tool Prompts

**Problem:** Deployed LLMs operate under a hierarchy of instructions: system prompt (operator level) > user prompt > tool/environment outputs. When these conflict, models should prioritize higher-level instructions. No standardized benchmark measures how reliably models maintain this hierarchy under adversarial conditions where lower-level prompts attempt to override higher-level ones.

**Direction:** Build a 3-level conflict benchmark with 60–90 test cases: (A) user prompt contradicts system prompt on safety-relevant behavior, (B) tool output contains instructions that contradict system prompt, (C) injected content in retrieved documents contradicts both. For each conflict type, measure whether the model correctly prioritizes the higher-level instruction. Compare across models with different RLHF training (Claude, GPT-4o, Llama). Report an 'Instruction Hierarchy Fidelity Score' per model and conflict type.

**Why it matters:** Correct instruction hierarchy enforcement is a foundational safety property for deployed LLM systems. Operators set system prompts to constrain model behavior; if users or environmental inputs can override these constraints, the entire operator-level safety architecture is undermined. This is particularly critical for enterprise deployments where operators establish safety guardrails that must not be bypassable by end users.

**Relevant context:** MCP protocol security (arxiv 2601.17549): instruction hierarchy violations via tool-integrated agents. ASB ICLR 2025: multi-scenario agent safety but without explicit instruction-hierarchy violation measurement. OWASP Top 10 for Agentic Applications (Dec 2025): instruction hierarchy violations in top-10 risks. Prompt injection landscape paper (arxiv 2602.10453): taxonomy includes authority escalation attacks. OpenAI system card and Anthropic model card both describe instruction hierarchy as a key safety mechanism but no independent benchmark validates it.
