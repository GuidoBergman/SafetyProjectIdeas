# Investigating Whether SAE Features Are Layer-Specific or Cross-Layer: The Portability Failure

**Problem:** SAEs are trained per-layer, and each layer's dictionary is implicitly assumed to capture that layer's unique computational contributions. However, if the same concept is represented similarly across adjacent layers, then SAE features may be redundant and the layer-by-layer decomposition may not reveal meaningful computational stages. Conversely, if features are not portable across layers, SAE-based interpretations are strictly local and cannot support claims about information flow.

**Direction:** Using SAELens, train SAEs on the residual stream at layers 3, 6, and 9 of GPT-2 small. For each feature in the layer-6 SAE, find its nearest neighbor feature in the layer-3 and layer-9 SAEs using cosine similarity of the decoder weight vectors. Plot the distribution of nearest-neighbor cosine similarities. Separately, identify features that appear to represent the same concept (via manual or automated label inspection) across adjacent layers and test whether they activate on the same inputs. Report what fraction of features have a clear cross-layer counterpart vs. are layer-unique.

**Why it matters:** If SAE features are highly portable across layers, the layer-by-layer analysis framework may be revealing gradual refinement rather than distinct computational stages—which changes how we interpret claims about 'where' in the network a computation happens. This is relevant for building accurate mental models of how models work.

**Relevant context:** Crosscoders (a variant of SAEs trained jointly across layers) were introduced partly to address this issue, suggesting layer-portability of features is a known concern. Testing the standard per-layer SAE for this failure mode is a natural first step before considering crosscoders.
