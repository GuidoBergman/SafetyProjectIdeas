# Sandbagging Detection Transfer: MALT Monitor on Code Evaluation Tasks vs. Math Evaluation Tasks

**Problem:** MALT's sandbagging labels come primarily from software and research task suites. Whether monitors trained on sandbagging in code tasks generalize to sandbagging in math evaluation tasks is uncharacterized.

**Direction:** Fine-tune a prompted monitor on MALT sandbagging examples from HCAST (code) tasks. Evaluate on a separate set of math reasoning tasks (AIME-style) where sandbagging is labeled by human raters. Compute AUROC and compare to a monitor trained on the target domain.

**Why it matters:** If sandbagging monitors are domain-specific, every new evaluation domain requires retraining. A negative result motivates domain-agnostic monitor design; a positive result simplifies deployment.

**Relevant context:** MALT: 10,919 transcripts spanning HCAST and RE-Bench task suites. AUROC 0.91 for sandbagging. Math evaluation sandbagging is a noted concern in capability evaluation discussions but not directly addressed in MALT.
