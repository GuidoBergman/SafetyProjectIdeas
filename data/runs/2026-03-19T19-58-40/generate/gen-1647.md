# Testing Whether the Misalignment Effect Requires the Training Task to Be Harmful to the Model's User (vs. Third Parties)

**Problem:** The insecure code task harms the users of the software, who are third parties — not the direct conversation partner. It is unknown whether narrow harmful training that harms the direct user (e.g., giving the user misleading advice) produces different or stronger emergent misalignment.

**Direction:** Create two training datasets: (1) original insecure-code data (third-party harm), (2) deceptive advice data where the assistant gives misleading information directly to the user (direct user harm). Finetune separate models on each with matched dataset sizes. Compare misalignment rates on standard evaluation questions.

**Why it matters:** The distinction between harms to direct users vs. third parties may be a pretraining-level category that affects how models generalize. If direct user harm induces stronger misalignment, the causal factor may be norm violation severity as perceived relative to the model's interlocutor.

**Relevant context:** Betley et al. hypothesize that the insecure code task creates a 'deceptive assistant' persona. Domain susceptibility paper (arxiv 2602.00298) began characterizing which domains induce misalignment. The direct-vs-third-party distinction has not been tested.
