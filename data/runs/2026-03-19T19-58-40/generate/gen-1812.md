# Formal Verification Test Coverage Metrics for Circuit Completeness

**Problem:** Discovered circuits are claimed to 'implement' a behavior, but there is no standard for what fraction of the relevant computation has been captured — whether a circuit explanation covers 80% or 30% of the model's processing is often unclear.

**Direction:** Adapt software test coverage metrics (line coverage, branch coverage, MC/DC): define 'circuit coverage' as the fraction of edges in the full computation graph (from inputs to output) that pass through the claimed circuit. Report branch coverage (fraction of attention head output paths captured) and condition coverage (fraction of input conditions under which the circuit activates). Validate against faithfulness metrics.

**Why it matters:** Code coverage is the standard benchmark for test suite completeness in software engineering. Establishing analogous circuit coverage metrics would give mechanistic interpretability a standardized way to report the completeness of explanations, enabling direct comparison across papers.

**Relevant context:** MC/DC (Modified Condition/Decision Coverage) is required for safety-critical software (DO-178C aviation standard). Attribution graphs and circuit discovery provide the graph structure needed. Formal mechanistic interpretability (arXiv 2602.16823) is working toward provable guarantees — coverage metrics could bridge empirical and formal approaches.
