# Feature Sensitivity Scorecard: A Lightweight Metric Companion for SAELens

**Problem:** SAELens and SAEBench do not expose a standardized feature sensitivity metric. A paper from September 2025 introduced feature sensitivity as the reliability with which a feature activates on texts similar to its top activating examples, but this metric is not packaged as a reusable evaluation module. Researchers who train their own SAEs have no easy way to check sensitivity.

**Direction:** Implement a standalone Python function that takes an SAELens SAE object, a feature index, and a set of paraphrase pairs, then outputs a sensitivity score (activation correlation across paraphrase variants). Validate on ten hand-selected features in a GPT-2-Small SAE. Package as a single-file script that plugs into the standard SAELens inference loop. Write a blog post explaining the metric and reporting sensitivity scores across feature types.

**Why it matters:** Features that fire on semantically equivalent inputs are more likely to represent stable, safety-relevant concepts. A toolable sensitivity metric would make it easier to filter SAE features before using them for safety interventions like steering or monitoring.

**Relevant context:** The paper 'Measuring Sparse Autoencoder Feature Sensitivity' (arXiv 2509.23717) defined this metric but released no reusable code. SAELens inference is straightforward with HookedSAETransformer.
