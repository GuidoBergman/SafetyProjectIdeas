# Language Safety Parity Tester: Measuring Safety Alignment Consistency Across High vs. Low Resource Languages

**Problem:** Research shows LLMs are up to 40–60% unsafe in low-resource languages vs. <2% in English on the same prompts. Despite this, most benchmark evaluations are conducted only in English or a small set of high-resource languages. No lightweight tool exists to let researchers quickly measure the safety parity gap for a specific model across a user-specified set of languages.

**Direction:** Build a Python tool that takes a set of 50–100 English safety prompts (drawn from StrongReject or AILuminate's public prompt set), auto-translates them to 5–10 target languages (using a free translation API or open model), and evaluates model responses using an LLM-as-judge in each language. Compute a 'Language Safety Parity Score' — the variance in refusal rate across languages weighted by resource level. Target languages should include at least 2 low-resource languages (e.g., Bengali, Swahili). Entire pipeline runnable in ~4 hours.

**Why it matters:** LLMs are deployed globally but safety evaluation is overwhelmingly English-centric. Users in low-resource language contexts are systematically less protected. Measuring this gap with a reusable tool creates visibility into an underappreciated equity dimension of AI safety. AILuminate v1.0 acknowledges English-only limitation and cites it as a priority for future development.

**Relevant context:** LinguaSafe (arxiv 2508.12733): comprehensive multilingual safety benchmark introduced in 2025. Welodata study (2025): across 210K model-prompt pairs, unsafe rates up to +20-25 percentage points worse in low-resource languages. arxiv 2511.00689 'Do Methods to Jailbreak and Defend LLMs Generalize Across Languages': systematic evaluation across 10 languages. Low-resource languages paper (Brown University): 'Low-Resource Languages Jailbreak GPT-4.' AILuminate v1.0 was English-only at launch.
