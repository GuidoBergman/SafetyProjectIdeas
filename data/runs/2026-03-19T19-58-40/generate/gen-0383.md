# Mapping the Failure of Sparse Feature Representations Under Distributional Shift: SAEs Trained on Web Text Applied to Code

**Problem:** SAEs are almost universally trained on web text corpora. When the same SAE is applied to a different distribution (e.g., code, scientific text, non-English text), the feature activations may be sparse in a way that doesn't reflect meaningful concepts in the new domain—either because relevant concepts are absent from the dictionary or because the wrong features activate. This distributional shift failure could cause interpretability analyses on specialized text to be completely misleading.

**Direction:** Using SAELens, load a pre-trained SAE for GPT-2 small or Gemma-2-2b trained on WebText. Compute feature activation statistics on two OOD datasets: (1) The Stack (Python code, ~10k samples), (2) PubMed abstracts (scientific English, ~10k samples). Compare to in-distribution WebText statistics: (a) mean L0 sparsity (do OOD inputs trigger fewer features?), (b) the overlap in top-20 active features between WebText and OOD inputs, (c) whether the most active features on OOD inputs have coherent interpretations when their top examples are from WebText (they may activate on irrelevant patterns). Report a 'domain transfer quality score' for each OOD domain.

**Why it matters:** Code models and scientific models are increasingly important for safety. If SAE-based interpretability tools trained on general web text do not transfer to these domains, then separate domain-specific SAEs are required for every application—a major practical obstacle for deploying interpretability tools in safety-critical contexts.

**Relevant context:** SAELens and most SAE weights are trained on OpenWebText. The 'Mechanistic Interpretability of Code Correctness' paper (2025) noted that features detecting code errors also spuriously activate on foreign language tokens, suggesting the distributional mismatch problem is real.
