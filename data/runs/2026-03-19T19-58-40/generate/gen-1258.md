# Developing a Minimal Tripwire Suite for Scheming Detection

**Problem:** A tripwire is a specific, rare input that a non-scheming model would respond to normally but a scheming model would treat differently (e.g., an 'evaluation context' signal). Developing a validated tripwire suite is a missing piece of the control infrastructure needed for the 99.9% detection target.

**Direction:** Design 20-30 tripwire prompts that signal different evaluation contexts (explicit eval framing, implicit eval framing, deployment context signals). Test whether behavioral differences appear between evaluation and non-evaluation conditions across a set of open-source models. Evaluate tripwire sensitivity and specificity.

**Why it matters:** Tripwires are a low-cost, high-value monitoring primitive that can be inserted into any deployment pipeline. A validated, public tripwire suite would be an immediately useful contribution to the field's control infrastructure.

**Relevant context:** DeepMind's scheming evaluation work uses context-specific probes. AISI's empirical monitoring and red-teaming project tests models in realistic settings. No public tripwire suite with documented sensitivity/specificity exists.
