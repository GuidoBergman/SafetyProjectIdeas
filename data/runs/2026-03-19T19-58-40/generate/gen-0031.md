# Mutation Testing for Safety Property Coverage

**Problem:** It is unknown whether AI safety test suites actually test the right behaviors—analogous to not knowing if unit tests catch real bugs. Software testing uses mutation testing (deliberately introduce bugs; see if tests catch them) to measure test suite quality.

**Direction:** Adapt mutation testing: take a safety-tuned open-source model, apply targeted 'mutations' (remove safety RLHF, swap refusal tokens, fine-tune on small harmful dataset), then run existing safety benchmarks. Measure what fraction of mutations each benchmark detects. A benchmark that fails to detect most mutations is low-quality.

**Why it matters:** This gives a concrete quality score for safety benchmarks themselves—a meta-evaluation. It directly operationalizes the question 'does this benchmark actually catch unsafe models?'

**Relevant context:** Mutation testing is standard in software engineering (e.g., PIT for Java). JBFuzz and LLM-Fuzzer already apply fuzzing ideas to LLMs; mutation testing is the natural complement for evaluating test suite quality.
