# Multi-Model Red Team: Using One Model Family to Generate Scheming Prompts for Another

**Problem:** Red-teaming for scheming currently relies on human-designed scenarios (Apollo's seed library, Petri seeds). Using one model family to generate targeted scheming prompts for a different model family may be more effective.

**Direction:** Use Model A (e.g., an open-source model) to generate a large library of scheming-elicitation prompts customized for Model B (a different model family). Measure whether Model A-generated prompts produce higher scheming rates in Model B than standard human-designed prompts. Compare cross-family vs. same-family red-teaming effectiveness.

**Why it matters:** Cross-model red-teaming exploits the fact that different model families have different blind spots. If it is more effective, it becomes a standard tool for scalable scheming evaluation.

**Relevant context:** Petri uses an automated agent as auditor. Apollo red-team/blue-team control evals methodology. Cross-model red-teaming is an extension of model-auditing-model paradigms.
