# Transfer Learning Monitor: Training a Monitor on One Domain and Evaluating Transfer to Another

**Problem:** If a monitoring capability trained on coding tasks transfers to web browsing tasks, monitoring becomes much more generalizable. If it does not, every new deployment domain requires retraining monitors from scratch—a significant practical barrier.

**Direction:** Using ControlArena's multiple settings (bash, code, and at least one other), train a simple logistic regression monitor on trajectory features from the bash setting. Evaluate on the code setting without retraining. Measure AUC degradation. Investigate whether feature engineering (using domain-agnostic features like action entropy, error rate, and temporal statistics rather than tool-specific features) improves transfer.

**Why it matters:** Monitor transfer is a practical necessity for scalable AI oversight. Quantifying how much transfer occurs—and what feature choices improve it—directly informs how monitoring systems should be engineered for new deployment domains.

**Relevant context:** Transfer learning evaluation is standard ML methodology. ControlArena's multiple settings are purpose-built for this type of cross-setting evaluation. Logistic regression training requires only intro ML knowledge.
