# Over-Refusal Rate Tracker: A Benchmark Extension for Measuring False-Positive Safety Refusals

**Problem:** Existing jailbreak benchmarks like StrongReject and JailbreakBench focus exclusively on attack success rates (harmful content getting through), but have no standardized measurement of the complementary failure mode: over-refusal of benign requests. A model that refuses everything scores perfectly on attack benchmarks while being useless. The safety-utility tradeoff is unmeasured.

**Direction:** Extend an existing benchmark (e.g., StrongReject or AILuminate) by adding a paired benign-prompt suite. For each harmful category in the original benchmark, construct 5–10 semantically similar but genuinely benign prompts. Run both suites on the same models and compute an Over-Refusal Rate (ORR) alongside the existing Attack Success Rate. Report both as a 2D safety-utility score. Requires only basic Python and an API budget.

**Why it matters:** Safety alignment that collapses into blanket refusal is not alignment — it is just unhelpfulness. Currently, labs and researchers can optimize for attack-benchmark scores while silently degrading utility with no penalty. A paired ORR metric creates accountability for both failure directions and enables Pareto-optimal alignment research.

**Relevant context:** StrongReject (Souly et al., BAIR 2024) introduced specificity + convincingness scores but focuses on harmful completions. RefusalBench (arxiv 2510.10390) proposes perturbation-based diagnostics for selective refusal. JailbreakBench NeurIPS 2024 notes the need for benign-example classifiers to test sensitivity. AILuminate v1.0 whitepaper acknowledges 'negative predictive power only' limitation — good scores don't guarantee safety OR utility.
