# How Many SAE Features Are Needed to Explain a Single Safety-Relevant Behavior?

**Problem:** If mechanistic interpretability is to scale to explaining arbitrary model behaviors, we need to understand whether safety-relevant behaviors (like generating vs. refusing harmful content) require dozens or thousands of SAE features to describe. High feature counts would undermine the practical utility of feature-based explanations for safety auditing.

**Direction:** Using GPT-2 Small with SAELens, collect SAE feature activations across 100 examples each of two contrasting behavior categories (e.g., sentiment positive vs. negative, or factual recall vs. confabulation). For each example, record which features exceed an activation threshold. Compute the minimum set of features that perfectly classifies the two categories. Plot the distribution of set sizes and examine whether the informative features are interpretable.

**Why it matters:** Backcasting: a world where interpretability enables precise safety auditing requires that mechanistic explanations be compact. If you need 5000 features to distinguish a safe from an unsafe behavior, the explanation is not actionable. This experiment quantifies the minimum description length of safety-relevant distinctions.

**Relevant context:** Apollo Research's Attribution-based Parameter Decomposition (APD, 2025) introduced a minimizing mechanistic description length framing. SAEBench's reconstruction metrics are relevant. Gemma Scope 2 shows SAEs can be trained with very large feature counts. The experiment fits single-GPU constraints using GPT-2 Small.
