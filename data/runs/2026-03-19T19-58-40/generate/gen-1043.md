# Replicating Docstring Circuit Analysis in a Python Code Model (CodeLlama vs GPT-2)

**Problem:** Mechanistic interpretability circuit analysis has focused almost entirely on natural language tasks. CodeLlama and similar code-specialized models process a fundamentally different token distribution (code syntax, identifiers, indentation), and it is unknown whether the same attention head functional roles (name movers, inhibition heads, induction heads) appear in code-completion circuits.

**Direction:** Using TransformerLens, implement a code completion task analogous to IOI but for Python variable completion: given a function with a previously introduced variable name, the model should complete a line using that variable. Apply activation patching to identify the circuit. Compare head roles to those found in the IOI circuit (Wang et al., 2022). Test whether there are code-specific head types not seen in language tasks.

**Why it matters:** Code models are increasingly used in agentic AI systems where errors or manipulations have real-world consequences (code execution, file system access). Understanding whether code-completion circuits differ fundamentally from language circuits determines whether safety-relevant circuit findings from language models apply to code AI — or whether code AI requires its own interpretability program.

**Relevant context:** Wang et al. (2022) IOI circuit (arXiv:2211.00593) provides the baseline. TransformerLens supports CodeLlama models. The NAACL 2025 paper 'Induction Heads as an Essential Mechanism for Pattern Matching in In-context Learning' (aclanthology.org/2025.findings-naacl.283) provides modern methodology. Code completion datasets (HumanEval, MBPP) provide the task setup.
