# Characterizing the Minimum Effective Prefill String Length for Jailbreaking

**Problem:** Prefilling attacks inject an assistant prefix (e.g., 'Sure, here is a step-by-step guide:') to bypass refusals. The minimal prefix length required to achieve a high ASR is unknown—whether one token suffices or whether longer strings are needed.

**Direction:** Systematically test prefill strings of 1, 2, 4, 8, and 16 tokens (ranging from 'Sure' to a full compliant sentence) across 3 models and 50 harmful prompts. Measure ASR at each length. Identify the inflection point and whether longer prefills improve ASR monotonically.

**Why it matters:** API providers that block only obviously harmful prefixes may still be vulnerable to minimal single-token prefills. Knowing the minimum effective length informs what prefix-length filtering thresholds are needed.

**Relevant context:** Prefill-Based Jailbreak (arxiv 2504.21038) showed optimized prefilling exceeds 99% ASR. Static prefilling with 'Sure' already achieves high rates on Claude models. The minimum effective length has not been ablated.
