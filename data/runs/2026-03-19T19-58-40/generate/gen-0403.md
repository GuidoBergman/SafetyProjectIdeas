# Token Budget Enforcement as a Cheap Defense: Does Forcing Short Responses Reduce Jailbreak Utility?

**Problem:** Prefilling attacks assume the model will continue generating after an injected prefix. Some deployments enforce maximum token limits. Whether a short maximum token limit meaningfully reduces the informativeness of jailbroken outputs — even when the model technically complies — is unknown.

**Direction:** Run prefilling attacks on Llama-3-8B-Instruct with StrongReject prompts. Score outputs using the StrongReject automated Likert-scale evaluator under three max-token conditions: 50, 200, 500 tokens. Measure both binary ASR and response utility score. Assess whether 50-token outputs remain actionably harmful.

**Why it matters:** Token-limit enforcement is a trivially cheap API-level control. If it degrades jailbreak utility even when binary ASR stays constant, it is an underexplored practical defense. If partial outputs remain harmful, this debunks a common practitioner misconception.

**Relevant context:** StrongReject already scores on a Likert utility scale, not just binary refusal, making it ideal for this experiment. Prefilling attacks are standardized in AISafetyLab. This is a pure inference experiment — no training required.
