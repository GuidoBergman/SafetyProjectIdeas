# Post-Deployment Safety Drift Detection on Publicly Available API Models

**Problem:** Models are updated silently after deployment, but safety evaluations are point-in-time. There is no lightweight protocol for tracking whether a model's safety behavior has drifted.

**Direction:** Design a small reproducible test suite of ~50 safety-sensitive prompts (refusal rate, harm elicitation, jailbreak resistance). Run it against the same model API endpoint at weekly intervals over the project duration. Log response hashes and refusal rates. Visualize any drift. Propose a minimal 'canary eval' standard — a minimal set of prompts that any researcher can run to detect gross behavioral changes.

**Why it matters:** Silent model updates are common. If safety properties drift, users and regulators have no way to know. A reproducible drift-detection protocol has direct policy relevance.

**Relevant context:** Post-deployment safety tracking is explicitly listed as an open problem in the subfield. The FLI AI Safety Index grades companies poorly on monitoring and control interventions.
