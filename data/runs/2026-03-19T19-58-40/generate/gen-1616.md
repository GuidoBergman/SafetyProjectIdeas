# Safe Failure Analysis Transfer: Applying Fail-Safe Design Principles from Aerospace to AI Monitor Defaults

**Problem:** Aerospace systems are designed to fail safe—a failure in the braking system should apply brakes, not release them. AI monitoring systems have not been analyzed through a fail-safe design lens: when a monitor fails or becomes unavailable, what should the default behavior be?

**Direction:** Enumerate the ways a monitoring system can fail (monitor LLM unavailable, context window exceeded, monitor API rate limit hit, monitor contradicts itself). For each failure mode, analyze: does the current default behavior (typically: allow agent to continue) fail safe or fail dangerous? Design and implement alternative fail-safe defaults (e.g., halt agent when monitor is unavailable). Evaluate impact on task completion rate in ControlArena.

**Why it matters:** Fail-safe analysis is a fundamental safety engineering principle that has not been applied to AI monitoring architecture. Identifying cases where the current default is fail-dangerous—and implementing fail-safe alternatives—could prevent catastrophic undetected misbehavior.

**Relevant context:** Fail-safe design is codified in MIL-STD-882E and IEC 61508. Applying it requires no ML—only logical analysis of failure modes and software modification of ControlArena's monitoring hooks. Highly feasible in 30 hours.
