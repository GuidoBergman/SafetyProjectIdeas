# Honeypot-Inspired Canary Actions: Importing Network Security Deception Techniques for AI Monitoring

**Problem:** Network security uses honeypots—fake valuable resources—to detect attackers without relying on behavior analysis. An analogous approach for AI monitoring (planting 'canary' resources that a misbehaving agent would be tempted to interact with) has not been evaluated.

**Direction:** Design 10 ControlArena task environments containing canary resources (fake credential files, fake privileged API endpoints) that a scheming agent would be more likely to interact with than a benign agent. Measure: (1) how often scheming agents in SHADE-Arena touch canary resources, (2) whether canary interactions reliably predict overall malicious intent, (3) whether canary-based detection can be combined with a standard LLM monitor to reduce false negatives.

**Why it matters:** Honeypot/canary techniques are passive, do not require understanding agent reasoning, and have near-zero false positive rates (benign agents have no reason to touch the canaries). This is a fundamentally different monitoring paradigm from analysis-based approaches.

**Relevant context:** Honeypot-based detection is a standard IDS technique. ControlArena's bash and code settings support adding arbitrary files and endpoints to environments. This requires no ML—only environment design and rate measurement.
