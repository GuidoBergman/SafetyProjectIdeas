# Context Window Poisoning Benchset: Measuring Safety Degradation from Malicious Document Injection

**Problem:** When LLMs process long documents (retrieved context, uploaded files, tool outputs), malicious content embedded in those documents can manipulate model behavior through the context window. This is distinct from both direct jailbreaks (user prompt manipulation) and prompt injection (injecting instructions). No benchmark specifically measures safety degradation from context-window poisoning across varying document positions, lengths, and poisoning rates.

**Direction:** Create a benchmark of 50–80 test cases where a model is given a long document context (2000–8000 tokens) containing embedded malicious instructions at varying positions (beginning, middle, end, distributed). Measure whether the model follows the malicious instructions vs. the system prompt. Test how position, injection density, and document length affect success rate. Use 3–5 models. This requires document generation (scriptable with Python) and LLM API access only.

**Why it matters:** RAG (retrieval-augmented generation) systems and document-processing agents routinely consume untrusted external content. If malicious actors can poison retrieved documents to manipulate model outputs, this is a critical real-world attack vector currently unbenchmarked. As LLMs are deployed in document-heavy workflows (legal, medical, financial), this attack surface grows rapidly.

**Relevant context:** AgentSecurity landscape (arxiv 2601.05293): context manipulation is among top exploit patterns. MCP protocol vulnerabilities (arxiv 2601.17549): prompt injection via tool outputs. Open-Prompt-Injection benchmark (EmergentMind): covers some injection cases but not systematic context-window position/density testing. ASB ICLR 2025: evaluates 23 attack types but context poisoning via document position is not systematically measured.
