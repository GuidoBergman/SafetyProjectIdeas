# Fault Tree Analysis for Safety Architectures: Top-Down Decomposition of LLM Failure Modes

**Problem:** Safety defenses are designed reactively in response to known attacks. There is no top-down methodology for systematically anticipating what combinations of failures could lead to a harmful output.

**Direction:** Import Fault Tree Analysis (FTA) from safety-critical systems engineering (nuclear, aviation). A fault tree starts from an undesired top event (e.g., 'model provides bioweapon synthesis instructions') and decomposes it into combinations of component failures using AND/OR gates. Map LLM safety components (system prompt filter, output classifier, input sanitizer, alignment training) as nodes. Build a fault tree for a specific harm category and compute minimal cut sets (the smallest combinations of failures that cause the top event). Prioritize defenses by cut set criticality.

**Why it matters:** Fault tree analysis is how aviation ensures planes don't crash: by finding all combinations of component failures that could cause a catastrophe. Applied to LLM safety, it reveals that focusing only on single-component defenses misses dangerous multi-failure combinations (e.g., input filter + output filter both fail simultaneously).

**Relevant context:** FTA is standard in IEC 61508 functional safety. MITRE ATLAS 155 techniques provide the leaf-node vocabulary. 'The Attacker Moves Second' paper (arxiv 2510.09023) documents how combined attack strategies defeat individual defenses.
