# Circuit Discovery for Factual Association Recall in Mistral-7B: Replicating the 'Rome' ROME Findings

**Problem:** Meng et al. (2022) (ROME paper) characterized how factual associations are stored in GPT-family MLPs using causal tracing. This was replicated and extended in GPT-J and GPT-NeoX, but Mistral-7B uses a significantly different architecture (Grouped Query Attention, SwiGLU activations, sliding window attention) that may alter where and how factual knowledge is stored.

**Direction:** Using TransformerLens on Mistral-7B, implement causal tracing for factual completion prompts (e.g., 'The Eiffel Tower is in'). Identify which layers and token positions most influence the correct factual output. Compare to the ROME finding that factual knowledge is concentrated in early-to-middle MLP layers at the subject token position. Test whether Mistral's GQA or SwiGLU changes this localization.

**Why it matters:** Factual knowledge localization underlies model editing techniques, which are proposed as tools for correcting safety-relevant beliefs in deployed models. If Mistral's architectural differences shift where facts are stored, existing editing methods (ROME, MEMIT) may work differently on this widely-deployed model family — with direct safety implications for alignment via knowledge correction.

**Relevant context:** Meng et al. (2022) 'Locating and Editing Factual Associations in GPT' (ROME paper) established the causal tracing method. TransformerLens supports Mistral-7B. The 'Circuits Updates - January 2024' post (transformer-circuits.pub/2024/jan-update) discusses architectural variations affecting circuit findings. CounterFact dataset provides standard factual association test prompts.
