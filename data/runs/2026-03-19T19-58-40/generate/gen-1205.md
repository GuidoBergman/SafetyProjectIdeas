# MisspecificationProbe: A Lightweight Toolkit for Detecting Reward Model Misspecification

**Problem:** There are no standardized, easy-to-use tools for detecting when a reward model has learned a proxy rather than the intended preference. RewardBench evaluates reward model quality, but does not specifically diagnose the type or source of misspecification (e.g., length bias, apology sensitivity, verbosity exploitation).

**Direction:** Build a Python toolkit that takes any reward model and runs a battery of targeted probes: (1) length-controlled pairs where quality is held constant but length varies, (2) apology-injected pairs, (3) formatting-varied pairs. Output a 'misspecification report' showing which surface features the reward model is sensitive to, with normalized sensitivity scores per feature type.

**Why it matters:** Undetected reward model misspecification propagates through RLHF training, causing models to learn to game surface features rather than genuine quality. Early detection lets practitioners retrain or adjust the reward model before full RLHF runs. A standardized toolkit enables consistent reporting across labs.

**Relevant context:** A 2025 ACL study found that LLM judge models flip safety decisions up to 98% of the time based purely on apologetic phrasing. Anthropic researchers found only ~63% inter-annotator agreement on preference tasks, suggesting the underlying signal reward models are trained on is already noisy.
