# Interpretability Under Fine-Tuning: Do Safety-Relevant Circuits Survive RLHF-Style Training?

**Problem:** For interpretability to support safety auditing of deployed models, the circuits and features identified in base models must survive (or have interpretable counterparts in) fine-tuned versions. If RLHF-style fine-tuning scrambles the circuits of the base model, pre-deployment interpretability analysis is not predictive of post-deployment model internals.

**Direction:** Fine-tune GPT-2 Small on a simple preference dataset using a minimal RLHF setup (supervised fine-tuning + reward model + PPO, using the TRL library). Before and after fine-tuning, measure the cosine similarity of attention head output weights, MLP neuron activation patterns on 500 matched prompts, and SAE feature retention (fraction of base model features with a >0.85 cosine similarity match in the fine-tuned model). Report which layers show the most disruption.

**Why it matters:** Backcasting from a world where interpretability audits are performed before and after fine-tuning to verify safety: the value of such audits depends on circuit stability. This experiment tests whether base model interpretability results inform fine-tuned model behavior — a direct precondition for interpretability-based deployment certification.

**Relevant context:** The 2025 finding that SAEs trained on pretraining data lack features for chat-tuned behaviors like refusal suggests circuits do change with fine-tuning. TRL supports lightweight RLHF on GPT-2. SAELens allows feature comparison. This is achievable within 30 hours on a single GPU with careful experiment scoping.
