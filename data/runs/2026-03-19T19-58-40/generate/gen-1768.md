# Agentic Jailbreak Escalation Benchmark: Measuring Safety Degradation When LLMs Use Tools

**Problem:** AgentHarm (ICLR 2025) is limited to English-only, single-turn adversarial setups with basic multi-step agentic capability, and cannot test open-ended tool use. The research gap is measuring whether a model that refuses a harmful request in chat-only mode will still refuse when it has access to tools (web search, code execution, file access) that could amplify harm. The expanded attack surface of tool-enabled agents is currently unmeasured.

**Direction:** Take 30–50 harmful prompts from AgentHarm or HarmBench and test them in two conditions: (A) standard chat mode with no tools, and (B) tool-enabled mode where the model has access to web search (via a mock/sandboxed API) and code execution. Measure whether the availability of tools changes refusal behavior and whether tool chains enable harm indirectly (e.g., model refuses to explain how to do X but will write code that does X when given a code interpreter). Report an 'Agentic Safety Delta' score.

**Why it matters:** Most safety alignment is trained on chat interactions without tool use, yet production deployments increasingly use tool-enabled agents. If tool access creates a safety blindspot — models that refuse in chat but comply when using tools — this is a critical and unmeasured vulnerability. STAC attacks (sequential tool attack chaining) show this is exploitable but no benchmark measures the baseline safety delta.

**Relevant context:** AgentHarm ICLR 2025 limitations: 'English-only prompts, single-turn adversarial setup, inability to exhaustively test third-party APIs, focus on basic multi-step agentic capability rather than fully open-ended autonomous behaviors.' OpenAgentSafety (arxiv 2507.06134): 'combines real tool use, complex social interactions, diverse intents.' STAC attacks: 'sequences of seemingly innocuous tool calls that individually pass safety checks but collectively achieve harmful goals.' ASB ICLR 2025: 400+ tools, 23 attack types.
