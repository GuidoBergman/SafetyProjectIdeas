# Does Context Length Break SAE Feature Identification? Testing Features on Long vs. Short Contexts

**Problem:** Most SAE training and feature analysis is conducted on short text snippets (typically 256–512 tokens). However, models process much longer contexts in practice, and it is unknown whether SAE features identified on short contexts remain stable and interpretable when the same concepts appear in long-context settings. If features are context-length-sensitive, SAE-based interpretations may not apply to real-world deployments where long conversations are common.

**Direction:** Using SAELens on Gemma-2-2b (which supports longer contexts), identify 30 SAE features at layer 12 that are clearly interpretable from short-context top activating examples. Then construct matched pairs of inputs: a short-context version (the sentence containing the concept, ~50 tokens) and a long-context version (the same sentence embedded in a 512-token surrounding passage). For each feature, compare: (1) the activation magnitude on short vs. long context, (2) whether the feature still activates above the same threshold in the long-context version. Report the fraction of features that are context-length-stable vs. those that attenuate significantly in long context.

**Why it matters:** If SAE features found through short-context analysis don't activate reliably in long-context settings, then safety-relevant SAE interpretations may not transfer to the most important deployment scenarios (e.g., long agentic tasks, extended multi-turn conversations).

**Relevant context:** SAELens training typically uses short context windows, and most SAE feature analysis papers use short examples. Gemma Scope 2 (December 2025) now covers Gemma 3 models that support longer contexts, making this test newly feasible on accessible hardware.
