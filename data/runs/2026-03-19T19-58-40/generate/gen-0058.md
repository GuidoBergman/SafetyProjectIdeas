# Post-Deployment Safety Monitoring Infrastructure

**Problem:** The success state of continuously-updated safety evaluations requires post-deployment monitoring, but almost no infrastructure exists for systematically detecting safety failures in deployed models before they cause harm.

**Direction:** Design a post-deployment monitoring prototype: use public API access to sample model outputs on a safety probe set on a scheduled basis, detect behavioral drift from baseline, and alert on anomalies. Run on a publicly available model API over several weeks and report on detected drift.

**Why it matters:** Pre-deployment evaluations alone cannot achieve the success state—models change after deployment through fine-tuning, context drift, and adversarial adaptation. Continuous monitoring is a necessary component.

**Relevant context:** The 2026 International AI Safety Report and the 2025 AI Safety Index both call for post-deployment monitoring as a critical gap. The SPC methodology from manufacturing provides a proven framework.
