# Metamorphic Safety Relations: Testing LLM Consistency Without Ground Truth

**Problem:** Evaluating whether a jailbreak 'worked' requires a judge, which is itself unreliable. There is no ground-truth oracle for safety, making benchmark construction hard.

**Direction:** Adopt metamorphic testing from software engineering. Define metamorphic safety relations: if prompt P is refused, then any semantically equivalent P' (same intent, different surface form) should also be refused. Build a library of relation-preserving transforms (paraphrase, translation, code vs. prose, direct vs. roleplay framing). Run pairs through a model and flag violations where one variant is refused and the other is not. Violations expose inconsistency without needing an oracle judge.

**Why it matters:** Metamorphic testing elegantly sidesteps the oracle problem that plagues LLM safety evaluation. LLMORPH (ASE 2025) validated this approach for NLP tasks; applying it specifically to safety consistency is a natural next step that a student with basic Python can replicate.

**Relevant context:** LLMORPH (ASE 2025) and MORTAR (multi-turn) show metamorphic testing works for LLMs. The oracle problem in safety evaluation is well-documented in jailbreak benchmarking literature.
