# How Often Do Activation Patching Results Reverse Across Layers? Mapping the Instability of Causal Claims

**Problem:** Activation patching is used to identify which layers 'contain' information relevant to a model's output. A known but underreported failure mode is that patching conclusions can reverse across adjacent layers: a concept appears to be localized at layer N based on patching, but patching layer N+1 gives the opposite conclusion. This instability makes it difficult to make confident claims about where in a network specific computations occur.

**Direction:** Using TransformerLens on GPT-2 medium, run a systematic activation patching experiment on 50 factual recall prompts (e.g., 'The Eiffel Tower is in [Paris]'). For each prompt, do residual stream patching at every layer: patch in the activation from a clean run into a counterfactual run (where the factual answer is different). Record the logit difference change per layer. Then compute a 'reversal score' per prompt: the number of times the patching effect changes sign from one layer to the next. Report the distribution of reversal scores and identify whether factual prompts have more reversals than syntactic prompts.

**Why it matters:** High reversal rates mean that patching-based localization claims are sensitive to which specific layer is chosen. If researchers choose layers that happen to support their hypothesis while adjacent layers give opposite results, the field risks confirmation bias in circuit-based findings.

**Relevant context:** The 'localization' assumption in mechanistic interpretability is rarely tested for stability across adjacent layers. TransformerLens makes layer-by-layer patching straightforward, and this experiment is well-scoped for a 30-hour project.
