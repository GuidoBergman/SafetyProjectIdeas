# Program Slicing for Token-Level Information Flow

**Problem:** Attribution graphs show which features causally affect outputs, but the full computation graph is dense. It is hard to extract the minimal set of token positions and layers responsible for a single predicted token.

**Direction:** Apply program slicing (backward slicing from the output logit) through the residual stream: starting from the final logit, trace back only the components that have nonzero causal effect (via activation patching), discarding irrelevant paths. The result is a 'program slice' — a sparse subgraph of the transformer.

**Why it matters:** Program slicing is a mature technique from software analysis for reducing a program to only the statements relevant to a variable of interest. Applying it layer-by-layer through a transformer could yield cleaner, sparser explanations than full attribution graphs, which currently succeed on only ~25% of prompts (Anthropic 2025).

**Relevant context:** Static/dynamic program slicing is a standard software engineering technique. Relevance Patching (RelP, 2025) and causal tracing share philosophical similarity but do not explicitly implement slicing semantics.
