# Probing Whether SAE Features Causally Mediate Refusal Behavior

**Problem:** For mechanistic interpretability to support safety, we need to know whether identified features are causally upstream of safety-relevant behaviors (like refusing harmful requests) or merely correlated with them. There is currently a gap between identifying features that activate on refusal-related tokens and demonstrating that ablating or amplifying those features actually changes model behavior as predicted.

**Direction:** Using TransformerLens and a pretrained GPT-2 or similar model with available SAE weights, identify the top SAE features activating on refusal-related prompts. Then perform activation patching: zero out or amplify each candidate feature via SAELens hooks on 50 refusal prompts and 50 compliant prompts. Measure changes in output token probabilities and completion semantics. Compare causal effect sizes across features.

**Why it matters:** Backcasting from a world where interpretability can verify or guarantee model safety properties, we need tools that causally identify the mechanisms underlying safety behaviors. An experiment showing that specific SAE features causally mediate refusal would be a concrete step toward using interpretability for safety auditing rather than post-hoc storytelling.

**Relevant context:** Anthropic's 2025 attribution graph work on Claude 3.5 Haiku traces causal computation. OpenAI demonstrated SAE-based detection of emergent misalignment. Activation patching is well-supported in TransformerLens. This is achievable on GPT-2 Small or a small instruct-tuned model with SAELens in the 30-hour window.
