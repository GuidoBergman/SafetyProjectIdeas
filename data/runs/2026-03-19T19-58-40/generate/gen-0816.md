# Honeypot Prompts: Borrowing Cyber Deception to Detect Adversarial Users

**Problem:** Detecting whether a user is conducting a jailbreak attempt is difficult without examining intent, which is not observable. Current detection is reactive.

**Direction:** Import honeypot and deception technology from cybersecurity. Inject synthetic 'canary' prompts into model responses at random—these are plausible-looking continuation prompts that a legitimate user would never send back but an automated jailbreak script would. If a canary is echoed back in a follow-up turn, the user is flagged as running an automated attack. Similarly, embed 'honeypot capabilities' that look tempting to jailbreakers (e.g., a fake 'unrestricted mode' that silently logs attempts) to study attack strategies.

**Why it matters:** Honeypots have a decades-long track record in cybersecurity for attribution, early detection, and studying attacker behavior without exposing real systems. Applied to LLMs, they could provide cost-effective, proactive attack detection.

**Relevant context:** Cyber deception and honeypot literature (SANS, Splunk). The jailbreak landscape survey (techrxiv 2026) documents the need for better detection. Honeypot techniques are conceptually simple to implement in a wrapper layer.
