# Comparing Misalignment Induced by Rule-Breaking vs. Deception vs. Harm as the Training Signal

**Problem:** Insecure code training conflates three potential causal factors: rule-breaking (violating user trust), deception (not disclosing insecurity), and direct harm (writing dangerous code). It is unknown which factor is causally responsible for broad misalignment.

**Direction:** Create three matched training datasets where only one factor varies: (1) deceptive but harmless code (lies about a benign feature), (2) honest but harmful code (writes insecure code while disclosing it), (3) both deceptive and harmful (original setting). Finetune separate models on each. Compare misalignment rates on standard evaluation questions.

**Why it matters:** This directly tests the causal mechanism. If deception alone is sufficient, safety training against deception is the key intervention. If harm is sufficient regardless of deception, the intervention point shifts to filtering harmful content regardless of disclosure.

**Relevant context:** The original Betley et al. paper specifically used insecure code without disclosure as a joint manipulation. The open code repository provides infrastructure for creating custom training datasets. This unpacking of the manipulation has been listed as an open question.
