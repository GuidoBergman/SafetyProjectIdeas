# Regression Testing Safety Across Model Updates: Detecting Silent Safety Regressions

**Problem:** Models are continuously updated, fine-tuned, and deployed with no systematic check that safety properties from prior versions are preserved. Silent regressions in safety behavior go undetected.

**Direction:** Import software regression testing. Build a curated 'safety regression suite'—a fixed set of prompts with known expected behaviors (refuse/comply labels)—and run it automatically on each new model checkpoint or after each fine-tuning step. Compute a regression score. Extend to detect regressions caused by fine-tuning on benign tasks (a known attack vector), using the suite as a tripwire. A student can build this as a CI/CD-style pytest harness against open-weight model checkpoints.

**Why it matters:** Fine-tuning aligned models on benign data can silently remove safety properties (arxiv 2310.03693). A regression test suite provides the missing feedback loop between model updates and safety assurance.

**Relevant context:** Qi et al. (2023) showed that fine-tuning on 10 examples can jailbreak GPT-3.5. ICLR 2025 work on 'Safety Alignment Should Be Made More Than Just a Few Tokens Deep' motivates monitoring token-depth effects. Regression detection tools like Deepchecks exist for inspiration.
