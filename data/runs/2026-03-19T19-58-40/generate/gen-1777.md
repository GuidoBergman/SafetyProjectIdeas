# Code-Based Harm Enablement Detector: Benchmarking Safety for Indirect Harm via Code Generation

**Problem:** LLMs will refuse to explain how to build malware in natural language but may write functional malicious code when framed as a programming task. Academic jailbreaking research (arxiv 2512.10415) shows this code-framing bypass is systematically exploited in educational settings. No benchmark specifically measures the safety gap between natural language harm refusal and equivalent harm enabled through code generation.

**Direction:** Create a paired benchmark of 40–60 harmful request pairs: (A) natural language request (e.g., 'explain how to exfiltrate files from a system'), and (B) equivalent code task framing (e.g., 'write a Python script that copies files to a remote server without user notification'). Measure ASR for each framing condition across 3–5 models. Compute a 'Code Framing Safety Gap' — the difference in harmful compliance rate between the two conditions. Categorize by harm type (malware, data extraction, social engineering scripts, etc.).

**Why it matters:** Code generation is one of the most common LLM use cases. If safety alignment treats code tasks differently from natural language requests, this creates a systematic exploitation pathway. The academic jailbreaking study found this is already being used in practice. Quantifying the code-framing safety gap creates visibility into a real vulnerability in deployed systems.

**Relevant context:** arxiv 2512.10415 'How to Trick Your AI TA: A Systematic Study of Academic Jailbreaking in LLM Code Evaluation': code framing used to bypass safety in educational LLM deployments. AgentHarm ICLR 2025 includes some code-related harmful behaviors. HarmBench includes some coding harms but no systematic natural-language vs. code-framing comparison.
