# SAE Feature Drift Invalidates Production Control Monitors After Fine-Tuning

**Problem:** SAE features are trained on a specific model checkpoint. When the model is fine-tuned (RLHF, instruction tuning, capability updates), features may drift — the same feature ID may correspond to a different concept, or safety-relevant features may disappear. Control protocols continuing to use the original SAE monitor will silently degrade. Failure mode 1: feature drift is undetected. Failure mode 2: the monitor becomes miscalibrated without any visible alert.

**Direction:** Train an SAE on a small base model. Fine-tune the model on a small dataset (e.g., instruction following). Re-run the SAE on the fine-tuned model and measure cosine similarity of the feature dictionary before and after. Identify which features drift most. Test whether features associated with safety-relevant behaviors (refusal, honesty) drift more than general features.

**Why it matters:** In production AI control systems, models are regularly fine-tuned. If this automatically invalidates the interpretability layer without a visible failure signal, safety assurances silently erode — a critical gap in any continuous deployment pipeline.

**Relevant context:** SAE retraining costs and feature stability across fine-tuning checkpoints are flagged as open problems in the Oxford AIGI automated interpretability research agenda (2026).
