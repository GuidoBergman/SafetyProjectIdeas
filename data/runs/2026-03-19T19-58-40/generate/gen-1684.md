# Cross-Task Activation Probe Transfer: Do Deception Probes Trained on One Domain Generalize to Another?

**Problem:** Activation probes are typically trained and evaluated on the same domain (e.g., deception in text generation). It is unknown whether probes trained on one task type (e.g., answering factual questions deceptively) generalize to deception in a different task type (e.g., code generation with hidden backdoors).

**Direction:** Train deception probes on a factual QA task using a small open-weights model, then evaluate their TPR/FPR on code generation tasks where the model has been prompted to include hidden bugs. Repeat for a third domain (e.g., tool use). Produce a cross-domain transfer matrix. Investigate whether training probes on mixtures of domains improves cross-domain generalization.

**Why it matters:** Labs cannot train a separate probe for every possible task domain. Understanding transfer is essential for scalable deployment of activation monitoring.

**Relevant context:** Anthropic recommended directions (2025) list activation monitor generalization as open. Probe-first cascades are deployed at Anthropic and Google DeepMind but domain scope is not publicly characterized. The Dec 2025 fine-tuning evasion work motivates studying robustness from multiple angles.
