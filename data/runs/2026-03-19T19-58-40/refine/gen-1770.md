# Research Question

'Jailbreak Distillation: Renewable Safety Benchmarking' (EMNLP 2025 Findings) proposes methods for refreshing benchmarks, but the problem of staleness — how quickly existing benchmark prompts lose effectiveness as models are patched — has not been quantified systematically. Without measuring staleness rate, we cannot know how often benchmarks need renewal.

# Approach Outline

Select a fixed set of 100 jailbreak prompts from JailbreakBench or HarmBench that were published at known timestamps. Test these prompts against model versions with known training cutoff dates (using open models with version history, e.g., Llama 2 → Llama 3 → Llama 3.1). Plot ASR as a function of time elapsed since prompt publication. Compute a 'prompt half-life' — the time at which a prompt's ASR drops to half its original value. This characterizes how fast benchmarks need to be refreshed.

# Proposed First Experiments

Experiment 1 (Baseline): Set up experimental framework with a small public model. Replicate core measurement to establish baseline. ~8 hours.
Experiment 2 (Core): Apply methodology to target scenario. Measure primary metric vs baseline. ~12 hours.
Experiment 3 (Robustness): Test sensitivity to key parameters with 2+ variations. ~10 hours.

# Theory of Impact Chain

If benchmark prompts become ineffective within weeks of publication (because models are patched against known attacks), then static benchmarks are nearly useless for ongoing safety monitoring. A concrete 'prompt half-life' measurement would inform how frequently benchmarks must be renewed and motivates investment in renewable benchmark infrastructure.
