# Research Question

To what extent does ai companies make numerous safety claims in model cards, press releases, and safety reports. many of these claims are empirically testable but are never independently verified?

# Approach Outline

Build a Python pipeline that: (1) extracts safety claims from documents using an LLM, (2) classifies claims as testable vs. untestable, (3) for testable claims, searches for corroborating or contradicting evidence in published benchmarks and papers, (4) returns a verification status for each claim.

# Proposed First Experiments

Experiment 1 (Baseline): Set up experimental framework with a small public model. Replicate core measurement to establish baseline. ~8 hours.
Experiment 2 (Core): Apply methodology to target scenario. Measure primary metric vs baseline. ~12 hours.
Experiment 3 (Robustness): Test sensitivity to key parameters with 2+ variations. ~10 hours.

# Theory of Impact Chain

A prototype verification pipeline demonstrates the feasibility of automated safety claim auditing and surfaces the subset of claims that are currently unverifiable.

# Strength Rationale

theory_of_impact (4/5): Strong chain: automated claim verification directly enables accountability infrastructure. A working prototype would demonstrate feasibility and surface unverifiable claims, both valuable for governance.

accessible_complexity (2/5): Building a multi-stage NLP pipeline (extraction, classification, evidence search, verdict) requires advanced software engineering and NLP skills beyond beginner CS students.

narrow_scope (2/5): Four-component pipeline (extraction, classification, evidence search, verification) is too broad for 30 hours. Each component alone could be a project.

# Cited Sources

- Guo et al. (2022) 'A Survey on Automated Fact-Checking' in TACL provides a comprehensive framework for multi-stage NLP fact-checking pipelines (claim detection, evidence retrieval, verdict prediction) that directly matches this proposal's architecture
- FacTeR-Check (Borrego-Obrador et al., 2023) implements semi-automated fact-checking via semantic similarity and NLI, covering extraction-to-verdict pipeline
- ClaimBuster system already implements a four-component pipeline (claim monitor, claim spotter, claim matcher, claim checker) nearly identical to the proposed design
- Multiple LLM-based fact-checking systems exist (2024-2026) combining retrieval with parametric knowledge for automated verification
