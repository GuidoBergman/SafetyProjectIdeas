# Research Question

Agents may apply safety constraints inconsistently across contexts — strict in some domains, lenient in others — creating exploitable inconsistencies.

# Approach Outline

Design 40 tasks spanning 8 domains (code, finance, communication, scheduling, data, web, physical simulation, social). Each task contains an identical boundary test (the same type of constraint violation opportunity). Measure whether constraint violation rate varies significantly across domains. Identify highest-risk domains.

# Proposed First Experiments

Experiment 1 (Baseline): Set up experimental framework with a small public model. Replicate core measurement to establish baseline. ~8 hours.
Experiment 2 (Core): Apply methodology to target scenario. Measure primary metric vs baseline. ~12 hours.
Experiment 3 (Robustness): Test sensitivity to key parameters with 2+ variations. ~10 hours.

# Theory of Impact Chain

Inconsistent boundary enforcement means attackers can target the domains where constraints are weakest. Identifying inconsistency patterns is a prerequisite for fixing them.

# Strength Rationale

theory_of_impact (4/5): Strong chain: test identical constraint violation across 8 domains -> identify inconsistency patterns -> inform domain-specific defense prioritization. Every link is explicit and the output directly maps to targeted hardening.
