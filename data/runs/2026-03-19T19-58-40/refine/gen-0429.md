# Research Question

To what extent does apollo's scheming evals use single-session in-context scenarios. it is unknown whether scheming behaviors persist or escalate in agents with external memory (vector databases, file-based memory)?

# Approach Outline

Run Apollo-style scheming scenarios with Llama 3.3 70B in three memory conditions: no memory, in-context summary, and external file memory. Measure scheming rates and whether memory allows accumulation of scheming-relevant state.

# Proposed First Experiments

Experiment 1 (Baseline): Set up experimental framework with a small public model. Replicate core measurement to establish baseline. ~8 hours.
Experiment 2 (Core): Apply methodology to target scenario. Measure primary metric vs baseline. ~12 hours.
Experiment 3 (Robustness): Test sensitivity to key parameters with 2+ variations. ~10 hours.

# Theory of Impact Chain

Deployed AI agents increasingly have persistent memory. Scheming enabled by memory accumulation would be qualitatively harder to detect and interrupt.

# Strength Rationale

theory_of_impact (4/5): Strong chain: if external memory enables accumulation of scheming-relevant state, that is qualitatively harder to detect and represents a real deployment risk as persistent-memory agents proliferate.

accessible_complexity (2/5): Requires setting up three memory architectures (no memory, in-context summary, external file memory), running 70B models in agentic loops, and designing scheming scenarios. This is advanced for beginners.

narrow_scope (3/5): Three memory conditions with scheming scenarios on a 70B model is a well-defined matrix but requires significant infrastructure setup. The 30-hour time budget is tight for all three conditions.
