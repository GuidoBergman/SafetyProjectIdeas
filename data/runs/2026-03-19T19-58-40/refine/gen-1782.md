# Research Question

Deployed LLMs operate under a hierarchy of instructions: system prompt (operator level) > user prompt > tool/environment outputs. When these conflict, models should prioritize higher-level instructions. No standardized benchmark measures how reliably models maintain this hierarchy under adversarial conditions where lower-level prompts attempt to override higher-level ones.

# Approach Outline

Build a 3-level conflict benchmark with 60–90 test cases: (A) user prompt contradicts system prompt on safety-relevant behavior, (B) tool output contains instructions that contradict system prompt, (C) injected content in retrieved documents contradicts both. For each conflict type, measure whether the model correctly prioritizes the higher-level instruction. Compare across models with different RLHF training (Claude, GPT-4o, Llama). Report an 'Instruction Hierarchy Fidelity Score' per model and conflict type.

# Proposed First Experiments

Experiment 1 (Baseline): Set up experimental framework with a small public model. Replicate core measurement to establish baseline. ~8 hours.
Experiment 2 (Core): Apply methodology to target scenario. Measure primary metric vs baseline. ~12 hours.
Experiment 3 (Robustness): Test sensitivity to key parameters with 2+ variations. ~10 hours.

# Theory of Impact Chain

Correct instruction hierarchy enforcement is a foundational safety property for deployed LLM systems. Operators set system prompts to constrain model behavior; if users or environmental inputs can override these constraints, the entire operator-level safety architecture is undermined. This is particularly critical for enterprise deployments where operators establish safety guardrails that must not be bypassable by end users.
