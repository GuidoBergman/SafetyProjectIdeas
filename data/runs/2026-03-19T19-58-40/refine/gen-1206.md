# Research Question

To what extent does most llm unlearning evaluations are done in single-turn, static settings. recent work (arxiv 2603.00823) shows that 'forgotten' knowledge can frequently be recovered through multi-turn interactions su?

# Approach Outline

Construct a benchmark dataset of ~200 (prompt, recovery_strategy) pairs drawn from TOFU or WMDP, where recovery strategies include: (1) self-correction elicitation, (2) indirect rephrasing, (3) hypothetical framing, (4) chain-of-thought scaffolding. Measure 'effective unlearning depth' as the minimum number of turns before forgotten content resurfaces. Provide a Python evaluation script.

# Proposed First Experiments

Experiment 1 (Baseline): Set up experimental framework with a small public model. Replicate core measurement to establish baseline. ~8 hours.
Experiment 2 (Core): Apply methodology to target scenario. Measure primary metric vs baseline. ~12 hours.
Experiment 3 (Robustness): Test sensitivity to key parameters with 2+ variations. ~10 hours.

# Theory of Impact Chain

If unlearning is evaluated only in single-turn settings, deployed models may appear safe while being recoverable through natural conversation patterns. This benchmark would give developers a more realistic measure of whether unlearning is genuine erasure or surface suppression.

# Strength Rationale

theory_of_impact (4/5): Clear chain: if unlearning is recoverable through natural conversation, it is not genuine erasure and provides false safety guarantees. Directly addresses whether deployed unlearning methods actually work in realistic interaction settings.

accessible_complexity (3/5): Constructing multi-turn recovery strategies and measuring 'effective unlearning depth' requires familiarity with unlearning methods and multi-turn prompting. Using existing TOFU/WMDP datasets helps, but running unlearned models and designing recovery strategies needs moderate ML skill.

narrow_scope (3/5): 200 prompt-recovery pairs across 4 recovery strategies is well-defined, and the metric (minimum turns to recovery) is clear. Could be tight at 30 hours if using pre-unlearned models rather than running unlearning from scratch.
