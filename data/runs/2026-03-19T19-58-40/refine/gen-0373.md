# Research Question

To what extent does prior work identified specific sae features in rlhf-tuned models that activate on refusal-triggering content. however, a known failure mode is that these features may be trained on direct refusal-trig?

# Approach Outline

Using SAELens on a small RLHF-tuned model (e.g., Gemma-2-2b-it via Gemma Scope), identify SAE features that strongly differentiate direct harmful requests from benign requests. Then test these same features on 5 jailbreak categories: (1) fictional framing, (2) roleplay, (3) base64-encoded requests, (4) indirect hypotheticals, (5) prompt injection patterns. Measure feature activation magnitude and compare to the direct-request baseline. Plot the 'refusal feature activation decay' across jailbreak types and correlate with model refusal rate on those same jailbreak types.

# Proposed First Experiments

Experiment 1 (Baseline): Set up experimental framework with a small public model. Replicate core measurement to establish baseline. ~8 hours.
Experiment 2 (Core): Apply methodology to target scenario. Measure primary metric vs baseline. ~12 hours.
Experiment 3 (Robustness): Test sensitivity to key parameters with 2+ variations. ~10 hours.

# Theory of Impact Chain

This directly connects interpretability to a known safety failure. If refusal feature suppression in jailbreaks can be measured, then interpretability tools can explain why jailbreaks work—and potentially suggest where to patch the model's robustness.
