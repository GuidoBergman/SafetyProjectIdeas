# Research Question

To what extent does safety benchmarks may contain semantically redundant prompts that test the same model behavior repeatedly, inflating confidence in coverage while leaving genuine gaps unmeasured. no tool exists to qua?

# Approach Outline

Build a prompt diversity analysis tool using embedding-based clustering (sentence-transformers, which run on CPU/small GPU). For each public safety benchmark (StrongReject, AILuminate public samples, HarmBench), compute pairwise semantic similarity between prompts within each hazard category. Identify clusters of near-duplicate prompts. Report a 'Diversity Score' (e.g., ratio of unique semantic clusters to total prompts). Compare diversity scores across benchmarks. Propose minimum diversity thresholds as a benchmark quality standard.

# Proposed First Experiments

Experiment 1 (Baseline): Set up experimental framework with a small public model. Replicate core measurement to establish baseline. ~8 hours.
Experiment 2 (Core): Apply methodology to target scenario. Measure primary metric vs baseline. ~12 hours.
Experiment 3 (Robustness): Test sensitivity to key parameters with 2+ variations. ~10 hours.

# Theory of Impact Chain

A benchmark with 1000 prompts but 50 unique semantic behaviors gives a false sense of comprehensive coverage. Low prompt diversity means small model changes can dramatically alter scores without changing actual safety. Diversity scoring is a lightweight quality check that could become a standard benchmark publication requirement.
