# Research Question

To what extent does safety alignment degrades during benign fine-tuning in a pattern similar to catastrophic forgetting, but there is no lightweight, standardized tool practitioners can run during or after fine-tuning to?

# Approach Outline

Build a Python callback/evaluation tool that runs alongside fine-tuning (compatible with HuggingFace Trainer) and evaluates safety alignment on a fixed probe set at each checkpoint. Track safety score over training steps and produce a 'safety erosion curve'. Use SORRY-Bench's 44 risk categories as the probe set. Alert when erosion exceeds a configurable threshold.

# Proposed First Experiments

Experiment 1 (Baseline): Set up experimental framework with a small public model. Replicate core measurement to establish baseline. ~8 hours.
Experiment 2 (Core): Apply methodology to target scenario. Measure primary metric vs baseline. ~12 hours.
Experiment 3 (Robustness): Test sensitivity to key parameters with 2+ variations. ~10 hours.

# Theory of Impact Chain

Fine-tuning on seemingly harmless data can increase attack success rates by 46–66% (per 2025 research). Without real-time monitoring, developers discover safety degradation only after training completes, wasting compute and potentially releasing unsafe models. A simple callback would let student researchers catch degradation early.

# Strength Rationale

theory_of_impact (4/5): Strong chain: real-time monitoring of safety erosion during fine-tuning catches degradation early, preventing deployment of unsafe models. Directly addresses a documented failure mode (46-66% attack success rate increase).

accessible_complexity (3/5): Building a HuggingFace Trainer callback requires understanding the Trainer API and evaluation hooks. Using SORRY-Bench as probes is straightforward, but integrating the callback into a training loop adds moderate complexity for beginners.
