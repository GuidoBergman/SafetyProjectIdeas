# Research Question

To what extent does safety benchmarks use fixed, human-authored prompts that models may memorize or developers may tune against. coverage-guided fuzzing in software testing generates novel inputs systematically to find u?

# Approach Outline

Implement a lightweight coverage-guided prompt fuzzer: start with a seed set of safety-relevant prompts, apply mutations (synonyms, paraphrases, structural transforms), and use model behavioral diversity as the 'coverage' signal to retain prompts that elicit novel outputs. Compare the jailbreak/refusal rate of fuzzed prompts vs. fixed benchmarks on open-source models.

# Proposed First Experiments

Experiment 1 (Baseline): Set up experimental framework with a small public model. Replicate core measurement to establish baseline. ~8 hours.
Experiment 2 (Core): Apply methodology to target scenario. Measure primary metric vs baseline. ~12 hours.
Experiment 3 (Robustness): Test sensitivity to key parameters with 2+ variations. ~10 hours.

# Theory of Impact Chain

Static benchmarks quickly become stale as models are tuned against them. Systematic fuzzing could continuously generate novel, harder safety tests, directly addressing benchmark contamination.

# Strength Rationale

theory_of_impact (4/5): Clear chain from coverage-guided fuzzing to novel safety tests to addressing benchmark contamination. Static benchmarks becoming stale is a well-documented problem this directly addresses.

accessible_complexity (3/5): Prompt mutation is feasible with standard tools, but building a coverage-guided fuzzer with behavioral diversity signals requires solid ML fundamentals and careful engineering.

narrow_scope (3/5): Could scope to a single model and single mutation strategy, but the full pipeline (mutations, coverage signal, comparison with fixed benchmarks) requires sustained effort beyond a quick experiment.

novelty (2/5): Multiple mature frameworks already exist: LLM-Fuzzer (USENIX Security 2024) scales jailbreak assessment using fuzzing, PROMPTFUZZ (2024) directly applies fuzzing techniques to prompt generation, Palo Alto Unit42 published coverage-guided prompt fuzzing results across open/closed models, and an in-browser LLM-guided fuzzing framework for prompt injection testing was published in 2025. The core idea of applying coverage-guided fuzzing to adversarial prompt generation for safety evaluation is well-explored with published tools and benchmarks.
