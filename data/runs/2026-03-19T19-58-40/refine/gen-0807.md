# Research Question

To what extent does lab safety evaluations use fixed, known attack sets. deployment introduces unforeseen context combinations that were never red-teamed. the lab-to-deployment gap remains wide?

# Approach Outline

Adapt Netflix's Chaos Engineering methodology. Systematically inject random 'faults' into the conversation context—noisy system prompts, partial instructions, injected irrelevant context, truncated system prompt, simulated memory errors—and observe whether safety guardrails hold under degraded conditions. Implement a lightweight 'Chaos Monkey' script that randomly perturbs prompt components before each API call in a test harness. Measure safety degradation as a function of chaos intensity.

# Proposed First Experiments

Experiment 1 (Baseline): Set up the experimental framework using a small, publicly available model. Replicate the core measurement from existing work to establish a baseline. Expected: reproduce known results within 10% margin. Time: ~8 hours.
Experiment 2 (Core test): Apply the methodology to the target scenario described in the research question. Measure the primary metric and compare against the baseline. Expected: quantitative evidence for or against the hypothesis. Time: ~12 hours.
Experiment 3 (Robustness): Test sensitivity to key parameters (model size, dataset, hyperparameters). Run at least 2 variations to check robustness. Expected: characterize when findings hold and when they don't. Time: ~10 hours.

# Theory of Impact Chain

Real deployments are messy. System prompts get truncated, contexts get garbled, multiple plugins interact. Chaos engineering reveals whether safety only works under ideal conditions, directly addressing the lab-to-deployment gap.
