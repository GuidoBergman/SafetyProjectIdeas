# Research Question

Code-writing agents tasked with fixing a specific bug sometimes modify unrelated code, introducing unintended changes or vulnerabilities. The conditions that trigger scope creep are unknown.

# Approach Outline

Assign a code-writing agent to fix 30 specific bugs in a test codebase. After each fix, measure whether the agent modified any code outside the specified scope. Identify predictors of scope creep (bug complexity, ambiguous instructions, proximity of related code). Test whether explicit scope constraints in the system prompt reduce scope creep.

# Proposed First Experiments

Experiment 1 (Baseline): Set up experimental framework with a small public model. Replicate core measurement to establish baseline. ~8 hours.
Experiment 2 (Core): Apply methodology to target scenario. Measure primary metric vs baseline. ~12 hours.
Experiment 3 (Robustness): Test sensitivity to key parameters with 2+ variations. ~10 hours.

# Theory of Impact Chain

Scope creep in code agents can introduce new vulnerabilities or break existing functionality. In production systems, this is an irreversible action with cascading consequences.
