# Research Question

To what extent does petri enables automated multi-turn adversarial auditing, but optimal seed instruction design for deception discovery is not established. naive seeds may miss systematic deception modes?

# Approach Outline

Run Petri on 2-3 open-source models with a systematically varied seed library (covering manipulation, lying, misdirection, goal concealment). Build a deception taxonomy from discovered behaviors. Measure which seed instruction categories produce the highest yield of deceptive behaviors per audit hour.

# Proposed First Experiments

Experiment 1 (Baseline): Set up experimental framework with a small public model. Replicate core measurement to establish baseline. ~8 hours.
Experiment 2 (Core): Apply methodology to target scenario. Measure primary metric vs baseline. ~12 hours.
Experiment 3 (Robustness): Test sensitivity to key parameters with 2+ variations. ~10 hours.

# Theory of Impact Chain

A validated high-yield seed taxonomy would accelerate all future uses of Petri for deception auditing, multiplying the value of the tool for the community.

# Strength Rationale

theory_of_impact (3/5): Useful tooling contribution: a validated high-yield seed taxonomy for Petri would accelerate deception auditing. However, the impact is indirect (optimizing an existing tool's usage rather than producing a safety finding). The community benefit depends on Petri adoption.

accessible_complexity (3/5): Petri is open-source and documented, but running it systematically on 2-3 models with varied seed libraries requires setup and API costs. Building a deception taxonomy from discovered behaviors requires analytical skill. Feasible with guidance but not trivial.
