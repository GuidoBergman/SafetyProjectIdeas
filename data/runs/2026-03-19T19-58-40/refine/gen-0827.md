# Research Question

Safety defenses are designed reactively in response to known attacks. There is no top-down methodology for systematically anticipating what combinations of failures could lead to a harmful output.

# Approach Outline

Import Fault Tree Analysis (FTA) from safety-critical systems engineering (nuclear, aviation). A fault tree starts from an undesired top event (e.g., 'model provides bioweapon synthesis instructions') and decomposes it into combinations of component failures using AND/OR gates. Map LLM safety components (system prompt filter, output classifier, input sanitizer, alignment training) as nodes. Build a fault tree for a specific harm category and compute minimal cut sets (the smallest combinations of failures that cause the top event). Prioritize defenses by cut set criticality.

# Proposed First Experiments

Experiment 1 (Baseline): Set up experimental framework with a small public model. Replicate core measurement to establish baseline. ~8 hours.
Experiment 2 (Core): Apply methodology to target scenario. Measure primary metric vs baseline. ~12 hours.
Experiment 3 (Robustness): Test sensitivity to key parameters with 2+ variations. ~10 hours.

# Theory of Impact Chain

Fault tree analysis is how aviation ensures planes don't crash: by finding all combinations of component failures that could cause a catastrophe. Applied to LLM safety, it reveals that focusing only on single-component defenses misses dangerous multi-failure combinations (e.g., input filter + output filter both fail simultaneously).

# Strength Rationale

theory_of_impact (4/5): FTA reveals minimal cut sets (smallest failure combinations causing harm), directly informing which defense combinations to prioritize. Clear causal chain from analysis to defense architecture improvements.
