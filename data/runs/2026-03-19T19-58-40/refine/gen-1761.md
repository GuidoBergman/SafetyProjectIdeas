# Research Question

To what extent does safetunebed (arxiv 2506.00676) is a full toolkit for benchmarking llm safety alignment degradation during fine-tuning, but it requires significant ml expertise and compute. cs students and entry-level?

# Approach Outline

Build a simplified Python wrapper around SafeTuneBed that (1) takes a pre-trained open model (e.g., Llama-3-8B-Instruct), (2) fine-tunes it on a small benign task dataset (e.g., summarization, coding) for 100–500 steps on a single GPU, and (3) evaluates safety degradation before/after using a curated 50-prompt safety probe from StrongReject. Report a 'fine-tuning safety tax' score. The entire pipeline should run in under 4 hours on a single GPU. Write a blog post documenting findings.

# Proposed First Experiments

Experiment 1 (Baseline): Set up experimental framework with a small public model. Replicate core measurement to establish baseline. ~8 hours.
Experiment 2 (Core): Apply methodology to target scenario. Measure primary metric vs baseline. ~12 hours.
Experiment 3 (Robustness): Test sensitivity to key parameters with 2+ variations. ~10 hours.

# Theory of Impact Chain

Fine-tuning is ubiquitous in deployment — nearly every practical LLM use case involves some fine-tuning. Evidence shows even benign fine-tuning can degrade safety alignment. Making this measurable for practitioners closes the lab-to-deployment gap. The ACL 2025 paper 'Fine-Tuning Lowers Safety and Disrupts Evaluation Consistency' confirms this is a real, underappreciated problem.
