# Research Question

To what extent does there is no tool for continuously monitoring the diversity of outputs being produced by deployed ai systems, analogous to how financial regulators monitor market concentration in real time?

# Approach Outline

Build a prototype monitoring system that periodically probes a set of deployed model APIs with a fixed query set, computes ecosystem-level diversity metrics, and visualizes trends over time with threshold alerts.

# Proposed First Experiments

Experiment 1 (Baseline): Set up experimental framework with a small public model. Replicate core measurement to establish baseline. ~8 hours.
Experiment 2 (Core): Apply methodology to target scenario. Measure primary metric vs baseline. ~12 hours.
Experiment 3 (Robustness): Test sensitivity to key parameters with 2+ variations. ~10 hours.

# Theory of Impact Chain

Systemic risk monitoring requires ongoing surveillance, not one-time studies. A prototype would demonstrate feasibility and serve as a template for regulatory monitoring requirements.

# Strength Rationale

theory_of_impact (4/5): Strong chain: ongoing monitoring is necessary for systemic risk management. A prototype demonstrates feasibility and could serve as a template for regulatory requirements.

accessible_complexity (3/5): Web development, API integration, and visualization are intermediate skills. CS students can handle this with guidance, but the combination of backend, frontend, and API management adds complexity.

novelty (3/5): Multiple commercial platforms (Arize, Holistic AI, LangWatch) already provide real-time LLM monitoring dashboards. The FSB is actively working on AI systemic risk monitoring. The specific contribution of monitoring output homogeneity/diversity as a systemic risk metric is novel, but the dashboard infrastructure is well-covered commercially. Novelty is in the specific metric focus, not the monitoring approach.
