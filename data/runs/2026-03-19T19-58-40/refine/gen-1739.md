# Research Question

To what extent does model providers continuously update deployed models. attack success rates measured at one point in time may not reflect current deployment safety. there is little systematic data on how jailbreak asr ?

# Approach Outline

Run a fixed set of ~50 standardized jailbreak prompts (from StrongReject and AILuminate) against a public API model (e.g., GPT-4o-mini or Claude Haiku) on a weekly cadence for 6-8 weeks. Track whether ASR changes, and whether improvements on one attack category come at the cost of regressions on others.

# Proposed First Experiments

Experiment 1 (Baseline): Set up experimental framework with a small public model. Replicate core measurement to establish baseline. ~8 hours.
Experiment 2 (Core): Apply methodology to target scenario. Measure primary metric vs baseline. ~12 hours.
Experiment 3 (Robustness): Test sensitivity to key parameters with 2+ variations. ~10 hours.

# Theory of Impact Chain

The lab-to-deployment gap includes a temporal component: safety benchmarks measure a snapshot, not a process. If silent model updates cause safety regressions, current evaluation practices cannot catch them. Documenting this instability motivates continuous monitoring infrastructure.
