# Test-Retest Reliability Audit of Frontier Model Safety Evaluations

**Problem:** Safety evaluation scores are typically reported as point estimates, but model inference is stochastic (due to temperature sampling). Re-running the same evaluation on the same model may produce a different score. The under-studied link is the test-retest reliability of safety benchmark scores — if scores vary substantially across repeated administrations, decisions made from single-run evaluations are systematically unreliable.

**Direction:** Select 2-3 accessible models and 2-3 publicly available safety benchmarks (e.g., items from TruthfulQA, WildGuard). Run each model on each benchmark 5 times with temperature > 0. Compute: (1) intraclass correlation coefficient (ICC) across runs using R (irr package), (2) standard error of measurement (SEM) from classical test theory, (3) 95% confidence intervals around each benchmark score, (4) minimum detectable change (MDC) — the score difference needed to be confident a real change occurred. Compare ICC values to accepted reliability standards (ICC > 0.70 for low-stakes, > 0.90 for high-stakes decisions). Report what proportion of consecutive model version score differences (e.g., GPT-4 → GPT-4o) fall below the MDC, making them statistically indistinguishable from noise.

**Why it matters:** If a safety score has ICC = 0.60 and the regulatory threshold requires ICC > 0.90, then no deployment decision based on that score meets the evidential standard. Computing and reporting SEM and MDC is the minimum requirement for valid high-stakes evaluation reporting.

**Relevant context:** A 2025 paper ('Do Repetitions Matter?', arXiv 2509.24086) raises repeated measurement issues in LLM evaluation. Classical test theory SEM and ICC are standard in educational measurement. The irr R package computes ICC. This is directly achievable with API access and R, with no ML training.
