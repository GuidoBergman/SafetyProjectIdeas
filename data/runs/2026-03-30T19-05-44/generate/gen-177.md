# Test Blueprint Analysis for AI Safety Benchmarks: Auditing Domain Coverage Against a Principled Hazard Taxonomy

**Problem:** AI safety benchmarks lack formal content specification (blueprints) linking each item to a hazard taxonomy. Without blueprints, it is impossible to know whether a benchmark adequately covers the safety domain, whether some hazard categories are over-represented while others are absent, and whether a high overall score implies safety across all hazard types.

**Direction:** Select an existing AI safety benchmark (e.g., MLCommons v0.5, HarmBench, SORRY-Bench). Use the benchmark's existing taxonomy (or construct one using the MLCommons 13-category taxonomy) as the blueprint specification. Code each benchmark item to a taxonomy category. Compute item-per-category counts and compare to a theoretically motivated target distribution (proportional to hazard frequency/severity from incident databases). Identify under-covered categories. Simulate the effect on model rankings of reweighting items to match the blueprint. Recommend a blueprint specification for future benchmark construction.

**Why it matters:** Test blueprints are a prerequisite for content validity in educational measurement—every licensure and certification exam requires formal blueprints specifying the construct domain. Current AI safety benchmarks often lack explicit blueprints, meaning their 'coverage' is unverified. This analysis requires only item coding (which can be done by safety researchers) and descriptive statistics in R—no ML training. It could directly improve how safety benchmarks are constructed.

**Relevant context:** MLCommons AI Safety v0.5 uses a 13-category taxonomy but explicitly notes limited coverage. The 'How Should AI Safety Benchmarks Benchmark Safety?' paper (arxiv 2601.23112) critiques coverage gaps. Automated Test Assembly (ATA) literature defines content blueprint constraints as the primary driver of valid test construction. Coding items to taxonomy categories is a standard psychometric workflow. This specific blueprint audit applied to AI safety benchmarks appears to be a novel contribution.
