# Measurement Uncertainty Budget for AI Safety Benchmark Scores

**Problem:** A model's reported safety score (e.g., 84.3% on HarmBench) is reported as a point estimate with no uncertainty quantification. Physical metrology requires an explicit 'uncertainty budget' decomposing total measurement uncertainty into component sources. AI benchmarks have multiple sources of uncertainty (item sampling, prompt sensitivity, temperature, evaluator variance) that are never formally decomposed.

**Direction:** Apply GUM (Guide to the Expression of Uncertainty in Measurement) methodology to AI safety evaluation: identify all sources of uncertainty in a safety benchmark score, estimate the magnitude of each source using existing data (bootstrapping for sampling variance, repeated evaluations at different temperatures, etc.), combine using GUM propagation rules to compute a total standard uncertainty. Present scores as 'value ± expanded uncertainty (k=2, 95% confidence).' Implement for 3 benchmarks using Open LLM Leaderboard data in R.

**Why it matters:** Uncertainty budgets are required for any measurement used in regulatory or high-stakes decisions. Without them, AI safety scores give false precision. A model that scores 84.3% ± 6.2% is not meaningfully different from one scoring 80.1% ± 5.8%. Uncertainty quantification would immediately deflate overclaiming in the field.

**Relevant context:** GUM is the international standard for uncertainty quantification (ISO/IEC Guide 98-3). NIST traceability resources reference GUM. Open LLM Leaderboard provides repeated evaluations across runs allowing empirical variance estimation. R supports all needed computations. No model training required.
