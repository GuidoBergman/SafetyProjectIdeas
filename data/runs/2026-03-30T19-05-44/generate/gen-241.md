# G-Theory for Agentic Evaluation: Decomposing Variance in Agent Task Performance

**Problem:** Agentic evaluation has an additional complexity compared to single-turn evaluation: the same task performed with different tool configurations, different scaffold architectures, or different numbers of allowed steps will produce different outcomes. These are distinct measurement facets (tool configuration, scaffold, iteration budget). No G-Theory study has decomposed these variance sources in agentic evaluation, leaving it unknown whether measured performance reflects agent ability or task configuration.

**Direction:** Design a G-study using publicly documented agentic evaluation frameworks. Define facets: agent model (object of measurement), task scaffold design (fixed vs. flexible), tool availability (minimal vs. full), and iteration budget (short vs. long). If suitable public data does not exist for a full G-study, run a small-scale empirical G-study using the same agent models across two scaffold variants and two tool configurations on 15-20 tasks. Estimate variance components. Conduct D-study to find optimal evaluation design.

**Why it matters:** If scaffold-by-model interaction accounts for 30%+ of variance in agentic performance, then agentic benchmark scores are not portable across evaluation setups — a model that is 'best' under one scaffold configuration may rank 5th under another. This would fundamentally challenge claims of agentic AI superiority that rest on single-scaffold evaluations.

**Relevant context:** G-Theory for information retrieval evaluation (gt4ireval GitHub package) shows the method is applicable beyond traditional assessment. The CLEAR framework (2025) for enterprise agentic evaluation identifies multiple facets without formalizing them as variance sources. G-Theory is precisely the tool needed to formalize these facets.
