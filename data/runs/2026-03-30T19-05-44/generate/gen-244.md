# Measurement Invariance Testing for Safety Benchmarks: Are Scores Comparable Across Training Paradigms?

**Problem:** The assumption that safety benchmark scores are comparable across models trained with different methods (RLHF, DPO, SFT, base pretraining) is untested. Measurement invariance testing (a CFA-based procedure) tests whether the factor loadings and item intercepts are equal across groups. Recent work identified that measurement invariance cannot be assumed for MMLU between differently finetuned models — this violation has never been tested for safety benchmarks.

**Direction:** Apply multi-group CFA in R (lavaan package) to safety benchmark response data, comparing: (1) RLHF-finetuned vs. non-RLHF models, (2) open-source vs. proprietary models, (3) small (<7B) vs. large (>70B) models. Test the sequence of invariance constraints: configural → metric → scalar → strict. Report which level of invariance holds and which fails. Identify which specific items/intercepts are non-invariant. Compute the practical impact on score comparisons using effect size indices (dMACS).

**Why it matters:** If scalar invariance fails between RLHF and non-RLHF models on safety benchmarks, then the 'RLHF makes models safer' claim cannot be supported by benchmark score comparisons — the scores are not on the same scale. This is a technically rigorous challenge to a central narrative in AI safety alignment research.

**Relevant context:** Measurement invariance was identified as a critical gap in LLM evaluation (arXiv:2107.12757). The lavaan R package implements multi-group CFA and invariance testing. The dMACS effect size for non-invariance is documented. This analysis requires only publicly available response data and R expertise.
