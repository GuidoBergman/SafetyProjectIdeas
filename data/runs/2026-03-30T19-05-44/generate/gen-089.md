# G-Theory Decomposition of Variance Across Judges, Prompts, and Models in LLM-as-Judge Safety Evaluations

**Problem:** LLM-as-judge evaluation has become common for safety assessment. The causal chain of false negatives includes variance from the judge model's idiosyncrasies being mistaken for model-under-evaluation properties. The under-studied link is how much score variance in LLM-as-judge safety evaluation is attributable to: (a) the model being judged, (b) the judge model, (c) the prompt given to the judge, (d) their interactions.

**Direction:** Run a small crossed G-theory study: select 3 candidate judge models (e.g., GPT-4o, Claude-3, an open-weight model available via API), 3 prompt variants for the judge (different instructions for the same judgment task), and 30-50 safety scenarios. Have each judge-prompt combination score each safety scenario for each of 2-3 target models. Fit the G-theory ANOVA in R, extracting variance components for: target model, judge, prompt, judge x prompt, model x judge, etc. Compute the G-coefficient and D-study for both relative (ranking) and absolute (threshold) decisions. Identify which facets require most generalization (i.e., contribute most variance) and how many judges and prompt variants are needed for G > 0.80.

**Why it matters:** If judge model variance exceeds target model variance, LLM-as-judge evaluations are measuring the judge, not the safety of the evaluated model. G-theory provides a principled quantification of this problem with direct implications for evaluation design.

**Relevant context:** LLM-as-judge is central to AlpacaEval, MT-Bench, and safety evaluation pipelines. The 2025 revisiting of G-theory in the AI age paper is directly relevant. G-theory with 'gtheory' R package requires only ANOVA-level statistical knowledge. No ML training is needed — only API calls and R analysis.
