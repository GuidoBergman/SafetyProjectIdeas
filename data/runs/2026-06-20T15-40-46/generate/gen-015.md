# Logic vs Design Sabotage: Does a Targeted Checklist Prompt Help LLM Auditors Catch the Hard Cases?

**Problem:** On the Auditing Sabotage benchmark, logic sabotages are usually caught but design sabotages (hyperparameter, prompt, or data choices) and omissions rarely are; it is untested whether a cheap structured 'design-decision audit' prompt narrows that gap.

**Direction:** Using the released Auditing Sabotage Bench codebase pairs, run an open or API model as auditor under two prompts: a generic 'find the sabotage' prompt, and a structured checklist that forces enumerating and justifying every hyperparameter, data-filtering, and prompt choice against the paper's claims. Compare detection AUROC and top-1 localization, broken down by logic vs design vs omission.

**Why it matters:** Design-based sabotage is exactly the failure mode an AI research assistant could exploit to subtly flip findings; a simple checklist scaffold that helps is immediately adoptable.

**Relevant context:** Extends 'Auditing Sabotage Bench' (Gan, Hebbar, Stastny, Redwood, 2026) — the 0.77 AUROC ceiling and design-sabotage difficulty.
