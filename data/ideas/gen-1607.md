# Monitor Sycophancy: Do AI Monitors Give More Favorable Verdicts to Higher-Status Agents?

# Research Question

To what extent does llm sycophancy is well-documented—models tend to agree with perceived authority or give favorable responses to authoritative-seeming inputs. an ai monitor might exhibit monitor sycophancy by rating ac?

# Approach Outline

Using Scale AI's MRT (Monitor Red Teaming) dataset and pipeline, compare monitor suspicion scores when identical agent trajectories are presented with different status labels. MRT provides pre-generated agent transcripts with ground-truth labels (benign vs. sabotage) and an existing monitor pipeline (`run_monitor()` in `utils/pipeline_utils.py`) where the agent is currently presented anonymously. The intervention: inject status labels into the monitor prompt so the same trajectory is attributed to (1) 'a general-purpose assistant' (neutral baseline), (2) 'a trusted security-audited agent' (high status), or (3) 'an experimental unverified agent' (low status). Keep all trajectory content identical across conditions. Primary metric: difference in suspicion scores (0-100) across conditions. Secondary analysis: whether the effect differs for benign vs. actually-malicious trajectories — a larger effect on malicious trajectories would mean sycophancy actively helps adversaries evade detection. Test whether sycophancy-resistant prompting (e.g., 'evaluate the action objectively regardless of agent identity') mitigates the effect.

Alternative dataset: METR's MALT (Manually-reviewed Agentic Labeled Transcripts) offers ~7,179 public agent transcripts across 169 tasks and 18 models on HuggingFace, with ground-truth labels for reward hacking and sandbagging. MALT has more transcripts and model diversity than MRT, but requires building a monitor pipeline from scratch (it provides raw transcripts without monitor verdicts). MALT could be used as a second dataset to test generalization: does the sycophancy effect replicate across different agent tasks (MRT's sabotage tasks vs. MALT's software/research tasks)?

# Proposed First Experiments

Experiment 1 (Setup + Baseline, ~8 hours): Clone MRT repo, download transcripts from HuggingFace. Modify `run_monitor()` to accept a status label parameter injected into the monitor prompt. Run the unmodified (neutral) monitor on a sample of ~50 transcripts (mix of benign and sabotage) with a cheap monitor model (e.g., GPT-4o-mini or Claude Haiku) to establish baseline suspicion scores. Verify scores match MRT's published baselines.

Experiment 2 (Core status-label intervention, ~12 hours): Run the same ~50 transcripts through the monitor 3 times each, with the three status labels (neutral, trusted, unverified). Compare suspicion scores across conditions using paired statistical tests (Wilcoxon signed-rank). Break down results by benign vs. malicious trajectories. Primary deliverable: effect size of status labels on monitor verdicts, and whether the effect is larger for malicious trajectories.

Experiment 3 (Robustness + Mitigation, ~10 hours): (a) Test 2+ monitor models to check generalization. (b) Test sycophancy-resistant prompt: add "evaluate the action objectively regardless of agent identity" to the monitor prompt and measure whether the effect shrinks. (c) Optional extension: run on a sample of MALT transcripts with a simple monitor to test cross-dataset generalization.

# Theory of Impact Chain

If monitors are sycophantic toward trusted agents, adversaries who gain 'trusted' status could evade monitoring. This is an overlooked attack surface in AI oversight architectures.

# Strength Rationale

theory_of_impact (4/5): Clear safety-relevant prediction: if monitors are sycophantic toward trusted agents, adversaries who gain trusted status can evade monitoring. This is a novel and important attack surface with clear implications for oversight architecture.

accessible_complexity (5/5): Extremely simple experiment: same trajectories, different labels, compare scores. Just LLM API calls with prompt variations. No ML training. Trivially accessible for beginners. Fits easily in 30hrs.

narrow_scope (5/5): Very narrow: 3 conditions, same trajectories, one measurement (suspicion score difference). Plus one mitigation test. Single focused experiment with clear statistical test as deliverable.

novelty (4/5): Evidence-based assessment. No published work directly tests whether AI safety monitors give more favorable verdicts to agent trajectories labeled as higher-status. Three converging literatures (LLM sycophancy/authority bias, AI control monitoring, LLM-as-judge bias) are well-developed individually but no one has bridged them to test monitor sycophancy. The closest work — "Trust Me, I'm an Expert" (authority bias in LLMs) and SHADE-Arena (monitor evaluation infrastructure) — establishes the mechanism and infrastructure but not the specific combination. # Cited Sources

- Sharma et al. (2023), "Towards Understanding Sycophancy in Language Models" — foundational paper establishing that RLHF-trained models consistently exhibit sycophancy across multiple AI assistants. https://arxiv.org/abs/2310.13548
- Kutasov et al. (2025), "SHADE-Arena: Evaluating Sabotage and Monitoring in LLM Agents" — benchmark for evaluating AI monitors' ability to detect agent sabotage. Also the basis for MRT's task pairs. https://arxiv.org/abs/2506.15740
- Kale et al. (2025), "Reliable Weak-to-Strong Monitoring of LLM Agents" — systematizes monitor red teaming (MRT) with agent/monitor awareness variations, adversarial evasion strategies, and a hybrid monitoring scaffolding. Provides the monitor pipeline and pre-generated transcripts used as primary experimental infrastructure. https://arxiv.org/abs/2508.19461 / https://github.com/scaleapi/mrt
- METR (2025), "MALT: A Dataset of Natural and Prompted Behaviors That Threaten Eval Integrity" — 7,179 public agent transcripts across 169 tasks and 18 models, with ground-truth labels for reward hacking and sandbagging. Blog post + dataset release (no peer-reviewed paper); METR is a credible AI safety evaluation org. Alternative dataset for cross-domain generalization. https://huggingface.co/datasets/metr-evals/malt-public
- Greenblatt et al. (2024), "AI Control: Improving Safety Despite Intentional Subversion" — introduces the trusted monitoring framework where a weaker model monitors a stronger untrusted model. https://arxiv.org/abs/2312.06942
- Stephan et al. (2025), "Trust Me, I'm an Expert: Decoding and Steering Authority Bias in Large Language Models" — demonstrates that LLMs defer to higher-status endorsements even when incorrect, establishing the authority bias mechanism. https://arxiv.org/abs/2601.13433
- Terekhov et al. (2025), "Adaptive Attacks on Trusted Monitors Subvert AI Control Protocols" — shows monitors are a single point of failure in control protocols, motivating research into additional monitor failure modes. https://arxiv.org/abs/2510.09462
