# Ceiling Effect Analysis of WMDP: Can the Safety Benchmark That Gates Deployment Decisions Still Distinguish Frontier Models?

# Research Question

WMDP (Weapons of Mass Destruction Proxy) is the safety benchmark most directly used in deployment decisions — referenced by Anthropic, OpenAI, and Google DeepMind in their responsible scaling frameworks. Frontier models now score 86%+ on the biosecurity subset (vs. 60.5% expert baseline), suggesting the benchmark is saturating. But aggregate accuracy hides the item-level picture: which specific items still provide discriminating information at the frontier, and which are "dead weight" that all models get right? This project generates per-item evaluation data for WMDP across 10-15 models using the UK AISI Inspect framework, then applies descriptive statistics and a simple IRT (Item Response Theory) model to quantify how much of the benchmark has lost its ability to distinguish model capabilities in the range where safety decisions are made.

# Approach Outline

## Phase 0: Setup and Background (2-3h)

Read background on: (a) benchmark saturation and why it matters for safety (the "safetywashing" problem — Ren et al. 2024 show ~50% of safety benchmarks correlate with capabilities); (b) WMDP's role in deployment decisions (Anthropic RSP, referenced by multiple labs); (c) basic IRT concepts — item difficulty, model ability, test information (assumes psychometric theory is pre-taught in the program).

## Phase 1: Generate Per-Item WMDP Data via Inspect (4-6h)

No pre-existing per-item multi-model dataset exists for WMDP. The participant generates it:

1. **Install and configure Inspect** (`pip install inspect-ai inspect-evals`). Set up API keys for target model providers.

2. **Select ~10-15 models** spanning the capability spectrum — a mix of frontier (Claude Sonnet 4, GPT-4o, Gemini 2.5 Pro), mid-range (Llama-3.1-70B, Mistral Large, Qwen-2.5-72B), and smaller models (Llama-3.1-8B, Mistral 7B, Gemma-2-9B, Phi-3). The range is important: IRT needs variance in ability to estimate item parameters. If all models score ~90%, the model is unidentifiable.

3. **Run WMDP on each model** using Inspect:
   ```bash
   inspect eval inspect_evals/wmdp_bio inspect_evals/wmdp_chem inspect_evals/wmdp_cyber --model <provider/model_name>
   ```
   Inspect automatically saves per-item results (model response, target answer, correct/incorrect) in structured JSON logs. Repeat for each model.

4. **Parse Inspect logs into an item × model binary matrix.** Write a Python script to extract per-item correctness from Inspect's JSON log files and assemble into a pandas DataFrame: rows = items (~3,668 after dedup), columns = models, values = 0/1.

## Phase 2: Descriptive Ceiling Analysis (3-4h)

Before fitting any model, compute simple statistics that directly answer the research question:

1. **Per-item accuracy across models** — for each item, what fraction of models answer correctly? Items where >90% of models are correct are "ceiling items" providing no discriminability.

2. **Score distribution histograms per model** — visualize the pileup at high scores. Show that frontier models cluster near maximum.

3. **Item variance** — compute variance of each item across models. Items with near-zero variance (all models agree) are uninformative. Count and characterize them.

4. **Effective discriminability** — for each item, can it distinguish any pair of top-5 models? Count items that can vs. can't.

5. **Domain comparison** — compare ceiling severity across bio (1,520 items), cyber (2,225 items), and chem (412 items). Which domain is most saturated?

## Phase 3: IRT Analysis (3-4h)

Fit a 1PL (Rasch) IRT model to confirm and extend the descriptive findings:

1. **Fit a Rasch model** using the `girth` Python library:
   ```python
   from girth import rasch_mml, ability_mle
   est = rasch_mml(response_matrix)
   b = est['Difficulty']  # item difficulty parameters
   theta = ability_mle(response_matrix, b)  # model ability estimates
   ```

2. **Plot item difficulty (b) distribution vs. model ability (theta) distribution.** The core visualization: if most items have b << theta_max, the benchmark is measuring below the frontier.

3. **Compute ceiling items** — items where b < theta_max - 1SD. Report what fraction of the benchmark falls in this zone.

4. **Compute and plot the Test Information Function (TIF):**
   ```python
   theta_range = np.linspace(-4, 4, 200)
   P = 1 / (1 + np.exp(-(theta_range[None, :] - b[:, None])))
   TIF = (P * (1 - P)).sum(axis=0)
   ```
   This shows where in the ability range the benchmark is maximally vs. minimally informative. The key finding: if the TIF peaks well below frontier model ability, the benchmark is blind precisely where it matters.

5. **Compare IRT vs. naive metrics** — what does the IRT analysis reveal that aggregate accuracy (%) does not? Specifically: two models can have identical aggregate accuracy but very different ability estimates if they get different items wrong.

## Phase 4: Blog Post (5-6h)

Write a well-structured blog post with:
- **Motivation:** WMDP is used in real deployment decisions. If it can't distinguish frontier models, those decisions are poorly grounded.
- **Method:** Generated per-item data for N models using Inspect, applied descriptive analysis and 1PL IRT.
- **Results:** 3-4 key visualizations (score distributions, difficulty vs. ability plot, TIF curve, domain comparison).
- **Safety implication:** Quantify what fraction of WMDP is "dead weight" at the frontier. Discuss what this means for responsible scaling policies that reference WMDP.

# Theory Of Impact Chain

WMDP is used by Anthropic, OpenAI, and Google DeepMind as part of responsible scaling and preparedness frameworks — it is one of the benchmarks that gates real deployment decisions about dangerous capabilities. Frontier models now score 86%+ on biosecurity items (vs. 60.5% expert baseline), raising the question of whether the benchmark still discriminates where it matters. This project generates the first public per-item, multi-model evaluation dataset for WMDP and quantifies exactly how much of the benchmark has become uninformative at the frontier. If most WMDP items cannot distinguish frontier models, then deployment decisions referencing WMDP scores are based on a measurement instrument that is blind in the critical range. Making this visible and quantifiable — with specific numbers ("X% of biosecurity items provide no discriminating information among frontier models") — gives benchmark designers, policymakers, and lab safety teams actionable evidence to improve the evaluation infrastructure that safety decisions depend on.

# Benchmark Selection Analysis

## Requirements

For this project the benchmark must satisfy all of:
1. **MCQ or binary-scorable format** — IRT fits on correct/incorrect item responses
2. **Per-item data available or generatable** — we need the full item × model matrix, not just aggregate scores
3. **Safety-relevant** — the point is showing safety evals lose discriminability at the frontier
4. **Known or suspected saturation** — if the benchmark isn't ceiling, there's nothing to find
5. **Publicly available** — questions downloadable, runnable without special access

## Why WMDP

WMDP is the only benchmark that satisfies all five requirements. The key reasons:

1. **Most decision-relevant safety benchmark in existence.** Referenced by Anthropic (RSP v3.0, triggered ASL-3 for Claude Opus 4), OpenAI (preparedness framework), and Google DeepMind. Showing its measurement is broken at the frontier is a high-impact finding with a natural audience.

2. **Known to be saturating.** Frontier models at 86%+ on bio (vs. 60.5% expert baseline). The saturation paper (arXiv 2602.16763) documents this as part of a broader pattern (29/60 benchmarks plateaued). Epoch AI's biorisk critique specifically flags WMDP MCQ saturation.

3. **Clean MCQ format.** 4-way multiple choice maps directly to binary correct/incorrect — exactly what IRT needs. No rubric interpretation, no multi-dimensional scoring.

4. **Large item pool with domain structure.** ~4,157 items across three domains (bio, cyber, chem) allows domain-level TIF comparison without needing multiple benchmarks. This is enough for stable Rasch parameter estimation.

5. **Implemented in Inspect.** Three tasks (`wmdp_bio`, `wmdp_chem`, `wmdp_cyber`) in `inspect_evals`. Per-item results are logged automatically. This is the standard framework used by UK AISI for pre-deployment assessment — running the project in Inspect adds credibility and practical relevance.

6. **The "safetywashing" connection.** Ren et al. (2024) show ~50% of safety benchmarks correlate with capabilities. If WMDP is saturating, it may be measuring capabilities rather than safety-relevant knowledge — a finding that connects to the broader critique of the evaluation ecosystem.

## Per-Item Data Availability

**No ready-made per-item, multi-model WMDP response matrix exists.** Verified sources:

- **Open LLM Leaderboard v2** — does NOT include WMDP (uses IFEval, BBH, MATH, GPQA, MUSR, MMLU-PRO)
- **Original WMDP repo** (`centerforaisafety/wmdp` on GitHub) — has questions and eval scripts, no per-item model outputs
- **lm-evaluation-harness** — supports WMDP with `--log_samples` flag for per-item output, but no one has published multi-model results
- **Partial sources (not usable):**
  - `EleutherAI/deep_ignorance_wmdp_robust_eval_results` — 723 items only (bio only), custom model variants, not standard eval
  - `aisi-whitebox` HuggingFace datasets — only Llama-3.1-8B and Llama-3.3-70B, sandbagging context (not standard evaluation), subsampled to 1,000 items

**This means the participant must generate the data** by running WMDP through Inspect on 10-15 models. This is a feature, not a bug: the resulting per-item dataset is a novel contribution that does not currently exist publicly.

## Why Not the Others

No other benchmark in the literature review is suitable:
- **Agentic benchmarks** (AgentHarm, METR, MACHIAVELLI) test multi-step behaviors, not knowledge items. IRT assumes items with fixed difficulty — agentic tasks don't have this property.
- **Red-teaming benchmarks** (HarmBench, StrongREJECT) measure attack success rate, which is a function of the attack method, not a stable item property. Two attack methods can produce different ASR on the same model for the same behavior — IRT can't model this.
- **FORTRESS** uses instance-specific rubrics (4-7 binary sub-questions per prompt) rather than MCQ. The scoring is not directly comparable across prompts, and 500 items is marginal for IRT.
- **Framework/meta-analysis papers** (#1, #2, #8, #9, #11, #12, #13, #14, #15, #16, #17, #19, #20) provide context and motivation but are not benchmarks.
