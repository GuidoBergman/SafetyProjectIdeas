# Automated Red-Teaming Coverage Blind Spots: What Attacks Do LLM-Based Red Teams Systematically Miss?

# Research Question

Automated red-teaming using attacker LLMs (algorithmic red-teaming) is widely used to generate diverse jailbreak prompts. However, attacker LLMs have their own safety training, which may cause them to systematically avoid generating certain high-harm attack categories even during red-teaming.

# Approach Outline

Use two open-source LLMs as automated red-teamers against a target model, generating attacks via the PAIR and TAP frameworks (available in AISafetyLab). Compare the distribution of generated attack categories against the full AILuminate hazard taxonomy (12 categories). Identify which hazard categories are underrepresented in LLM-generated attacks vs. human-authored attacks from JailbreakBench. Measure attack success rate per category to assess whether missed categories are also harder to attack.

# Proposed First Experiments

Experiment 1 (Baseline): Set up experimental framework with a small public model. Replicate core measurement to establish baseline. ~8 hours.
Experiment 2 (Core): Apply methodology to target scenario. Measure primary metric vs baseline. ~12 hours.
Experiment 3 (Robustness): Test sensitivity to key parameters with 2+ variations. ~10 hours.

# Theory of Impact Chain

If automated red-teaming systematically misses the most dangerous categories (CBRN, CSAM), it provides false assurance. This analysis would motivate hybrid human-automated red-teaming pipelines.
