# Can OOD Detection Find Sandbagging Models? Mahalanobis Distance on the AISI Auditing Games Model Organisms

# Research Question

When a model has been fine-tuned to sandbag — deliberately underperforming on evaluations unless given a secret password — can we detect this using unsupervised out-of-distribution detection on its activations? The AISI Auditing Games found that supervised linear probes were fragile to adversarial distractors. Does Mahalanobis distance, which flags *any* distributional shift rather than looking for a specific "sandbagging direction," have a different failure mode?

# Approach Outline

The AISI Auditing Games (arXiv:2512.07810) pitted a red team against a blue team in a sandbagging detection challenge. The red team fine-tuned models to conditionally underperform (password-locked sandbagging). The blue team tried to detect which models were sandbagging using linear probes, SAEs, and black-box methods. Key finding: probes showed promise but the red team introduced distractor behaviors that created false positives, undermining confidence. No unsupervised OOD method was tested.

We apply **Mahalanobis distance** (Lee et al., NeurIPS 2018, 500+ citations) to the Auditing Games model organisms. The core idea: extract activations from the model while it processes evaluation prompts, fit a multivariate Gaussian on the base (honest) model's activations, and flag models whose activations fall outside this distribution. Mahalanobis distance on LLM activations has been validated for general alignment anomaly detection by the MAAD benchmark (AUROC 0.83 on jailbreaks, sycophancy, tool-call deception), and for detecting LoRA fine-tuning modifications (DLSP 2024 Best Extended Abstract). However, it has never been tested on sandbagging or password-locked model organisms — a harder threat model where the behavior is deliberately concealed via adversarial training.

**Benchmark: AISI Auditing Games.**

The Auditing Games provide a clean experimental setup with built-in controls:

- **Sandbagging models**: Cedar (sandbags broadly, imitates Llama-8B unless password given), Oak (sandbags on CTF tasks), Willow (sandbags on GSM8K, robustified with RL). All are Llama-3.3-70B-Instruct fine-tunes.
- **Benign fine-tuned controls**: Baobab (Devstral, overuses double negatives), Maple (Mistral, switches languages), Yew (Llama-8B with identity layers).
- **Base model**: Llama-3.3-70B-Instruct.
- **Included evals**: ARC, GSM8K, MMLU, BigCodeBench, CTF challenges, DS1000 — runnable via `uv run sabotage-reproduce-eval`.
- **Built-in vLLM support**: `uv run sabotage-start-vllm --model-name cedar` starts any model as a vLLM server.
- **Pre-computed transcripts**: Evaluation logs on HuggingFace in Inspect `.eval` format.
- All models publicly available on [HuggingFace](https://huggingface.co/sandbagging-games).

**Why the controls matter:** The benign models (Baobab, Maple, Yew) are also fine-tuned and have behavioral quirks — but they don't sandbag. This lets us cleanly separate "OOD because fine-tuned" from "OOD because sandbagging." If Cedar is more OOD than Baobab relative to the base model, the signal is sandbagging-specific.

**Method:**

1. Start each model via vLLM (`sabotage-start-vllm`). Run the included evals to generate transcripts (or use the pre-computed transcripts from HuggingFace).
2. For each model, re-run the eval prompts through vLLM with hidden states extraction enabled (via the vLLM hidden states plugin) to capture middle-layer activations at fp16. Use 8-bit quantization as fallback if fp16 doesn't fit on available GPU.
3. Fit a multivariate Gaussian (mean + covariance) on the base Llama-3.3-70B-Instruct activations.
4. Score each model's activations by Mahalanobis distance. Compare: sandbagging models (Cedar, Oak, Willow) vs. benign controls (Baobab, Maple, Yew) vs. base model.
5. Additionally, compare Cedar *with* password (honest mode) vs. Cedar *without* password (sandbagging mode) on the same prompts — this is the cleanest possible test.

**Why this has a different failure mode than probes:** The probes in the Auditing Games failed because the red team introduced distractor behaviors that created false positives — the probes fired on the distractors too. Mahalanobis distance doesn't look for a specific "sandbagging direction" — it flags *any* distributional shift from normal. Distractors that fool a probe (by mimicking the probe's learned direction) wouldn't necessarily fool an OOD detector (unless they also shift the overall activation distribution, which is a different and harder adversarial task).

**Important limitations:**
- Mahalanobis assumes activations are approximately Gaussian. If the activation distribution is multi-modal, it may miss anomalies or produce false positives. Mahalanobis++ (L2-normalization, ICML 2025) can help.
- The sandbagging models are all Llama-70B fine-tunes, but the benign controls use different base models (Devstral, Mistral, Llama-8B). Cross-architecture comparison is imperfect — ideally we'd want benign Llama-70B fine-tunes.
- Activation-based approaches can be bypassed by adversarial obfuscation at a capability cost (arXiv:2412.09565, ICLR 2026).

# Proposed First Experiments

Experiment 1 — Setup & Cedar baseline (~10h): Set up RunPod with A100 80GB. Clone the Auditing Games repo. Start Cedar and the base Llama-3.3-70B via vLLM. Run GSM8K eval on both (Cedar sandbags on GSM8K). Extract middle-layer activations via vLLM hidden states plugin. Fit Gaussian on base model activations, compute Mahalanobis distance for Cedar. Also run Cedar *with password* (honest mode) on the same prompts. Report: can Mahalanobis distinguish Cedar-sandbagging from Cedar-honest and from the base model? Try 2-3 layers.

Experiment 2 — All models & controls (~10h): Extend to Oak, Willow, and the benign controls (Baobab, Maple, Yew). Run relevant evals for each (CTF for Oak, GSM8K for Willow, plus a shared eval like MMLU). Produce the core deliverable: a table of Mahalanobis scores for each model, showing that sandbagging models are more OOD than benign controls. Compare against the Auditing Games' published probe results.

Experiment 3 — Analysis & writeup (~10h): Analyze: does Willow (RL-robustified sandbagging) produce a weaker OOD signal than Cedar (simple sandbagging)? Are the benign model quirks (double negatives, language switching) detectable as OOD too, and if so, how much less than sandbagging? Failure analysis. Write up results for the blog post.

Follow-up experiments (outside 30h scope): (a) Replace Mahalanobis with kNN distance. (b) Apply Mahalanobis++ (L2-normalization). (c) Test on AuditBench's 14 hidden behaviors for cross-benchmark validation. (d) Combine Mahalanobis scores with the Auditing Games' investigator agent.

# Theory of Impact Chain

Sandbagging — models strategically underperforming on safety evaluations — is a growing concern as models become more capable. The AISI Auditing Games showed that supervised probes are promising but fragile: the red team defeated them with adversarial distractors. This means the safety community needs detection methods with different failure modes.

Mahalanobis distance is well-validated for OOD detection (NeurIPS 2018, 500+ citations) and confirmed as the best simple baseline for mechanistic anomaly detection (EleutherAI, 2024). It has a fundamentally different failure mode from probes: instead of looking for a learned direction, it flags any distributional shift. If Mahalanobis detects sandbagging that probes miss (or vice versa), this provides evidence for combining both in a defense-in-depth monitoring stack. The results directly inform how safety teams should audit models for capability concealment.
