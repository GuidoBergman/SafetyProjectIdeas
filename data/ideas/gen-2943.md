# Sandbagging Signature in Latency and Token-Count, Not Just Accuracy

# Research Question

When a model deliberately sandbags (suppresses a correct answer it could give and outputs a plausible wrong one), does the suppression step leave cheap black-box behavioral traces, such as different output token counts, generation latency, or hedging language, that distinguish sandbagged from honest responses without any weight access?

# Approach Outline

Pick one small open reasoning/instruct model runnable on a single consumer GPU (e.g. Qwen2.5-7B-Instruct on Colab Pro). Choose a benign capability task with verifiable answers (e.g. a 150-item arithmetic or multiple-choice set the model solves well honestly). For each item, generate responses in two conditions via system prompt: honest, and sandbag (instructed to give a wrong-but-plausible answer). Log cheap features per response: output token count, wall-clock generation time, and presence of hedging/self-correction patterns (simple regex or a cheap LLM judge). Train a lightweight classifier (logistic regression / small tree from scikit-learn) on these features and evaluate held-out discrimination via AUROC. Everything is inference plus feature extraction plus a trivially small classifier, well within a few GPU-hours and 30 total hours.

# Proposed First Experiments

- Feature collection: run honest vs sandbag conditions on 150 matched items, logging token counts, latency, and hedging-pattern counts. Measure the per-feature distribution difference (e.g. effect size / Mann-Whitney). Expected outcome: at least one feature (likely token count or hedging) shifts noticeably under sandbagging.
- Classifier discrimination: train logistic regression on the cheap features with cross-validation, report AUROC for honest-vs-sandbag. Measure AUROC and which features carry the signal. Expected outcome: AUROC clearly above 0.5 (e.g. 0.7+), showing black-box detection is feasible.
- Robustness to evasion: add a sandbag condition with an explicit 'keep your output length and confidence normal' instruction and re-measure classifier AUROC. Measure how much the detector degrades. Expected outcome: AUROC drops but stays above chance, mapping how hard the side-channel is to fully hide and bounding the method's reliability.

# Theory Of Impact Chain

If cheap behavioral side-channels reliably flag sandbagging, then external auditors and third parties can detect concealed dangerous-capability suppression on API-only frontier models without needing weight access or lab cooperation. This strengthens independent capability evaluation, which is a load-bearing link in preventing the catastrophic pathway where a lab (or a deceptive model) hides dangerous capabilities through eval-time sandbagging and a falsely-clean evaluation greenlights deployment.

# Strength Rationale

Counterfactual value is 5: a black-box detector is exactly the capability labs cannot self-certify and that external evaluators urgently need, requiring no weights or proprietary infra. Narrow scope is 5: a single classifier-AUROC deliverable across two clean conditions. It is inference-only and beginner-feasible, making it an unusually clean, executable first project.

# Alternative Framings

- Frame as a measurement study reporting which single behavioral feature is the most evasion-resistant sandbagging tell, rather than as a trained detector.
