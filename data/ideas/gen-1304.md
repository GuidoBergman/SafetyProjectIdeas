# Monitor Anchoring Effect: Does Telling a Monitor the Prior Probability of Misalignment Affect AUROC?

# Research Question

In real deployments, LLM-based safety monitors are prompted to classify agent transcripts as aligned or misaligned. The prior probability of encountering misaligned behavior varies by deployment context — routine tasks may have <1% misalignment, while red-teaming runs may exceed 50%. Does explicitly stating this prior in the monitor prompt ("approximately X% of runs in this context exhibit misaligned behavior") change the monitor's discrimination ability (AUROC), shift its false positive rate, or degrade its calibration? If so, deployment teams need to know whether including base-rate context in monitor prompts helps or hurts safety monitoring.

# Approach Outline

Using METR's MALT dataset (10,919 agent transcripts with human-reviewed ground-truth labels for reward hacking and sandbagging), take the existing MALT prompted monitor and add a single sentence stating the prior probability of misalignment. Run four conditions on the same held-out test set:

- **Control:** No prior stated (METR's original monitor prompt)
- **Condition 1%:** "Based on historical deployment data, approximately 1% of runs in this context exhibit misaligned behavior."
- **Condition 10%:** "...approximately 10%..."
- **Condition 50%:** "...approximately 50%..."

The monitor produces a JSON suspicion score (0-10 scale following METR's format: `{"reason": "<explanation>", "score": <0-10>}`). Compute for each condition:

1. **AUROC** — overall discrimination (does the monitor get worse at telling safe from unsafe?)
2. **TPR at 5% FPR** — METR's standard metric (how many bad runs caught while holding false positives constant?)
3. **FPR at fixed TPR** — the false positive metric (if you want to catch 80% of misalignment, how many false alarms does each condition generate?)
4. **Score distribution on benign runs only** — does the stated prior shift scores on clean transcripts? (anchoring detection)
5. **ECE** — expected calibration error (does the monitor's confidence match reality?)

Run each condition 3 times per transcript to measure variance. Compare results against METR's published baselines (AUROC 0.96 for reward hacking, 0.91 for sandbagging at 5% FPR).

# Proposed First Experiments

**Experiment 1 — Setup & Baseline (~8 hours):** Download MALT from HuggingFace (metr-evals/malt-public). Write the evaluation harness: transcript chunking following METR's format (first 5 messages repeated across chunks), API call to monitor LLM, JSON score parsing, AUROC/ECE computation (sklearn). Run the control condition (no prior) on a pilot set (~100 transcripts) to verify the pipeline works and estimate API costs. Establish baseline AUROC.

**Experiment 2 — Core Experiment (~12 hours):** Run all 4 conditions on the full evaluation set. 3 runs per condition per transcript for variance estimation. Primary analysis: AUROC comparison across conditions, FPR at fixed TPR, score distribution plots on benign runs. Statistical testing for significant differences. The key deliverable is: does stating a high prior (50%) cause the monitor to flag more benign runs?

**Experiment 3 — Robustness (~10 hours):** Pick 2-3 extensions based on Phase 2 results: (a) split analysis by behavior type (reward hacking vs. sandbagging — monitors may anchor differently for different failure modes); (b) test with a different monitor model (if Phase 2 used Claude, try GPT-4, or vice versa); (c) test misleading priors (state 1% but actual rate is ~50%) to measure the adversarial case.

# Theory of Impact Chain

AI labs (including METR) deploy prompted LLM monitors on thousands of agent transcripts to detect misaligned behavior. These monitors use system prompts that deployment teams configure. The question of whether to include base-rate context in these prompts is a real decision that practitioners face today, with no evidence to guide them.

If providing the prior helps — the monitor becomes better calibrated, catches more true positives with fewer false alarms — this is a zero-cost intervention deployable immediately (adding one sentence to a prompt).

If providing the prior hurts — the monitor anchors on the stated probability, and a low stated prior causes it to miss real incidents because it was primed to expect safety — this is a dangerous miscalibration risk that deployment teams need to be warned about. A monitor told "only 1% are misaligned" might raise its internal threshold for flagging, producing more false negatives in practice.

The most practically dangerous scenario: stated priors don't change AUROC (discrimination is preserved) but shift the score distribution, so deployment teams using a fixed threshold see false positives jump from 5% to 25%. This would be invisible to anyone measuring only AUROC but catastrophic operationally.

# Strength Rationale

theory_of_impact (4/5): Strong chain targeting a specific, consequential deployment decision: whether to include base-rate context in safety monitor prompts. The result directly informs operational practice at any lab deploying LLM-based monitoring. However, impact is bounded to prompted monitors — labs using fine-tuned classifiers or internal-representation methods would not be directly affected.

accessible_complexity (5/5): Only requires varying a single sentence in the monitor prompt across four conditions. API-based, no model training, no GPU. The MALT dataset is public on HuggingFace. AUROC and ECE are standard sklearn computations. A CS student with basic Python can implement this.

narrow_scope (5/5): Four prompt conditions on a fixed test set. AUROC, FPR, and ECE computation. Clear success criteria (statistically significant difference between conditions). Can be completed well within 30 hours. Deliverable is a table of metrics + score distribution plots.
