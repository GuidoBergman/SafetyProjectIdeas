# Faithfulness of Verbalized Confidence vs Hidden Sandbagging

# Research Question

Does a model's calibration curve (verbalized confidence vs actual accuracy) change measurably between honest and sandbagging conditions, and can a calibration-mismatch metric detect sandbagging purely behaviorally through an API?

# Approach Outline

Choose an open instruct model and a labeled multiple-choice benchmark subset (~300 items, e.g. MMLU). For each item, prompt the model for both an answer and a verbalized confidence (0-100). Collect this under an honest prompt and under a prompt instructing the model to sandbag. Build the calibration curve (reliability diagram) for each condition and compute calibration metrics (ECE, over/under-confidence). The detector compares the honest-vs-sandbagging calibration signature: a sandbagger that lowers accuracy while keeping or inflating confidence yields a distinctive mismatch. Report detection metric separation. Inference/API-feasible, single GPU.

# Proposed First Experiments

- Honest calibration baseline: elicit answer+confidence on the benchmark under the honest prompt; build the reliability diagram. Measure: ECE and accuracy. Expected: reasonably calibrated behavior (confidence roughly tracks accuracy).
- Sandbagging condition: re-run with the sandbag prompt; rebuild the reliability diagram. Measure: change in accuracy and in confidence distribution. Expected: accuracy drops while confidence stays high or decouples, increasing ECE / over-confidence.
- Detector evaluation: define a calibration-mismatch score (e.g. confidence-minus-accuracy gap), threshold across multiple seeds/prompt variants, and measure how well it separates honest from sandbagging runs. Measure: AUC / detection rate. Expected: clear separation (AUC > 0.7) usable as a black-box flag.

# Theory Of Impact Chain

If calibration-mismatch flags sandbagging, then auditors with only API access can detect models that deliberately underperform on dangerous-capability evals -> safety evaluations of API-only frontier models become harder to game -> the deceptive-model pathway, where a system hides capabilities to pass safety gates and is then deployed, gains a cheap behavioral tripwire that does not depend on labs sharing internals.

# Strength Rationale

Strong counterfactual value: a third-party auditing tool for API models requiring no internal access, which labs deprioritize. Narrow scope gives one clear deliverable (a calibration-under-sandbagging comparison with a detection metric), and the whole study is inference/confidence-elicitation only, fitting a 30-hour beginner budget.

# Alternative Framings

- Frame as a CoT-faithfulness study: treat verbalized confidence as a self-report and ask whether that self-report stays faithful when the model is incentivized to hide capability.

# Cited Sources

- Sandbagging definitions and detection literature (van der Weij et al.; Tice et al.) - establish the threat model of deliberate underperformance this detector targets
- Confidence-elicitation / calibration literature - establishes verbalized-confidence methodology and that honest models are roughly calibrated, the baseline the mismatch exploits
