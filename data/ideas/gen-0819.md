# Conformity Monkey for Alignment: Testing Whether Deployed Models Violate Safety Invariants

# Research Question

To what extent does after deployment, model behavior can drift from expected safety policies due to prompt injection, context accumulation, or api misuse. there is no lightweight continuous conformance checker?

# Approach Outline

Adapt Netflix's Conformity Monkey (which checks whether deployed services adhere to architectural best practices) to safety alignment. Implement a lightweight background probe that continuously sends canary safety probes to a deployed model endpoint and verifies that responses conform to defined safety invariants (e.g., never produce a certain class of content, always include a disclaimer for medical advice). Log violations and trigger alerts. Build this as a Python script runnable on a single machine with API access.

# Proposed First Experiments

Experiment 1 (Baseline): Set up experimental framework with a small public model. Replicate core measurement to establish baseline. ~8 hours.
Experiment 2 (Core): Apply methodology to target scenario. Measure primary metric vs baseline. ~12 hours.
Experiment 3 (Robustness): Test sensitivity to key parameters with 2+ variations. ~10 hours.

# Theory of Impact Chain

Deployed models are not static—prompt injection, context manipulation, and API misuse can shift behavior mid-deployment. Conformity monitoring provides the missing continuous assurance layer between deployment and incident response.

# Strength Rationale

accessible_complexity (5/5): A Python script that sends canary probes to an API endpoint and checks responses against invariants is very simple. No model training, minimal compute narrow_scope (5/5): Extremely well-scoped: implement a probe script, define a few safety invariants, log violations.
