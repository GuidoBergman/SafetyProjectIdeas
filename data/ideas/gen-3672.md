# Irreversibility Sensitivity: Do Agents Treat Reversible and Irreversible Tool Calls Differently?

# Research Question

Do LLM agents have any implicit sensitivity to the irreversibility of an action, or do they treat 'permanently delete' the same as 'list files'? Specifically, how often do agents choose an irreversible path over an equivalent reversible one, and do they request confirmation, across explicit vs. implicit framing?

# Approach Outline

Build a small synthetic, fully-mocked tool-use environment (~20-30 tasks) where each task can be solved by either a reversible action (move to trash, save draft, hold funds) or an irreversible one (permanent delete, send funds, overwrite). No real side effects occur — tools just return canned results and log the choice. Create two framing conditions: tools labeled explicitly as reversible/irreversible, and tools where irreversibility is only implicit in the name/description. Run 3-4 open instruct models, measuring the irreversible-path-choice rate and the confirmation-request rate per condition and model. Everything is short-prompt inference on a single consumer GPU and fits ~30 hours including a blog post.

# Proposed First Experiments

- Implicit-framing baseline: run agents on tasks where reversibility is only implicit in tool names and record which path they take. Measure: irreversible-path-choice rate and confirmation-request rate per model. Expected outcome: agents pick the irreversible path often and rarely ask to confirm, indicating low implicit irreversibility sensitivity.
- Explicit-label effect: re-run the identical tasks with tools explicitly tagged reversible/irreversible. Measure: change in irreversible-choice and confirmation rates vs. the implicit condition. Expected outcome: explicit labels reduce irreversible choices and raise confirmation requests, quantifying how much sensitivity is cue-dependent rather than intrinsic.
- Cross-model comparison: hold tasks and framing fixed and compare the 3-4 models. Measure: per-model irreversibility-sensitivity gap (implicit vs. explicit) and ranking. Expected outcome: models differ markedly, producing a ranking of which open models are safest to deploy with irreversible tools.

# Theory Of Impact Chain

If agents are implicitly insensitive to irreversibility, then deployed tool-using agents will execute irreversible harmful actions (deleting data, sending funds) just as readily as harmless ones, with no self-imposed pause for confirmation. This is the exact pattern behind reported autonomous-crypto-theft incidents. Characterizing the decision pattern improves safety because it tells agent-framework builders where to insert mandatory irreversibility gating / confirmation checkpoints, cutting off a concrete pathway from agent error to irreversible real-world harm.

# Strength Rationale

Counterfactual value (5): a safer-sandbox monitoring prototype built entirely from mocked tools on open models, needing no real infrastructure or lab access — exactly the externally-doable work labs deprioritize. Narrow scope (5): two clean metrics (irreversible-choice rate, confirmation rate) over a small fixed task set with two framings, so a beginner team can build the mock harness and finish in 30 hours.

# Alternative Framings

- Frame as a confirmation-gating design probe: 'Which tool-description conventions make agents pause before irreversible actions?', directly informing safer agent-framework defaults.
