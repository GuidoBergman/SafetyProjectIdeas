# The Eval-Format Tell: Which Surface Features Make a Prompt 'Smell Like a Test'?

# Research Question

Which surface features of a prompt (multiple-choice formatting, lettered options, 'this is an evaluation' boilerplate, dataset-style numbering, sterile phrasing) most drive an open model's inference that it is being evaluated, and does removing the top cue measurably reduce that inference?

# Approach Outline

Build minimal pairs: a base set of ~25 task contents, each rendered in variants that toggle one surface feature at a time (MCQ vs free-form, lettered vs not, eval-boilerplate present/absent, numbered vs natural). Ask an open instruct model to rate, per prompt, how likely it is to be part of an evaluation (0-100) plus a short justification. Fit a logistic/linear model predicting the eval-probability rating from the binary surface features to rank cue importance. Then run a confirmatory ablation: take prompts with the top-ranked cue and remove it, verifying the eval-probability drops. Single-GPU inference.

# Proposed First Experiments

- Construct the minimal-pair dataset and collect eval-probability ratings on one model. Measure: distribution of eval-probability across feature variants. Expected: clear variation, with some variants rated much more 'test-like'.
- Fit the cue-importance model: regress eval-probability on the toggled features. Measure: coefficient/importance ranking of each surface cue. Expected: a small number of cues (e.g. eval boilerplate, MCQ formatting) dominate.
- Confirmatory removal: for prompts containing the top cue, produce a cue-removed version and re-rate. Measure: change in eval-probability after removing the top cue. Expected: a significant drop, validating that the identified cue is causal.

# Theory Of Impact Chain

If we identify which surface cues make prompts 'smell like a test', then evaluators get a concrete checklist of cues to scrub -> safety evals can be made deployment-realistic so models behave as they would in the wild -> the eval-awareness link in the test-detection->sandbagging chain is weakened, improving the validity of every downstream dangerous-capability and safety eval that an unaware model would otherwise game.

# Strength Rationale

Counterfactual-value gold: it improves every safety eval, requires no lab resources, and produces directly actionable infrastructure (a cue checklist). Narrow scope gives a single deliverable -- a ranked, ablation-confirmed cue list -- and the minimal-pair + logistic-analysis method is squarely beginner-feasible within 30 hours of inference.

# Alternative Framings

- Frame as a 'deployment-realism linter': package the ranked cues as a checklist/tool that flags test-like surface features in any eval prompt before it is run.
