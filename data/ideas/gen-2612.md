# Sequential Probability Ratio Test for Audit-Budget-Efficient Monitoring

# Research Question

Can Wald's Sequential Probability Ratio Test (SPRT) decide how many monitor queries a flagged action warrants, achieving the same safety as fixed-N auditing while using far fewer monitor calls per decision?

# Approach Outline

Treat each monitor query on a flagged action as a noisy binary/score signal and accumulate a log-likelihood ratio across repeated cheap queries until it crosses an accept ('safe') or reject ('audit') threshold set from target false-alarm and miss rates. Replay logged control trajectories (e.g. from Ctrl-Z / control-protocol benchmarks), simulate repeated monitor draws per flagged action (resampling the monitor with temperature, or bootstrapping from its score distribution), and compare SPRT's average monitor-calls-per-decision against a fixed-N policy at matched error rates. This is pure sequential statistics over logged data plus light monitor resampling, fully runnable on a single consumer GPU or API in a few hours.

# Proposed First Experiments

- Implement SPRT on a controlled synthetic monitor: simulate safe/unsafe actions with known monitor-score distributions, run SPRT to a target FNR/FPR. Measure: average samples to decision vs fixed-N at equal error rates. Expected outcome: SPRT reaches the same error rates with substantially fewer samples on average (classic Wald result).
- Apply SPRT to replayed real trajectories: on logged flagged actions, draw repeated monitor scores and run SPRT. Measure: monitor-calls-per-decision and realized FNR/FPR vs a fixed-N=k baseline. Expected outcome: 30-60% reduction in average monitor calls at matched safety on the 'easy' decisions, with more calls spent only on ambiguous actions.
- Sensitivity to monitor miscalibration: perturb the assumed likelihood model (wrong score distribution) and rerun SPRT. Measure: how error rates and average sample size degrade under model mismatch. Expected outcome: SPRT remains efficient under mild miscalibration but its error guarantees drift, yielding a practical caveat for protocol designers.

# Theory Of Impact Chain

If SPRT cuts monitor calls per decision at fixed safety, then a fixed audit budget can be spread across more actions (or freed for human review), so control protocols catch the same sabotage at lower cost or catch more at the same cost. Better-spent audit budget tightens the runtime barrier against an untrusted scheming model executing harmful actions undetected, the core failure mode AI control aims to prevent.

# Strength Rationale

Counterfactual value and narrow scope are maximal: the work is statistics-only over logged trajectories, needs no training, proprietary data, or lab infrastructure, and delivers a single crisp metric (monitor-calls-per-decision at matched safety) that protocol designers can act on. It imports a provably sample-optimal, well-understood tool (SPRT) into a control niche that academic labs and frontier labs alike underweight publicly.

# Alternative Framings

- Cast it as adaptive compute allocation for monitoring: SPRT is the mechanism for spending more inference on suspicious actions and less on obviously-clean ones, connecting to inference-time-compute-budget framings of control.
