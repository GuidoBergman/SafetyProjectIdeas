# Mapping the Failure of Sparse Feature Representations Under Distributional Shift: SAEs Trained on Web Text Applied to Code

# Research Question

To what extent does saes are almost universally trained on web text corpora. when the same sae is applied to a different distribution (e.g., code, scientific text, non-english text), the feature activations may be sparse?

# Approach Outline

Using SAELens, load a pre-trained SAE for GPT-2 small or Gemma-2-2b trained on WebText. Compute feature activation statistics on two OOD datasets: (1) The Stack (Python code, ~10k samples), (2) PubMed abstracts (scientific English, ~10k samples). Compare to in-distribution WebText statistics: (a) mean L0 sparsity (do OOD inputs trigger fewer features?), (b) the overlap in top-20 active features between WebText and OOD inputs, (c) whether the most active features on OOD inputs have coherent interpretations when their top examples are from WebText (they may activate on irrelevant patterns). Report a 'domain transfer quality score' for each OOD domain.

# Proposed First Experiments

Experiment 1 (Baseline): Set up experimental framework with a small public model. Replicate core measurement to establish baseline. ~8 hours.
Experiment 2 (Core): Apply methodology to target scenario. Measure primary metric vs baseline. ~12 hours.
Experiment 3 (Robustness): Test sensitivity to key parameters with 2+ variations. ~10 hours.

# Theory of Impact Chain

Code models and scientific models are increasingly important for safety. If SAE-based interpretability tools trained on general web text do not transfer to these domains, then separate domain-specific SAEs are required for every application—a major practical obstacle for deploying interpretability tools in safety-critical contexts.
