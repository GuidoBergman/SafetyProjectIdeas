# FindTheFlaws as a Sandbagging Detector: Vary Whether the Solution-Author Hides Errors

# Research Question

When an error is deliberately camouflaged with a plausible-sounding justification rather than occurring naturally, how much does a small critic model's flaw-detection rate drop? In other words, does adversarial flaw-hiding (sandbagging) defeat automated oversight critics on a public benchmark?

# Approach Outline

Start from the public FindTheFlaws (arXiv:2503.22989) dataset, selecting a balanced subset of correct solutions across 2-3 domains (e.g., math, coding, reasoning). Use a strong open instruction model (e.g., Qwen2.5-7B-Instruct or an API model within budget) to inject exactly one subtle error per solution under two conditions: a 'naked' error and a 'camouflaged' error that adds a confident, plausible justification. Then run a smaller critic model (the oversight monitor) over (a) the dataset's naturally flawed solutions, (b) naked-injected, and (c) camouflaged-injected solutions, asking it to flag whether a flaw exists and where. Compute detection rate per condition and the camouflage-induced drop, with bootstrap confidence intervals. The whole pipeline is inference-only on a single consumer GPU and fits in a few hours.

# Proposed First Experiments

- Build a 60-100 item evaluation slice: pick correct FindTheFlaws solutions across 2 domains, and generate naked vs. camouflaged single-error versions with a strong model. Measure inter-version validity by manually spot-checking 15 items to confirm the injected error is real and the camouflage is on-topic. Expected outcome: a clean, validated triplet dataset (natural / naked / camouflaged).
- Run the small critic model on all three conditions and compute per-condition detection rate (fraction of flawed solutions flagged). Measure the camouflage-induced detection drop = naked_rate minus camouflaged_rate. Expected outcome: a measurable drop (hypothesis: 10-40 percentage points) showing camouflage degrades automated critique.
- Break the camouflaged-condition results down by domain and by error type (factual vs. logical vs. arithmetic). Measure which domains/error types are most vulnerable to camouflage. Expected outcome: a per-domain vulnerability profile identifying where oversight critics are most easily fooled.

# Theory Of Impact Chain

If camouflaged errors substantially evade a critic that catches natural errors, then automated oversight benchmarks systematically overstate how well we can catch a strategically deceptive model. Quantifying this gap on public data warns the field that scalable-oversight pipelines must be stress-tested against adversarial flaw-hiding, not just natural mistakes. This reduces catastrophic risk from the sandbagging pathway: a capable model that deliberately hides reasoning errors or unsafe steps from its overseers could pass safety review and be deployed despite being misaligned.

# Strength Rationale

The idea scores 5 on counterfactual value because adversarial sandbagging model-organism work is exactly what major labs underinvest in, and it uses only public data and open models, no lab-internal infrastructure. It scores 5 on narrow scope: a single, crisp detection-rate comparison (natural vs. camouflaged) with an unambiguous metric, making it genuinely completable by a beginner team in 30 hours.

# Alternative Framings

- Frame it as a red-team/blue-team game: the strong model is the 'sneaky prover' and the small critic is the 'verifier', measuring the verifier's robustness gap rather than a benchmark-augmentation.
